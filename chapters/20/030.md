将参数为 (3, 0)、(3, 1)、(3, 2) 的 T\_worker 放进同一个线程束。假想我是 CUDA Runtime，对它做 Single Step。以最后写入像素的操作为例，下标是 ScreenRow 乘 1920 加 Column。每个线程的 PC 相同，所以都会先把 Row load 到寄存器，或者计算 Row 乘 1920，写入寄存器。

所有线程执行同样的动作，但寄存器的值可能不同。保存 Row 乘 1920 的临时寄存器里，都是 3 乘 1920；加上 Column 后，分别得到 3 乘 1920 加 0、3 乘 1920 加 1、3 乘 1920 加 2，寄存器的值就不同了。

寄存器值不同，下一步操作仍然完全相同：把 color 写到 screen 中算出的下标。整个线程束都执行一条 Store 指令。如果有 CUDA 模拟器，对它 single step，就能看到要写入的地址依次是 3 乘 1920 加 0 等位置，写入值来自各自的寄存器。

下一次写入对应 1920 加 1 的相邻位置，数据来自另一个寄存器。add 或 move 是寄存器内部的操作；这里的 load、Store 则将多个线程的访问合成一条很长、地址连续的访问。我们 computer scientists 喜欢连续访问，连续地址有助于用好内存控制器的带宽。

这又回到了前面的 SIMD。AVX512 可以在动态流水线里，将 512 字节内存 load 到一个 ZMM 寄存器，再把 ZMM 寄存器 Store 到 512 字节内存。这里的 Single Instruction, Multiple Threads 自然产生了类似效果：32 个线程，每个写 4 字节，一个 Stream，也就是 Stream Processor，就能产生 32 乘以4 的写入。

这样可以形成一个 128bit 的 Store。还可以更长：刚才每个线程做四字节 Store，如果换成 64 位整数或 64 位浮点数，每个线程乘 8，就能形成 256bit 的 Store。
