这个想法对你们可能很自然。NES 的 PPU 接收一个小数据结构，可以理解成 struct sprite，比如有 64 个 sprite。PPU 执行固定渲染流程，将它们画出来。要画的内容越来越复杂时，人们就会想：能否直接提供一种编程语言，用程序描述？

既然都是描述，写一段程序，编译后在 GPU 上并行执行，也没有根本困难。当时的图形处理器越来越复杂，要做矩阵乘法、处理贴图，已经接近通用处理器，只是并行度更高。于是有了 shader，也叫着色器。这个名称带着时代特点，因为它是在图形渲染管线中出现的。

先看 vertex shader。原先一个 sprite 包含 x、y 和其他信息。现在可以有一个程序 P，也可以理解成 tvertex：T\_vertex 接收所有 vertex，或者通过匹配决定接收哪些 vertex，并允许修改它们。程序中可以给 this\.x、this\.y 赋值。

也可以修改顶点颜色等其他信息。CPU 先构造基础场景，再把经过编译的程序装到 GPU 里。显卡每看到一个顶点，就执行这段固定程序，修改顶点。它的 killerapplication 是什么？改变顶点坐标，可以让顶点轻微扭动，实现水面波纹、毛发摆动等效果。

这些计算原本要在 CPU 上完成。毛发很多，水面波纹也需要大量计算，但每个顶点做的事相同，和 Mandelbrot set 类似。有一个t，根据当前坐标在水面上的位置，以及可能的上一时刻水面状态，通过波的方程计算，就能用 vertex shader 修改这个点的坐标。
