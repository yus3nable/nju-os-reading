我们之前学了线程库：有 Spawn，还可以在 Spawn 的基础上加入互斥锁、信号量、条件变量等互斥和同步操作，控制并发程序的执行。控制并发执行时，我们脑中有一个计算图：有些部分可以并行，有些部分不能并行。不能并行的部分要按顺序执行，能并行的部分就尽可能放出去执行。之前讲的很多机制，都是在线程上实现各种计算图。

要把计算图实现好，并不简单。一个思路是让线程尽可能轻量。我们从 Python 的 generators 讲到协程，再讲到 Go 语言的 Goroutine：用起来和线程一样，又能像协程一样轻量。另一个途径是在编程语言里提供支持。编译器受到我们的控制，原则上，甚至可以允许在编程语言里嵌入一段自然语言，让它帮忙并行执行。在编程语言的发展中，我们已经可以用 JavaScript 的 event\-based concurrency，通过 Promise API 描述计算图。

比如创建几个 HTTP 请求，用 Promise\.all 等待它们全部结束。此前讨论的都是 CPU 上的并行和并发模型。今天是时候推翻 CPU 在计算上的统治了，我们来看看这意味着什么。
