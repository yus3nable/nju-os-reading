这个代价无法接受：假设每个线程有 1kb 的 cost，创建 200 万个线程就不可能了。CUDA 允许创建大量线程，但会小心地将它们调度到实际硬件上。刚才那个设想中，每个 CPU 都要有 ALU，也要各自保留一份 registers。

T\_worker 被送到 CPU，或者说 GPU 执行单元上。例如有多个 T\_worker，参数分别为 (3, 0)、(3,1)、(3, 2)。

课件中的三个相邻像素写入片段；省略其他线程，color\_0 等表示各线程计算的结果。

```
screen[3 * 1920 + 0] = color_0;
screen[3 * 1920 + 1] = color_1;
screen[3 * 1920 + 2] = color_2;
```

于是，三个执行单元的寄存器分别保存 3 和 0、3 和 1、3 和 2。每个像素都要计算 Mandelbrot set 的颜色，因此还要有一个寄存器保存最后算出的 color。也可以有更多寄存器，比如保存循环变量 i。每个执行单元都有 ALU 和寄存器，接下来要让它们并行执行。

图 56：各执行单元的 ALU、寄存器与不同线程参数（01:19:36）。

CPU 上把三个线程分别加载到三个 CPU，它们就各自执行，没有同步。spawn 后放出去执行，需要等待结束时再 join。GPU 则引入了线程束，也叫 Thread warp，将它们捆在一起。不过，只有 ALU 和数值寄存器，还无法执行程序，还缺什么？

还缺 Program Counter。只有它，处理器才知道下一条该执行什么指令。CPU 中，每个 CPU 都有独立的 Program Counter，也各有一套取指和译码部件。

译码要占用电路。你们写过 NEMU 的译码逻辑，指令只有 32 个字节，译码却需要大量 if\-else：是不是 Jump，是不是 LoadStore，Load 的是一个 byte、两个 byte 还是四个 byte？在实际电路中，这些信息各自对应一根线，要占用电路、逻辑门和触发器。

这里将线程捆起来，是指它们没有独立 PC，一捆线程只共享一个 PC。在现代 NVIDIA 实现中，一个 Thread warp 有 32 个线程，也就是 32 个执行相同代码的 T\_worker。共享 PC，就只需要一套译码单元，省下了电路，也减少了 overhead。

寄存器不能省，否则无法计算和执行指令；ALU 也不能省，否则无法并行。保留这些必需电路，将 PC、Decoder 等可共享部件只放一份，就能减少相对于实际计算的开销，让交的税很少。

这就是 CUDA 的 Single Instruction，Multiple Threads 模型，单指令多线程。只有一个 PC，一次让许多 T\_worker 一起向前执行一步。接着看参数为 (3, 0)、(3, 1)、(3,2) 的线程放在一起后，会发生什么。
