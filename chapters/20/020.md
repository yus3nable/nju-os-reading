回到图形渲染，我们有一个描述。描述的方式很多：可以用寄存器，比如用 XY 寄存器记录坐标；也可以把 Sprite Buffer 放在内存中，通过内存映射读写。只要描述好一个数据结构，就可以让另一套硬件专门把它变成图形。

数据结构就是一组数据，平坦地存储在内存里。无论用寄存器还是内存，都可以理解成你们做 NEMU 时的 Struct CPU State。这次对应的是 Struct GPU State，也就是 GPU State，里面保存 XY 等信息。什么样的硬件能把这个状态变成图形？

GPU 就是一个程序，负责将 State 翻译成像素，而且这个程序是 embarrassingly parallel 的。NES 的GPU 大致这样工作：逐行扫描。硬件内部可以看作有一个叫 Line 的寄存器，从 0 到 1，逐行扫过整个画面。他们设计硬件时并没有按这个程序思路实现，但在硬件上实现的就是这样的过程。

第 0 行做完，再做第 1 行、第 2 行，这是时序逻辑电路。我在伪代码中借用 OpenMP，有一点“作弊”：用它表示这些事情好像并行完成，同时扫过前景的 64 个 Sprite。

扫描到某个像素时，先确定背景颜色，只要做一个加法就能取出。然后匹配每个 Sprite，算出这个像素上叠了几个 Sprite，取优先级最高的颜色。这有些像今天的 Zbuffer：图形逐层覆盖，只能看到最上面的一层。

如果扫完所有 Sprite，都没有与当前像素相交，就显示背景颜色，这样完成图形组合。逻辑门可以并行，因此能同时处理多个像素，但未必一次就处理整行。可以再用一个叫 Chunk 的寄存器。你们实现过计数器电路，用计数器就能得到类似循环的效果。

![图 34：行与 chunk 两级计数控制固定电路的扫描（00:53:37）。](/assets/images/20/0034.webp)

图 34：行与 chunk 两级计数控制固定电路的扫描（00:53:37）。

Line 从 012 开始逐行向后扫描。如果每行分成 10 个 Chunk，Chunk 就从 0123456789 依次计数。每个 Chunk 计算 20 个或 32 个像素，并行求出它们的值。数据结构固定，处理逻辑也固定，就可以把计算固化成电路。这个想法反复出现，比如矿卡。如果意识到 1983 年 NES 就做过类似的事，在比特币热潮时想到把 hash 部分固化到电路里，可能就发大财了。这就是早期 PPU，用固定电路实现并行化。
