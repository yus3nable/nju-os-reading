对于 CPU 的 state，每次调用 rv32ima\_step，就向前执行一小步。但我们也讲过，顺序执行只是 CPU 精心维护的假象。程序里写下 x 等于 1、y 等于 2，这两条语句最终会编译成指令，在 CPU 里并行执行。我们再看一些细节。

图 3：CPU 的顺序语义、逻辑门并行与指令级并行（00:02:11）。

逻辑门天生可以并行。前几天我和大一同学聊天，大家抱怨数字逻辑电路课要用 Logisim 连接一个很大的电路，觉得没有意义：用编程语言可以写 for 循环，创建 100 个、1000 个、10000个东西，编写的代价都一样；手动连线却费力。有同学说，这极大地提升了他操纵鼠标的精准度。不过，Logisim 的电路图能给人直观的感受：信号从左边传到右边时，所有逻辑门同时执行。逻辑门组成的系统天生并行，可以放很多逻辑门。既然能一次从内存取出 32 个 bit，也就可以在电路上设计成一次取出 64 个或 128 个 bit。一个 load 指令可以这样设计；如果同时取出两条指令，还可以送到两份电路上分别译码。

译码后，我们知道一条是 mov eax，另一条是 mov rbx。还可以加一组电路，判断两条指令能否并行执行，或者彼此是否存在需要等待数据的依赖。如果可以并行，就用电路把两个值写入两个寄存器。你们都实现过双口的 register file，可以选择两个寄存器，同时写入两个值。从理论上看，让 CPU 同时执行两条指令没有根本困难。

现在的 CPU 内部可以说都有一个“编译器”。它处理的不止两条指令：CPU 内部有一条很长的队列，每个时钟周期会固定往里放指令，可能是三条、四条或更多指令。我用 compiler 作比方未必很合适，但至少可以说，CPU 里有一个数据流分析器。

它能知道某条指令要等另一条指令算出结果才能执行，以及某条指令可能产生什么后果。队列中要保存很多信息，未必全是译码信息。有些指令执行快，有些慢，比如发生 cache miss 时，这条指令可能很慢。理论上，只要分支预测一直正确，指令执行速度最终又能跟上，就能一直保持很高的执行速度。
