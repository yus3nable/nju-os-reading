无论 for each vertex，还是 for each fragment、pixel，都是对每个顶点或像素并行执行。既然程序可以控制，能否用来做通用计算？大约 2001 年，就有了这样的尝试。我这里的 digital library 因为网络原因一直打不开，不知道为什么。我建议读一下这篇论文，下面的图就摘自论文。当时，研究者尝试将 GPU 用于 general purpose 计算。

他们用可编程 shader，把科学计算问题转成图像处理问题。今天从 computer scientist 的角度看，这有些奇怪：似乎应该直接编程。但他们把矩阵乘法变成图片。假如矩阵来自天气预报计算，图片看起来可能很随机，在图像意义上并不合理。不过，一旦变成图片，就能利用渲染管线中的 vertex shader、Pixel shader 进行计算。

比如矩阵乘法可以分解为行列向量外积的和，也就是 pairwise 的 product 再相加。我们常用内积，较少用外积。外积看起来有些浪费：一行向量和一列向量做外积，得到一个完整矩阵，rank 却只有 1。

结果只包含这两个向量的信息，却生成了整个矩阵。但把它转成点 BMP，再送到显卡上运行，如果显卡比 CPU 快很多，这样做可能仍有收益。论文讨论了如何将矩阵乘法分解为外积之和。一旦转成外积，矩阵就是图片，显卡就能处理；相对来说，内积在显卡上更复杂。他们用外积生成图片，最后再把几张图片叠加。

图片叠加也能用 Pixel shader 完成，就是 for each pixel，把对应值加起来。
