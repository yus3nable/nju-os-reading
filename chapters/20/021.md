PPU 将画图从 CPU 中解放出来。在这个过程中，游戏产业发展起来；娱乐是人的天性，NES 热卖后赚了很多钱，就能聘请世界上最好的软硬件工程师，开发下一代产品。图形处理器要做的是把数据结构变成图像，描述格式并不局限于规则排列的背景块加上 64 个前景块。

![图 35：从 PPU 到 2D 贴图渲染引擎（00:54:39）。](/assets/images/20/0035.webp)

图 35：从 PPU 到 2D 贴图渲染引擎（00:54:39）。

任何数据结构都可以，只需满足两个条件：CPU 有足够算力，能在一帧时间里生成描述；硬件能把描述变成图像。随着 CPU 和 GPU 发展，就可以使用大小可变的贴图，还能对它的四个顶点做线性变换。可以想象成一张有弹性的小纸片，拉动角，纸片和像素就相应拉伸。贴图可以放大、缩小、裁剪，再拼到画布上，这也是合理的图形描述方式。比如描述一个 bitmap，以及它在屏幕上的 x1，y1，x2，y2，对应左上角、右上角，再给出 x3，y3，x4，y4。当然，实际设计未必如此，这样讲是为了方便理解。

可以指定 ROM 中的 bitmap \#1，也就是 number1，贴到屏幕哪里，再指定 bitmap number2 的位置，依次描述。这也是一个 massive parallel 问题：对每个像素遍历每个 bitmap。

![图 36：把 bitmap 贴到屏幕上的不同位置与形状（00:57:01）。](/assets/images/20/0036.webp)

图 36：把 bitmap 贴到屏幕上的不同位置与形状（00:57:01）。

找到对应的颜色，取最上层颜色，就能画出图形。即使完全二维的 2D 图形引擎，也能实现许多效果。它原本用来画卷轴、马里奥、金币等二维图形。刚才的动画中，把 logo 拉伸、放大，就有了放大特效；再经过其他处理，还能实现模糊。这个游戏看起来是 3D，却是用二维模拟出来的：把矩形向不同方向挤压，就能形成 3D 效果。

![图 37：V\-Rally 3 中的车辆展示画面（00:58:08）。](/assets/images/20/0037.webp)

图 37：V\-Rally 3 中的车辆展示画面（00:58:08）。

仔细看，3D 贴图有些不对，因为没有深度信息，只是强行挤压成这个形状。旋转角度不能再大，否则就会穿帮。不过，游戏实际运行起来的效果仍然很酷，通过旋转一张张图片，就能拼出一个 3D 游戏。

![图 38：V\-Rally 3 运行中的道路与车辆画面（00:58:45）。](/assets/images/20/0038.webp)

图 38：V\-Rally 3 运行中的道路与车辆画面（00:58:45）。

它已经算好了整个三维世界的坐标，最后仍用二维贴图拼出 3D 的样子。随着镜头移动，背景部分可以变小，前景部分可以变大。这是 Gameboy Advance 掌机上一款有代表性的游戏。
