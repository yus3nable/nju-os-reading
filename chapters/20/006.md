instruction level parallelism 意味着什么？CPU 设计者作出了一个艰难的决定。做加法需要的电路，无非是超前进位加法器；乘法也有固定的电路。这些运算电路放在 ALU 里。与、或、非等位运算更省电路，浮点运算的电路会稍大一些。但如果要在 CPU 里放入一个“编译器”，再放一个 1024 项的队列，情况就不同了。

队列要支持 push 和 pop，每个队列项要用一个 bit 记录有没有东西，还要记录队头位置。电路里只能做出类似 array 的结构，队列却要不断向后增长，再绕回前面，所以它是循环的。除了维护 FIFO 队列，还要维护“编译器”和数据流分析器，分析队列中任意两条指令是否存在数据依赖。

理论上，这需要 Nsquare 的复杂度。当然，有些聪明的办法可以降低复杂度。但这些队列和分析电路会占用大量电路，挤占运算部件的空间。每个门电路的翻转也要消耗能量：如果一个时钟周期内，整个模块都不动，比如时钟信号没有送来，或者 enable 信号未启用，这个电路就没有功耗。

一旦逻辑门从 0 变 1，或者从 1 变 0，就会发热。“编译器”和动态流水线部分的功耗，可能比实际执行指令大很多，比如计算一个 1 并写入寄存器。编程时，我们看到指令 1、2，认为先执行 1，再执行 2；为了让它们同时执行、加快速度，处理器要付出这些代价。
