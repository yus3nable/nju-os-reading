语法围绕文本替换设计。c 的预处理、预编译也如此，\#define 可以定义字面常量，甚至宏自身并非合法表达式，只要替换进上下文后有效。比如用括号拼接。

预编译器做字面替换，shell 也继承这种方式。用 dollar 括号，就能把程序结果作为字符串贴进命令。

![图 99：用宏展示预处理器的文本替换（01:24:17）。](/assets/images/08/0099.webp)

图 99：用宏展示预处理器的文本替换（01:24:17）。

屏幕上的宏定义与替换结果片段：

```
#define X ), (

( ), ( )
```

还可以把程序结果包装为文件描述符，贴入它的路径。比如 echo 1，或网络上动态取回的数据，不想先另执行命令存文件，就能生成路径，再用 cat 读取。

这里生成 /dev/fd/63，读它就得到命令全部输出。比如从两个网页抓数据，接着 diff。

![图 100：进程替换生成文件描述符路径（01:25:57）。](/assets/images/08/0100.webp)

图 100：进程替换生成文件描述符路径（01:25:57）。

diff 要两个文件，标准输入却不能同时代表两份。我觉得这是 UNIX 的缺陷，但进程替换这样的 workaround 解决了。shell 也支持重定向，也就是改变文件描述符的指向，execve 会继承父进程描述符。

![图 101：通过进程替换比较两条命令的输出（01:26:05）。](/assets/images/08/0101.webp)

图 101：通过进程替换比较两条命令的输出（01:26:05）。

进程替换与 diff 的输入输出：

```
$ echo <(echo 1)
/dev/fd/63
$ cat <(echo 1)
1
$ diff <(echo 1) <(echo 2)
1c1
< 1
---
> 2
```

比如执行 \./a\.out，我［听辨不清，01:26:39］a\.txt，只需先 fork，再把编号一替换成指向 a\.txt 的文件描述符。

![图 102：将程序输出重定向到 a\.txt（01:26:47）。](/assets/images/08/0102.webp)

图 102：将程序输出重定向到 a\.txt（01:26:47）。

正在输入的重定向命令：

```
./a.out > a.txt
```

之后 execve，无论运行什么命令，往编号一写数据，都会写入 a\.txt。大于号重定向标准输出，小于号把文件作为标准输入，也能重定向标准错误。

比如用这套有点别扭的语法，把标准错误送到 /dev/null。程序还支持其他组合。
