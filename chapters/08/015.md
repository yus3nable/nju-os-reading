屏幕上以 dollar 提示输入命令的小程序，就是 shell，每个人都能写。若先省略 job control、Ctrl 加 Z 后转后台等机制，只需同步循环：while (1)，printf 提示，再 read stdin。

读命令后 execute command，就构成 shell，最早确实如此。今天有一份从 xv6 取来的最小 zero dependency UNIX Shell，连库函数都不依赖。

![图 94：读取命令并执行的 Shell 循环草稿（01:19:34）。](/assets/images/08/0094.webp)

图 94：读取命令并执行的 Shell 循环草稿（01:19:34）。

它既运行命令，也承载 UNIX philosophy。keep it simple stupid，让工具各做一件事，再用文本、管道把输出接成输入，背后很大程度由 UNIX Shell 这门语言实现。

有个程序员笑话：坐在 linux、VT100 面前，每按一个字符都在编程。整理文件也一样，因为 unix shell 把每条命令当表达式、程序解释执行。它是基于文本替换的极简语言。

设计和 C 不同，最早甚至没有整数。今天 bash 能用 dollar 一加二这类表达式，但早期加法要把数字变字符串，调用外部进程 expr。

![图 95：expr 的参数与运算说明（01:21:58）。](/assets/images/08/0095.webp)

图 95：expr 的参数与运算说明（01:21:58）。

expr 从命令行收表达式。一加二分开传，得到三；连成一个字符串，就不会计算。它没有完整语言解析器，几十到一百行就能实现。

![图 96：expr 1 \+ 2 与 expr 1\+2 的不同结果（01:22:07）。](/assets/images/08/0096.webp)

图 96：expr 1 \+ 2 与 expr 1\+2 的不同结果（01:22:07）。

两种参数写法的实际输出：

```
$ expr 1 + 2
3
$ expr 1+2
1+2
```

这很符合 UNIX philosophy：空格把一、加、二分成三个字符串，放到 argv。expr 看第二个字符串是否加号，再决定操作。小于等于也能算，但要注意 shell 处理。

![图 97：未引用比较符导致 Shell 尝试重定向（01:22:48）。](/assets/images/08/0097.webp)

图 97：未引用比较符导致 Shell 尝试重定向（01:22:48）。

未引用比较符时的错误：

```
$ expr 1 <= 2
bash: =: No such file or directory
```

刚才没引用比较符，出现重定向错误；加引用，就能正确得到一小于等于二的结果。shell 只有字符串，通过文本替换，把命令转成系统调用序列，比如启动进程、打开文件。

![图 98：引用比较符后得到运算结果（01:22:51）。](/assets/images/08/0098.webp)

图 98：引用比较符后得到运算结果（01:22:51）。

引用比较符后的结果：

```
$ expr 1 '<=' 2
1
```

做表格、打印、转换格式，要把工具连起来，最终靠 fork、execve、waitpid、pipe，以及文件描述符调整。shell 就负责这层转换。
