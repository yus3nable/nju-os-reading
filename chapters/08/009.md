现在还有一个问题：按 Ctrl 加 C 到底发生什么？讲过终端后，可能更困惑。刚才 minitty 请求原样接收所有字符，Ctrl 加 C 就不再退出。

![图 63：课件：Ctrl\-C、Ctrl\-D 与终端收到的字符（00:50:58）。](/assets/images/08/0063.webp)

图 63：课件：Ctrl\-C、Ctrl\-D 与终端收到的字符（00:50:58）。

它只是一个送给应用的字符。有时按下 Ctrl 加 C，会在屏幕看到对应符号，说明程序收到了，却没有按熟悉的方式结束。大家可能听过“操作系统会发送信号”。

这个行为来自驱动。实体 VT100、模拟终端都由软件处理，键盘 Ctrl 加 C 先送出对应字符，再由系统决定怎样解释，原来的字符交换模型没变。

Shift 不单独发送数据，按 Shift A 才有大写 A。驱动根据应用的终端配置工作。默认 cat 使用 canonical mode，系统模拟行编辑。

驱动有 buffer。比如进程 read /dev/pts 下的 4，用户按 A、退格，并不会每次立即交给进程。

![图 64：板书：read、终端驱动和字符输入（00:53:24）。](/assets/images/08/0064.webp)

图 64：板书：read、终端驱动和字符输入（00:53:24）。

A、B 先进入驱动缓冲，backspace 删除 b，行编辑完全由驱动实现。它还能向终端发送字符，所以可以开关回显。

![图 65：板书：终端驱动中的行缓冲与字符回显（00:53:52）。](/assets/images/08/0065.webp)

图 65：板书：终端驱动中的行缓冲与字符回显（00:53:52）。

sudo 输密码时不显示输入，就是关闭回显，行编辑仍正常。平常每按一键，驱动回显字符；关闭后就不显示。Ctrl 加 C、Ctrl 加 D，分别对应 End of Text、End of Transmission，也会被驱动特殊处理。

具体行为取决于配置。若要求所有字符原样送给应用，就会像前面那样，控制键也退不出去。stty \-a 能查看配置，比如 interrupt 是 Ctrl 加 C，quit 是 Ctrl 加反斜杠。

![图 66：stty \-a 显示控制键绑定（00:55:04）。](/assets/images/08/0066.webp)

图 66：stty \-a 显示控制键绑定（00:55:04）。

Ctrl 加 C 无效时，也能试 Ctrl 加反斜杠。这里显示 terminate by Sig、SIGQUIT。yes 收到 Ctrl 加 C，是正常退出提示；换 Ctrl 加反斜杠，则是 SIGQUIT。

yes 这时表现为异常退出。stty \-a 还有其他控制键，比如 end of file、end of transmission、EOF 对应 Ctrl 加 D，end of line 则没有绑定。

![图 67：yes 收到 SIGQUIT 后退出（00:55:55）。](/assets/images/08/0067.webp)

图 67：yes 收到 SIGQUIT 后退出（00:55:55）。

现在解开了这部分疑问：在行编辑的 canonical mode 下，只有这个模式，操作系统才会把 Ctrl 加 C 解释为 interrupt。它是驱动配置的一项，甚至能换成别的按键。
