VT100 是实体终端，可以读写字符、Escape Code。现代系统却能创建任意多个终端。

![图 25：课件：伪终端、主从设备与终端录制（00:27:45）。](/assets/images/08/0025.webp)

图 25：课件：伪终端、主从设备与终端录制（00:27:45）。

每次打开一个窗口，就得到不同终端、不同 /dev/pts。操作系统可以分配像 VT100 的虚拟终端，要一个就创建一个。

![图 26：同时打开多个终端窗口（00:28:09）。](/assets/images/08/0026.webp)

图 26：同时打开多个终端窗口（00:28:09）。

不用时销毁，名字还能复用，这就是 Pseudo Terminal、伪终端。Demo 中也 vibe code 了一个。tmux 能分屏成多个独立终端，可以三个、四五六个。自己能实现吗？我写了 minitty，在当前终端里再申请 /dev/pts 设备，用 TTY 查看。

minitty 在中间显示窗口，里面是 PTY 设备。外层程序接收内部 Terminal 输出，也把输入转发进去：程序在 PTY3 下，需把 3 的输入送到 PTY4。

![图 31：请求 Claude 解释 minitty\.c 的 PTY 输入输出（00:30:20）。](/assets/images/08/0031.webp)

图 31：请求 Claude 解释 minitty\.c 的 PTY 输入输出（00:30:20）。

再把 PTY4 输出转回 PTY3。这里用到一组操作系统 API。UNIX 的 everything is a file，终端也用 file 表示，但不能像普通文本直接创建。要打开特殊设备 /dev/ptmx，请操作系统分配。流程是 Open PTY Master，再 grantpt、unlockpt，得到从设备路径、文件描述符等。

![图 32：Claude 对 PTY 分配和读写流程的回答（00:31:58）。](/assets/images/08/0032.webp)

图 32：Claude 对 PTY 分配和读写流程的回答（00:31:58）。

Master 持有 PTY，就能读写数据。它是完整终端，其他细节可以再和 AI 讨论。

![图 33：grantpt、unlockpt 与从设备名称（00:32:16）。](/assets/images/08/0033.webp)

图 33：grantpt、unlockpt 与从设备名称（00:32:16）。
