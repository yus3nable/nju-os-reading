作为输出设备，终端接受 putchar，把字符显示出来，像 typewriter。它还有键盘，可以输入，但不再是机械打字机那样按什么就打什么。按 A，video teletypewriter 把字符 A 送入计算机，由操作系统接收。

是否显示 A，还是改显示 B，由操作系统、软件决定。设备只负责按键后发送字符。esc 也有 ASCII 码，写 escape sequence 时常见的 033，就是它。

按 esc，编码送入操作系统，再由软件处理，可以原样显示，也可以不显示。当前两个程序的表现就不同，是操作系统和应用共同决定的。

终端的工作很简单。无论终端模拟器还是 VT100，按 shift 不会单独发送数据，状态留在终端中，像打字机换档；再按 A，才送出大写 A。可以直接读这些原始字节。我让 AI 写 demo，配置终端，把假想 VT100 送来的所有按键码、字符原样打印，不加工。

tty\-input\.py 的原始输入与恢复代码：

```
#!/usr/bin/env python3
import sys
import tty
import termios

def main():
    fd = sys.stdin.fileno()
    old = termios.tcgetattr(fd)
    try:
        tty.setraw(fd)
        print("Press 'q' to exit.\r\n", end="", flush=True)
        while True:
            b = sys.stdin.buffer.read(1)  # 读1个字节
            print(f"{b!r}  hex={b.hex()}\r\n", end="", flush=True)
            if b == b'q':
                exit()
    finally:
        termios.tcsetattr(fd, termios.TCSADRAIN, old)

if __name__ == "__main__":
    main()
```

可以做到。Press Q to Exit，按 Q 确实退出。A B C D E F 都正常收到 ASCII，单按 Shift 没有输入，再按 A 才有。按 Ctrl 加 C 会怎样？程序会被杀掉吗？

会先收到 Ctrl 编码再收到 C，还是直接收到编号 03？实际是 03。这也解释 ASCII 里那些初学时看不懂的编码：它的设计与 Teletypewriter 有关。

Ctrl 加 C 得到 03，Ctrl 加 D 得到 04，平常后者用来结束输入。ASCII 没有上下左右，按方向键会怎样？先看回车，收到 \r，非 \n，与 typewriter 相同。还有 backspace，可能解释为 delete；tab 是 \t，空格是 space。上箭头则会送来多个字符。

因为 ASCII 没有对应编码，只能用 Escape code。既可以给终端发 Escape code 设置颜色，也能收到它，用来表示方向键等扩展按键。上下左右这里对应 41424443。

这就展示了终端与操作系统的关系。现在 Ctrl 加 C、Ctrl 加 Z 都退不出去，幸好代码留了 backdoor。
