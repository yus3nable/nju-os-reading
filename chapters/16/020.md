这个想法聪明，很像考试题：要求用信号量实现某个正确、无死锁的同步。但它不通用。如果每人需要一组不同叉子，情况就变了。

例如 A 非要一二四号叉子，这种计数方法又不适用。条件变量仍然相同：线程一若需要三四五，等它们都 available，再持锁将三个状态置为 0 即可。只要想清条件，就能扩展。另一个解决原哲学家问题的方法，是给叉子编号，固定按编号取。每人先左再右很对称，protocol 相同也容易理解，但要 fix 死锁，可以打破这种对称。左右编号分别是 A 的 2、1，然后 3、2，4、3，5、4，最后 1、5。

除 E 外，左手编号大、右手小，E 则相反。若所有人总先拿编号小的，再拿大的，算法就正确。大家想清楚了吗？

![图 49：交换编号，使程序总先取得较小编号的叉子（01:03:30）。](/assets/images/16/0049.webp)

图 49：交换编号，使程序总先取得较小编号的叉子（01:03:30）。

```
if (lhs > rhs) {
  int tmp = lhs;
  lhs = rhs;
  rhs = tmp;
}
```

这可能不易想清。后面讲死锁、并发 bug 时，会专门讲 lock ordering。先把问题留下：按从小到大顺序申请叉子，为什么正确？有兴趣可以先想，后续课程再讲。
