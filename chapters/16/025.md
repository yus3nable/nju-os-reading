底层细节暂时不要求掌握。是否意味着哲学家问题就不该用信号量？还有其他方式。

图 56：通过 waiter 线程统一决定谁可以继续（01:17:50）。

```
void T_philosopher(int tid) {
  while (1) {
    send_message_to_waiter();
    P(&can_proceed[tid]);
  }
}
```

理论上任何同步问题都能转为生产者消费者。例如引入 waiter、服务员线程，由它管理全局条件，持有五把叉子 12345，知道谁占用哪些。其他线程不再直接访问叉子的全局状态，就是另一种并发控制。

无须每个线程 self\-organize、ad\-hoc 自组织，商量先左后右、编号不同时反过来的 protocol。引入全局 waiter，管理状态，绝大部分时候也未必损失性能。

T\_philosopher 想吃饭，就 send 消息给 waiter。waiter 循环从 buffer 读取消息。消息队列可以由 buffer 实现，send 放球、receive 取球，是标准生产者消费者。

也就是 P(empty)、V(fill)，P(fill)、V(empty) 的对称过程。哲学家请求叉子，waiter 拥有全部控制权，检查所需叉子。例如请求 431，查看 134 都在，就从自己的私有内存状态中移除 134，无须各线程直接改全局内存。

再用 PV 通知许可：waiter V、release，哲学家 P、acquire。先发消息，再等服务员给叉子，获准后继续；完成后再发归还消息。仍用信号量，但状态由服务员统一管理，避免各线程自行设计协议。原本指数多种调度，变成 waiter 的简单串行逻辑。

它将所有 send 请求排队。
