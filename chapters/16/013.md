这里有全局 invariant：empty 数量、fill 数量，再加正在生产和正在消费这两种中间状态的数量，总和一直等于 buffer 大小。球和槽位的对应关系，使算法正确而精巧，第一次见往往会觉得信号量很妙。上节课我演示生产者消费者时出错，也想说明原来的难点。

signal、broadcast 用起来需要留意。想清 CAN\_PRODUCE、CAN\_CONSUME 条件，再用 broadcast 可以保证正确；若不喜欢唤醒不该继续的线程，想省这点性能，就得额外思考。看到信号量这种写法，会觉得简洁。

信号量最主要用来管理计数资源，生产者消费者是代表问题。遇到它可以 follow 这个 pattern。示例代码相同：P(empty)、打印左括号、V(fill)；P(fill)、打印右括号、V(empty)。

![图 33：pc\.c：生产者和消费者的循环（00:43:25）。](/assets/images/16/0033.webp)

图 33：pc\.c：生产者和消费者的循环（00:43:25）。

```
void T_produce() {
  while (1) {
    P(&empty);
    printf("(");
    V(&fill);
  }
}

void T_consume() {
  while (1) {
    P(&fill);
    printf(")");
    V(&empty);
  }
}
```

可以尝试深度 2，再看 1，以及 2、3，能看到正确同步。这里有 8 对 producer、consumer，可以长时间压力运行，用脚本检查，应该都正确。信号量就是从互斥锁模型扩展而来。

```
int main(int argc, char *argv[]) {
  assert(argc == 2);
  SEM_INIT(&fill, 0);
  SEM_INIT(&empty, atoi(argv[1]));
  for (int i = 0; i < 8; i++) {
    spawn(T_produce);
    spawn(T_consume);
  }
}
```

桌上原本只能放一把钥匙，现在允许任意数量；lock 拿走一个，unlock 放回一个。创建多个这样的对象，就能同步。这就是从最初想法发明信号量的过程。
