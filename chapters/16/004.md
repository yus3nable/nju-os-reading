```
struct edge {
  int src, dst;
  mutex_t lk;
} edges[] = {
  {0, 1}, {0, 2}, {0, 3},
  {1, 4}, {2, 4}, {4, 5},
};
```

```
for (int i = 0; i < LENGTH(edges); i++) {
  if (edges[i].dst == tid) {
    mutex_lock(&edges[i].lk);
  }
}
printf("Computing node #%d...\n", tid);
sleep(1);
for (int i = 0; i < LENGTH(edges); i++) {
  if (edges[i].src == tid) {
    mutex_unlock(&edges[i].lk);
  }
}
```

有入边就尝试获得锁。没有入边时，第 26 行条件一直不满足，不执行 mutex\_lock，直接到 32 行开始计算。若无入边节点耗时较长，其他节点起初就会等待。等第一个 a 算完，将全部出边的锁释放。

锁释放后，x 就能继续。编译运行，看起来确实和此前一样，123 同时执行，再到 45、complete。逻辑上能表达同步，但线程库不允许这种用法：acquire、release 必须发生在同一线程，否则属于 undefined behavior，因为内部有 fast path 优化。
