Dijkstra 发明了信号量。沿着刚才思路也能推导出来：允许任意线程 release，另一个 acquire，建立 happens-before；再将互斥锁扩展成多把钥匙。条件未满足、count 不大于 0 就等待，满足后 count 减减；release 则 count 加加。

考研等场景常说 PV 操作，P、V 是发明时采用的荷兰语单词。P 意味着 acquire、try and decrease，也叫 down、wait：等待同步条件，再减 1。V 是 increase、up、post、signal、release，令 count 加加。一个拿走钥匙、占用车位，一个放回钥匙、增加车位，能管理计数资源。用条件变量按模板实现，count 初值可以任意设，也可以设为 0。

例如 count 等于 4，有 4 把钥匙。T1、T2、T3、T4 分别 P，检查 count 大于 0，依次看到 4、3、2、1，四次都能成功。

随后 count 为 0，第五个线程必须等待，像泳池最多容纳四人。第二个线程游完执行 V，count 加 1，回到 1。

T5 正在等，P5 此时就能在 V 后继续，拿走钥匙后 count 又为 0。等所有人结束、执行 V，count 最后回到 4。这个模型和停车场、泳池一致，但信号量只管入口，即能否进入。进入后，找车位仍在共享空间中进行。

若真用线程模拟停车场，P 返回意味着已进入；P 内 assert 的同步条件是 count 大于 0，并把一把钥匙收进口袋，count 减 1。

因此能保证这段时间至少有一个车位，具体停哪里仍需和其他线程协商，例如另加互斥锁。P 像闸门，入场空位减 1，出场加 1，却不负责里面怎么操作。内部若执行 Undefined Behaviour，也可能把停车场内存 corrupt。

所以仍须谨慎编写内部代码。
