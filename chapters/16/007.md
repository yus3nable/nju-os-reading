用严谨 API 描述信号量：P 操作接收 semaphore，对应 acquire、try and decrease，先获得内部互斥锁。

![图 15：用互斥锁和条件变量实现 P 与 V（00:21:44）。](/assets/images/16/0015.webp)

图 15：用互斥锁和条件变量实现 P 与 V（00:21:44）。

```
void P(sem_t *sem) {  // Acquire
  mutex_lock(&sem->lk);
  while (!(sem->count > 0)) {
    cond_wait(&sem->cv, &sem->lk);
  }
  sem->count--;  // 消耗一个 token (信号)
  mutex_unlock(&sem->lk);
}

void V(sem_t *sem) {  // Release
  mutex_lock(&sem->lk);
  sem->count++;  // 创建一个 token (信号)
  cond_broadcast(&sem->cv);
  mutex_unlock(&sem->lk);
}
```

再按通用同步模板，条件未满足就等待，满足后 count 减一，消耗 token。V 对应 count\+\+、broadcast，适合停车场、泳池这类场景。信号量是互斥锁的扩展，互斥锁则是它的特例：初始化 counter 为 1，就只有一个玩具。

也就是桌上一把钥匙、停车场一个车位。任何人进来，都先 P 这个 semaphore。

![图 16：初始值为 1 的信号量实现互斥（00:22:49）。](/assets/images/16/0016.webp)

图 16：初始值为 1 的信号量实现互斥（00:22:49）。

```
sem_t sem = SEM_INIT(1);

void lock() {
  P(&sem);
}
void unlock() {
  V(&sem);
}
```

P、acquire 成功，只允许一辆车进入，其余再多也得等，这就是 mutually exclusive。离开临界区时 unlock、release，归还钥匙，计数回到 1。假设 lock、unlock 正确配对，每次只有一个人进出。若某条路径有 bug，情况就不同了。

例如 unlock 两次，相当于凭空增加车位，违反只有一个车位的约定。V 可以创建新钥匙，之后就允许两辆车同时进入。正确使用时，它确实能实现互斥，这就是互斥锁为信号量特例的原因。

对照用条件变量实现的两段代码，也能看出这个扩展关系。
