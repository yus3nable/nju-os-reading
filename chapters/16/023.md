条件变量实现信号量很简单：互斥锁的扩展，c、counter 大于 0 才能执行 p，令 c 减减；v 则直接 c\+\+、broadcast。反过来，用信号量实现条件变量，就复杂得多。

report 说，implementing condition variables out of a simple primitive like semaphores is surprisingly tricky。可能会写出下面的实现。记住，使用条件变量时，lock、unlock 之间调用 cond\_wait。

图 53：尝试用信号量实现条件变量的 wait 和 broadcast（01:10:39）。

```
void wait(cond_t *cv, mutex_t *mutex) {
  cv->nwait++;
  mutex_unlock(mutex);
  P(&cv->sleep);
  mutex_lock(mutex);
}

void broadcast(cond_t *cv) {
  mutex_lock(&cv->lock);
  for (int i = 0; i < cv->nwait; i++) {
    V(&cv->sleep);
  }
  cv->nwait = 0;
  mutex_unlock(&cv->lock);
}
```

正确使用时，调用 cond\_wait 必然持锁。在 while not condition 的循环中，要记录 condition variable 的 nwait 加加，再实现 wait：既要睡眠，也要释放互斥锁。

不能直接 p sleep，否则持着锁睡着，别人再也拿不到同一把锁，无法将 condition 改成 true。任何影响条件的共享状态修改，都必须持锁。所以不能先 P，得先释放互斥锁。

再 P cv 的 sleep，进入睡眠。将来被唤醒，再 acquire、lock，只有睡眠期间没持锁，其余仍受保护，看似符合条件变量语义。broadcast 则假设锁都已上好，用 nwait 统计等待者，有多少就 V 多少次、往桌上放多少玩具。例如三个等待者，就放三把钥匙。
