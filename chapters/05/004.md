## 进程管理：创建、销毁、复制与复位

![图 64：进程管理：创建、销毁、复制与复位（00:36:29）。](/assets/images/05/0064.webp)

图 64：进程管理：创建、销毁、复制与复位（00:36:29）。

用状态机看，可以设计 Spawn。程序执行到这个系统调用，传入 Path，即二进制路径，以及参数，比如 /hello，就创建新进程。原来的 init 仍在，pid 是 1，新 hello 的 pid 可能是 2，ppid 是 1。根进程的 ppid 可以指向自己，也可以用非法值，取决于系统设计。有 spawn 就能创建进程，马上可以在 CrazyOS 实现。现场考考豆包，我没提前准备。

实现应该不难，和 main 初始调用 proc\_init 一样：创建新进程，申请一个结构体。

分配 struct proc，准备内存、寄存器，设置正确的初始 program counter，就是 proc\_init 的工作。但豆包没遵守命名规则，看现有代码应该知道，所有 system call 都用 sys 前缀，它却直接给了 spawn。

图 67：新增 spawn 包装函数与命名约定（00:38:47）。

它遵循指令不够好，但实现已经不错，spawn 基本和 proc\_init 做相同的事，先让它继续。windows API 也有这种创建方式：指定 \.exe 文件，再给 main 传参数，程序就能启动。类似在 Dev\-C\+\+，或者现在的 vscode 写好 C 程序。

点击运行，后台先编译成 \.exe，黑窗口弹出时，就通过类似 spawn 的方式创建进程。这是合理设计，Unix 却采用另一种抽象。再看正在执行的程序状态。

## UNIX 的创建方式：fork 复制状态机

![图 68：UNIX 的创建方式：fork 复制状态机（00:40:15）。](/assets/images/05/0068.webp)

图 68：UNIX 的创建方式：fork 复制状态机（00:40:15）。

Unix 提供 fork。spawn 创建新状态机，从新程序的初始状态执行；fork 则把现有状态机完整复制一份，A copy。可以理解为在 CrazyOS 中，逐字节拷贝内存、寄存器。

![图 69：复制的程序状态与系统内部状态（00:41:07）。](/assets/images/05/0069.webp)

图 69：复制的程序状态与系统内部状态（00:41:07）。

也复制相关操作系统内部状态。比如进程 A 持有指向终端 tty 的指针，复制后，两个进程共享这个 tty。VS code 的终端里，父进程输出字符。

![图 70：fork 完整复制已有状态（00:41:49）。](/assets/images/05/0070.webp)

图 70：fork 完整复制已有状态（00:41:49）。

子进程默认也输出到同一终端，因为继承父进程资源，包括内存、寄存器现场。用 CrazyOS 很容易理解：复制进程本身以及相关的操作系统状态，但不包括管理数据结构自身的状态。还要区分父子进程。

## fork 的返回值与复制行为

![图 71：fork 的返回值与复制行为（00:42:30）。](/assets/images/05/0071.webp)

图 71：fork 的返回值与复制行为（00:42:30）。

如果一个字节都不差，就无法区分原进程和副本。所以 fork 在父进程返回子进程 PID，比如新 PID 是 100，就返回 100；子进程副本返回 0。这是用来区分两者的方式。代码可以这样写，类型也能用 pid\_t，我现在在古法编程。

![图 72：父子进程得到不同的返回值（00:43:18）。](/assets/images/05/0072.webp)

图 72：父子进程得到不同的返回值（00:43:18）。

PID 等于 \-1，就做 error handling；等于 0，执行 child 分支；否则执行 parent 分支。也可以按不等于 0 来安排两个分支。

![图 73：fork 失败时的返回值检查（00:43:25）。](/assets/images/05/0073.webp)

图 73：fork 失败时的返回值检查（00:43:25）。

假设 fork 成功，程序经过这里时，就有两个进程、两份状态。可能先后到达，但都会经过这个程序点：一个 PID 等于 0，走子进程路径；另一个不等于 0，走父进程路径。

![图 74：用返回值区分 child 与 parent（00:44:03）。](/assets/images/05/0074.webp)

图 74：用返回值区分 child 与 parent（00:44:03）。

```
pid_t pid = fork();

// Two copies
if (pid == 0) {
    // child
} else {
    // parent
}
```

这样只用 fork，也能写不同的父子进程逻辑。开始可能有点绕，回去可以再理解。无论 fork 还是 spawn，创建出来的进程都有父子关系。

## 进程树：父进程退出后怎么办

![图 75：进程树：父进程退出后怎么办（00:44:31）。](/assets/images/05/0075.webp)

图 75：进程树：父进程退出后怎么办（00:44:31）。

调用者创建孩子，也就是 descendant、后代。比如 A fork 出 B，再 fork 出 C，B、C 又可以继续 fork，就形成进程树。早期 UNIX 只有 fork 这一种创建途径，今天方式更多。不过系统每增加一点功能，也会带来新问题。

![图 76：fork 关系构成进程树（00:45:33）。](/assets/images/05/0076.webp)

图 76：fork 关系构成进程树（00:45:33）。

比如 A 是 B 的父进程，B 是 C 的父进程，三者独立运行，能执行任意代码。如果 B 退出，C 的父亲是谁？继续指向 B 也有问题，因为 PID 有限，未来可能被另一个进程复用，父亲就变成别人了。UNIX 的处理利用了一号进程永不终止这一点。

![图 77：父进程退出后的托孤关系（00:46:18）。](/assets/images/05/0077.webp)

图 77：父进程退出后的托孤关系（00:46:18）。

没有父亲的进程会转挂到一号进程，成为它的孩子，叫托孤。这样 PPID 始终合法，不会用空或错误的 parent。如果向 1 发消息，它会忽略。这是广泛使用的 workaround。PID 终究会重复利用，现在应该能到 100 万。

也能配置更大。Linux 还有专门子系统，用另一方式确保 unique PID，但第一门操作系统课不讨论细节。听到托孤，就能让 AI 写程序验证。比如这是去年演示：一个 prompt，要求创建五层进程树，再随机退出部分进程。
