把时间倒回 198 几年，假设只有一台没有 MMU、分页、中断的计算机。即使什么都没有，能不能让它同时运行程序？或者先用普通 C 程序考虑：有 P1 main、P2 main 两个函数，直接依次调用，只会等 P1 结束后再执行 P2。

如果 P1、P2 都是死循环，能否让 main 的效果看起来像它们同时运行？C 程序本来顺序执行，假设没有操作系统，直接像 Firmware 一样运行在硬件，或者在没有 MMU 的机器上，这件事能办到吗？这是第一个问题，大家可能觉得可以。

还记得 Tower of Hanoi 吗？非递归模拟递归，可以写成解释器。

![图 10：P1 与 P2 如何在一个程序中共同运行（00:08:12）。](/assets/images/05/0010.webp)

图 10：P1 与 P2 如何在一个程序中共同运行（00:08:12）。

解释器每次取一条语句执行，call、return 对函数调用栈做一点操作。任意程序都能用这种形式描述。那么可以从 P1 取一句，再从 P2 取一句，轮流执行。它们各自是状态机，有函数调用栈、全局变量，理论上可以模拟。我叫它 CrazyOS，像虚拟机，也像操作系统。主循环加载任意多个程序 P1、P2、P3，每次选一个，推进一条语句，让内部状态改变。遇到 system call，就执行相应系统调用，比如给 P1、P2 提供 putchar。

执行 putchar 就打印字符，也能提供 exit，执行后不再调度这个程序，释放内存。这就是操作系统的基本思路。实际操作系统让硬件直接执行二进制文件里的指令序列，把程序当前状态加载到 CPU，叫上下文切换。这门课不讲具体过程，先有概念：把 P1 放到 CPU 运行一会儿。

中断发生后，再换 P2，P1、P2 交替，实现时间片轮转。用这个模拟器就能理解虚拟化：多个程序装入内存，通过交错执行，让它们好像并发运行。在较长时间尺度上看输出字符，确实会交替打印。接下来发生了让我感到压力的事。

图 11：模型自报身份与实际调用记录（00:11:02）。

给出这样一个 prompt，CrazyOS 就实现出来了：用 crazy\-os\.c 模拟操作系统，加载多个 RISC\-V 二进制文件。

最开始提过 mini\-rv32ima 模拟器，它能模拟执行一条 RISC\-V 指令。

![图 14：模拟 CPU 的寄存器与内存状态（00:11:27）。](/assets/images/05/0014.webp)

图 14：模拟 CPU 的寄存器与内存状态（00:11:27）。

它正好符合这个模型。为每个二进制文件分配 struct cpu state 和一份内存，把程序加载进去，就得到状态机。每次用模拟器做 single step，执行一条指令，就能推进。模型确实这样实现了，小操作系统能执行真实程序，回去也可以修改、运行。

比如 p1\.c。为了实现简单，不支持全局变量、全局状态；要支持会增加代码量。

![图 15：p1\.c 每次将 x 增加 10（00:12:15）。](/assets/images/05/0015.webp)

图 15：p1\.c 每次将 x 增加 10（00:12:15）。

```
#include "lib.h"

int main() {
    int x = 0;
    while (1) {
        x += 10;
        myprintf("P1: x = %d\n", x);
    }
}
```

我选择最简单的做法。局部变量 x 等于 0，p1 每次加 10，再打印 x；p2 每次加 1，再打印。打印函数比较长，就是上次的 printf。可以写任意合法 C 代码。

![图 16：应用程序的数字打印函数（00:12:41）。](/assets/images/05/0016.webp)

图 16：应用程序的数字打印函数（00:12:41）。

前提是不用全局状态，这里也没用。两个重要函数中，开头是 \_start，第一条指令落在这里，再调用 main，可以理解成 libc 的入口。另一个特殊函数实现 putchar 系统调用，代码也由 AI 完成。

![图 17：入口 \_start 与系统调用 sys\_putchar（00:13:12）。](/assets/images/05/0017.webp)

图 17：入口 \_start 与系统调用 sys\_putchar（00:13:12）。

```
int main();

void _start() {
    main();
}

static inline void sys_putchar(char ch) {
    register int a0 asm("a0") = ch;
    register int a7 asm("a7") = 42;
    asm volatile ("ecall" : "+r"(a0) : "r"(a7));
}
```

以前需要学习的这些技能，现在只要知道能实现系统调用，AI 就能写。它把字符参数放进 a0，把编号 42 放进 a7。应用编译方法也由 AI 准备：用 RISC\-V 的 CC，相当于 GCC，带一组编译选项。这些暂时不必懂。这里写了两份，有个小 bug，可能是我的问题。

CC 编译后，用计算机系统基础讲过的 objcopy 提取指令序列，生成 binary。现在能正常编译，但中间结果被删了，我不想删除 ELF。Makefile 里却没找到对应命令，只有 make clean 中有 remove。

## CrazyOS 的加载与调度主循环

![图 23：CrazyOS 的加载与调度主循环（00:16:02）。](/assets/images/05/0023.webp)

图 23：CrazyOS 的加载与调度主循环（00:16:02）。

它先从命令行参数读多个 binary 文件，对每个调用 proc\_init，创建相应结构体，再进入死循环。若操作系统要管理 p1、p2，就要分别为它们创建 state。

![图 24：struct proc 保存程序状态和系统内部状态（00:16:25）。](/assets/images/05/0024.webp)

图 24：struct proc 保存程序状态和系统内部状态（00:16:25）。

state 分两部分：一部分是程序运行需要的 memory、register，也就是 cpu state 和内存；另一部分是操作系统内部状态，比如进程编号。我还做了一个小 trick：putchar 暂时不打印字符，每个程序各有一个 buffer。

![图 25：每个进程独立的字符输出缓冲区（00:17:10）。](/assets/images/05/0025.webp)

图 25：每个进程独立的字符输出缓冲区（00:17:10）。

比如 hello 的字符先逐个进入 buffer，快满或遇到换行，才真正输出。p1、p2 各有一个缓冲区。调度部分用 procs 数组保存各程序，每轮循环后，指针加一模 N，采用 round robin，按 123123123 的顺序，公平地让每个程序推进一条指令。模拟器单步执行时，如果遇到系统调用，就转到 handle\_ecall。

![图 26：handle\_ecall 分派系统调用（00:18:12）。](/assets/images/05/0026.webp)

图 26：handle\_ecall 分派系统调用（00:18:12）。

它检查 a7 的系统调用编号，42 就调用 sys\_putchar。理论上可以继续加 Exit 等任何系统调用，模拟其他操作系统，甚至实现优化虚拟机、半虚拟化。

![图 27：程序状态与操作系统中的输出缓冲区（00:18:40）。](/assets/images/05/0027.webp)

图 27：程序状态与操作系统中的输出缓冲区（00:18:40）。

回到 20 年前，这可能就是一个不错的操作系统领域工作。试试这个 crazy idea：CrazyOS 运行 p1\.bin，可以配管道；P1 每次加 10，输出 10、20、30、40、50、60。运行 p2\.bin，会看到 1234567890，程序确实正常执行，System call 也被正确调用。

谁运行得更快？P2。因为模拟器每次执行一条指令，P1 打印的数字更大，printf 耗时更长，循环次数逐渐拉开。P2 已到 69，也就是循环 69 次，P1 只有 61。
