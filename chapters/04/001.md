## 第一次在操作系统课上使用 ChatGPT：内联汇编示例

![图 3：第一次在操作系统课上使用 ChatGPT：内联汇编示例（00:01:47）。](/assets/images/04/0003.webp)

图 3：第一次在操作系统课上使用 ChatGPT：内联汇编示例（00:01:47）。

ChatGPT 刚火起来，我就试着在课堂上用它，发现很厉害。那时操作系统课还讲内核，内容很硬核。ChatGPT 刚发布两个月，用的是 GPT\-3\.5，大家原本还在微调 BERT，突然感觉世界变了。它是面向所有人的聊天工具，天文地理都能聊，情绪不好也能找它发泄，还可以问编程。比如这段程序，编译器会做怎样的优化？模型至少得先看懂 C 代码中的 inline assembly。内联汇编有训练语料，但并不多。

```
int return_1() {
    int x;
    for (int i = 0; i < 100; i++) {
        // Compiler will assign [%0] an assembly operand
        asm("movl $1, %0" : "=g"(x)); // "x = 1;"
    }
    return x;
}
```

整个训练集里，内联汇编文档可能只出现过几遍，它却回答得很好，对编程有很好的直觉。那时我觉得世界可能变了。后来模型越来越强，我一直在想为什么。最后想到一个解释：薛定谔有一本小册子，我大概在大家这个年纪读过，开篇就问，为什么我们这么大？

## 大、语言与模型

![图 4：大、语言与模型（00:03:10）。](/assets/images/04/0004.webp)

图 4：大、语言与模型（00:03:10）。

听起来有点好笑，相对的问法是：为什么原子这么小？这个问题很深，也与今天的 Scaling Law 有些关系。一百多年前的这套思路是：如果相信量子力学或经典原子理论，每个原子携带的信息很少。化学中，原子外面有多少电子、两个原子怎样反应，都有相当精确、经典的模型。

几个原子组成的极小系统，不该有生命这么复杂的行为。对人、生物而言，要应对复杂的宏观环境，大是必要条件。这是我对大语言模型中“大”的解释。接着问，为什么选语言？在它以前，深度神经网络的爆发性案例是 2016 年 DeepMind 的 AlphaGo，第一次击败人类围棋世界冠军；再早是 AlexNet 的图像分类，大家发现深度神经网络能看懂图像。为什么直到语言模型才出现今天的质变？我的理解是，语言是人类沉淀几千年的世界模型，好用，也能在人与人之间对齐。举个常讲的例子。

说“今天来上课的路上，看到一个美女”，这句话很短，背后却带着大量信息。我吃了三十几年饭，见过无数女生，对美女有自己的理解，别人又有不同理解。宿舍卧谈时，男生女生可能都会争论谁是帅哥、美女。语言是一种抽象，丢掉很多信息。让大家闭眼在脑中 diffuse 一个美女，每个人的结果不同，却又有结构上的相似性。

因为我们在类似环境里长大，虽然见过的人、生活地方、接触的文化不同，但共享一个物理世界，都上小学、中学，学习同一套教材。相似又略有差异的 grounding，让语言可以在人与人之间对齐。语言保留了人类世界中能传承的抽象，也就能让大语言模型在一定程度上表达世界。

这也能解释模型为什么有时工作得好、有时不好。语言没法直接与外星人对齐，可能需要其他办法。七十年代，美国发射旅行者号卫星，设想外星人有一天捕获它，通过里面像 CD、磁带的东西，或大板上的图案，知道这是智慧生物发出的。今天也许可以换成能生成图形内容的多模态模型。

把模型固化在南极某处，即使人类灭亡，以后外星人挖出来，也可能从中复原这个世界。今天让生图模型生成教室上课的图片、视频，它能做到，只需要足够多参数。这是我对大、语言、模型的理解。再看语言模型怎样工作。大家知道它有上下文 context，也经常遇到 context 溢出、不够用的问题。

它从 context 不断补全文本。训练分预训练、后训练两个阶段，GPT 叫 generative pre\-trained model，也就是生成式预训练模型。预训练直接用语言文本，让模型学会说话，生成看起来正常的人类语言；之后再把它调整成能对话的助手。用特殊符号标记人在说什么。

再标记机器回复、人继续说话，把整个对话写在一起。人说完后，模型根据前面全部文字给出下一个字的概率分布，比如“好的”。实际过程更复杂。本学期会有一个实验，让大家实现并行的大语言模型推理。这个过程叫 next token prediction，庞大神经网络给出一个概率分布，根据前文预测接下来输出什么。

图片最后也会以某种方式变成文字。比如“好”的概率是零点零点一，“大”是零点零零零零一，Unicode 字符、笑脸、哭脸也都有概率。大致选概率最高、认为最可能的结果，再继续往后生成。我很惊讶，这样的东西为什么能做这么多事？

包括编程，也能做得好。我以前参加程序设计竞赛，某种程度上代表“古法编程”的巅峰。2022 年 ChatGPT 出来之前，Google 发布 AlphaCode，大家听说过吗？它声称能写代码，是类似 BERT 的 Transformer 模型。

![图 6：板书：context 与下一个 token 的概率分布（00:10:50）。](/assets/images/04/0006.webp)

图 6：板书：context 与下一个 token 的概率分布（00:10:50）。

AlphaCode 在编程竞赛网站 Codeforces 上，大概能达到 2000 多分 Rating，那时看很不可思议。它并非今天这样多轮 chat。想象把一道 C\+\+ 或数据结构的上机期末题交给它：给一个现实问题，需要先转成图，再求最短路径，可能要写一两百行代码。题目作为文字，简单说就是单词、字符序列输入。模型经过大量数据训练，就能逐步输出代码，比如 int、空格、main、括号，每次输出一个字符或一小组字符。

每次输出只依据前面内容形成的概率分布，却能顺序写完整代码。和人的方式不同，人做结构化程序设计，会先规划 ABC 三步：先读数据、建 graph，再实现 Floyd\-Warshall 最短路径算法，最后加工并输出结果。

写程序时，可能先写 main，留些空白，规划先 A、再 B、再 C。机器当时却逐个输出，AlphaCode 发布时，我们很惊讶，讨论为什么能这样写。后来想到，人也会先在草稿纸推导。

![图 7：板书：人先规划 A、B、C，再组织程序（00:13:43）。](/assets/images/04/0007.webp)

图 7：板书：人先规划 A、B、C，再组织程序（00:13:43）。

写好伪代码，想清楚 ABC 各做什么，再写代码，就类似机器翻译，把一种语言转换成另一种，几乎不用重新思考。我作为程序设计竞赛选手，最重要的训练就是熟练写代码，把想法以接近顺序的方式直接写下来，当然也并非完全顺序。这是专门练过的能力。给大家讲个以前的故事：比赛三人一台电脑。今天 Agentic AI 时代，可能会想部署十个、一百个 parallel Agent，但那时三个人只有一台电脑，要和队友分配使用时间。所以我专门训练过在纸上写代码。

先写 int，再想要定义哪些变量，接着往下写。比赛时，我能写满三页 A4 纸，读一遍、修掉小错，再 type 进电脑，程序就能编译，而且结果正确。人类可以做到。那时 BERT 的机器翻译也已经做得很好。

BERT 系列在机器翻译上表现很好，Google translation 已是日常工具。那时我们就觉得，Transformer 这类神经网络，只要参数足够大，或许就能做到。它得大到能在 Short\-term memory、短期记忆里放下推导结果，像人先想出伪代码，但不写出来。大家也有这样的能力：高考数学，老师可能会做自己不会的题，但解题速度未必比大家快，因为年轻的大脑经过大量训练，短期记忆能容纳许多步骤，比如三角函数怎样一步步变换。我现在需要写下来慢慢推，像大家这个年纪时，却能心算 arctan x 这样的不定积分。人能训练成这样，大模型加大量语料，也应有可能在内部完成类似的过程。

看到 context，在内部形成 idea，把 idea 想清楚，再按照它继续生成，就类似翻译。当时还没人知道训练怎样的网络才能做到，这些也只是道理上的可能，是不严格的 arguments。但可能足以让人相信，投入当时看起来疯狂的事情；事后回看，又会觉得合理。
