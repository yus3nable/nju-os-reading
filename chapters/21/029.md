写 CUDA 程序完成 GPT 训练，相当于 spawn 很多 T\_worker。但每条指令执行都有代价，比如译码。SIMD、SIMT 都在一定程度上分摊了译码代价，能否在 SIMT 中再引入 SIMD？也可以。刚才看到，GPT 的典型运算很固定、很 regular。

主要是矩阵运算。SIMT 模式下，线程靠寄存器算 position。比如前面写的 index，分别是零、一、二；所有线程束执行 base 加 row 乘以 stride 加 column 这样的指令，算出各自的 index，再按 index 做 store 或 load，实现高带宽内存访问。

不过计算下标的指令也有代价，需要电路、译码，消耗能源。想尽可能提高能效比，连这条指令都想省掉，直接用矩阵乘法指令、矩阵乘法 FMA。这样就发明了 Tensor Core。今天 NVIDIA GPU 中都有 Tensor Core。这个名字有一点 misleading，虽然我觉得它也没有误导，还是对的。

它做的是 A 矩阵 M 乘以 K，乘上 B 矩阵 K 乘以 N，得到 D 矩阵 M 乘以 N。它处理矩阵，并没有处理任意 tensor。我开个玩笑，NVIDIA 也可以宣传成 matrix multiplication extension，简称 MMX，借用英特尔 multimedia extension 的名字。

但 matrix multiplication extension 显然显得太土。它吸取英特尔失败的教训，用一个更现代、响亮的名字 Tensor Core，强调这种能力，避免只说指令级增加了某项扩展。它用得最多的功能就是 FMA，可以加。
