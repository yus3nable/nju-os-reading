其中一篇说 NVIDIA 的市值已经超过印度股票市值的总和。一家公司的产业体量超过一个世界大国，印度确实是世界大国。NVIDIA 支撑着一个 10 万亿美元的产业生态。回顾计算机硬件、软件的发展史，再看 UNIX 的系统调用、分页等 Linux 上熟悉的机制，就能作类比。

这些底层机制之上，逐渐长出了今天的整个系统世界；GPU 加速器生态之上，也长出了今天的人工智能应用。最底下是 GPU。我觉得 DeepSeek 这次用昇腾卡做推理 serving，是很大的进步。传言说它为了适配国产卡而延期发布，但没有任何证据证明这一点。

GPU 和 CUDA 之上，还有 cuBLAS 等重要库函数，叫 Basic Linear Algebra，基础线性代数，比如矩阵乘法。英特尔发布有 MMX 的处理器，如果没人会为扩展指令集写程序、编译程序，就没人能用好处理器性能。同样，想用好 Tensor Core、内存带宽，就要选择内存布局、访问模式。

对于两个大矩阵，怎样分块、块多大，都与底层硬件相关。不同 GPU 可能需要编译出不同代码才最优：下一代 GPU 的 Tensor Core 可能更大、更多，分块大小也得变化。cuBLAS 随 Cuda 持续更新，像操作系统中的 Lib C，紧密配合底层机制。硬件体系结构更新，Lib C 也会相应调整。

比如今天的 Memory Copy，用 C 写，再用高等级优化编译，可能会看到编译器使用 SIMD 的 XMM、YMM 寄存器，做很长的 load 和 store，减少许多短 load、store 的开销。编译器认为这样更快，也确实可能更快。

类似的事情在 GPU 上再次发生。除了 cuBLAS，DeepSeek V3 发布时还有 DeepGEMM，它叫 General Matrix Multiplication，仍是矩阵乘法；NCCL Communication Library 则负责通信。库函数之上有应用系统、工具生态，相当于 Coreutils。不过人工智能应用需要的工具，与面向系统管理员的 Coreutils 不同，它需要算子 Kernel Fusion，比如 Flash Attention，把多层计算打包成计算图发给 GPU。再往上有训练、推理框架，以及面向 AI 用户的交互程序。这里说的用户是训练、研究神经网络的人，排除了妈妈使用豆包这样的最终用户。比如 PyTorch、TensorFlow 这样的高层编程语言，可以用更高级的方式描述计算图，再用 FlashAttention 编译、调用 cuBLAS，最终变成 CUDA 程序，到 CUDA 上训练。这套生态与学过的 Unix 世界很像。

再往上还有 Ollama、OpenWebUI，以及 Claude Code、OpenClaw。和 Linux 生态一样，能想到的事情都有人在做。
