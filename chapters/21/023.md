系统还能自动存储副本，提供很高的可靠性，不用担心租用的服务器 crash。现在数据中心里租用的服务器也很可靠。租过云服务器会发现，存储和计算分别计费。实际数据中心里，带 CPU、内存的计算节点，通过超高性能网络连接到 SSD 集群。

比如在云上租一个 Linux，写一个 a\.txt，看起来是在文件系统的连续空间里写，实际写入 SSD cluster，并自动存两份或三份副本。虽然只写了一份，底下的 SSD 存储集群有副本，数据就很安全。这也关系到阿里云等厂商挣钱的独门秘诀：a\.txt 会进入它的存储 cluster。

进入 cluster 后，只要文件系统没有加密，它随时可以压缩。给文件系统加密，它就比较难处理；厂商赌的就是普通文件系统通常不加密，还能 deduplicate。比如每个人租的虚拟机都有同版本 libc，文件一模一样，SSD cluster 发现后，就不用再存一次。

只需要把引用计数加一。实际数据可能仍有三份副本，但即便如此，存储比例、写放大也可能小于一：向用户收一 GB 存储费，SSD cluster 的总占用却小于一个 GB。我不知道是谁赚谁亏，反正厂商挣到了钱，我们也得到了服务，我觉得这在某种程度上理所应得。数据中心里发生着这么多复杂的事。

操作系统课没法讲完 systems 领域这些年来让人激动的工作，但至少开了一个头。它们背后仍是 system calls，read、write、send，再逐层实现整个系统。现在，刚才 api key 相关的增删改查就讲清楚了。
