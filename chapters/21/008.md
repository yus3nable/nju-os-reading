比如让 AI 用命令查看 DNS 到底发生了什么。在本机逐步展开这些行为，就会发现实际计算机系统中的更多问题。刚才无论 curl 还是 strace，远端服务器都对应一个 IP 和一个端口，443 是 HTTPS 的端口。访问课程主页时也是这样，但 DeepSeek 的情况会复杂一些。

![图 15：dig 返回的两个 A 记录（00:13:41）。](/assets/images/21/0015.webp)

图 15：dig 返回的两个 A 记录（00:13:41）。

用 DIG 查看 api\.deepseek\.com，会发现它有不止一个 IP。为什么？它是大型服务提供商，可能还使用别家的服务来做分布式 DNS。查询结果告诉我们，58\.49\.197\.113、218\.92\.141\.107 两个 IP 都可以用。在地球另一处执行同样的命令，很可能看到不同的 IP。面向全球提供服务的网站，情况就是这样。

![图 16：DNS 记录与 connect 的目标地址（00:14:16）。](/assets/images/21/0016.webp)

图 16：DNS 记录与 connect 的目标地址（00:14:16）。

它背后可能比想象中复杂，DNS 会给出多个 IP。它还能告诉我们，这是腾讯运营的 CDN 域名，API 请求没有直连 DeepSeek 源站，经过了 CDN 节点。这也能帮助复习网络课。想知道包怎样到达另一端，还可以用 traceroute。

![图 17：DNS 与逐跳转发（00:14:50）。](/assets/images/21/0017.webp)

图 17：DNS 与逐跳转发（00:14:50）。

课件中的 DNS 查询和路径探测命令：

```
dig api.deepseek.com +short
traceroute api.deepseek.com
```

网络课应该讲过 traceroute，我也可以让它执行，不过可能需要更长时间。它通过操纵 Time to live 的值，让包的寿命逐次增加：多一跳，就能再到达更远的一个节点。用这种方式探查网络链路经过的路由器，网络课应该也展示过。
