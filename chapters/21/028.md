相当于 CPU 把一张计算图发给 GPU。比如 kernel4 是一个 SIMT kernel，本身可能是高度并行的程序，但要等所有 SIMT 线程都执行完，这个 kernel 才结束。

![图 49：一个 kernel 的线程完成后再进入下一阶段（01:12:28）。](/assets/images/21/0049.webp)

图 49：一个 kernel 的线程完成后再进入下一阶段（01:12:28）。

随后才进入下一个 kernel，这就是程序写法和 cuda 程序的含义。这种方式显然还有改进空间：多线程程序中，SIMT 可能创建 100 万个线程，总有少数线程比较慢。刚开始并行度高，GPU 可能满负荷运行。

到最后，由于随机原因或调度等原因，只剩几个线程、两个线程束，就会降低整个 GPU 的利用率。利用率前期很高，末尾下降。能不能把所有 kernel 打包成一个？下一个 kernel 可能只需要前一个中的几项计算，它们也构成计算图。把计算图连接起来，就可能更充分地利用 GPU 算力。

![图 50：kernel 之间的计算依赖（01:13:37）。](/assets/images/21/0050.webp)

图 50：kernel 之间的计算依赖（01:13:37）。
