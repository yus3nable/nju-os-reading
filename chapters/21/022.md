C10 million 的问题交给厂商处理。不过 function as service 也没有这么简单：代码随时可能消失，运行到一半出问题，serverless 就会重启函数，从头执行。因此绝大部分 serverless function 都应该是 idempotent 的。离散数学里讲过，这叫幂等性。

同一个操作做几次，结果应该一样。比如计费，可以像 shared memory 那样，先 load sum 到 t，再 t\+\+，最后 store(t)。但如果 store 已完成，机器随后 crash，函数再执行一遍，就会记两次账。

写函数时要小心，可以改用集合来记账：生成一个 randomkey，往 set 里加入这个 key，sum 就取集合 s 的大小。这就实现了 idempotent。不过这个 random 必须在 serverless function 刚开始调用、请求进入系统时生成，由系统 assign 一个唯一的 idempotent key。

板书中的计数自增示意；load、store 是教学伪代码：

```
t = load(sum);
t++;
store(t);
```

向集合加入这个 key，就能实现 idempotent 的 counting。编程方式需要做这些小调整。只要程序是 idempotent 的，就可以放心交给分布式环境，让它帮助容错。
