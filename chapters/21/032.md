如果推理集群只运行 GPT 的 1\.5B 模型，也就是 GPT\-2 XL，配 1K 上下文，问题几乎就解决了。可以把它类比成 HTTP 请求到达业务节点。

图 56：Prefill、Decode 与 KV cache（01:24:58）。

对应的业务节点做一次数据库增删改查就结束；对应到推理，直接启动一个 Kernel，完成整个流程。但如果是今天的 1\.6T 模型、1 兆 Context，就很困难。一张 GPU 卡没有 1\.6T 显存，必须把计算分到很多卡上。像 N 平方的 Full Attention，计算量又很大。今天像水电一样的推理基础设施，普遍做 PD 分离，也就是 Prefill 和 Decoder 分离。刚才讲 Attention 像看书。每一层如果 Q 以前用过，K 和 V 就可以保存到 KV cache。因此 DeepSeek API 会有 cache hit、cache miss 两种价格。

cache hit 意味着此前已经完成过 Prefill，KV cache 可能还在显存里、仍然热着，没有被别的请求挤掉；时间太久就会被挤掉。KV cache 的 Prefill 开销很大，Decode 又有另一部分开销：读取完整 KV cache，根据当前 Q 计算，就像一遍遍看不同的书。

每看完一本，得到自己的短时记忆，再重写 Q，以此生成下一个 Token。
