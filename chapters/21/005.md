curl 获取到的提交脚本；变量由课程提交环境提供。

```
FILE=/tmp/upload.tar.bz2
cd .. && tar caf "$FILE" ".git" $(find . -name "*.pdf") && \
  curl -F "token=$TOKEN" \
       -F "course=$COURSE" \
       -F "module=$MODULE" \
       -F "file=@$FILE" \
       https://jyywiki.cn/api/upload/
```

大家有没有好奇过，为什么执行考试脚本里的 make submit，作业就交上去了？可以直接把这个问题交给 AI，让它阅读代码。最后会发现，我们用 curl 从服务器下载了一个脚本。要关闭 make submit，我可以在后台拒绝，也可以直接修改服务器上的这个文件。刚开学时大家看到的 not open 就来自这里。

当时 OJ 理论上已经开放，可能可以直接通过 API 提交程序，但我改掉 script 文件后，执行 make submit 就会看到 not open。它的做法是下载脚本，再通过管道交给 sh。很多软件也这样安装，比如 homebrew 的网站会要求把一行命令粘到命令行里，然后完成安装。

我也准备了一个类似的程序，用 requests 库构造 data，调用 DeepSeek V4 Flash 模型，返回 chat completion。随时可以让 AI 实现这样的命令行聊天程序，不用打开网页。命令行的好处是，各种输入都能通过管道交给它。程序返回了 response，接下来呢？
