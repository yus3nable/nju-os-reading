我还让 AI 输出全部 strace log，只需要求它提取每个 LVM 命令的 system call，就能查看 strace\.log，再让它解释。

![图 10：strace 中的 LOOP\_CTL\_GET\_FREE 与 LOOP\_CONFIGURE（00:10:13）。](/assets/images/26/0010.webp)

图 10：strace 中的 LOOP\_CTL\_GET\_FREE 与 LOOP\_CONFIGURE（00:10:13）。

通过 pipe 把整份 log 送给模型。第一步创建 loopback device，访问 /dev/loop\-control，调用 ioctl。

![图 11：Agent 对回环设备系统调用的解释（00:10:48）。](/assets/images/26/0011.webp)

图 11：Agent 对回环设备系统调用的解释（00:10:48）。

LOOP\_CTL\_GET\_FREE 取得空 loop device，创建多个回环设备。pvcreate 初始化物理卷后，LVM 开始工作，通过 /dev/mapper/control 映射器通信。这些功能同样交给 ioctl，还查到了 block device 大小。

![图 12：Agent 对物理卷初始化的解释（00:11:29）。](/assets/images/26/0012.webp)

图 12：Agent 对物理卷初始化的解释（00:11:29）。

再写标签、建组、建逻辑卷，方式与 loopback device 类似。先 ioctl 查询 device mapper 能力，再用 DM\_DEV\_CREATE 创建设备，写入 name、UUID。分区映射也会为各分区创建 dm 设备。

![图 13：回环设备、LVM 与 device mapper 的 ioctl（00:12:02）。](/assets/images/26/0013.webp)

图 13：回环设备、LVM 与 device mapper 的 ioctl（00:12:02）。

这些主要由 ioctl 实现。打开软件系统、观察系统调用，就能知道它怎样与内核交互。
