所以你们也知道要在文件系统这层要做缓存，和 Memory Hierarchy 一样，Memory Hierarchy 里面有一级，二级三级的缓存，我们也需要在内存里面留一份数据，然后我们的 bread 和 bwrite 就看起来，看起来这是一个 disk。对吧，我可以对它做 bread 或者bwrite。但是操作系统内核会统一分配一个当然 Linux 内核里面这个东西叫 buffer cache，是一个很糟糕的名字，你就可以认为它是一个 cache。buffer cache 这两个东西连起来。

这是一个历史原因，不应该这么叫它就是一个 cache，文件系统的 cache，然后你的 bread，你可以类比成是共享内存，就内存的load，然后 bwrite 是 store，你就很好理解了，就跟你的 cache 一样，你如果 load 的话，你必须从 cache 里面 load，如果 cache miss 的话，就是说这个 cache 里没有的话，它就要去这个设备里面找。当然如果设备是这样的话，这个设备又会去这个里面找，这个又会从去 loopback device 里面。

又会到文件里面找，经历一层转发的过程，写的时候和 memory hierarchy 里面的不太一样，因为我已经是一个 block 的写了，所以我这个 block 可以直接写到写到这个 cache 里面，把旧的东西给覆盖掉。然后就相当于是 cache hit，我直接写到 cache 里，下一次 reader 我就可以直接从 cache 里面给读走了。这是你要做的一个优化。所以其实你看到很多操作系统里面做的事情，和另外的系统。比如说存储系统。内存系统里面做的事情是一样的，它也用了这种 locality 的原理。如果你想要让这个文件系统高效的话，你就希望尽可能的把一起，就会常见一起访问的数据结构要放到一个块里，对吧，很自然的一个想法，这样你 cache hit 以后，我这一次比如说我读到这个数据结构，我下次要读到它临近的那个数据结构的时候，我的 cache 就会 hit，这样可以减少访问的次数，一定程度上减少这个读写放大。但是有些读写放大还是不可避免的，比如说我就是要写一个字节，那确实会造成比较显著的读写放大。
