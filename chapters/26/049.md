xv6 会把多次系统调用的 transaction 合成一个，把多个 ongoing write 批量提交，只需 flush 一次。代价是 crash 时可能多丢一点内容。

这样减少了等磁盘同步的次数。Linux 有 journaling block device，JBD、第二版 JBD2，每个设备都有后台 journaling daemon。

![图 58：进程表中的 jbd2 后台线程（01:12:15）。](/assets/images/26/0058.webp)

图 58：进程表中的 jbd2 后台线程（01:12:15）。

比如每隔 30 秒做一次 snapshot，写文件不会马上落盘。ext4 还有另一种做法：前面靠 flush 建立 happensbefore，确保内容先落盘再提交；它则可以省去 TxBegin、TxEnd，也不必真的等待 flush，虽然主动把日志推落盘更安全。日志头放 checksum 和长度，crash 后扫描 journal。

![图 59：用 checksum 和 length 检查日志完整性（01:13:21）。](/assets/images/26/0059.webp)

图 59：用 checksum 和 length 检查日志完整性（01:13:21）。

按长度读取，checksum 正确就认为已完整落盘，replay；不对就丢弃后续内容，用校验替代这部分落盘 synchronization。另有 metadata journaling：数据占大部分磁盘写入，而数据本身是否丢失，通常可由应用负责保证。

保存文件不能丢数据，应用有相应义务。ext4 default 采用 metadata journaling，inode、bitmap 更新都入日志，文件内容修改则不记。crash 可能丢近期内容，但它主要保证目录树完整。
