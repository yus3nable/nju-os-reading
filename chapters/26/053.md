所以我们在用户空间是可以控制这个行为的，用户空间为了实现，对吧，如果你想要是在用户空间实现 crash consistency，有一个叫 sync 系列的系统调用，有一个 sync 命令，如果你们去看我们的 makefile 的话，在你的 git committed 以后，我会加一个sync，做一个全局的文件系统的同步，确保数据都落盘。

![图 63：sync、syncfs、fsync 与 fdatasync（01:19:22）。](/assets/images/26/0063.webp)

图 63：sync、syncfs、fsync 与 fdatasync（01:19:22）。

所以我们那个 make 会比较慢，尤其是如果你们也像我一样，是在一个树莓派这样的比较慢的存储设备上，你会明显感到一个肉眼可见的延迟，这就是我为了实现 crash consistency，说我告诉操作系统，我们说 sync 说，请你把所有东西都落盘。

![图 64：sync 命令的手册（01:19:55）。](/assets/images/26/0064.webp)

图 64：sync 命令的手册（01:19:55）。

对吧，请你把所有东西落盘，确保数据的一致性，然后这是一个 family of system calls，你也可以带一个文件描述符，比如说有syncfs，可以去同步这个文件描述符所在的整个文件系统，也可以就同步这个文件的 data 和 metadata，就这一个文件描述符，甚至还有一个非常有用的系统，那叫 fdatasync(fd)，它同步文件的 data，并且只有它的 metadata 变了，只有 metadata 变了，这个metadata 才会同步。这个是很有用的。
