这个 block device 有三个接口，你可以这样理解，实际上它会更复杂一点，它有一个队列，然后你可以往那个队列里面提交请求，并且你能知道这个请求完成。但是简单起见你可以对比，例如我们并发程序写程序的时候的共享内存，有点像啊，对吧，内存也是一个字节序列，只是内存它的寻址方式是按字节寻址的。你可以在 memory hierarchy 帮你藏起来了整个从 L1，L2，L3，然后到memory，甚至还有更多层级的存储，的存储站，内存站，然后你可以用 load 和 store 去按字节的方式去寻址。

这个类似的我们的 block device 也是，它是一个 block array，一个数组，然后它的数组可能是 4K 或者比如说软盘上面是 512 个字节，你看着那个块去一起把它读出来写进去。以及并发程序里面我们有一个说 data race 是很危险的，如果两个线程同时读写一个memory location 就很危险，所以我们可能要用互斥锁这样的东西来实现互斥。然后我们的 block device 也有这样的一个类似于barrier 的指令，它可以像并发程序里面你能够从并行变成串行一样，它有一个叫 block sync，它可以等待 ongoing 的所有正在在途当中的写入落盘以后再返回。

你可以这样理解，就用这三个操作来实现，你可以就用它来实现任何数据结构，就像你可以用 load 和 store 来实现任何的内存里的数据结构一样。
