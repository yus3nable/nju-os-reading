还有一个很重要类型的死锁，就是 ABBA 型的死锁，那这个就更直观了，也就是我们在那个，哲学家吃饭的时候，我们看到的情况，对吧，所有的人都举起左手，acquire 一把锁，然后它试图去 acquire 另外一把锁的时候，就没有人可以 make progress 了，就跟我们刚开始的时候，看到那个公交车的例子一样。

![图 8：哲学家就餐中的 ABBA 型死锁（00:10:23）。](/assets/images/17/0008.webp)

图 8：哲学家就餐中的 ABBA 型死锁（00:10:23）。

```
void T_philosopher() {
  mutex_lock(&avail[lhs]);
  mutex_lock(&avail[rhs]);
  // ...
}
```

所以如果有一个线程 lockA，然后它再 lockB，好，那如果线程 T1 和 T2，它没有交错执行，那这个程序好像 OK，先 A 后 B，但是如果 T2 它 lockB，然后这个时候，T1 和 T2 都持有了自己的锁，那这时候 T1 试图去 lockB，它就要等到 T2，把锁释放掉。但是同时 T2，如果这个时候执行 lockA，它就需要等待 T1，把这个锁释放掉。

![图 9：T1 持有 A 等 B，T2 持有 B 等 A（00:11:14）。](/assets/images/17/0009.webp)

图 9：T1 持有 A 等 B，T2 持有 B 等 A（00:11:14）。
