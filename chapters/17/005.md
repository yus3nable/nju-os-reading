ABBA 型死锁也很常见。哲学家吃饭时，所有人都举起左手，acquire 一把锁，再尝试 acquire 另一把锁，就没有人能继续前进，与开头公交车的例子一样。

![图 8：哲学家就餐中的 ABBA 型死锁（00:10:23）。](/assets/images/17/0008.webp)

图 8：哲学家就餐中的 ABBA 型死锁（00:10:23）。

```
void T_philosopher() {
  mutex_lock(&avail[lhs]);
  mutex_lock(&avail[rhs]);
  // ...
}
```

假设线程先 lockA，再 lockB。如果 T1 和 T2 没有交错执行，程序看起来没有问题。但如果 T2 先 lockB，此时 T1、T2 各持有一把锁，T1 再 lockB 就要等 T2 释放；同时 T2 执行 lockA，又要等 T1 释放。

![图 9：T1 持有 A 等 B，T2 持有 B 等 A（00:11:14）。](/assets/images/17/0009.webp)

图 9：T1 持有 A 等 B，T2 持有 B 等 A（00:11:14）。

这样就形成了循环等待。Dining Philosophers 有五个人、五个线程，等待形成环，情况比 ABBA 更复杂，也可以将其理解为 ABBA 型 Deadlock。做实验拆锁时，很容易遇到这种死锁；实际系统中它也最常见，就不再展示了。如果不用上一节课那些办法打破上锁时的环形等待，Dining Philosophers 打印一会儿就会停止，整个系统陷入静默。好消息是，死锁通常比较容易检查：程序前一秒还在不停输出日志，突然一条也没有，就知道可能发生了死锁。此时 attach 一个 GDB，也相对容易检查。

为了解决死锁，早期操作系统有了锁以后，人们开始研究它为什么发生。
