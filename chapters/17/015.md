这些例子可能让人觉得，自己不会犯不上锁这种错误。大家知道共享数据结构需要保护，但结构复杂以后就容易出问题。前面讲互斥锁时提过链表：访问节点时，除了持有该节点的锁，还必须持有 Previous 和 Next 的锁，否则结构性修改就可能出错。

```
void T_1() { mutex_lock(&A); sum++; mutex_unlock(&A); }
void T_2() { mutex_lock(&B); sum++; mutex_unlock(&B); }
void T_1() { mutex_lock(&A); sum++; mutex_unlock(&A); }
void T_2() { sum++; }
```

常见情况之一是上错锁：一个线程 Lock A，另一个 Lock B，看似各自互斥，两个 sum 实际仍可能发生 data race。sum\+\+ 同时有 ReadWrite、WriteWrite 的竞争。另一种情况是罕见路径漏锁，例如 Ctrl\+C handler 或异步事件处理。

在这样的路径上忘记代码会并发，漏掉锁，就形成 data race。它是 UndefinedBehaviour，可能有毁灭性后果。也许有人认为，只要保持清醒就能避免。现在实现高性能 malloc 时，如果第一次没有把锁加对，可以请 AI 仔细分析。
