文件例子涉及资源级竞争：访问操作系统对象时发生 ABA、atomicity violation。希望得到的原子性被违反，就成了并发 bug，情况千奇百怪。

还有事件未按预定顺序发生的问题，例如 concurrent use\-after\-free。free 必须等所有可能的 user 结束，类似先 join 再 free。可以用信号量：若已知三个线程可能 use，就 P 三次，从桌上拿走三个玩具；每个线程确认不再访问后放回一个玩具。若放回的时机错了，放完还访问，就会形成 concurrent use\-after\-free。有兴趣可以看 GhostRace：即使程序原本没有 use\-after\-free，处理器的投机执行也可能造成问题。假设代码正确使用了 lock、unlock。

例如一边在锁内 free 后把 pointer 置空，再 unlock；另一边加锁后判断 pointer 非空才 use、dereference。程序正确实现了互斥。麻烦在于 lock 的实现：做 atomic exchange，成功就进入 lock region。

失败则 goto retry。按顺序执行逻辑，只有另一边 unlock，retry 才会结束，后续才会执行。所以读 ptr 一定 happens\-after 前面的操作，使用空指针的那部分代码不会执行。但 cpu 遇到 if 时，尚不知道判断结果。

cpu 有剩余算力时，可能把两个分支都执行，再抹掉预测错误的一半，弥补分支预测延迟等开销；指令已经 load 并执行。但这种投机执行会产生影响。

例如留下 cache footprint 等 side channel，可以利用访问时间等侧信道，窃取 pointer 解引用涉及的信息。若这条路径被投机执行，线程实际没有获得互斥锁，cpu 却执行了锁内路径。

此时 pointer 可能仍有值，cpu 读到它后继续投机执行。如果导致信息泄露，就成为可利用的漏洞。这些情况非常复杂，很难全部想清楚。
