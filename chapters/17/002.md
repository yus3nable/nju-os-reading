然后并发编程，我们讲到，其实已经讲完了，因为你们理论上说已经可以用我们讲过的机制实现各种各样的并发程序了。我们最开始的时候把线程比作人，把共享内存比作物理世界，然后这样我们构建了很多的并发的算法，像 Peterson 的协议啊这些。然后又有spawn，join，lock、unlock，wait、broadcast，P/V 操作这些 API。然后就是因为有了这些 API，当然它底层的操作系统，比如说操作系统提供的是像 clone 啊，或者是 futex 这样的系统调用。

然后帮我们实现了这些并发编程的基础的 API 以后，你就可以去实现比如说像计算图啊，像 dining philosophers 啊，生产者消费者啊这样的各种各样实际中有用到的并发编程。当然了，我还是要告诉大家并发编程其实是很难的，因为我们人类本质上我们的整个训练过程，预训练，后训练，微调过程都是在物理世界中完成的。然后在这个物理世界中有一个非常基本的物理规律就是，我们的脑子是在我们脑壳里的，它飞不出来。然后我们能够感知到的都是我们自己的手脚眼睛看到的东西。所以人天生就是一个物理世界这个shared memory 里面，视角非常小的一个东西，然后我们就被训练成了这样的东西。

所以没办法，我们，包括我们写程序的时候，你们学编程的时候，一开始也是教你们顺序执行。你们都没有，对吧，没有意识到，其实程序编程语言是一个顺序执行的模型，因为它实在是太自然了。然后一旦我们从顺序执行变到并发程序，那就很容易产生程序执行的各种各样的幻觉，你会不由自主的会觉得，我的程序应该是顺序执行的，然后就错了。因为你要理解所有的并发程序的行为是 NP\-hard，你必须要枚举指数多个东西才能知道并发程序真正的行为是什么。所以今天我就来给大家讲一讲 Learning from Mistakes，是我们在实际的并发编程的时候会遇到什么样的问题，以及我们人类是怎么样解决这个问题的。

首先，第一类我要讲的并发 bug 叫死锁，这个名字也非常的直观啊，死锁。
