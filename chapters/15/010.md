图 19：从忙等循环到条件变量 cond\_wait（00:23:54）。

```
mutex_lock(&lk);
while (!check_condition()) {
    cond_wait(&cv, &lk);
}
mutex_unlock(&lk);
```

前面直接写同步的代码都有相同模式：线程没全结束、室友没到，就继续等待。模式都是 while 循环，这里写成 do\-while，先上锁检查条件，检查后解锁；条件满足就退出，否则重试。

乐团同步正确，却很浪费。线程为了等指挥挥拍，不断观察状态，是忙等。此时更应把 CPU 让给真正在工作的线程，例如 VS Code、浏览器。

同步条件可能几天后才满足，没有必要浪费几天 CPU Cycles。既然这些场景都符合条件检查循环，能否让库函数和操作系统提供 API？这些并发 API 实际都通过 futex 系统调用实现，可以增加一个帮助等待的接口。

条件不满足时，让线程睡眠；条件满足，再唤醒，就发明了条件变量。操作系统或库提供这个机制，用来等待同步条件满足。
