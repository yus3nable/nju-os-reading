实现同步主要有两个函数。wait\_for\_beat 要等待同步条件满足，把这句话翻译成代码即可。但所有共享变量访问都必须加锁，否则会有 sum\+\+ 那样的问题。加锁让执行顺序成为 ABBA 这样的互斥次序，还提供可见性保证。

![图 17：读取拍号和增加拍号都由同一把锁保护（00:21:30）。](/assets/images/15/0017.webp)

图 17：读取拍号和增加拍号都由同一把锁保护（00:21:30）。

```
void wait_for_beat(int current_beat) {
retry:
    mutex_lock(&lk);
    int conductor_beat_ = conductor_beat;
    mutex_unlock(&lk);
    if (current_beat >= conductor_beat_) {
        goto retry;
    }
}

void release_beat() {
    mutex_lock(&lk);
    conductor_beat++;
    mutex_unlock(&lk);
}
```

再强调一次：锁的 release happens\-before 下一次上锁的 acquire。因此 release 前的共享内存写入，例如 x 等于 1、sum\+\+ 或数据结构更新，在后续 acquire 后都可见。

往链表插入节点，后续就能正确看到它。例如本次把 sum 加到 10，释放锁后，下一次加锁读取时也一定能看到这个 10。

![图 18：release 与下一次 acquire 之间的数据可见性（00:22:28）。](/assets/images/15/0018.webp)

所以任何共享变量访问都要由同一把锁保护。乐手等待指挥释放拍子，会不断读取当前拍号，读完立即释放锁。自己的拍子还没到，就继续检查；到了就赶紧返回，调用 play。像乐手必须盯住指挥，注意力不集中就可能跟错拍。指挥 release beat 同样是并发代码，要加互斥锁，再把拍号加一。这样正确实现同步：不按回车，所有线程都停在等待中。
