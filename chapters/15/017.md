解决生产者消费者，乃至各种并发同步问题，先想清同步条件：生产者等桌上有空位，消费者等桌上有苹果。明确等什么，再套用前面的模板。

![图 29：等待条件满足后仍持有锁（00:44:00）。](/assets/images/15/0029.webp)

图 29：等待条件满足后仍持有锁（00:44:00）。

先加锁，继续条件未满足就 wait。循环退出后，可以 assert 条件满足，且当前仍持锁，安心拿走或放入苹果，无人能在此时干扰。操作会更新共享状态：放苹果，可能满足等待苹果的线程；拿苹果，可能满足等待空位的线程。直接 cond\_broadcast 唤醒所有人，包括生产者、消费者。看起来多唤醒了些人，例如放苹果后，主要需要消费者。

广播却把生产者也叫醒，有的发现仍没空间，就绕回 cond\_wait 再等。通常这点开销微不足道，先写绝对正确的代码；确实有性能问题，再找办法优化。

![图 30：生产条件 depth &lt; n，消费条件 depth &gt; 0（00:45:49）。](/assets/images/15/0030.webp)

图 30：生产条件 depth &lt; n，消费条件 depth &gt; 0（00:45:49）。

```
void T_producer() {
    mutex_lock(&lk);
    while (!(depth < n)) {
        cond_wait(&cv, &lk);
    }
    assert(depth < n);
    depth++;
    printf("(");
    cond_broadcast(&cv);
    mutex_unlock(&lk);
}
```

桌上苹果数、括号深度小于 n，就能生产；消费条件刚才说大于 n，准确说是大于 0。将 condition 代入模板即可。更新所有共享状态时仍须持有同一把互斥锁，print 时最好也持锁，否则输出可能不对。
