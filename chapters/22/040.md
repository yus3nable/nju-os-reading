查看 nuke0，可以看到它是字符设备。直接用 cat 读取时，cat 先执行 open，打开设备文件。

终端中的模块加载和设备文件列表：

```
$ sudo insmod driver.ko
$ ls /dev/nuke*
/dev/nuke0  /dev/nuke1
```

![图 59：普通 cat 被拒绝后用 sudo 读取设备（01:04:10）。](/assets/images/22/0059.webp)

图 59：普通 cat 被拒绝后用 sudo 读取设备（01:04:10）。

终端先报告权限不足，随后用 sudo 读取成功：

```
$ cat /dev/nuke0
cat: /dev/nuke0: Permission denied
$ sudo cat /dev/nuke0
This is dangerous!
```

得到文件描述符后，再执行 read，Linux 转到设备驱动的 read。我在 struct file\_operations 里指定了回调，所以会调用 launcher\_read。

![图 60：read、write 回调接入 file\_operations（01:04:31）。](/assets/images/22/0060.webp)

```
图 60：read、write 回调接入 file_operations（01:04:31）。
```

驱动将两个回调接入文件操作接口：

```
static struct file_operations fops = {
    .owner = THIS_MODULE,
    .read = launcher_read,
    .write = launcher_write,
};
```

函数返回 this is dangerous，于是终端上就显示它。向 nuke 写错误密码时，内核会记录 incorrect secret, cannot launch。对应到真实设备，也可以点亮一个提示灯。
