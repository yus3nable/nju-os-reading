设备复杂性无法消除。NVIDIA 每代 GPU 都有新功能，每项功能在某种意义上都需要开关，应用侧就要提供控制程序，比如开启或关闭 DLSS。

还有各种 feature 的开关。功能这么多，就成了 Unix 的负担，ioctl 有复杂的 Hidden Specifications。Everything is a File 看起来是干净的抽象，再想想 ProcFS 中一万个文件。如果只看到 Linux 大约 300 条系统调用，可能觉得做一个兼容系统不太难。

微软曾做 Windows Subsystem for Linux。大家应该用过，在 Windows Terminal 中直接启动 Linux，本地运行。最早它的每个进程就是 Windows 进程。

每次调用 Linux 系统调用时，Windows 将其拦截，模拟执行后返回。每个 Linux 进程、线程都对应 Windows 进程、线程，我觉得实现很天才。但 Unix 世界的 ioctl、ProcFS 有太多隐藏细节，工程上无法做到百分百兼容。最后微软放弃这种做法，改用虚拟机，在里面运行 Linux 内核，才实现完整功能兼容。

网卡、GPU 等设备，都高度依赖 ioctl。
