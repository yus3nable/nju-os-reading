对吧，然后还有各种各样的 feature 都可以打开和关闭，因为这个系统就有这么多功能，所以这其实是一个 Unix 很大的负担，ioctl有非常复杂的 Hidden Specifications，你觉得比如说像 Unix，Everything is a File 是一个非常干净的抽象，那你回头想一想ProcFS 里面的一万个文件，你如果要做一个对吧，你一开始的时候，你第一感觉是，Linux 系统当中也就 300 条，那我做一个Linux 兼容的操作系统。

应该不太难的，就像微软，他想做一个 Windows Subsystem for Linux，你们应该用过这个功能，你可以在 Windows 里面直接启动一个 Windows Terminal，然后它就是 Linux。然后这个 Linux 是跑在本地的，然后最早的时候，每一个 Linux，就 Windows Subsystem for Linux 的进程，它都是作为一个 Windows 进程，跑在 Windows 上的，然后只是它每一次调用 Linux 系统调用的时候。

Windows 都会悄悄地把这个系统调用给拦截走，然后模拟地执行这个系统调用，然后再返回给它，甚至每一个 Linux 进程都是一个Windows 进程，每一个 Linux 线程都是一个 Windows 线程，这是一个非常天才的实现，就是因为这个 Unix 世界。比如说 ioctl，ProcFS，这里面有太多隐藏的细节，使得它想要做到百分百的兼容，就是不可能，从工程意义上，就是不可能的，所以最后它们放弃了，微软放弃了，放弃最后还是用虚拟机。然后在虚拟机里面有一个 Linux 内核。

然后这样它才能实现完整的功能性的兼容，然后在这个 ioctl 上，像比如说像网卡，像 GPU 这种，都是非常重度依赖 ioctl 这个系统调用的。
