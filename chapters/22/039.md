因为 Everything is a File，反正是一个 file，一个核弹发射器，然后那这个 file，如果我从这个 file 里面读，我就总会读出这个字符串，叫 this is dangerous，理论上说我可以送这个this is dangerous，那我就可以送任何。比如说我从核弹发射井，我的一些传感器里面读取一些数据。

![图 55：launcher\_read 返回字符串（01:02:19）。](/assets/images/22/0055.webp)

图 55：launcher\_read 返回字符串（01:02:19）。

launcher\_read 的函数体片段；offset、count 和 buf 为调用参数。

```
if (*offset != 0) {
    return 0;
} else {
    const char *data = "This is dangerous!\n";
    size_t datalen = strlen(data);
    if (count > datalen) {
        count = datalen;
    }
    if (copy_to_user(buf, data, count)) {
        return -EFAULT;
    }
    *offset += count;
    return count;
}
```

然后把这个数据送给它，当然我就这里就送了一个字符串，我就把这个字符串拷贝到用户态就行了，我在 write 的时候，我会做一个密码的校验，相当于是你核弹也不能直接就，像我那个 LED 灯一样，往里面写一个 1。然后核弹就发出去了。所以我会往里面写一个密码。然后我在我的驱动里面，会对这个密码做一个校验，就像实际当中，你不仅会有这样的软件的校验。比如说你需要把这个钥匙插进去，两把钥匙同时转一下，以及它内部还有一些冗余的逻辑，确保。

![图 56：launcher\_write 复制并比较输入（01:02:52）。](/assets/images/22/0056.webp)

图 56：launcher\_write 复制并比较输入（01:02:52）。

launcher\_write 中复制用户输入的片段，后续比较密码并输出字符图案的分支见原画面。

```
char databuf[4] = "\0\0\0\0";
if (count > 4) {
    count = 4;
}
if (copy_from_user(databuf, buf, count)) {
    return -EFAULT;
}
// 后续：memcmp(databuf, "\x01\x14\x05\x14", 4)
```

比如说有些部件发生误短路，对吧？误短接的时候，你的核弹不会错误的发射出去，要做很多的检查，然后这里做了一个简单的检查，就是一个 memory compare，如果我收到写入的这个 password 是正确的话，我就会把这个核弹给。然后现在以前写驱动是一个还是一个挺麻烦的事情，但今天就直接 vibe coding 了，我的旧的代码在新的 kernel 上面，不能编译。
