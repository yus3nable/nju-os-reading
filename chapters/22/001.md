前面已经讲完 Virtualization 和 Concurrency。先是经典 Unix 的进程与系统调用世界，从底层 System Call 开始，经由 libc 等逐层构建整个 Linux 应用世界。之后稍作扩展，介绍线程的 spawn、join API，打开了并发编程这个魔鬼的盒子，从入门到放弃。

后面讲的各种并发编程模型，都可以用 spawn 线程来理解。但并行计算、JavaScript 异步计算，以及 GPU 异构计算，编程方式有所不同：有些为了方便程序员，有些为了硬件执行效率。有了这些前提，终于可以补上操作系统课最后一部分：操作系统中的对象。前面讲系统调用时提过，可以用 open 打开操作系统对象。

打开后得到文件描述符。它是很重要的概念，是指向操作系统对象的 handle，也就是把柄。UNIX 和 Linux 采用 Everything is a File 的设计，用同一套 API 访问各种对象。比如遍历 procFS 目录就能查看进程树，读取 proc 下 pid 下的 maps 文件，就能查看进程地址空间。

通过文件系统 API 可以访问这一切。之前只告诉大家，有 TTY 字符终端、disk 磁盘等对象，可以直接使用。今天就打开这个黑盒，讲清计算机系统中的 I/O 设备如何实现。
