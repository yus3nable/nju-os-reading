还有 cudaMemcpy 等命令。GPU 有显存，它觉得 CPU 内存太慢，共享内存没有意义。实际也可以在 CUDA host 上做 Memory Allocation，分配 CPU、GPU 共享的内存，只是速度慢一些。大多数时候，GPU 希望使用自己更快、比金子还贵的显存。

CPU 通过 GPU 的寄存器通信、配置，告诉它做什么，再把编译好的 Kernel 代码，以及 cudaMemcpy 的数据，通过 DMA 送进显存。这些数据最初在内存，另一个处理器 DMA 负责完成 cudaMemcpy 和 Kernel 的 Copy。

![图 40：CPU 把代码和数据送入 GPU 显存（00:39:54）。](/assets/images/22/0040.webp)

图 40：CPU 把代码和数据送入 GPU 显存（00:39:54）。

全部拷完后，CPU 告诉 GPU，从显存某个 address 开始运行，像启动程序一样。GPU 也是一台电脑，但受 CPU 控制，逐个启动 Kernel，运行大量 T\_worker 线程。其他加速器也类似，比如手机高通处理器上的 NPU 引擎。它与 NVIDIA GPU 的独立显存不同，采用共享内存，只需告诉 NPU 执行什么程序，它就会在共享内存上执行。讲过这么多设备，应该能看到，每个设备都有自己的细节。
