原示例中的 guest 指令字节、复制和 PC 设置片段；依赖 KVM 初始化和 set\_core\_reg。

```
unsigned char guest_code[] = {
    0x20, 0x08, 0x80, 0xD2, // mov X0, #0x41
    0x21, 0x00, 0xA0, 0xD2, // mov X1, #0x10000
    0x20, 0x00, 0x00, 0x39, // strb W0, [X1]
    0x02, 0x00, 0x00, 0xD4, // hvc #0
};
memcpy(guest_mem, guest_code, sizeof(guest_code));
set_core_reg(vcpufd, ARM64_CORE_REG(pc), GUEST_ENTRY);
```

![图 71：进程中的虚拟机对象与 vCPU（01:17:05）。](/assets/images/22/0071.webp)

图 71：进程中的虚拟机对象与 vCPU（01:17:05）。

code、data 像传给显卡一样，放入当前进程的这段内存，再初始化 VCPU 的寄存器。虚拟机在内核中创建，用户程序无法直接访问、控制，但可以通过 ioctl 改寄存器，并在进程中分配归它使用的内存。执行 130 行，对 VCPU 文件描述符调用 KVM\_RUN，就开始运行虚拟 CPU。它可以执行特权指令，比如关中断，外面不干涉，内部能看到关中断的状态。

调用 ioctl、KVM\_RUN 后，当前进程就像变成虚拟机，连续逐条执行指令。遇到某些特殊指令会退出，例如 I/O、MMIO，触发 KVM exit；这不属于系统调用。

![图 72：VM exit 返回用户程序处理（01:18:44）。](/assets/images/22/0072.webp)

图 72：VM exit 返回用户程序处理（01:18:44）。

退出原因还包括 Hypercall、VM exit、Shut down 等。比如要执行 I/O，但这个虚拟机没有 I/O 设备，无法完成，就触发 VM exit，回到原来的进程继续执行。

原程序执行 KVM\_RUN 的调用片段，位于 while (1) 内；随后按 run\-&gt;exit\_reason 分支处理。

```
if (ioctl(vcpufd, KVM_RUN, 0) < 0) {
    perror("ioctl KVM_RUN");
    exit(1);
}
```

此时可以读取 exit reason。如果是 memory I/O，就在用户程序里模拟 I/O 设备，送回一个值。整个过程只用了 ioctl 这一个 API。考试不会考 KVM，但这个例子能说明 ioctl 有多复杂：整个虚拟化子系统都建立在它之上，承载着访问操作系统内部对象、子系统的复杂性。
