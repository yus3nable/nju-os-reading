可以把 DMA 理解为一个 CPU，只是指令集很受限，无法像我们的 CPU 一样执行任意指令，可能根本没有指令集，只能做一件事。比如英特尔 8237 DMA 有四个通道，每次依次检查，发现某通道待拷贝字节数大于零，就复制一个字节。DMA 与 CPU 共享内存，还可以共享 I/O 端口地址空间。

![图 37：CPU 和 DMA 共享内存（00:36:37）。](/assets/images/22/0037.webp)

图 37：CPU 和 DMA 共享内存（00:36:37）。

学过多线程、多处理器编程后就容易理解：另一个 CPU 不断执行 memory copy，可以从内存到内存、内存到端口、端口到内存，把 CPU 从耗时的 I/O 中解放出来。比如刚才 ATA 的读数据过程，磁盘准备好后把数据放到自己的缓冲里，CPU 再从端口每次读四个字节。如果读一兆数据，CPU 就得执行一个很大的循环。让更小的 CPU 专门做 memory copy，就能承担这个任务。CPU 看来，DMA 依然是一组寄存器。

读写这些寄存器，就能配置 memory copy 的地址、端口、字节数，控制 DMA 开始、结束，可能还可以取消正在执行的任务。

![图 38：DMA 在内存与 I/O 设备之间搬运数据（00:37:43）。](/assets/images/22/0038.webp)

图 38：DMA 在内存与 I/O 设备之间搬运数据（00:37:43）。

启动后，DMA 在 CPU 内存、内存或 I/O 设备之间传送数据，释放 CPU 算力。一旦设备除了提供寄存器协议，还能访问内存，就可以做更多复杂功能，比如 GPU、NPU 这样的异构加速器。
