所以我们不应该做这件事，我们应该做一个抽象，对吧？做一个抽象，抽象，我们希望在应用程序上面用一组 API，一组 API 来访问我们说的这些对象，然后这些 API，其实大家都知道了，我们说我们把文件变成操作系统里面的对象，然后对象，那 Everything is a File，那么 Everything is a File。所以我们的设备也被抽象成了 file。这是大家非常熟悉的对象。比如说我们在/dev 底下，/dev 底下有好多好多的设备。然后每一个设备它都是一个 file。

这个 file 我们用的就是文件的那些 API，open, read, write，然后如果我们要比如说要互斥的访问，你可以用 flock 这样的机制给它上锁，因为 Everything is a File，所以其实你只要实现文件的操作，你的设备就可以被接入为文件系统。

课件中的文件操作接口片段，类型来自 Linux 内核；其余成员以 \.\.\. 省略。

```
struct file_operations {
    struct module *owner;
    loff_t (*llseek)(struct file *, loff_t, int);
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *,
                     size_t, loff_t *);
    ...
}
```

然后你要显示一个比较复杂的图形的时候，你甚至感觉那个图形的显示也是有滞后的，这就是因为你在没有设备驱动的时候，这个设备其实 CPU 是不知道应该怎么样正确的把它变成这些 API 的。
