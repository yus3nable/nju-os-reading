需要用一组 API 抽象设备，让应用访问操作系统中的对象。沿用 Everything is a File，设备也被抽象为熟悉的 file。比如 /dev 下有很多设备，每个都是一个 file。

访问时使用 open、read、write 等文件 API；需要互斥访问，可以用 flock 加锁。只要实现文件操作，设备就能接入文件系统。

![图 51：/dev 下的设备文件（00:55:13）。](/assets/images/22/0051.webp)

图 51：/dev 下的设备文件（00:55:13）。

这就是设备驱动的作用。硬件通常需要对应驱动才能运行。比如没有显卡专用驱动，只用默认驱动，虽然可能正常显示图形界面，性能却很差，移动鼠标都可能有延迟。

课件中的文件操作接口片段，类型来自 Linux 内核；其余成员以 \.\.\. 省略。

```
struct file_operations {
    struct module *owner;
    loff_t (*llseek)(struct file *, loff_t, int);
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *,
                     size_t, loff_t *);
    ...
}
```

显示复杂图形时也可能滞后，因为没有对应设备驱动，CPU 就不知道怎样把设备操作正确转换为这些 API。
