接下来用 mmap 分配缓冲区，通过 ioctl 告诉 UVC 驱动：缓冲区已经准备好，有数据就送到这个内存地址。然后等待数据。

图 78：缓冲区出入队、停止流和清理（01:23:06）。

Agent 时序图中的调用顺序，保留其简写形式：

```
openat("/dev/video0")
ioctl(VIDIOC_QUERYCAP)
ioctl(VIDIOC_S_FMT)
ioctl(VIDIOC_REQBUFS)
ioctl(VIDIOC_QUERYBUF) x4
mmap x4
ioctl(VIDIOC_QBUF) x4
ioctl(VIDIOC_STREAMON)
ioctl(VIDIOC_DQBUF)
write("capture.jpg")
ioctl(VIDIOC_STREAMOFF)
munmap x4
close
```

这里有四块缓冲区。程序有时处理慢，有时处理快而摄像头数据慢，由摄像头 subsystem 协调。stream on 后，通过 ioctl 等待一帧就绪，从 buffer 取出，再用 write 写到 capture\.jpg。这就是 Linux 摄像头的 V4L2 subsystem。

摄像头控制通过 ioctl 完成，read、write 主要提供数据接口。直接要求设备执行某项功能、任务，通常要用 ioctl，其中也有生产者消费者关系。
