另一个设备是摄像头。今天买到的摄像头，比如刚才用于放大的显微镜，基本应该都是 USB 的，也都免驱。这是因为 USB 有一个标准 UVC，USB Video Class，规定了如何枚举系统中的 USB 摄像头设备。

Linux 中会看到 /dev/video0、/dev/video1 这样的设备。摄像头与操作系统或应用协商图像格式、分辨率、帧率、压缩方式等。我觉得刚才摄像头与树莓派可能协商错了某个参数，也可能用了山寨软件，没有完整实现 UVC 标准，导致像素颜色出问题。协商完成后就开始传输。

UVC 支持逐帧读取，每次读一张图片，可以是未压缩图像，也可以是 Motion JPEG、H\.264 等压缩图像。虽然经过 USB，交换的仍是字节流，和寄存器模型相同。行车记录仪、显微镜、内窥镜、平板扫描仪、眼球鼠标等，都是 UVC 设备，这让开发很方便。

买一个 UVC 兼容摄像头，在 Windows 上开发软件，就能构成这样的设备。底层模型虽然只是交换数据的寄存器，有了程序、协议，就能交换不同数据，造出打印机、摄像头这样的设备。要借助 I/O 完成更复杂的任务，还需要进一步扩展。

课件中的 DMA 四通道执行模型，属于教学伪代码；channels 和通道结构未展开。

```
void T_i8237() {
    while (1) {
        for (int i = 0; i < 4; i++) { // Channel
            struct channel_t *ch = &channels[i];
            if (ch->count-- > 0) {
                if (ch->mode == READ)
                    ch->io = ch->mem[ch->addr++];
                else
                    ch->mem[ch->addr++] = ch->io;
                break; // Priority
            }
        }
    }
}
```
