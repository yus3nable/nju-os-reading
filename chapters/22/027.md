每个设备都暴露一组寄存器接口。IBM PC 时代，端口是写死的，比如 0x3f8、0x60、0x64，都绑定具体设备，这是当时标准化的做法。

![图 41：总线的设备注册与转发（00:41:00）。](/assets/images/22/0041.webp)

图 41：总线的设备注册与转发（00:41:00）。

当时设备不多，没有想到未来会出现这么多种类。怎样兼容无限的设备？既然设备都是一组寄存器，可否做一个类似虚拟地址空间的东西，用 012345 这样的地址，memory map 到设备寄存器，再 memory map 到进程地址空间？插入打印机时，这里分配 234，那里分配 678。每天使用的总线就能做这件事。总线也是特殊的 I/O 设备，可以理解为一组组寄存器。

![图 42：总线为多个设备分配接口（00:42:06）。](/assets/images/22/0042.webp)

图 42：总线为多个设备分配接口（00:42:06）。

与摄像头等具体设备相比，总线的寄存器更多，可以动态分配，并提供一套协议。CPU 只需与总线通信，就能轮询有哪些设备。设备变化时，总线也能给 CPU 发中断，可能还自带 DMA。CPU 配置总线上的 DMA，指定从哪个端口、把哪些数据搬到内存哪里，就能完成传输。

总线相当于 I/O 设备管理器。建立这样的生态，硬件厂商才能持续生产兼容设备。
