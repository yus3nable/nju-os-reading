UNIX 因此设计了文件描述符。C 程序在 int main 中操作内存、寄存器，UNIX、Linux 还提供另一种“地址空间”，不能直接用 pointer dereference 访问。

![图 48：文件描述符：另一个地址空间（00:49:01）。](/assets/images/07/0048.webp)

图 48：文件描述符：另一个地址空间（00:49:01）。

int x、int g 等全局或局部变量，可以 load、store；main 地址也能读取，上节做过。另一种空间却在内核，0、1、2 指向打开文件，必须通过系统调用访问，这就是文件描述符。其实大家已经用过。

最早的 minimal 用 write 向终端输出，第一个参数就是 1。write，1，buff，size，表示向编号 1 的对象写数据，有点像 x86 I/O 要指定端口。

向端口写数据，才能交给外部设备。文件描述符也不能直接 dereference，而是让系统调用根据编号访问文件。

![图 49：应用程序通过编号访问文件对象（00:50:50）。](/assets/images/07/0049.webp)

图 49：应用程序通过编号访问文件对象（00:50:50）。

read 0，就从编号 0 对应文件读取。也不必把它看成地址空间，它就是应用访问内核对象的整数编号。everything is a file，所以 file descriptor 也可以理解为 everything descriptor。

它像间接指针，由操作系统解释 0、1、2 各指向什么。若这些编号已经占用，再 open a\.txt，就需要分配新编号。

它会选择最小未分配编号，比如 3，让它指向 a\.txt 的 file。应用只能通过系统调用访问。概念很明确，虽然“文件描述符”这个 term 有些 misleading。

记住它是指向操作系统对象的编号就可以。接着还能让 AI 帮忙探索：这个空间有多大？平常 wc、grep 组合，可能只用 0、1、2，甚至不再 open 文件。

提出问题就能探索。Windows 把类似概念叫 handle，门把手也是 handle，比如特斯拉车门，第一次用可能不知道怎么开。把手给人控制对象的能力。

握住门、窗、锅的 handle，就能控制它。我觉得“把柄”更形象：掌握对象的把柄，就能操作它，像通过编号 1 做 read、write。准备了 try\_open 示例，它用可读可写方式 open 文件，再检查结果。

![图 52：try\_open：打开文件并检查返回值（00:55:14）。](/assets/images/07/0052.webp)

返回值小于 0，比如 \-1，表示失败，可以 perror 打印原因。这里尝试的路径都不存在，所以打开失败。

![图 53：打开不存在的路径与 /dev/sda 均返回 \-1（00:55:34）。](/assets/images/07/0053.webp)

/dev/sda 不存在，是因为树莓派用 SD 卡，设备叫 mmcblk0，是 MMC 的 SD 卡。大家机器可能叫 SDA，或用更快的 NVMe。改文件名再试。不存在时返回 \-1，提示 No such file or directory。系统语言不同，这句话甚至会显示中文。

perror 会根据当前语言设置打印系统调用、库函数失败原因，讲 libc 时再解释。描述符总分配最小可用编号，若 0、1、2 分别是标准输入、标准输出、标准错误，再打开文件就是 3、4、5，关闭后又可复用。很容易写示例验证。Windows 用 Ctrl Shift 加 ESC 打开任务管理器，展开详细版本，也能看到相关信息。

![图 56：句柄一词的翻译讨论（00:57:21）。](/assets/images/07/0056.webp)

图 56：句柄一词的翻译讨论（00:57:21）。

里面叫“句柄”，就是 handle。Windows 定义了这种类型，比如 OpenProcess 返回 handle。它更像指向内核对象的指针，包含对象编号。

还带权限等信息。UNIX 描述符主要是 0、1、2 这样的编号，信息保存在内核，要查是否可读可写，还需额外系统调用。那“句柄”这名字怎么来的？handle 叫“把柄”似乎更直观。

这是一个沿用的误译。以前编译书里说 sentence handle、handle of a sentence，表示句子的柄。翻译后来被套用到 Windows 官方术语，留下“句柄”。记住文件描述符、句柄都用来访问内核对象，就能理解它们的关系。

这些大多是计算机系统基础已经接触过的内容。
