再看 Unix 的 Everything is a File，一切皆文件。什么是文件？小学电脑课，老师可能让大家双击桌面对象打开它，从那时有了最初概念。

![图 21：Everything is a File：字节序列、流与目录（00:17:43）。](/assets/images/07/0021.webp)

图 21：Everything is a File：字节序列、流与目录（00:17:43）。

现在已接触许多文件，可以把它定义为有名字的数据对象，比如 \.markdown、readme\.markdown、lab\.c、\.png。可以用 fopen 等 API 打开，fwrite、fread 读写，也能用 cin、cout、fin、fout。

它的模型是字节序列，在计算机中很通用。冯·诺依曼结构里的代码、数据，几乎都能用字节表示。数据流也可以：每次键盘按键产生新数据，像 append\-only list；静态数据则像数组。

图片、数据结构、JSON 都能转成数组。浏览器下载页面，HTML 逐字节传来，前面还有浏览器隐藏的头部，说明 URL、长度等，空行后才是文本。

网页符合字节序列抽象。打印机、终端、显卡也可以用字节序列表示，设备驱动部分会解释。锁、传数据的管道，也能当作文件。所有东西采用文件模型，就能用同一套工具处理。

UNIX 有 cat、wc 等工具，能处理文件，就能处理各种对象。设计者把操作系统对象暴露出来，再提供工具，让用户组合操作。Windows 则面向软件开发者，对象使用方式不同。

Windows 用户通常不直接管理内部对象。UNIX 用户却会打开 terminal，删除对象，或统计 CLAUDE\.md 行数。我的 agent 一直输出中文，就是因为有 CLAUDE\.md。Windows 不预期用户这样工作，而给程序员提供符合软件工程规范的接口。

Windows 接口也追求高效。UNIX 面向会写命令的黑客，让内部对象以简单方式暴露，复用小工具。文件再放入分层目录，于是对象有了名字。前几年带大家速通操作系统实验时，文件系统也能这样实现。

用路径名到字节序列的映射，表示整个文件集合，每个文件有路径属性，再模拟当前目录、路径解析，完全可行。文件是带名字的对象。Windows 暴露的命名对象，主要是用户实际看到的；UNIX 则进一步把内部信息也作为文件展示。

两者在对象暴露方式上有这个区别。
