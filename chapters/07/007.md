内部实现很普通：每个进程有 buffer 和长度，putchar 写入字符。这可以看成打开的文件，像往 default file 写一个字符，符合 everything is a file。

![图 43：进程内部的 buf 与 buf\_len（00:43:12）。](/assets/images/07/0043.webp)

图 43：进程内部的 buf 与 buf\_len（00:43:12）。

若文件在内核里有内存或缓存，就能用 buffer、长度和指向当前写入位置的指针表示。CrazyOS 每次写字符，再把 buf\_len 加一。类似把 libc、C 标准库的 struct FILE 嵌进 struct proc，就能实现文件。用户看到的则是 /home 下的 a\.md 等命名对象，对应 readme 等字节序列。

/proc 下 1234 的 maps 也一样，对应字节序列或可访问内容。对象在操作系统里，进程要访问，类似 C 用 fopen 得到 struct FILE。在 process1 的 struct proc 中，也可以放打开文件的信息。

里面的 file 有指针指向对象，再有 offset 记录读写位置，与 CrazyOS 相似。基于这个结构，就能提供类似 open、fopen、fread 的 API。

实际是先有 UNIX 系统调用，再有 C 的 fopen、fread 封装。大家先学 C，所以反过来解释。

![图 44：文件路径、字节序列与进程中的文件对象（00:46:15）。](/assets/images/07/0044.webp)

图 44：文件路径、字节序列与进程中的文件对象（00:46:15）。

open 在内核分配 file 结构体，需要内存，再指向指定文件；close 则释放这份打开状态，不再指向文件。read、write 类似 CrazyOS 的 putchar。

用 pointer 或 offset 表示当前字节位置，读写后向后推进。lseek 类似 fseek，叫 reposition read write file offset，修改这个位置。

可以增加偏移、设为零或负一，像 Python 的负数 index。C 有 SEEK\_SET、SEEK\_CUR、SEEK\_END 三个宏，选择从头、当前位置、尾部移动。文件描述符一会儿再讲，这里先看已打开文件里的 offset。
