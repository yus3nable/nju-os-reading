simple 里有两个测试。test\_pass 检查 exit\_status 等于零，test\_fail 一定会 fail，检查 exit\_status 不等于零。

![图 101：SystemTest 中的 test\_pass 与 test\_fail（01:27:08）。](/assets/images/07/0101.webp)

图 101：SystemTest 中的 test\_pass 与 test\_fail（01:27:08）。

assert 零会让整个程序 crash，后面都不执行。为什么 testkit 在 verbose 等于 1 时，test\_fail 后还能继续打印，告诉你两个 test case pass？

![图 102：测试输出：test\_fail 失败，1/2 test cases passed（01:27:46）。](/assets/images/07/0102.webp)

图 102：测试输出：test\_fail 失败，1/2 test cases passed（01:27:46）。

可以让 AI 读代码，原因是创建了子进程。

![图 103：共享 mmap 缓冲区、fork 与 alarm（01:28:00）。](/assets/images/07/0103.webp)

图 103：共享 mmap 缓冲区、fork 与 alarm（01:28:00）。

每个注册测试先用 mmap 创建共享 buffer，收集输入和子进程输出，再检查结果。创建子进程后，设置闹钟、timeout，超时就结束子进程。

![图 104：子进程设置 alarm 并运行单个测试（01:28:19）。](/assets/images/07/0104.webp)

图 104：子进程设置 alarm 并运行单个测试（01:28:19）。

死循环也会被 test case 发现。父进程等待完成，检查输出，可以把它作为进程管理、mmap 的综合例子。
