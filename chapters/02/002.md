这里说的是广义的编译器，包括汇编器和链接器，把 \.c 变成 a\.out。a\.out 的执行模型，就是计算机系统基础课里，指令操作 memory 和 register 的模型。早期的 C 语言编译器没有今天这么复杂。今天让大家看 GCC 源代码，可能都会拒绝。那时的编译器更像今天的 transpiler。用过 JavaScript 的同学应该见过很多 transpiler，它通过简单的语法变化，把一种语言转换成另一种形式，比如把新版本 JavaScript 变成旧版本 JavaScript。

最早期的编译器把语句逐条原样翻译成指令。后来大家发现，编译器可以改变程序的内部行为，未必需要原样翻译每条语句。最早在 70 年代，乃至更早的 60 年代，大家还没意识到这一点。当时的想法是，只要把语句原样翻译成指令，程序就一定等价；只要编译程序没有 bug，就像解释器或大家写的 NEMU 模拟器没有 bug，事情就做完了。但还有别的可能，比如写一个 X 等于 1 加 2 加 3。

再回到编译器。状态机执行时，许多操作只改变内部变量的数据。可以这样想：假设程序会中止，也不打印任何数据，编译器应该把它优化成什么？空程序。无论程序多复杂、做了多少事，只要永远不向外输出任何东西，理论上都可以全部优化掉。唯一不能随意优化的是一些特殊语句，比如编译器看不到其行为的外部调用。这是针对今天的编译器而言。

比如编译一段调用 printf 的代码，printf 以后才链接进来，编译时就不知道它的行为。它可能用汇编语言写成，执行后甚至可能让整个世界毁灭。计算机把电平、数据电信号送到外部时，后果可能无法预知。一个电信号就能驱动物理世界的变化，可能把核武器发射出去。

这些不能随意优化的外部调用，行为对编译器不可见。已知行为的内部操作，原则上可以改变；对外的行为必须保持原样。比如 printf x，把当前 x 变量的值作为参数传给 printf。

![图 34：与外部世界交互的调用（00:39:31）。](/assets/images/02/0034.webp)

图 34：与外部世界交互的调用（00:39:31）。

如果这次运行时 x 等于 1，传到外部的值就必须等于 1。按原程序解释执行会输出低电平，编译优化以后也必须输出低电平。编译正确，就是在任何输入下，输出序列都完全相同。这句话含义丰富，我说得也不够严谨，以后学编程语言的形式语义时会再学。暂时没完全反应过来也没关系，有个大致理解就可以了。这也说明了为什么要用状态机视角理解操作系统。编程语言学科诞生之初就一直在用这个视角，我觉得它甚至不应该到这门课才第一次出现：语言和机器都是这样构建的，天然存在这种映射。再往前想一点，还能发现更多问题。编译正确性不会考，大家听过即可。
