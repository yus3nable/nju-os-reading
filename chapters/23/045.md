对于电路来说，你就需要额外的寻址的电路，对吧，行选通信号，列选通信号，然后对于磁盘来说，这样的磁盘来说，你就需要有读写头，需要一个转轴，所以定位是代价很大的，或者说在存储设备里面，除了这种 SSD，它靠电路，本来它就是电路。然后它再加上一些电路，可能就不是特别的困难，但像磁盘，Project Silica 这些的，这些存储介质上定位，都是要付出额外的代价的，需要额外的物理器件的配合。所以为了减少这部分的代价，所有的这样的存储设备，虽然它是一个 byte array。

但是它都希望让尽可能多的 byte，能够共享一个定位组件，比如说我的 SSD 里，哪怕是 SSD 里，它一般是组织成 page，在我们的SSD 里面，它有这样的一个 die，到一个 plane，到一个 block，它一层一层的结构。然后直到一个 page，16KB。然后这个 16KB，一般来讲。当然这不是一个固定的 size，一般来讲 16KB，这个 16KB，它要读就是一起同步的，并行的直接读出来，要写，要erase，要 erase 就是甚至更大的一个可能 4 兆的，要 erase 可能是 4 兆的一个一起擦掉。

然后如果要写的话，它也是以 16KB 一次性写入，所以这样就减少了这个寻址的开销，它也不需要为里面的每一个 bit，单独去做一根行选通线和列选通线，你省掉了这部分的电路，然后同样的，我们的这些磁盘也是的，它会把比如说比如说这样磁盘或者软盘，它是以 512 个字节为单位存储的，然后它会把 512 个字节，我们说盘片吧，叫磁盘，它会连续的一段。比如说 512 个字节，称之为一个 sector，一个扇区。然后这样一旦开始读，它就会把这 512 字节给连续的读出来。

而不是说我可以转到任意一个位置上读一个字节，因为我们在写程序的时候，是有办法写出有这种 memory access locality，我是可以通过写一个好的程序，让我的访问读写具有局部性，所以它就可以通过这样的方式来省成本，这两个是互相成就的，所以实际上，虽然理论上说这是一个 byte array，我们希望看到一个 byte array。但是在设备层，你看到其实这样的一个东西，是一个 struct block 的数组，它每一块都是一个 block。那这个 block 可能是比如说 16KB。

当然也许更大，或者 4KB 等等，一个一个的 block。
