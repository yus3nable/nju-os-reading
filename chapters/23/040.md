与 MMU 的 pagetable 类似，修改映射后，写入物理块 2，它的写入次数就加 1。每个物理块记录写入次数，让写操作均匀分摊到颗粒的各块上，这叫 Wear Leveling。映射表本身也要 persistent，必须存进闪存，所以也会借用持久化数据结构。

![图 56：改写逻辑块时更新到另一物理块（01:04:30）。](/assets/images/23/0056.webp)

图 56：改写逻辑块时更新到另一物理块（01:04:30）。

不能直接像普通 hash table 一样反复改同一项。如果给 number1 写 100 万次，不断 hash\[1\] 等于 2、hash\[1\] 等于 3，映射表第一项本身就会被写坏。

![图 57：映射表自身也需要持久化（01:05:00）。](/assets/images/23/0057.webp)

图 57：映射表自身也需要持久化（01:05:00）。

因此还需用 append\-only 持久化数据结构保存映射表，又是 random read 加 append\-only write 实现任意数据结构的例子。
