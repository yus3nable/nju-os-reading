我对现有线程库做了简化，只适用于最简单的情形，有两个 API。spawn 接收函数指针，创建以 function 为入口的线程。function 可以有一个整数线程号参数，从 1 开始编号。例如连续两次 spawn 同一个 t，第一次启动线程调用 T(1)，第二次调用 T(2)。它们共享内存、独立运行。另一个 API 是 join，等待所有创建的线程结束。函数返回，线程就结束，join 会等待所有函数返回。

这个库默认在 main 返回时 join 所有线程，pthread 库没有这个行为。这是为了让示例容易理解。可以把实现理解为计数：调用两次 spawn，记录创建了 2 个线程；每结束一个线程，再记录结束数量。等所有线程都结束，main 才能完成。有兴趣可以看实现，它很直接，调用的是 POSIX 标准线程。成为标准的好处是，绝大部分足够完善的平台都会支持，可以放心使用。

例如鸿蒙可能与 Linux 不兼容，但一般也兼容 POSIX thread，以便移植更多第三方库和应用。再看线程库怎样用。hello\.c 是普通 C 程序，遇到 spawn，系统中就多出一个独立运行的函数。

![图 13：hello\.c：两个线程分别输出 a 和 b（00:22:39）。](/assets/images/13/0013.webp)

图 13：hello\.c：两个线程分别输出 a 和 b（00:22:39）。

```
#include <thread.h>

void T_a() {
  while (1) {
    printf("a");
  }
}

void T_b() {
  while (1) {
    printf("b");
  }
}

int main() {
  setbuf(stdout, NULL);
  spawn(T_a);
  spawn(T_b);
}
```

第一个函数 while (1) 输出 a，第二个 while (1) 输出 b，两者独立执行。预期会看到 a、b 交替出现，无法让某一个一直输出到底。在此前没有并发的模型中，多个进程理论上可以做到，但一个进程、一个程序内部还做不到。运行看看。

![图 14：a、b 交替输出（00:23:17）。](/assets/images/13/0014.webp)

图 14：a、b 交替输出（00:23:17）。

假设线程库实现正确，就能看到随机交替的 a、b，符合预期。我们不知道操作系统何时让各线程执行，也不知道谁快谁慢，所以会一会儿输出 a、一会儿输出 b。它们实际在并行执行，符合并发、并行的预期。这就是线程库的运行方式。
