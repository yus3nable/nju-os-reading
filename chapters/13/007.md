可以低成本自己写程序，或让 AI 写程序，验证共享内存多线程模型。再问一个问题：多线程程序能用 GDB 调试吗？当然可以。加上 \-g 编译选项，直接运行 GDB，程序会全部结束。要调试，先在两个线程入口打断点，这些操作 AI 都能告诉大家。

以前上这部分课，我会先说 read the friendly manual，让大家去 GDB 文档的 threads 部分读怎样调试多线程。现在 AI 已经读过，我可以直接展示。GDB 有 info threads，info 下还有很多功能。输入 info 后按 Tab 补全，会看到许多有用的信息，其中有些熟悉，有些可能没见过，值得花时间学。

info threads 显示现在只有一个线程，id 为 1。调试多线程一般会用 set scheduler\-locking on。前面有两种模型：一种每次选 T1、T2 或 T3 中的一个执行，其他线程暂停；另一种所有线程同时向前推进。

![图 24：GDB：info threads 与 scheduler\-locking（00:33:25）。](/assets/images/13/0024.webp)

图 24：GDB：info threads 与 scheduler\-locking（00:33:25）。

```
(gdb) b T_a
(gdb) b T_b
(gdb) info threads
(gdb) set scheduler-locking on
```

默认 scheduler\-locking 为 off，线程一执行一步时，线程二、三也会继续，可能影响调试。set scheduler\-locking on 则回到每次只选一个线程的模式。可以正常单步，但若 continue，main 返回时会进入 join。

join 等待其他线程结束，而其他线程被暂停，无法执行，程序就卡住了。现在需要手动中断。

![图 25：main 等待其他线程，手动中断（00:34:08）。](/assets/images/13/0025.webp)

图 25：main 等待其他线程，手动中断（00:34:08）。

再 info threads，会看到三个线程，一二三。切到 thread2 并 continue，会停在 T\_a；切到 thread3 再 continue，会停在 T\_b。这样就能在线程间切换。

![图 26：切换到线程 2 与线程 3 的断点（00:34:35）。](/assets/images/13/0026.webp)

图 26：切换到线程 2 与线程 3 的断点（00:34:35）。

```
(gdb) thread 2
(gdb) c
(gdb) thread 3
(gdb) c
```

这是真正在 CPU 上运行的程序，可以查看 assembly。现在把它对应到概念模型：有多个线程，每个有自己的栈和 pc。

![图 27：GDB 中查看实际汇编（00:34:39）。](/assets/images/13/0027.webp)

图 27：GDB 中查看实际汇编（00:34:39）。

每次在 GDB 中选择一个线程单步，thread1 对应 t1，thread2 对应 t2，thread3 对应 t3，就能调试并理解这个模型。多线程调试仍很麻烦，要花很多时间在线程间切换，AI 目前做得也不太好。也许明年就能很好地帮助调试并发程序。这就是多处理器编程入门。

用线程库写一些有趣代码，验证自己的理解，就算入门了。
