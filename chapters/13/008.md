接下来是“放弃”的部分。多处理器编程首先要放弃状态迁移的确定性，麻烦就来自这个模型。

![图 29：确定性的数学与程序模型（00:35:54）。](/assets/images/13/0029.webp)

图 29：确定性的数学与程序模型（00:35:54）。

先说确定性。大家在哪门课遇到过这个词？算法，还是计算复杂性？有同学学过计算复杂性。确定性的字面含义是绝对明确，只有一种可能，没有分歧。我喜欢数学的确定性，它来自函数的定义。离散数学中，大家可能花过一些时间适应函数为什么要这样定义。

例如 f(x) = x² \+ 1，它一旦存在并确定下来，f(1) 永远是同一个值。无论何时何地调用 f，都产生唯一、确定的函数值。这让世界各地研究数学的人能使用同一种语言、达成共识，数学和计算机科学才得以发展。程序的确定性与之类似。

无论 SimpleC、C 程序，还是 NEMU 模拟器，状态一旦确定，迁移也确定。例如 SimpleC 的汉诺塔，迁移就是函数 f。大家实现 NEMU，做的就是 f(s) = s′：对于状态 s，可以确定地算出下一个状态。即使从外部读入随机数，它也属于状态的一部分。

这至少绝大部分是数学意义上的确定函数，将一个状态变成下一个状态。给定相同初始状态，程序无论运行多少次，输出都一样。假设每个单步确定，根据数学归纳法，整个执行过程也确定。虽然课程去掉了数学视角的操作系统内容，理解并发时仍能回到这个视角。

![图 30：状态迁移函数 f(s) = s′（00:38:30）。](/assets/images/13/0030.webp)

图 30：状态迁移函数 f(s) = s′（00:38:30）。

我觉得这个视角仍然有用。确定性让程序可控，代码不改，同一测试用例今天 pass，明天提交作业仍然 pass，结果可以重复。这也是喜欢 functional programming 的原因。学过 SICP 就知道，它要求把内容写成数学意义上的 function；pure function 就是 deterministically reproducible 的。引入并发，却彻底破坏了这一点，仿佛引入一个魔鬼。

![图 31：共享内存打破确定性（00:39:25）。](/assets/images/13/0031.webp)

图 31：共享内存打破确定性（00:39:25）。

补充一点，实际程序也在某种程度上确定。假设不调用随机数，程序的不确定性都来自系统调用。execve 后的初始状态有些内容是随机的，例如地址空间、main 地址；auxv 中也有系统信息。讲链接和加载时说过，内核加载器会把随机数种子等信息放到栈上。

进程初始状态确定后，除系统调用外，迁移函数就确定了。read 不确定，不知道下一次键盘按 a 还是 b，但程序执行本身可以理解。共享内存并发打破了这一点，因为线程执行速度没有保证。回看两个线程分别让 x、y 加加，第三个线程读取 x、y 的例子。

当时大家只看到它验证了共享内存，可能没有意识到麻烦。例子用了 sleep 系统调用，线程速度没有保证；即使只执行 x 等于 x 加 1，两个处理器的频率、缓存状态也可能不同，速度也就不同。每次读都可能看到其他线程的 store，这是共享内存允许读到别的线程所写内容的结果。

这是需要的特性，但一次读可能看到了写入，也可能错过，等下一次才读到。程序执行模型也随之变化：有两个线程时，每一步既可以选 T1，也可以选 T2，到了下一状态仍然如此。每步都有选择，路径呈指数增长。
