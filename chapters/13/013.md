一段最简单的程序，你很聪明，你很聪明，你说你想实现 Join，你想实现 Join，你想实现 Join，这个时候我们就要用到并发编程里面一个我也会反复讲到一个很重要的视角，把线程想象成人，每一个线程都是一个人，那人有自己的大脑，你们读不到我的想法，我也读不到你的想法，能够互相读想法，是一件很危险的事情，也就是在我们的 SimpleC 的模型里面，我的这个局部的 private 的东西，我别人是不能访问的，当然只要我不把这个指针，只要我不把我指向我。我这个线程不主动把指向我自己堆栈的指针泄露给别人，别人是读不到我的头脑里的思想的，那我们就把每一个线程想象成是自己，然后我们自己有一个自己的小的 memory，就是我们自己的栈，对吧，我们自己的这个 memory，是说我们的脑子里面的 memory，头脑里面的 memory，是自己的栈。然后我们的物理空间就是全局的变量。那我们的每一个线程，我们所有的人在教室里面都是共享这个教室的空间的，对吧，我们俩可以同时对一个物体发生，发出动作。对吧，我可以拿这个东西，你可以拿这个东西。这是可以同时发生的，那我们就可以这样。

实现这样的一个协议，比如说我想要等到某一件事情，比如说你把什么东西算好以后，我再继续，那我可以写这样的一份代码，我给一个同学一个旗子，这个旗子就叫一个变量叫 flag，然后这个 flag 开始的时候等于零，然后呢，我在这里执行一个代码，就是 while(\!flag)，我就等待，那我到这的时候，我 flag 肯定，第一次到这的时候 flag 肯定是零，相当于我就看着这个同学，如果这个同学，你旗子还没有举起来，我就要不停地等等等等等等，直到这个同学把旗子举起来了。

我会发生什么呢？对吧，有一个同学，他在有一刻 flag 等于 1，他就把旗子举起来了，旗子举起来以后，我的这个条件就成立了，我的 while 循环就退出了，好，我就继续执行了，所以，所以我的程序就可以等到那个同学把 flag 等于 1 举起来以后，我再执行。好，没问题，这个程序看起来挺对的，对吧，也应该能够实现我们想要的功能。但是它实现不了，为什么呢？在编译器的意义上，编译器认为没有人可以改这个 flag。所以这是一个循环，如果没有人可以改 flag。你想呢？

如果这里有一个循环，对吧，如果我这里有一个循环，有一个比如说 x 加 1，比如说 sum 加等于 x 加 1，编译器很聪明的，他知道这个 x 在循环里面没有改过，所以他就可以把这个东西提到循环的外面去，对吧，他可以写 t 等于 x 加 1，s 加等于 t，而且他也会把这个 t 直接放到一个寄存器里。对吧，这样甚至反正这个代码就变得更快了，编译器会不断地、一点一点地改写这个代码，做等价的改写。好，那如果我们改写这个 while (\!flag) 会发生什么呢？他发现 flag。

它可以直接把这个 while 循环改写成这样，它可以 if (flag)，那我就什么也不做，如果我现在不是 flag，又没有人能改 flag，意味着什么呢？我不需要再读，我永远不需要再读了，我这里就是个死循环。对吧，因为 flag 不会改。所以我可以把它提到循环的外面，外面去先做一个判断，如果 flag 是举起来了，我就什么也不用做了，我就出去了，否则我这再也没有人能把旗子举起来了，这不就死循环了吗？
