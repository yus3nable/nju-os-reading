上节课结束了虚拟化部分。从应用视角看，操作系统是一组 API，前面围绕这些 API 讲了很多内容。需要留下的概念是：整个计算机系统，无论我的电脑还是大家的笔记本，都从 CPU reset 开始，有一个最初状态。

![图 2：从系统调用到应用生态（00:00:12）。](/assets/images/13/0002.webp)

图 2：从系统调用到应用生态（00:00:12）。

CPU reset 以后，程序开始执行。Firmware 先加载操作系统，操作系统再加载 initramfs 的文件系统树到内存，形成文件系统并执行其中的 init。更早还讲过什么是程序，execve 怎样接收可执行文件、把它加载到内存，再放到 CPU 上运行。init 加载磁盘上的实际文件系统后，会执行系统调用，切换到新的 init，也就是 pstree 中第一个进程 systemd。它再通过各种系统调用，创建屏幕上看到的应用程序世界。操作系统提供的是 system call API，构建应用生态还需要上面的多层软件，例如具有 ISO 标准、可以移植的 libc。

C 程序可以很容易地移植到其他平台，包括微小的控制器。libc 之上还有许多库函数，在终端上显示、读取字符，访问屏幕、创建图形界面，都有相应的底层库函数。上面又有 JavaScript、Python 等应用生态。例如 Visual Studio Code 使用 Electron 框架，运行的是 JavaScript 程序。

这些程序会一直依赖到底层的 libc 和库函数。OS 的 API，也就是系统调用，向上支撑不断扩大的应用生态，向下可以兼容多个体系结构。以前课程通常在讲台电脑上展示，使用 x86；今天换成树莓派，使用 ARM64。还可以有 RISC\-V 等架构，不同体系结构运行的却是同一套操作系统 API。

Linux 内核主要用 C 实现，现在也开始加入 Rust。C 有一定可移植性，freestanding 环境可以运行在 x86、ARM64 上。操作系统 api 提供了合适的中间接口：底层硬件只需机械地执行指令，无须知道应用在做什么；上层应用也可以无须了解具体 CPU，只要用 C 写出可移植的代码。

这样的代码在 x86、ARM 上都能正确运行。Linux 内核仍有体系结构相关代码，但占比相对较少。这个抽象构建了计算机系统的世界，复习课程时可以回看应用程序怎样逐步构造出来。
