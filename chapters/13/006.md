可以验证线程确实并行、共享内存，以及栈相互独立。每个线程的栈都在地址空间中，有头有尾，究竟多大？这些问题能帮助理解概念模型。刚才提过，在指令级视角下，线程和进程的地址空间是平坦的，是从零到某个大数字的字节数组。一切由寄存器中的地址控制：栈有栈顶指针，也能对 main 取地址并打印。要验证，就自己写程序。例如这里有两个线程，分别执行 x\+\+、y\+\+。

![图 16：test\_shm\.c：主线程读取两个计数器（00:25:25）。](/assets/images/13/0016.webp)

图 16：test\_shm\.c：主线程读取两个计数器（00:25:25）。

```
#include <thread.h>
#include <unistd.h>

int x = 0, y = 0;
void inc_x() { while (1) { x++; sleep(1); } }
void inc_y() { while (1) { y++; sleep(2); } }

int main() {
  spawn(inc_x);
  spawn(inc_y);
  while (1) {
    printf("\033[2J\033[H");
    printf("x = %d, y = %d", x, y);
    fflush(stdout);
    usleep(100000);
  }
}
```

x 每加 1 后 sleep 1 秒，y 每加 1 后 sleep 2 秒。main 每隔一小段时间读取 x、y 并打印。在一个线程写、另一个线程读，如果能读到，就说明共享内存。运行后确实能看到结果。

图 17：共享计数器的运行画面（00:26:02）。

![图 19：test\_stack\.c：记录栈地址范围（00:27:14）。](/assets/images/13/0019.webp)

图 19：test\_stack\.c：记录栈地址范围（00:27:14）。

```
char * volatile low[N];
char * volatile high[N];

void update_range(int T, char *ptr) {
  if (ptr < low[T]) {
    low[T] = ptr;
  }
  if (ptr > high[T]) {
    high[T] = ptr;
  }
}
```

![图 20：无限递归 probe 与线程入口（00:27:15）。](/assets/images/13/0020.webp)

图 20：无限递归 probe 与线程入口（00:27:15）。

```
void probe(int T, int n) {
  char scratch[64];
  update_range(T, scratch);

  if (n % 10 == 0) {
    printf("Stack(T%d) >= %ld KB\n",
      T, (high[T] - low[T]) / 1024);
  }
  probe(T, n + 1);  // Infinite recursion.
}

void T_probe(int T) {
  T -= 1;
  low[T] = (char *)-1;
  high[T] = (char *)0;
  probe(T, 0);
}
```

probe 每次调用都定义一个不用的 scratch 数组，每个栈帧分配 64 字节，再无限递归。总有一次 stack overflow，线程就会 crash。递归过程中，把局部变量地址范围记录到 high、low 两个指针中。

update\_range 持续更新见过的最小和最大地址。老师声称线程栈在地址空间里，虽然暂时不知道具体位置，但刚调用函数时，栈只用了一点空间，大部分仍可用。它可以从高地址向低地址生长，也可能相反；实际这里是从高地址向低地址生长。每次调用增加一个栈帧。

栈帧中有 64 字节局部变量，不断递归，总会 overflow。在溢出前持续打印最小、最大地址，就能观察栈大小，看到它逐渐增长。

![图 21：栈探测到 8183 KB 后崩溃（00:29:03）。](/assets/images/13/0021.webp)

图 21：栈探测到 8183 KB 后崩溃（00:29:03）。

不断探测 Stack T1、T2、T3，最后打印 T1 的 Stack 大于等于 8183。大家觉得栈多大？8183 离 8192 很近，即 8192 KB，所以每个新线程有 8 兆栈。这和日常程序的栈有所不同。
