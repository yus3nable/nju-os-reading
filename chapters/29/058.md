用 lsns 可以看到系统现有 Namespaces。我这里好像没装 Docker，大家回去 Docker Run 几个 container，就会看到不同 Namespace。

![图 44：lsns 列出的进程命名空间与 systemd 服务（01:06:29）。](/assets/images/29/0044.webp)

可以让 AI 解释 lsns，也可以 strace，看它怎样从文件和目录读取信息，比如 NS 下的 Net、P、Cgroup。应该能想到，是从 Proc 里各进程的 Namespace 取得。

［现场查看 lsns 的系统调用。］

```
strace lsns |& less
strace lsns |& vim -
```

原理类似每个进程有一个 OSID，但实际可以分别设置 IPC、Mount、Net 等 Namespace。两个进程可以共享 Net Namespace。

![图 47：/proc/15018/ns 下的十个符号链接（01:07:33）。](/assets/images/29/0047.webp)

图 47：/proc/15018/ns 下的十个符号链接（01:07:33）。

［现场当前目录为 /proc/15018/ns；命令依次查看位置、目录和链接。］

```
pwd
ls
tree .
```

它们同时可以使用不同的 Mount 或 IPC Namespace。可以简单理解成不同类型的 OSID，在 ProcFS 查看。比如 /proc/15018/ns，就能看到 IPC 的 Namespace 编号，以及 Mount Namespace。
