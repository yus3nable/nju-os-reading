比如 pidfd\_open，可以打开 PID。这个 API 看起来诡异，想想又有道理：everything is a file，访问、引用操作系统对象需要文件描述符，要有一个指针指向 PID。

![图 34：pidfd\_open 手册：通过 syscall 获得进程文件描述符（01:00:09）。](/assets/images/29/0034.webp)

图 34：pidfd\_open 手册：通过 syscall 获得进程文件描述符（01:00:09）。

［手册中的调用形式，按原手册展示；并非完整程序。］

```
#include <sys/syscall.h>
#include <unistd.h>

int syscall(SYS_pidfd_open, pid_t pid, unsigned int flags);
```

这个指针在某种意义上也指向进程。为此需要 Open，也就是 pidfd\_open。打开后持有 PID，引用计数加一，它知道还有引用，不能释放这个 PID。之后可以调用 pidfd\_send\_signal。

![图 35：pidfd\_open 手册：poll 等待、close 与信号相关接口（01:00:41）。](/assets/images/29/0035.webp)

图 35：pidfd\_open 手册：poll 等待、close 与信号相关接口（01:00:41）。

［手册示例中的等待与关闭片段；变量及错误处理依赖前后文。］

```
pollfd.fd = pidfd;
pollfd.events = POLLIN;
ready = poll(&pollfd, 1, -1);
/* ... */
close(pidfd);
```

用它 Kill 这个 PIDFD，就能确保目标不会丢失。打开时持有引用，直到释放引用前都不会释放。这是关于 PID 的补充。
