比如说这里有一个这有一个叫pidfd\_open，你可以打开一个PID，这是一个设计的，非常诡异的 API，但是你仔细一想，OK 还是很有道理的，因为，everything is a file，所以你想要，访问操作系统里面的对象，想要引用操作系统里面的对象，就必须通过文件描述符，因此，如果你想要打开，你想要有一个指针，指向一个 PID。

［手册中的调用形式，按原手册展示；并非完整程序。］

```
#include <sys/syscall.h>
#include <unistd.h>

int syscall(SYS_pidfd_open, pid_t pid, unsigned int flags);
```

所以不是指向一个进程，当然也某种程度上，指向一个进程，对吧，指向一个进程，你指向一个 PID，那你也需要用一个 Open，所以用的是一个pidfd\_open，然后就可以持有这个 PID，然后持有这个 PID 以后，你的引用计数就会加一，它的引用计数就加一，它就知道，有一个人，有个东西要引用着我，我是不能释放的，这个 PID 就不能释放了，这个 PID 不能释放，你就可以在之后，你看这里有一个pidfd\_send\_signal，你就可以去 Kill 它。

［手册示例中的等待与关闭片段；变量及错误处理依赖前后文。］

```
pollfd.fd = pidfd;
pollfd.events = POLLIN;
ready = poll(&pollfd, 1, -1);
/* ... */
close(pidfd);
```

Kill 这个 PIDFD，OK，你就可以确保，杀的这个东西，不会丢失，相当于你在打开的时候，你就持有一个引用，直到你释放这个引用，它都不会释放，OK，这是我说，关于 PID 的补充。
