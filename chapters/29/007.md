Just\-in\-time 一般这样工作：优化后的 NEMU 启动时先用解释模式，逐条执行，虽然慢，但持续取得进展。同时为 basic block 计数，每执行一次加 1；只执行过一次的，计数器始终为 1，也可以配合 hash 等机制。如果一个 basic block 不断执行，达到 1 万次或 10 万次等阈值，认为后续执行收益能抵消编译开销，就在后台启动编译。

比如启动一个线程，调用编译器。通常编译器直接写在 just\-in\-time 系统内部，无须创建进程调用外部编译器。编译完成后，下次遇到这个 basic block，就通过指针跳到编译后的代码。现在的 language VM，包括 Java Virtual Machine 以及 Node\.js Virtual Machine，都遵循这个循环。
