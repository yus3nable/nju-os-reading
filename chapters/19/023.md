网页请求耗时长，点击、浮动 banner 移动等事件又动态到来，无法预知鼠标何时点击、请求何时结束，JavaScript 需要良好并发支持。它既没有选择线程，也没有选择刚才的协程，要从语言定位考虑。

JavaScript 面向任何人，在 HTML 里写一行就能用，无需编译、额外工具，各种操作系统开箱即用。并发课已经讲了这么多次，大家才理解 data race、atomicity violation 等 bug。怎样让没有这些知识的人也用好并发？需要简单的计算图描述模型。

JavaScript 采用基于事件的并发模型。网页加载、鼠标点击、发起网络请求、请求返回，都会创建事件。我觉得部分设计有失误，动态语言理论上也可以允许某些并行行为。

但它选择事件永不并行执行，中间不能切换出去。线程可能被随时打断，协程能 yield；JavaScript 事件必须执行到返回。代码若意外死循环，或有性能问题耗时太长，整个网页就会失去响应，点击也没用。
