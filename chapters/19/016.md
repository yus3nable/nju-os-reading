课件教学伪代码：编译器与运行时配合改写 sleep 和 read；保留课件中的 \-EAGAIN 判断。

```
// 程序员写出的调用
sleep(1);
read(fd, buf, size);

// 课件展示的改写
put_my_self_into_sleep(1); yield();
while (read_async(fd, buf, size) == -EAGAIN) {
  yield();
}
```

仍写 spawn、T\_worker，里面该 sleep 就 sleep，该 read 就用 blocking read。编译器由我控制，可以将 sleep 改写为：把自己放入等待队列，标记至少一秒内不再调度。像前面的 Python，通过 random\.choice 选一个轻量线程运行。

标记不可运行后就 yield，让别人执行。read 可以改成 non\-blocking 循环：返回 EAGAIN 就 yield。这样把同步写法变成异步行为，代码仍像多线程，却成为高性能轻量线程，这就发明了 Goroutine。

借助编译器，把同步写法都改为异步，还能进一步扩展：操作系统允许同一共享内存进程创建多个线程。前面“线程”有时指模拟的轻量线程，有时指用 Spawn 创建的操作系统线程，注意区分。现在可以创建多个操作系统线程，再创建大量轻量线程。

轻量线程仍写 Spawn 等代码，编译器将其改写成 Goroutine。每个 OS worker thread 跑循环，从就绪队列取可运行的 Goroutine。一个协程执行 put myself into sleep，yield 后就从就绪队列移除，一秒后再加回。遇到 read\_async 需要阻塞，也记录它 yield 的原因：read\_async 没数据。

把它放到等待队列，标记 read\_async，再由调度程序用 epoll 监听对应文件描述符。有数据时放回就绪队列。这样既像前面的模拟线程一样轻，又能在不同 CPU 上并行。前面 C、C\+\+ 的演示做不到并行。

那时一个进程、一个线程，靠 yield 在 coroutine 间切换；Goroutine 能利用 CPU 并行资源，用起来与线程一样，前提是使用标准库。

若自己用汇编或库函数硬写 blocking reader，仍会占用那个线程。标准库的同步接口则由系统自动改为异步，得不到资源时移出调度队列。同一进程内存共享，Goroutine 被送到各线程运行，也共享内存。

相当于在一个进程中实现了小操作系统。
