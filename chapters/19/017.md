课件中的 UNIX 管道示例。

```
(cat *.txt; cat *.cpp) | wc -l
```

好像有点熟悉，好像有点熟悉，因为你再回过头来想，我前面讲过很多并发控制同步，然后你会发现，像互斥锁信号量这些，它实现了同步，但是你的数据的交换，依然是通过共享内存的，对吧，我说要有一个 buffer 生产者消费者里面，我还要手工维护一个buffer。然后每次生产者产生东西以后，我批得到一个东西，我还要再上一把互斥锁。然后往那个 buffer 里面放一个数据。所以同步和通信是分开的，这其实带来很大的问题。但是 UNIX 时代其实已经有一个非常非常好的并发编程的机制，甚至可以并行。

在多处理器的时代可以并行，它就描述了一个计算图，什么机制呢？就是管道，我们的管道，就你看这样的一个我 cat \*\.txt，cat\*\.cpp，然后我再管道给 word count，这其实不就描述了一个计算图吗？对吧，我在第一个 cat \*\.txt 里面，我就会不断产生一行一行的数据。然后相当于第一个 cat 执行完了以后，我会执行第二个 cat，它也会产生一个一个的数据，一行一行的数据。然后我的word count，它会读完一行。读完一行。读完一行。读完一行。

读完一行，读一行处理一行，读一行处理一行，读一行处理一行，它不就是描述了一个这样的计算图吗？然后这个计算图就是等我这行数据出来了以后，我的这个计算节点才能工作，这个数据出来以后，这个计算节点才能工作，对吧，它的本质是一个并发的计算图，而且是多个进程合作的，自带生产者和消费者同步。所以Go 语言做了一个非常，我觉得是一个非常好的抽象，它干了这样的一件事，我可以在任何的 Goroutine 之间建立起 channel，channel 就是管道。我可以创建好多好多个管道。

就跟我们的进程可以随便的创建管道一样，unix 里面的进程，对吧，我可以创建一个命名管道，然后有两个进程可以往管道里面写，一个进程可以从管道里面读，然后我就可以，对吧，通过管道的方式，我可以创建好多个管道，来管理这个进程之间的同步，这样我就既可以同步，又可以传递数据了。
