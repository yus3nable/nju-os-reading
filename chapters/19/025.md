还用它构建出庞大 JS 世界。期间出现许多库，今天常用的答案是 Promise API。严格区分有 Promise、Future，这里先简化为 Promise。

![图 55：Promise 节点、then 链与 Promise\.all（01:12:11）。](/assets/images/19/0055.webp)

图 55：Promise 节点、then 链与 Promise\.all（01:12:11）。

课件中的 Promise\.all 教学片段；省略号代表未展开的请求和回调。

```
Promise.all([
  fetch(...).then(...), fetch(...).then(...), ...
]).then(
  // succeeded
).catch(
  // error handling (catches exceptions in the fetch)
)
```

Promise 能直接用代码画计算图。例如我的 OnlineJudge 用 Fetch，在课程网页中 Fetch 某 URL，立即返回一个 Promise。JavaScript 没有这种同步 Io，不能等漫长操作完成再继续。

因此立即返回，严格说是 Future，表示未来会完成一件事。所谓 Promise，当前状态为 Pending，仍在等待。

![图 56：fetch 立即返回 pending；另一个相对地址请求显示 HTTP 404（01:13:20）。](/assets/images/19/0056.webp)

图 56：fetch 立即返回 pending；另一个相对地址请求显示 HTTP 404（01:13:20）。

例如 r = fetch('/')，当前事件结束时仍 Pending，过一会再看就成了 Fulfilled。

![图 57：将 fetch('/') 的返回值赋给 r，此时仍为 pending（01:13:30）。](/assets/images/19/0057.webp)

图 57：将 fetch('/') 的返回值赋给 r，此时仍为 pending（01:13:30）。

浏览器控制台中的赋值；fetch 返回的 Promise 此时显示为 pending。

```
r = fetch('/')
```

![图 58：再次查看 r，状态已为 fulfilled，值为 Response（01:13:38）。](/assets/images/19/0058.webp)

图 58：再次查看 r，状态已为 fulfilled，值为 Response（01:13:38）。

可以查看 Response。Promise 还有 then、catch、Promise\.all 等 API。all 接收多个 Promise，then 表示先后，catch 处理 error。fetch\.then 的节点和另一个分支，可以用 Promise\.all 像线程 join 那样汇合；all 后面的 then 必须 happens\-after 两个分支，它们也各自可能 error。一行代码就能描述计算图。所有函数，包括 promise\.all，都立即返回。

HTTP 请求此时可能已经开始工作，代码只是构建好图，eventually 每个 promise 都会完成。等最后一个 promise 即可。
