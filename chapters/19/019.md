轻量化线程是一条路线：在用户空间降低创建、管理、切换代价，也能借助操作系统线程。另一条路线是直接在语言中更好地描述并行、并发计算图。

![图 39：1995 年：Brendan Eich、Netscape 与 JavaScript（00:54:29）。](/assets/images/19/0039.webp)

图 39：1995 年：Brendan Eich、Netscape 与 JavaScript（00:54:29）。

前面从 UNIX 讲到 Go，另一个发展过程始于 1995 年。Brendan Eich 加入 Netscape，负责设计嵌入网页的脚本语言。他花十天融合 C、Java、Scheme、Self 等特性，主要想做一种像 Java 的语言，吸引使用者，因为当时 Java 已经兴起。他的兴趣在函数式编程，对这件事不太上心，做了些糟糕设计；但也正因兴趣，把 Function is first class citizen 放进 JavaScript。梗图左侧厚厚的 JavaScript Guide，右侧薄薄的 good parts，就是调侃好的部分很少。

![图 40：JavaScript 的 this 与相等判断（00:55:35）。](/assets/images/19/0040.webp)

图 40：JavaScript 的 this 与相等判断（00:55:35）。

它有很多坑。例如 this 动态绑定，语义与 C\+\+、Python、Java 完全不同。早期 react 常要 bind(this)，不熟机制就容易出错。还有“三位一体”的调侃：God is the father，God is the son，God is the holy spirit，但彼此不同，the father is not the son。

JavaScript 中可以打开 F12 控制台复现：按 ECMAScript 标准，零可以等于空 list、字符串零、whitespace 字符串，但这些对象彼此又不等。weakly typed 的动态性很好用，却也容易让看似正确的代码出错。
