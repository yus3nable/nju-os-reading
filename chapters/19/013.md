切换由程序主动进行，操作系统没有强制切换。SimpleC、Python 可以实现，C、C\+\+ 也可以。以前有个作业要求用 setjmp、longjmp 实现栈切换，后来觉得太难，从实验 set 中删掉了。C 编译成汇编，每次调用是 call。

返回是 return，并不关心栈在哪里。可以 malloc 一段栈空间，再用汇编 mov 将栈顶指针移过去。这里的汇编由 AI 写，x86\_64、AArch64 都能工作。

C 协程状态结构片段；依赖 setjmp\.h，其余创建与调度代码未列出。

```
enum { INIT, YIELD, DONE };
struct coroutine {
  jmp_buf ctx;       /* caller context */
  jmp_buf coro_ctx;  /* coroutine context */
  char *stack;
  int state;
  int name;
  int i;
  char buf[128];
};
```

例如 RSP 原先在一处，调用函数后挪到另一栈，程序就继续执行，相当于切到另一线程，全程不进操作系统，由进程指令控制。setjmp 保存寄存器现场。

C 协程的恢复与主体片段；依赖 coroutine 结构和 coro\_yield，其余实现省略。

```
static const char *coro_resume(struct coroutine *c) {
  if (setjmp(c->ctx) == 0) {
    longjmp(c->coro_ctx, 1);
  }
  return c->buf;
}

static void coro_entry(struct coroutine *c) {
  while (1) {
    c->i++;
    snprintf(c->buf, sizeof(c->buf), "[%d] i = %d", c->name, c->i);
    coro_yield(c);
  }
}
```

coro\_entry 的代码与前面相同：i\+\+，用协程自己的 buffer 记录结果，本地计算完成后 yield，通过 longjmp 转到另一个协程。C 可以这样切栈，c\+\+20 还引入 co\_yield，实现相同功能。

C\+\+20 协程主体片段；依赖画面中的 Coroutine 类型及其 promise\_type，调度部分省略。

```
static char buf[128];

Coroutine T_worker(int name) {
  int i = 0;
  while (true) {
    i++;
    snprintf(buf, sizeof(buf), "[%d] i = %d", name, i);
    co_yield buf;
  }
}
```

例如先做 x 等于 1、y 等于 2，二者都是局部变量。能做闭包的语言，可以在此创建函数状态快照，把 x、y 存到内存，再记下 pc，就封存了运行状态，可以切换栈。

也可以直接跳到别处，无需切栈。c\+\+ coroutine、python generator 都是这样的无栈实现；刚才的 c 实现确实为每个模拟线程分配了栈。没跟上这部分也不要紧。
