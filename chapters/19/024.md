当前事件的全部代码执行完，才能执行下个事件。期间可以用 $\.ajax 请求后端页面，不知道何时返回，但 $\.ajax 会立即返回，后续代码继续执行。请求完成再创建新事件。因为运行在浏览器，语言可以禁止并行、取消 blocking I/O，操作系统课上那些 read 调用在 JavaScript 中不存在。请求网页时要提供回调。

例如 success callback 是函数，这得感谢 JavaScript 的函数式设计。浏览器自行等待，期间还可能有 click 等其他事件；收到网页后，再创建事件调用 function。

function 同样 run to completion，没有并行。每个 JavaScript 事件原子执行，无需担心与其他事件并行，可避免 data race、atomicity violation。这就描述了计算图：先做一件事，完成后创建新节点。

课件中的嵌套回调片段；依赖 jQuery，省略号保留为课件中的未展开处理。

```
$.ajax({
  url: "/api/user",
  success: function(user) {
    $.ajax({
      url: `/api/user/${user.id}/friends`,
      success: function(friends) {
        $.ajax({url: `/api/friend/${friends[0].id}`, ...});
      },
      error: function(err) { ... }
    });
  }, ...
});
```

数据返回后创建事件、调用函数，带来 callback hell，回调地狱。例如三件事依次依赖：登录、fetch friend list、fetch 好友 feed。这个计算图要求先请求登录。

每步都有成功、失败，失败执行错误处理，成功调用下一步。顺序 ABC 必须分成三个函数，大家又常把下一次 ajax 和函数嵌在 success 中，结果产生多层缩进。

例如 ajax /api/user 成功后请求 Friends，再请求后续数据，每做下一件事就多两层缩进，很快难以维护、理解和调试。原本顺序计算图，无法直接用语言的顺序结构写先 A 再 B 再 C，必须分为几个部分，增加了编程困难。
