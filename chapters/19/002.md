算法、数据结构课总关注 worst case，希望最坏情况尽可能好，才能通过算法题。拿到问题就想 O(1)、O(n)、O(n log n)，因为总被这样问。例如排序，会研究已经有序或精心构造的数据是否最差。但实际系统需要面对真实分布。

业务中的内存分配序列，或集合 insertion、deletion 序列，符合现实世界的概率分布，需要在这种分布下尽量做好。同时 worst case 也不能太差，例如指数级最坏情况会被攻击者利用，用恶意请求拖慢系统。apache httpd 曾长期支撑互联网，就遇到过这类问题。

HTTP 请求可带参数，问号后写 A 等于 B and C 等于 D，字符串会插入 hash table。如果精心构造，使所有 key 映射到同一桶，就能拖慢 apache server。这曾是针对 hash table 的复杂性攻击漏洞。性能问题很复杂，优化前先明确到底需要什么性能。

回到 malloc，第一反应可能是：所有 malloc 都一样。
