好，在前几节课里面我们更多地展开了你们怎么样写各种各样的并发程序，对吧？怎么应对并发的 bugs。然后在这个过程当中我们其实引入了一个非常重要的概念，就是计算图。我每次课我都会提一下，哦，我们在这里会有个计算图，会有个计算图是长什么样的。这是一个非常核心的概念，然后在今天我们会看到我们之前几节课学的东西怎么样能够一下子让你们能理解今天在各种地方，不管是数据中心里，还是像网络浏览器里面他们的并发编程，它到底是怎么实现的?所以我觉得我做了很长时间的铺垫，我并发其实已经上了很长的时间了，但终于在这一刻你们可以体会到你们学到的东西真正是有一点用处的。

然后上一节课我讲了并行的算法，尤其是这种 embarrassingly parallel 的各种问题，还有很酷的 Mandelbrot set 的演示，然后以及我讲了一些并行的数据结构，比如说会讲 hash table 会实现起来会很困难，然后你们可以用一个 sloppy 的 counter，去牺牲一定的，有一定延迟的情况下，然后来把计算留在本地，这样可以让这个程序能够 scale up。然后我们上节课的时候还有一些收尾的部分，比如说我们讲到 hash table 之后，其实还有一个和大家相关的就是你们作业里面的 malloc/free。

然后在做任何的性能调优的时候，你们一把大锁保平安的你们就可以通过几个 easy test case，但是你们那个 hard test case 过不了。然后在正确的基础上，你们始终记得这句话，就是 premature optimization is root of all evil，如果你们总是想当然的去脑热去做优化的话，那很有可能那个结果不是符合你的预期的。
