也没有同学反馈过这个问题。可以让 AI 阅读 Linux 源码回答，也可以实验测量。写一个最简单的程序，函数调用后几乎不占额外内存，按命令行读入 N，创建 N 个线程。只要知道该问什么，就能让 AI 帮忙写脚本，我连看都没看。

![图 13：sleep\.c：创建 N 个休眠线程（00:17:08）。](/assets/images/19/0013.webp)

图 13：sleep\.c：创建 N 个休眠线程（00:17:08）。

sleep\.c 的画面代码；依赖课程 thread\.h，未包含该头文件实现。

```
#include "thread.h"

void T_worker(int T) {
  while (1) {
    sleep(10);
  }
}

int main(int argc, char *argv[]) {
  int N = atoi(argv[1]);
  for (int i = 0; i < N; i++) {
    spawn(T_worker);
  }
}
```

我在 prompt 中要求小心 cross check，估算每线程资源。方法很简单：启动前读取系统资源 status，再创建一万个或一百万个线程——一百万可能有点多，先一万个；比较可用资源变化，除以线程数。以前不做，往往因为觉得麻烦，虽然知道线程有代价，弄清细节的收益可能不值得投入。今天，想搞清楚的东西都值得尝试。

这是我希望操作系统课传达的重要事情。例如创建 1000 个线程，算出每线程约 16\.9KB，包含内核各种数据结构增长。一个线程的增长看不出来，足够多时就能看到。再和 agent 求证，系统还有哪些资源。
