## DMA 与 CXL

![图 101：DMA 与 CXL（01:12:19）。](/assets/images/06/0101.webp)

图 101：DMA 与 CXL（01:12:19）。

有些硬件外挂已经做出来，比如 DMA。它更像金手指，通过物理线路访问内存，和用 GDB 在操作系统里调试不同。DRAM 通过总线连系统，CPU 中间还有缓存。可以在总线上接设备，不停 memory copy，把内容送到其他设备，甚至另一台计算机或 FPGA 板。

![图 102：CPU 与内存之间的数据通路（01:13:08）。](/assets/images/06/0102.webp)

图 102：CPU 与内存之间的数据通路（01:13:08）。

比如每秒 30 次，把游戏内存复制出去，形成很难、几乎无法防止的外挂。今天还有 CXL 高速内存，可以做 double write、memory mirror。卖出的内存条除正常接口，再带另一个接口，输出写入内容。

数据中心可以用 CXL 做多副本，用两台、三台机器容错。这套机制也能用于外挂，或更好的 copilot。未来电脑接一个旁路，copilot 就能知道发生了什么。今天讲的这些，在操作系统意义上都联系到地址空间接口：第三方库、malloc 内存、ELF 指定的区域，理论上都可以用这组系统调用构建。再看 mmap 参数。

![图 103：回顾 mmap、munmap 与 mprotect（01:14:20）。](/assets/images/06/0103.webp)

图 103：回顾 mmap、munmap 与 mprotect（01:14:20）。

第一个 address 是期望映射地址，只是建议。若那里已有数据，系统会调整位置，不保证从这里分配；也有 flag 能要求固定地址。

![图 104：mmap 在地址空间中选择映射区域（01:15:12）。](/assets/images/06/0104.webp)

图 104：mmap 在地址空间中选择映射区域（01:15:12）。

length 指定长度，权限可以是可读、可写、可执行。anonymous 匿名映射相当于分配大片全零内存，也可以传文件描述符、offset，映射文件一部分。大小几乎不受限制，刚才也申请过与物理内存一样大的区域，能访问其中位置。

![图 105：映射的长度、权限与文件（01:15:54）。](/assets/images/06/0105.webp)

图 105：映射的长度、权限与文件（01:15:54）。

还可以把整个磁盘映射进来。mmap 添加映射，munmap 移除，mprotect 修改权限，这三个接口能构成进程地址空间。操作系统还有其他机制。比如进程 23829，在 procfs 的 maps 能看到完整映射；游戏修改器则用 /proc 下 23829 的 mem 文件。

图 107：/proc/23829/mem 文件（01:16:39）。
