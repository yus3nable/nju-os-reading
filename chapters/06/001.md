上次介绍了 fork、execve、exit 三个进程系统调用。从这个星期开始，学习操作系统 API，再用它们写程序。这是 UNIX 的设计，Windows 有 spawn 这样的 API。Linux 其实也有类似 spawn、比 fork 更轻量的 API，可能后面再讲。

fork 有不少用法，比如 Zygote process，或 DFS 同时探索多个分支，创建多份状态副本，各自选择分支，在多处理器上并行推进。

这里的典型代码用 fork、execve、exit 创建子进程，再运行其他程序。父进程可以继续处理自己的事情，也可以 waitpid 等待子进程完成。知道能复制、重置、删除运行状态，就能让 AI 帮忙开发多进程并行程序。

## 观察 CrazyOS 的进程内存

![图 2：观察 CrazyOS 的进程内存（00:01:21）。](/assets/images/06/0002.webp)

图 2：观察 CrazyOS 的进程内存（00:01:21）。

今天继续用上次的 CrazyOS 模型。也许以后能从它出发讲完整个学期。进程有内存，MEM\_SIZE 规定固定大小，MEM\_OFFSET 是 0x80000000。

![图 3：MEM\_SIZE、MEM\_OFFSET 与 struct proc（00:01:31）。](/assets/images/06/0003.webp)

图 3：MEM\_SIZE、MEM\_OFFSET 与 struct proc（00:01:31）。

```
#define MEM_SIZE   (1 << 20)
#define MEM_OFFSET 0x80000000u
#define STACK_TOP  (MEM_OFFSET + MEM_SIZE)

struct proc {
    // Process "virtual machine" state:
    // Register & memory
    struct CPUState cpu;
    uint8_t mem[MEM_SIZE];

    // Operating-system internal state
    char buf[256];
    int buf_len;
};
```

CrazyOS 直接运行二进制文件，指令序列像被加载到 0x80000000，形成内存映像。大小为 MEM\_SIZE，栈顶指针指向这里，push 时从上往下。

![图 4：STACK\_TOP 与栈的初始位置（00:02:04）。](/assets/images/06/0004.webp)

图 4：STACK\_TOP 与栈的初始位置（00:02:04）。

内存映像直接放在 struct proc。无论 fork 复制，还是 proc\_init 创建进程，都会分配 struct proc，里面的数组与进程内存一样大，保存一份副本，这是进程自身状态的一部分。

![图 5：进程结构中的 mem 数组（00:02:45）。](/assets/images/06/0005.webp)

图 5：进程结构中的 mem 数组（00:02:45）。

终端、浏览器等真实程序则更复杂，超出了 CrazyOS 的简单指令序列。

CrazyOS 主要使用栈上数据，真实进程内存还有更多内容。计算机系统基础讲过，指令代码位于内存，全局变量的数据也在。比如 int x 等于 1，这个初始值 1 会出现在二进制文件，直接编辑文件就能看到。

![图 6：进程的内存映像与栈（00:03:27）。](/assets/images/06/0006.webp)

图 6：进程的内存映像与栈（00:03:27）。

如果 int x 等于 0，或定义 100 万个元素的 int x 数组，就不出现在二进制文件，而属于 BSS section。今天讲进程地址空间，了解比 CrazyOS 更复杂的真实进程内存里到底有什么。
