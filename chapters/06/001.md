## 观察 CrazyOS 的进程内存

![图 2：观察 CrazyOS 的进程内存（00:01:21）。](/assets/images/06/0002.webp)

图 2：观察 CrazyOS 的进程内存（00:01:21）。

我们今天继续上一次课讲的简单的模型，来看一眼。上一节课我做了一个 CrazyOS，也许以后上操作系统课，就可以直接从这个CrazyOS 开始，把整个学期的课程都给讲出来。在 CrazyOS 里，我们观察到进程是有内存的。里面有几个比较关键的变量，比如这有一个 MEM\_SIZE，进程的内存大小是固定的，然后 MEM\_OFFSET 是 0x80000000。

![图 3：MEM\_SIZE、MEM\_OFFSET 与 struct proc（00:01:31）。](/assets/images/06/0003.webp)

图 3：MEM\_SIZE、MEM\_OFFSET 与 struct proc（00:01:31）。

```
#define MEM_SIZE   (1 << 20)
#define MEM_OFFSET 0x80000000u
#define STACK_TOP  (MEM_OFFSET + MEM_SIZE)

struct proc {
    // Process "virtual machine" state:
    // Register & memory
    struct CPUState cpu;
    uint8_t mem[MEM_SIZE];

    // Operating-system internal state
    char buf[256];
    int buf_len;
};
```

因为 CrazyOS 可以直接运行一个二进制文件。对里面的指令序列，就好像这个指令序列被加载到了 0x80000000 里面，有一个这样的内存映像，相当于是 0x80000000。这里有一个，这是 MEM\_SIZE，栈顶的指针是指向这里的。所以如果我们要往栈里面 push 东西的话，它会从上往下 push。这是一个进程的内存映像。

![图 4：STACK\_TOP 与栈的初始位置（00:02:04）。](/assets/images/06/0004.webp)

图 4：STACK\_TOP 与栈的初始位置（00:02:04）。

这个进程的内存映像是直接写在 struct proc 里的。所以每当你分配一个新的进程的时候，无论是用 fork 创建一个新的进程，还是像我们在这里面用 proc\_init，直接无中生有生成一个进程，它都会生成一个 struct proc，或者说都会分配一个 struct proc。里面有一份内存的副本：我内存有多大，这个数组就有多大，它会有一份拷贝。这是进程自己状态的一部分。

![图 5：进程结构中的 mem 数组（00:02:45）。](/assets/images/06/0005.webp)

图 5：进程结构中的 mem 数组（00:02:45）。

但是，对于实际的程序，比如你看到的我终端里面的这些程序，或者浏览器，这些更复杂的程序来说，它不像是我们 CrazyOS 那么简单，只有一小段指令序列。

然后这小段指令序列直接就跑起来，它只用栈上的数据，对吧，我们的整个进程的内存，会比这个模型复杂一点，在计算机系统基础课上面，其实大家已经学过一次了，大家都知道像代码，也就是指令序列是在内存里的，然后数据你定义的各种各样的，全局变量。对吧，如果你写 int x 等于 1。那这个 x 等于 1 的 1 是会出现在二进制文件里的，你们可以直接去编辑那个二进制文件，看到初始化的那个变量的值。

![图 6：进程的内存映像与栈（00:03:27）。](/assets/images/06/0006.webp)

图 6：进程的内存映像与栈（00:03:27）。

然后如果你 int x 等于 0 的话，或者你定义一个 int x 数组是 100 万的话，那这个它就是不出现在二进制文件里，它在一个叫 BSS 的section，对吧，那内存里面有，有比大家想象的要多一些的内容，比 CrazyOS 要复杂一些的，所以这就是今天我们要讲的，进程的地址空间，也就是我们要弄清楚进程的，内存里面到底有什么东西。好。
