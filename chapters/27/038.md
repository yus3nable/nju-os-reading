这就是关系数据库模型，仍然在表达对象和指针的关系，但通过三重或任意多重循环，可以 join 无穷多个表。比如 studentID 和课程 ID 各自唯一，在对应表里就叫 primary key，可以用来寻找记录。

![图 45：Students、Courses 与 Takes\_Course（00:46:01）。](/assets/images/27/0045.webp)

图 45：Students、Courses 与 Takes\_Course（00:46:01）。

这里的课程号也是一个 key，也可以用来寻找。我可以选择 course 的 title，from Student 开始 join。join 就是 Cartesian product，再配上 take course 选课。［课件中的查询，表名与字段沿用原例。］

```
SELECT Courses.Title
FROM Student
JOIN Takes_Course
  ON Student.ID = Takes_Course.ID
JOIN Courses
  ON Takes_Course.ClassID = Courses.ClassID
WHERE Student.Name LIKE '张%'
```

图 46：用 JOIN 和 key 配对查询课程（00:46:30）。

要求 student\.id 等于 take course\.id，再 join courses，要求 take courses\.classid 等于 course 的 classid，就是这些 key 之间的对应。还可以加任意过滤条件，比如 where student\.name LIKE，以“张”开头。基于选课这些最小的、不能再分解的事实，可以写查询，选出这次课程成绩尚未录入的记录，或成绩不及格的记录，再通过程序处理这些查询结果。
