怎么回滚也有很多复杂性。1980 年代实现这样一个好的 Data Base System，对程序世界产生了多大的冲击。Two\-phase Locking 的想法很直观：读时加读锁，写时加写锁。另一种是多版本并发控制，我用一个比方说明。我觉得这样概括挺好：任何时候，数据结构都有一个快照，代表当前所有数据的状态。Transaction Begin 时，可以想象所有东西已经 Git Add、Committed，当前状态已经就绪。要做 Transaction，就 Git Checkout 一个新的 Branch，相当于复制一份世界，在里面修改。

读永远读取自己这个世界，别人怎么改都无关；写也写到自己的世界，不修改 Main 分支。多个线程并发做 Database Transaction，每个都 Checkout 新分支，各做各的，完成后试图向 Main 分支发起 Merge。比如 T1 改这一行，T2 改另一行，Merge 没有 conflict。类似 write\-ahead log，replay 各自操作即可；没有冲突，就可以分别 Commit。

如果两个分支都写了同一行、写入不同值，就有冲突，其中一个分支会被摧毁。multi\-version 类似 Git Checkout，Commit 时向 Main 做 Merge。它与 Git 有一个区别：Git 可以 resolve Merge conflict，数据库不能，因为 Transaction 中间可以执行任意计算，值可能由程序算出，Database System 只管理 Transaction。

理论上，也许可以实现性能更好的 Multi\-Version Concurrency Control。
