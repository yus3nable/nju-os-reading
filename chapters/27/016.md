第一个代价是：文件系统本身有 crash consistency，但在它上面维护这个数据结构时，可能涉及 multiple write。比如把一个同学的选修课名单完整导入系统，需要写多个文件，文件系统本身不支持多文件写的 atomicity。假设要写 100 个文件，写到第 50 个时系统 crash，数据结构就进入不一致状态。

我需要手工写一个 fsck，或者像 git 那样用 append\-only 机制。在文件系统上实现 crash consistent 的 application 很有挑战，但可以做到。比如文件系统的 rename 支持原子性，很多时候可以先创建目录，再 atomic 地把它 rename 过去，实现 atomicity。
