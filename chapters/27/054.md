就算是传统的 SQL 的 database，它是也可以 scale 到很多台机器上的，但是如果你想要，一劳永逸的解决 scalability 的问题，一个好的想法是你可以做一个够用，但是又可以 scale out 的一个子集，就是说大家又会回头踩了很多坑以后会觉得，SQL 给我们太多了。

![图 59：缩小接口：可 scale out 的 key\-value 子集（01:10:05）。](/assets/images/27/0059.webp)

图 59：缩小接口：可 scale out 的 key\-value 子集（01:10:05）。

对吧，太多了，太多就意味着一旦滥用，你就会带来 performance bug，那也许在某一些应用里面，我可以给你给的少一点，给你少一点的时候，我的系统实现会更容易，系统的性能可能会更高，更容易分布式，而且也基本上也能够用来，帮助你来构建，你需要的应用程序，那什么数据结构，大家用的最多，最简单，又够用，key value dictionary，一个 key 和 value，这就是一个 map，或者一个 unordered\_map，或者就是一个 Python 里面的 dict。

你的应用程序理论上说，是可以靠 key 来管理各种各样的数据的。
