理论上，传统 SQL database 也可以 scale 到多台机器。如果想一劳永逸地解决 scalability，一个想法是提供够用、又能 scale out 的子集。大家踩过很多坑以后，会觉得 SQL 提供的功能太多。

![图 59：缩小接口：可 scale out 的 key\-value 子集（01:10:05）。](/assets/images/27/0059.webp)

图 59：缩小接口：可 scale out 的 key\-value 子集（01:10:05）。

这些功能一旦滥用就带来 performance bug。对某些应用，少提供一些功能，可以让系统更容易实现，性能可能更高，更容易分布式，也基本够构建所需应用。什么数据结构最常用、简单又够用？key value dictionary，也就是一个 key 和 value，对应 map、unordered\_map 或 Python 的 dict。

理论上，应用程序可以靠 key 管理各种数据。
