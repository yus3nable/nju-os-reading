相当于写三层 for each：对 students 里的每个 s、courses 里的每个 c、enrollment 里的每个 e，完成 join 后检查 if 条件。只有 e 的 student id 等于 s 的 student id，且 e 的 course id 等于 c 的 course id，才 yield 一个 s、c。这个操作会筛掉绝大多数结果。

因为 student id 和课程 id 在各自表里唯一，对 enrollment 中的一行记录，比如三号学生选四号课，只能找到学生三、课程四满足条件。于是生成 student 三、课程四和这条记录，把三号 student 与四号 course 关联起来。这个实现看起来很低效，但如果程序能高效完成这个操作，哪怕写五十层嵌套循环也能高效算出来，就提供了我们所需的抽象。
