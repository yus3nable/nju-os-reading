比如管理用户或课程数据，可以用 useruid，把 uid 拼在 user 后面作为 key。read 时取出一个字符串，比如保存个人信息的 json。write 时，如果用户要修改用户名，就把 serialize 好的 json 写回 useruid 这个 key。这样就能查询、修改用户信息，也支持增删改查。

还可以扩展 key value：比如 user1、user2 的 key 各指向一个 json，保存用户自己的 metadata 等信息，1 号 user 也这样保存；enrollment 则可以指向一个 append\-only 列表，也可以清零，把全部选课和退选记录放进去，也就能实现教务系统。当然还可以有 course。一个学生通常不会选一万个课、退一万个课，即使有，我相信也是自己写脚本时出了 bug。这就是对系统中某些数据的 knowledge。append\-only 比较容易实现，比如列表里先记录 os2026 的 enroll，再记录 os2026 退选，总有办法用 append\-only data structure 追加这些信息。
