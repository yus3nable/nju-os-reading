要进一步实现国民级应用，一个数据库就有些困难。比如微信聊天记录，可以用这个模型实现，只用一张表也可以。

［课件中的最近十条聊天记录查询。］

```
SELECT *
FROM chat_records
WHERE (sender_id = @user_id1 AND receiver_id = @user_id2)
   OR (sender_id = @user_id2 AND receiver_id = @user_id1)
ORDER BY timestamp DESC
LIMIT 10
```

减号下面再放上回复。微信解析到这个格式，就会自动 link 到被回复的消息，也会保存一些 metadata。这样还保持了兼容：不支持这个功能的老版本、某些 pad 版本或网页版微信，可以直接显示那些减号。微信聊天记录可以看作一张 chat records 表。点开聊天记录，查看最近十条，只需一个 SQL 查询：知道自己和对方是谁，在全世界的微信聊天记录里 select \*，用 filter 要求 sender ID 是你、receiver ID 是对方，再按时间排序，取最近十条。再考虑微信达到百万、千万用户时的处理方式。
