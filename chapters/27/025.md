希望写入的数据进入磁盘，就需要 msync 系统调用。msync 是 synchronize a file with a memory map，有地址、长度、flags 三个参数。

![图 30：msync 的参数与手册描述（00:28:14）。](/assets/images/27/0030.webp)

图 30：msync 的参数与手册描述（00:28:14）。

写了一段内存，就要通过它告诉操作系统：请把这段内存写回磁盘。它与 fdatasync 的区别是，它通知操作系统同步这段修改，不会等内存写入磁盘后再返回。msync 没有 fdatasync 的保证，与 crash consistency 无关，用过以后还需要额外的 fdatasync。

要实现有 crash consistency 的写，需要额外的 fdatasync，还需要配合其他系统调用。

![图 31：madvise 给内存区域提供访问建议（00:28:54）。](/assets/images/27/0031.webp)

图 31：madvise 给内存区域提供访问建议（00:28:54）。

其中一个是 madvise 系统调用，含义是 give advice about memory，可以建议用怎样的方式管理这段内存，以获得较好的性能。这还涉及 POSIX 以外的 api，比如 BSD 或 Linux 中的接口。normal、random、sequential 等选项让行为越来越复杂。

![图 32：MADV\_NORMAL、RANDOM 与 SEQUENTIAL（00:29:17）。](/assets/images/27/0032.webp)

图 32：MADV\_NORMAL、RANDOM 与 SEQUENTIAL（00:29:17）。

操作系统想提供透明抽象：这是一个 memory\-mapped file，可以随意读写。但写回策略仍需要控制。
