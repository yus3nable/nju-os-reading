上一节课讲了文件系统的实现。文件系统是磁盘上的一个数据结构。如果掌握了数据结构课的内容，应该很容易理解：我们要做一棵目录树，或者像 UNIX 文件系统那样做一个目录图，以图的方式存储这个数据结构。块设备按块访问，内存按字节访问，两者在这个问题上没有根本区别。我还讲了两个额外的话题：文件系统的 crash consistency 和应用程序的 crash consistency。这是 persistence 特有的问题：数据或线程随时可能消失，重启以后仍要能 recover 到正确状态。可以丢掉最近几次数据结构操作，但整个数据结构不能 corrupt。

沿着文件系统继续讨论：有了一个好的文件系统实现，无论是 FAT 还是 ext4，我们可以用它做什么？文件系统保存应用程序的数据。虽然我们常说要访问文件、打开点 PPTX 或作业点 DOCX，实际访问文件的是应用程序。我们通过键盘、鼠标和屏幕与计算机交互，应用程序接管键盘、鼠标输入，并向屏幕的某个区域输出。

访问文件系统、保存数据的都是应用程序。哪怕只想把文件 cat 出来，也是最简单的应用程序调用 read、open 等系统调用完成文件访问。这也是上一节课说应用程序的 crash consistency 很重要的原因：即使文件系统一致，应用如果有 data loss，使用者也很难接受。我们一直用文件系统管理应用数据，PPTX、DOCX、电影和 OS Labs 都在文件、目录这套目录树 API 上工作。今天讨论有没有更好的方法：应用程序要服务一万人、十万人时，该怎样管理数据？
