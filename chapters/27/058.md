key value 还可以做成 in memory 的结构。所有请求到来后，先进入这个 in memory key value。

![图 62：Redis：内存数据结构与缓冲（01:15:19）。](/assets/images/27/0062.webp)

图 62：Redis：内存数据结构与缓冲（01:15:19）。

隔一段时间合并请求，再写入后端 database。比如统计点赞，每次都形成 transaction 并 persist，代价较大。如果全世界很多人给你点赞，可以在内存放 counter。点赞数据没那么重要，丢失的损失也许较小，特别是几百万人同时点赞时。每次请求进入 in memory 后都加 1，可以用 list append，也可以 atomic 加 1，让 key 映射到 integer。每隔一分钟或其他时长，知道 list 长度后，再写 SQL，从 database 取出原点赞数据。
