刚才的内核 blockIO 生命周期工具，用 bpftrace 的 .bt 程序实现。既然都是从内核执行提取信息，能否插入由自己代码生成的 probe？

![图 16：bio\-trace\.bt 的事件说明与入口代码（00:16:06）。](/assets/images/25/0016.webp)

图 16：bio\-trace\.bt 的事件说明与入口代码（00:16:06）。

bio\-trace\.bt 的启动片段；后续 tracepoint 处理器未展开：

```
BEGIN
{
    printf("{\"type\":\"ready\",\"ts\":%llu}\n", nsecs);
}
```

假设每次内核函数调用都经过一段自己的代码，能知道 function name、function id 及 arguments，相当于 hooking。之前用 LD\_PRELOAD 讲过这个机制。

可以劫持 malloc、free、printf 等函数，知道调用名和参数，也能修改它表现出的行为。比如变速齿轮改变进程对时间的感知。同样，能否把手写代码插进内核？

![图 17：在操作系统执行中插入带参数的 probe（00:17:09）。](/assets/images/25/0017.webp)

图 17：在操作系统执行中插入带参数的 probe（00:17:09）。

每个内核函数执行时都运行这段代码，理论上就能自己实现 inotify 所做的事情，无需专门调用它。
