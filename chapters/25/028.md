Git 就是这三类 object，加上文本表示的指针。分支指向 commit object，再次 commit 后，分支指针向后移动。head 是 ref，也能写 tail 这样的直接引用。

![图 31：分支、HEAD 和 stash 的对象模型（00:40:01）。](/assets/images/25/0031.webp)

图 31：分支、HEAD 和 stash 的对象模型（00:40:01）。

git checkout、git commit 都是文件系统上的数据结构操作。刚才在一个分支上，现在创建 new、newnew 两个 branch，objects 不变，只多出 refs/heads 下的 new、newnew。与 master 一样，里面是某个 commit 的 hash。当前在 newnew，把 git\-cat commit 进去，heads/newnew 就会改变。

![图 32：newnew 提交后，分支指针变为 531edd8（00:41:03）。](/assets/images/25/0032.webp)

图 32：newnew 提交后，分支指针变为 531edd8（00:41:03）。

newnew 分支提交后的指针内容：

```
$ git commit -m 'check in git-cat'
[newnew 531edd8] check in git-cat
 1 file changed, 85 insertions(+)
 create mode 100755 git-cat
$ cat ./.git/refs/heads/newnew
531edd8e67359bedc84adfa2e5c6f9c6a83d2cac
```

现在变成 531ed，所有引用都以明文文本存进文件系统，符合 unix 设计。Git 的设计者是 Linux 创始人 Linus，我觉得这个设计很好。此前用 SVN，要 check in、check out，我经历过那个时代，觉得很难用。Git 出现后，情况改变了。

GitHub 今天已成事实标准。简单的对象设计还能承载后来的需求，比如 Git LFS、Worktree，稍后再讲。
