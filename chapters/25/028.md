所以这个世界上 Git 没有任何神秘的，它所有东西都是刚才那三种 object 之一，然后你可以剩下所有东西都是指针，以文本方式去存储的指针，比如说一个什么是一个分支，分支就是一个指针，指向一个某一个这个 commit object。然后当然这个指针会随着分支。比如说你再次 commit 的时候，它指针会往后移，不停地往后移。比如说 head 也是这样的一个往后移的指针，它是一个 ref，但我也可以直接写这样的 tail。然后就可以做 git。没有任何神秘的东西。

你的 checkout，git checkout，你的 git commit，都是这种非常非常平常的文件系统里面的操作，就是一个数据结构，刚才我们展示的都是在一个分支上面，的操作，如果我现在创建一个分支呢？比如说我去 git checkout，我创建一个叫 new 的 branch，我可以再创建一个叫 newnew 的 branch，没问题。然后就这时候我们发现，object 其实是没有变化的，但是多了一些这个东西，叫 refs底下的 heads 下的 new 和 newnew。然后他们实际上都和刚才我们看的 master 是一样的，对吧，对，它就是一个 hash，就是一个 commit object，然后所以如果，如果你看这个 newnew 的话，它也是同一个 commit object，但因为我现在是在，比如说我现在在 newnew 这个分支上。所以如果我。比如说我现在把这个 git\-cat，commit，那我的 heads 下的 newnew 就会变。变成。

![图 32：newnew 提交后，分支指针变为 531edd8（00:41:03）。](/assets/images/25/0032.webp)

图 32：newnew 提交后，分支指针变为 531edd8（00:41:03）。

newnew 分支提交后的指针内容：

```
$ git commit -m 'check in git-cat'
[newnew 531edd8] check in git-cat
 1 file changed, 85 insertions(+)
 create mode 100755 git-cat
$ cat ./.git/refs/heads/newnew
531edd8e67359bedc84adfa2e5c6f9c6a83d2cac
```

对吧，就变了，然后 531ed，我现在这个就是 531ed，所以就是这么简单，它所有东西都是以文本，明文的形式存储在文件系统里的，这是一个非常非常符合 unix 的设计，所以你们猜这个 Git 设计者是谁，是 Linus 对吧，是 Linux 的发明人，你就觉得这是一个非常非常非常漂亮的设计，在这之前大家用的是 SVN，你们没有经历过那个时代，我经历过那个时代，就是都要 SVN check in check out。然后那 SVN 难用的像什么什么一样，直到 Git 来了以后。
