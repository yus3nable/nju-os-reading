就是 rebase，rebase 是一个非常危险的操作，好，很好，这就是 git，基本上你就已经超过，就知道这些基本上已经超过 90%的 git的用户了应该，然后我在准备这个幻灯片的时候，我惊人的发现，历史总是在重演。然后 git 刚才我们说，git 是一个 persistent data structure，它是为单线程设计的，也就是说它假设你的开发者就一次做一件事，还记得 unix 吗？unix 我们说最开始的它就是进程模型，没有线程。

然后那只有操作系统里面有共享的状态，一个进程里面它就是一个执行流，然后当我们一个进程变成线程，引入了 pthread 的时候，我就打开了一个魔鬼的盒子，我花了那么多节课讲并发，讲并发 bug，讲并发 bug 应该怎么应对。OK，就是为了把进程模型变成线程模型。然后 git 也是一个很像是 unix 单进程的模型，它只有一个工作区，一个 HEAD，你在本地工作的时候你是一个线性的committer，你们自己不自知，你们在做实验的时候每一次 make 的时候，都是在线性的往后加一个往后加一个往后加一个然后直到你比如说你需要跟别人同步的时候。你才和别人 merge 一下，大部分时候这个模型都工作得很好，但是一旦你开始从单线程变成多线程的时候，事情就麻烦了，你可以这样想，如果我现在正在一个分支上面工作，比如说我现在修到一半，修到一半突然老板给我打电话，说你现在做实验不要干了，你切换到另外一个 feature 分支上，去把那个上面一个高危漏洞给修了。好，那我应该怎么办呢？我应该 stash。对吧，我现在做到一半的事情我不能 commit，我得 stash，变成一个 stash。好。然后我再做一个上下文切换。

我 check out 到那个分支上，你有没有感觉到开始并发了，对吧，因为我做了一半的东西被保存下来了，然后我切换到另一个地方工作，然后这时候我又做了一半，老板又打电话来，说你有一个我有一个更高优先级的 bug 需要你修，那我就没办法，我再 stash。然后你发现这个 stash 是一个 stack，它是一个线性的 stack。然后你发现它的设计，在设计之初就没有让你多线程工作。所以当你一定要多线程工作的时候，你会有一个 stash，虽然还好。一般来说从人道主义的角度考虑。

老板一般不会做这么过分的事，所以你一般有个两个 stash，就同时 multi\-task 两个事情。
