我们为什么不能把树直接复制一份呢？没有道理不能让我们把整个 git repository 假装复制一份，因为复制是没有代价的，我是永远不修改的，所以我复制一个指针，这只是一个指针指的这个位置就可以了，所以就有了 git 的 worktree。所以你看，我如果现在我在这个目录里。然后我现在可以这样做这样，git worktree add。当然我现在 add 的时候，我就得再换一个目录了。比如说我要换到它点点下面的，我要起一个分支的名字。比如说 hot\-fix。我被老板要求要 hot\-fix。

然后在这个时候我就可以创建一个 git 的，worktree，好，这时候我就有一个 hot\-fix，我那有一个点，点 git，然后但这个点 git，你有发现有点不太对劲吗？它不是一个目录，刚才那个点 git 是一个目录，就是那个原始的那个 git 是一个目录。

从 git\-test 目录创建另一个工作区：

```
$ git worktree add ../hot-fix
Preparing worktree (new branch 'hot-fix')
HEAD is now at 92255fa Merge branch 'newnew' into new
```

对吧，目录里面有 objects，就是那个 persistent data structure 就存在那个目录里，但 worktree 不是的，worktree 我可以直接cat 它，所以你看又是一样的设计，跟那个什么 head 对吧，一样，head 说是我这个 reference 指向了某一个东西。好，他说这个点git 说这是一个 git 的目录。实际上是这个东西。那这个是什么呢？我也可以 cd 进来对吧。这是你看到它是在这个 worktrees 下的，对吧。

我的真实的点 git worktrees 下的，hot\-fix，啊，一堆指针，对吧，没有 object，它不需要存 object，因为是 persistent data structure，所有东西都是指针就可以了。所以我只要有一个 head。对吧，指向一个合法的 HEAD，head 再指向一个合法的commit，这件事情就搞定了。

hot\-fix 中的 \.git 文件，以及它指向的目录里的 HEAD：

```
$ cat .git
gitdir: /tmp/vibe/git-test/.git/worktrees/hot-fix

# 进入上述目录后
$ cat HEAD
ref: refs/heads/hot-fix
```

这是 persistent data structure 带来的一个，完全免费的 feature，当然当时是为了解决这个老板不停地给我打电话的这样的需求，但是今天 worktree 就成了这个 agent 时代的一个非常标准的特性。
