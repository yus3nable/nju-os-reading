正式定义，Git 是分布式版本管理系统，管理很多目录树快照，每个 Commit 对应一个 Tree，还能分支。

![图 38：分叉历史、merge 与 rebase（00:45:13）。](/assets/images/25/0038.webp)

图 38：分叉历史、merge 与 rebase（00:45:13）。

课件用 A、B、D 表示提交的 rebase 示意；提交名依赖当前教学例子：

```
git reset --hard D
git cherry-pick A  # git diff CA A | git apply
git cherry-pick B  # git diff A B | git apply
```

同一 Tree 上，一台机器产生 A、B 两个 Commit，另一台产生 C、D，历史就分叉了。Git 合并有三种情况，用对象模型就能理解。

基础的 Merge 是新增 E 节点。比如与我的课程代码合并，本地 Main 已前进很远，我的 Main 却还在早期。

![图 39：共同祖先上分出的两条提交历史（00:46:15）。](/assets/images/25/0039.webp)

图 39：共同祖先上分出的两条提交历史（00:46:15）。

我在早期 Main 上做 M1、M2 提交，就形成两条历史。拉取远端后，创建 E，两个 parent 是 B、D。做三方合并时，比较公共祖先 Tree、B Tree、D Tree；中间即便有一万、十万提交，也先展平成三个状态。
