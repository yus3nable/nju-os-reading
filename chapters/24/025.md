对，首先做一个文件系统的探测，你看它会以只读的方式打开这个文件，然后找到这些文件系统是什么，这也是 mount 命令做的事情，在那个系统调用里面，你就必须告诉它是什么文件系统，那个操作系统不会负责探测文件系统，如果它认为这个文件系统不合法，它会直接拒绝这个 mount。但是你在应用程序这一侧，它会探测这是什么文件系统，它确定这是一个 VFAT 的文件系统。

Agent 在画面中列出的 loop 设备配置顺序；结构参数仅转录可见字段：

```
openat("/dev/loop-control", O_RDWR)
ioctl(3, LOOP_CTL_GET_FREE) = 0
openat("M5-frecov.img", O_RDWR)
openat("/dev/loop0", O_RDWR)
ioctl(4, LOOP_CONFIGURE, {
    fd=3,
    lo_flags=LO_FLAGS_AUTOCLEAR,
    lo_file_name="M5-frecov.img"
}) = 0
```

然后接下来它会分配 loopback device，它会打开一个叫 /dev/loop\-control 的设备，以读写的方式打开，打开完以后就对它做ioctl，你看就所有的，我们说操作系统会创建一个 loopback device，这句话本身。当然我说的是对的，我没有忽悠你们。但是这句话到底意味着什么，其实它是在 Trace 里的，它是通过一个 ioctl 的系统调用，用一个 LOOP\_CTL\_GET\_FREE，也就是说你第一次Getfree 会得到一个比如说 0。然后再第二次它会得到 1,2,3,4。

如果失败会得到\-1，所以你可以创建很多的 loopback device，然后这个 API 就会返回一个它唯一的编号给你，然后有了这个编号以后，你就可以访问这个/dev/loop0 了，因为这是 0，如果它返回 1 的话，你就可以访问 Loop1。然后在你们的系统里面，如果你没有 Snap 或者什么［听辨不清，00:36:47］，你会看到很多 loop device，如果你用 lsblk 的话，你会看到很多 loopback device。然后还有一些绑定镜像文件的文件描述符等等。

然后有了这样的一个 loopback device 以后，这个 loopback device，然后就可以执行一个真正的 Mount，这时候它就变成了块设备，它就变到了文件系统上，这就是整个系统调用的流程，所以没有什么是理解不了的，你就问 AI 就可以了。
