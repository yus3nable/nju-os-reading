接着看实现层面。文件系统是一棵目录树，每个存储设备，或者说它的文件系统，也对应目录树。刚才列出的 block device 就是例子。

![图 11：设备分区对应的挂载点（00:15:55）。](/assets/images/24/0011.webp)

图 11：设备分区对应的挂载点（00:15:55）。

列表中能看到 mount points。mmcblk0 中的 0 是设备号，第 0 个设备，p1 是第一个 partition，p2 是第二个。两个分区各对应一棵目录树，都放进当前系统。比如 /dev/ 下的 nvme0n1、p2 这样的 block device，都能有从根到 a\.txt 等文件的树。U 盘也一样。世界上这么多目录树，怎样管理？

![图 12：Windows 对象根、网络路径和盘符（00:16:55）。](/assets/images/24/0012.webp)

图 12：Windows 对象根、网络路径和盘符（00:16:55）。

课件中的 Windows 设备访问片段；HANDLE、常量和 CreateFile 来自 Windows API：

```
HANDLE hDevice = CreateFile(
    "\\\\.\\PhysicalDrive0", GENERIC_READ | GENERIC_WRITE,
    FILE_SHARE_READ | FILE_SHARE_WRITE, NULL, OPEN_EXISTING, 0, NULL);
```

网络盘也是目录树。我的 NJU Box 通过 WebDAV 挂到办公室机器上，机器一直录像，比如组会结束，录像自动同步到 WebDAV 网盘。我还没把它接入 Agent，但觉得方向不错，可以自动管理生活、工作的各方面。这就意味着，到处都有目录树。

操作系统设计者要管理很多棵树。大家已经习惯插 U 盘后，文件管理器多出 E 盘，点进去就看到另一棵目录树。
