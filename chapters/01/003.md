接下来讨论技术内容：什么是操作系统？教科书给出的 operating system definition，常用 a body of software 来描述，也就是帮助其他程序运行的软件。

## 操作系统的教科书定义

![图 16：操作系统的教科书定义（00:39:16）。](/assets/images/01/0016.webp)

图 16：操作系统的教科书定义（00:39:16）。

它让程序共享内存、与设备交互。但读完这个定义，仍有很多问题。单是“run programs”里的 program，就包括窗口管理器、终端、浏览器、虚拟机和 Claude Code。不同程序需要怎样的 memory，又怎样 interact with devices？一个概括性的定义还不足以回答这些问题。

## 理解操作系统的发展历史

![图 17：理解操作系统的发展历史（00:40:29）。](/assets/images/01/0017.webp)

图 17：理解操作系统的发展历史（00:40:29）。

学习时，可以先大致了解定义，再去理解它概括的内容。我不赞成为了考试背定义：高度概括会省略很多细节。操作系统帮助我们开发程序，原因就在于许多事情直接做起来很复杂。

理解操作系统，要追问它怎样产生、怎样发展。事物刚起步时往往比较简单，适合从头理解。今天的 AI 也还处在一个有机会看清来龙去脉的阶段：基础足够，就能阅读开源代码，逐步了解它怎样工作。

再看它如何从简单发展到复杂。AI 最初没有工具链，只能在对话框里聊天，后来才逐步能够调用工具。理解操作系统也可以沿着历史追问：第一台计算机没有操作系统，为什么发展到今天，打开手机就会接触这样复杂的系统？

这段历史可以沿硬件、软件和操作系统来看。操作系统直接接管硬件，管理在硬件上运行的程序。抖音、淘宝、终端、服务器等应用程序，则是上层软件。本学期主要从应用的角度，理解现代操作系统提供哪些功能。

操作系统位于硬件和应用软件之间，它本身也是软件。先复习硬件和软件，就更容易理解这个中间层。大家在数字逻辑电路课上学过硬件，那门课讲了什么？

大家做过数码显示屏之类的实验。为了复习这些概念，我写了一个数字逻辑电路模拟器，提供导线、时钟、逻辑门等组件。如果实验时连过线，就会熟悉这里的 wire 和 reg。

组件之间通过许多 wire 连接。这份电路是 AI 写的，有些地方比较奇怪，里面仍然是时钟、导线、逻辑门和触发器。采用边沿触发时，时钟到达相应边沿，值就锁入 flip\-flop。

![图 22：板书：导线、触发器与逻辑门（00:46:19）。](/assets/images/01/0022.webp)

图 22：板书：导线、触发器与逻辑门（00:46:19）。

flip\-flop 还会输出锁存的值。按这些规则写一个数字电路模拟器，就是一道 C/C\+\+ 编程作业。

RISC\-V 处理器也能这样模拟。用逻辑门和触发器构造处理器状态，每个寄存器、每个内存单元都有自己的值。计算机系统基础课中的模拟器，也是记录这些状态，再让状态按规则变化。整个 computer system，也就是硬件系统，可以看成状态机。

![图 23：RISC\-V 模拟器中的寄存器与 PC（00:47:21）。](/assets/images/01/0023.webp)

图 23：RISC\-V 模拟器中的寄存器与 PC（00:47:21）。

内存和寄存器中的每个 bit 共同构成状态，例如 0101 这样的二进制值。这里先假定每个时钟周期执行一条指令。

![图 24：板书：内存、寄存器与状态转移（00:47:47）。](/assets/images/01/0024.webp)

图 24：板书：内存、寄存器与状态转移（00:47:47）。

执行完这条指令，系统就进入下一个状态。这一过程也能用程序模拟。

![图 25：RISC\-V 模拟器的一步执行函数（00:47:53）。](/assets/images/01/0025.webp)

操作系统支撑着整个应用生态。它除了让普通程序用 print 显示文本、调用 read 和 write，还提供能彼此复用、组合的工具，这也是 unix 设计中的重要特点。

编程语言中的组件可以自由组合、反复复用，代价很低。相比之下，今天 AI 使用 skills、MCP 时，往往还要先把相关内容读进上下文，再复用它们。

这个数码管例子展示了 Unix 的组合方式，Claude Code 今天生成的代码也常用这些工具，［听辨不清，00:57:59］。管道就是把一个程序的输出交给下一个程序作输入，不断连接，就能组合出更多功能。本学期会反复讨论这种命令行设计。

## 复习计算机软件与状态机

计算机系统基础课里，高级语言源文件 a\.c 经过编译等过程，变成可直接在 CPU 上运行的 a\.out，也就是 binary。

程序同样是状态机，状态包括寄存器和内存的值。大家在 GDB 中调试过程序，看到的就是这些状态。程序要在硬件上运行，两者的模型必须对应。

以大家在 C\+\+ 中接触过的汉诺塔为例：有多少同学能不借助额外辅助写出非递归汉诺塔，［后半句听辨不清，01:00:03］？下节课会讲非递归版本，今天先看熟悉的递归版本。

在 GDB 中打印堆栈，就能看到当前程序状态。除此之外，还有一个在计算机组成课上学过的状态：执行位置。

## 硬件、软件与操作系统

![图 44：硬件、软件与操作系统（01:03:47）。](/assets/images/01/0044.webp)

图 44：硬件、软件与操作系统（01:03:47）。

操作系统管理许多程序的状态，也提供各种操作系统对象。本学期会用一整个学期讨论这些机制。从应用软件来看，操作系统提供的是一组 API，程序调用这些 API，就能访问打开的文件、磁盘、显卡、显示器等对象，也能操作其他软件。

例如，调用操作系统 API 可以终止另一个程序，刚才就试过终止 vscode。这个中间层抽象硬件，为上层软件提供服务。

相同的设计思路也适用于其他系统：把多台机器抽象成一组 API，就能访问机器集群，形成分布式系统；把 GPU 的许多核心抽象出来，就得到 CUDA 这样的编程模型，使用者主要表达要计算什么。

编译器再把这些表达编译成 GPU 能执行的代码。对存储做抽象，则形成存储系统。要理解操作系统，可以沿着下层硬件与上层软件的发展历史，再走一遍这些抽象形成的过程。
