执行过程却往往还没完全弄明白。看到非递归 Hanoi 后，就可以把原来大步执行的 C 程序，改写成小步执行的程序。

在我定义的 Simple C 模型中，每条 C 语句都有精确行为，包括函数调用和返回。这样，就能明确以前似懂非懂的细节。

［非递归程序中的 call、ret 宏；Frame、top 与 retval 依赖函数上下文。］

```
#define call(...) ({ *(++top) = (Frame){.pc = 0, __VA_ARGS__}; })
#define ret(val) ({ top--; retval = (val); })
```

每个 StackFrame 都必须记住执行位置。可以有 PC，并记录返回值的地址，这是计算机系统基础课中学过的表达方式；也可以像这里一样，保存当前运行到哪里、下一步到哪里的指针。有多种等价表达，但都要记录程序的执行位置。

［非递归程序的栈帧结构；pc 记录下一条待执行语句。］

```
struct Frame {
  int pc;
  int n;
  char from, to, via;
  int c1, c2;
};
typedef struct Frame Frame;
```

由此可以理解 Simple C 怎样在计算机系统上运行，也可以写出一个 C 解释器。
