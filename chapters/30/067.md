git 相比于你们没有用 SVN，SVN 里面存储的是 diff，听起来很高效对吧，但是你如果想要去下载某一个版本，那你就惨了，你就得从一个快照版本开始，不停的打 patch，打 patch，打 patch，打 patch，patch 到这个时间点，你才知道，终于知道我现在版本是什么，而且版本的回退等等都非常的复杂。所以 git 就做了一个我就是管文件系统快照的数据结构，我很简单。对吧，它有 tree of blobs，它有好多个文件系统的树。然后提交和提交之间自然而然的形成一个 commit 的有向无环图。

然后在这个数据结构上，你就把它变成一个数据结构问题，就可以非常自然的从需求推导出，像 branch，stash，worktree，这个我上课的时候讲过的，你自己从零开始推一遍，如果让你自己设计一个 agent 好用的 git，你自己就能发明这个 worktree，你自己发明过一次，你就不会忘记它了，或者说你就算是忘了，在下一次你想到这个需求的时候，你还可以再发明一遍，这就相当于是把把这个东西真正的理解了。所以只要有概念你就不需要去做那种无意义的肌肉记忆。
