父进程持有一个操作系统对象，child 也应持有同一个对象，这就涉及设计选择。例如，文件描述符的 offset 怎样处理？父子进程同时写入时，各自会写到文件的哪个位置，test\.txt 最后是什么内容？我觉得这是不错的考题。

［AI 原题代码；waitpid 的声明依赖原图未展示的头文件。］

```
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main() {
  int fd = open("test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
  write(fd, "Hello", 5);
  int pid = fork();
  if (pid == 0) {
    write(fd, "Child", 5);
    _exit(0);
  } else {
    waitpid(pid, NULL, 0);
    write(fd, "Parent", 5);
  }
  close(fd);
}
```

这段程序有唯一答案。如果在 fork 前 close，再由父子进程各自 open，会有什么不同？UNIX 为什么让 fork 继承文件描述符，这与 everything is a file 有什么关系？课堂上认真思考过这些问题，就会觉得它们自然地联系在一起。
