这就是应用视角的操作系统。讲了很长时间，过程有些绕，基本原理却是：cpu reset 决定确定的初始状态，firmware 加载操作系统，操作系统再加载第一个程序。

从第一个程序的初始状态开始，操作系统给应用世界提供的就是对象和 API。拿起 Android 手机打开抖音，可以想到它也是从 initramfs 开始，最后屏幕上每个像素点都由系统调用实现。我觉得这仍然让人惊叹。从进程启动到屏幕显示，再从 UNIX、27 行汇编的 fork，到 Minix、论战、Linux，直到今天成熟稳定的系统，是个精彩的故事，而且还在对象和 api 之上继续。在 Linux API 上，没有什么做不了：大语言模型、agent、抖音、淘宝都由此构建。最后再讲一点应用生态。

只有操作系统 API 还不够，它们很大程度上与应用程序共同研发。应用发现性能不够，操作系统就提供性能更好的 API、新文件或新对象，两者共同进步，形成今天的样子。应用生态带来了操作系统的繁荣，脱离生态，操作系统自身只是一套 API。厂商、个人开发者每天在 GitHub 发布新应用，还需要工具支撑，核心工具集也是操作系统的一部分。这就有狭义和广义的操作系统之分：操作系统原理主要讲 API，谈“中国为什么没有国产操作系统”时，很多时候谈的却是生态。它需要核心工具集、libc 等基本运行库、3D 库和图形库，工作很麻烦；这些工具中不能有安全漏洞，一个漏洞就会拖垮整个系统。

安装、版本管理、系统管理也都是代码。Linux 内核有 2000 万行代码，看起来庞大，和应用生态相比却很少，一个复杂应用的业务代码就可能上千万行，应用之间还要协作。生态也逐步发展而来。早期 DOS 时代用软盘、光盘发布软件，CDkey 写在光盘上，或贴在里面的纸条上，所以很容易破解。

进入互联网时代，有了更好的分发方式：App Store、apt、RPM、Python 的 Package Index、NPM、HuggingFace、Ollama，都是内容分发生态。操作系统由此逐层构建：最下面是内核 API，上面有库函数、shell、核心工具集和整个应用生态。

例如树莓派上的 Debian，它的使命是 Our mission is creating a free operating system。这里 free 强调自由，When we use the word free，We are not talking about money；费用与这个概念无关，它强调 software freedom。所有软件都可见，每行源代码都能查看、理解。

还可以为它贡献代码。我觉得 CS、Computer Science 发展得好，很大程度上因为 Linus 这样的人愿意分享：有了好东西，就迫不及待地交给别人。别人看过这些分享，做出好东西后，也自然愿意继续分享。1998 年 apt 被发明时，想装 Firefox，执行 apt\-get install firefox 就行。

苹果 App Store 到 2000 几年才出现，apt 在 1998 年已经有跨时代的 advanced packaging tool，以及整套开源供应链管理流程。软件包从 unstable、不稳定的状态，像 GitHub 上每天提交的代码那样，逐渐合入 testing 分支。
