需要强调，shell 加载以后，看起来调用的是命令行工具，背后执行的全是系统调用。

![图 93：用 ln \-s 创建命令入口的脚本（01:11:17）。](/assets/images/12/0093.webp)

图 93：用 ln \-s 创建命令入口的脚本（01:11:17）。

执行第 23 行的 busybox ln 时，当前 shell 会先 fork，再 execv 运行 BusyBox。busybox 的 ln 解析 ln \-s 参数后，执行创建符号链接的系统调用，在文件系统中创建链接。mkdir 命令背后同样有 mkdir 系统调用。

mkdir 在初始的内存文件系统中创建目录。mount 也会创建很多操作系统对象，例如 mount \-t proc none /proc，就把 procfs 中的对象都创建在 /proc 目录下。

![图 94：mkdir 与 mount 创建 procfs、sysfs 对象（01:11:58）。](/assets/images/12/0094.webp)

图 94：mkdir 与 mount 创建 procfs、sysfs 对象（01:11:58）。

这个命令调用 mount 系统调用，在操作系统中创建许多对象。每个命令都有对应的系统调用，mknod 也一样。例如创建一个叫 /dev/vda 的磁盘设备。

![图 95：mknod 创建设备的主、次设备号（01:12:22）。](/assets/images/12/0095.webp)

图 95：mknod 创建设备的主、次设备号（01:12:22）。

驱动与设备创建片段：

```
insmod modules/virtio.ko
insmod modules/virtio_ring.ko
insmod modules/virtio_blk.ko
insmod modules/virtio_pci_legacy_dev.ko
insmod modules/virtio_pci_modern_dev.ko
insmod modules/virtio_pci.ko
insmod modules/jbd2.ko
insmod modules/mbcache.ko
insmod modules/crc16.ko
insmod modules/crc32c_generic.ko
insmod modules/ext4.ko

mknod /dev/random  c 1 8
mknod /dev/urandom c 1 9
mknod /dev/null    c 1 3
mknod /dev/tty     c 4 1
mknod /dev/vda     b 254 0
```

vda 是 virtio、QEMU 的虚拟磁盘，在阿里云租服务器也能看到 /dev/vda。创建设备文件需要指定主设备号和从设备号。/dev 下的文件都以这种方式创建：random 的主设备号是 1、从设备号是 8，urandom 是 1、9，null 是 1、3，tty 是 4、1。列出文件时也能直接看到它们是设备。

这里有字符设备，也有块设备，已经能正常工作。看操作系统日志，此时 shell 的功能已比较完善。
