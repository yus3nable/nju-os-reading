用 Tree 打印这个目录，大家从未在自己的 Linux 上见过这样的文件系统，却很确信它属于系统：系统可能就这一个文件，Linux 内核启动日志也确实指向它，叫 initramfs。它必须存在，却从没见过，到哪里去了？看起来 systemd 是整个进程树的根、是一号进程，但启动时还有前面的过程。

![图 76：解包后目录树的顶层（01:03:22）。](/assets/images/12/0076.webp)

图 76：解包后目录树的顶层（01:03:22）。

Linux 启动加载时，在 initramfs 阶段还能弹出命令行 shell，供人交互、重新配置。例如 /etc/fstab 指定的启动盘找不到，可以在这里选择另一块盘。等事情都完成，会执行 pivot\_root 这个 syscall。man 2 中写着 change the root mount。不必严格掌握行为，只要知道它切换了系统的根，之后形成以 systemd 为根的进程树。这个程序也可以指定，取决于新系统根里的配置。

![图 77：switch\_root 背后的 pivot\_root（01:04:34）。](/assets/images/12/0077.webp)

图 77：switch\_root 背后的 pivot\_root（01:04:34）。

系统调用声明：

```
int pivot_root(const char *new_root, const char *put_old);
```
