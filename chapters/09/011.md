libc 还封装了很多进程管理功能，包括之前用过的 abort、exit、atexit。atexit 可以注册 exit handler，让程序正常退出时再调用自己的函数。

例如，C 程序可能创建临时文件。大家做 online judge 题目比较多，习惯只分配资源，不管回收，因为提交以后 online judge 会负责回收一切。实际系统中，在哪里创建临时文件，用完最好都删掉，包括 temp 目录中的文件。如果工具每次都创建很大的临时文件，又被反复调用，迟早会占满存储空间。/tmp 空间有限，占满以后，管理员执行其他任务就没有空间，回头会发现这些不必要的临时文件。atexit 能在正常退出时帮忙清理；异常退出偶尔留下一两个，管理员可能容忍，或者删除足够老的文件。还有一种退出方法 abort，它给自己发送 SIGABRT。

这也是信号，类似上次讲的 SIGINT：按 Ctrl\+C 时，终端给前台进程组的每个进程发送 SIGINT。abort 会触发 core dump。assert fail 时会调用 abort，assert 中止时不会调用 exit(1) 来报告错误。观察 assert fail 时的 exit status，返回值也是一百多，在补码意义上是负数，表示收到了 SIGABRT。配置 core dump 的 size 后，就会生成核心转储文件，把进程内存 dump 下来，之后仍可用调试器调试。core dump 这个词来自早期的 core memory，也就是磁心内存。我应该提过，可以用磁铁的方向表示 0 或 1。

把 core memory 的状态转储到另一个永久存储器，就叫 core dump。现在这个词指把进程内存保存到文件的过程。libc 也提供了有限的、与其他进程协同的功能，例如 system。大家用得最多、也最好用的可能就是它。例如程序要清屏，可以使用正确的 ANSI escape code。

现在可以让 AI 在 cursor 中直接完成，这时 cursor 仍然有用：光标停在哪里，就让它在该位置做所需操作。手边没有 AI 时，可以直接 system("clear")。用 sprintf 生成命令字符串再执行，也很方便。system 背后会启动 Shell，在 Shell 中执行命令，开销相对较大，但确实好用。还有 popen、pclose，它们的手册属于 Library Function Manual，标注为 standard C Library，也就是 libc。

popen 返回 FILE \*。它与 pclose 的缺点是管道单向，只能选择写或读；Python 的 subprocess\.Popen 则可以让两个程序互相读写。pipe 返回两个文件描述符，C 的 FILE \* 中只有一个。要是让这个 API 返回两个 FILE \*，接口就会很难看，最终 API 设计者作了妥协。

我觉得这种妥协比较糟糕，带有历史包袱。单向管道大部分时候仍然有用：调用其他程序并获取结果时，它比 system 好用，因为 system 无法控制输出。
