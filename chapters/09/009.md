还有一组特殊的函数，今天着重讲讲。还记得刚开始上课的 SimpleC 模拟器吗？我们说 C 程序执行时有状态，并以非递归 tower of Hanoi 为例。我相信看过代码示例后，在座同学都能写一个非递归的 tower of Hanoi。SimpleC 的计算模型里有 stack frame，也就是一个个栈帧。最底下是 main 的调用，之后可以任意调用 f1、f2 等函数。每个栈帧都有自己的 pc，记录当前执行位置。函数调用是在上面放一个新栈帧，函数返回则把 top frame pop 出来。

![图 50：main、f1、f2 的调用栈（00:49:25）。](/assets/images/09/0050.webp)

图 50：main、f1、f2 的调用栈（00:49:25）。

每次都从 top frame 的 pc 取一条语句执行，进入下一个状态。setjmp 和 longjmp 做了一个特殊的 hack，稍微改变这个语义。setjmp 接收一个 buffer，可以把它设为全局变量；例如全局变量 xx，执行时可以通过指针访问这些变量。执行 setjmp 时，会在 buffer 中记住当前栈的高度，例如 h 等于 3，同时记住 pc。随后 setjmp 正常返回，程序可以继续执行任意代码。

栈深度已经记录下来了，在这个模型中只要记住 3 即可。计算模型上可以做到，但只用纯 C 做不到，因为纯 C 无法知道下面有多少层函数调用。实际实现可以做到；概念上保存栈高度，实现时大概只需一个指向对应栈帧位置的指针。

![图 51：setjmp 保存栈深度和执行位置（00:50:49）。](/assets/images/09/0051.webp)

图 51：setjmp 保存栈深度和执行位置（00:50:49）。

之后程序可以任意执行，调用 100 个、10000 个函数。有一天执行 longjmp，并传入这个 buff，就会把上方几百、几千层栈帧全部弹掉，像一个大号 goto。C 的 goto 可以在函数内跳转，即使处于循环或分支中，也可以 goto 到外面。

![图 52：setjmp 保存的栈深度和 PC（00:51:20）。](/assets/images/09/0052.webp)

图 52：setjmp 保存的栈深度和 PC（00:51:20）。

这是 C 中经典的用法：一个很大的函数中有分支和循环，各处都可能申请内存、资源。如果在 for 循环中直接 return，可能忘记释放资源。C 和 C\+\+ 很容易出现这种错误。C 中有一种 idiomatic 写法：在循环中需要退出时，goto out 或 goto release，在 release 处检查所有可能申请资源的地方，逐个释放。它可能增加一些不必要的检查，效率未必最高，但比较安全。longjmp 就像大号 goto，setjmp 则把相当于 label 的位置写进 buffer，其中包括当前栈深度。

setjmp 之后，即使调用栈变得很深，执行 longjmp 也会回到记下的栈位置和 PC。这组函数很有用，有一个实验会让大家用它实现协程。我准备了代码示例。它无需任何系统调用，只需编译器配合生成正确的指令序列就能完成。

setjmp\.c 中的 second 函数

```
jmp_buf buf;

void second(int x) {
    printf("In second(), x = %d\n", x);
    longjmp(buf, x);
}
```

演示程序先执行 setjmp；如果 return value 等于 0，就继续调用 first，再由 first 调用 second，函数调用逐层积累。在 second 中执行 longjmp，就会跳回 main 中刚才 setjmp 的位置。调试时可以看到，先 setjmp，再 first、second，最后返回。第一次 setjmp 如期返回 0，程序就像什么都没做过一样继续执行，打印 setjmp returns 0。
