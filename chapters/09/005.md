这就是完整的 C：指针、数组、结构体、函数调用等基本语言成分，可以归入 SimpleC；再加上 Foreign Function Interface，就能实现世界上的所有东西。能够进行系统调用，就能实现应用世界里看到的所有功能，由此逐步构建出整个应用生态。

这与计算机系统的发展历史也相似。1950 年代只有汇编语言，大家被迫用汇编或戳孔的方式写代码。到了 1970 年代，用汇编编程就成了行为艺术：只有少量与机器相关的代码需要汇编，绝大部分代码都没必要这样写，C、Pascal 已开始普及。大家可能听说过结构化程序设计。我觉得它在今天的 AI 时代又复活了：设计软件时先分为几个比较抽象的部分，再逐步 refine，这适用于 vibe coding。1970 年的时候有了 UNIX 和 C，C 成为重要的生态入口，用 C 写的代码可以在 UNIX 上运行。到了 2010 年，C 又成了古法编程，主要由学 computer science 的人学习。

就像学汽修的人需要了解汽车构造，开车的人未必知道。2010 年的 C 仍然很好用，经久不衰，但它之上已经发展出了其他语言：C 上有 C\+\+，C\+\+ 上有 Java、Javascript，C 上又有 Python。更多程序员不再需要用那么底层的方式编程。到了今天，用高级语言编程也被调侃为行为艺术，每天都在做古法手工编程，像一项非遗技能。今天绝大部分时候，我们用自然语言编程；支撑这种能力的，是 C 逐步构建出的世界。刚才讲的 Assembly、Foreign Function Interface 和 SimpleC 模型，虽然很小，却已经有标准。ISO C 标准规定了 SimpleC 以及更复杂的 C 的语法和语义。在它上面还有 libc、POSIX，也就是 Portable System Interface。这些构成了基础，之上又有 Python、JavaScript、Java，以及 Java 上的 Android 等生态。C 世界有 ISO 标准，这意味着什么？

有了标准，大家就会努力遵守，在共同的体系下交流。标准的制定也以此为目的。稳定可靠的标准让人不用担心版本升级破坏实现。用 JavaScript、Python 开发时，今天很方便，明天 dependency 可能就 break 了；迁移到新的 dependency，程序可能无法运行，还得让 AI 修，修成什么样自己也不清楚，软件处于能用却又失控的状态。C 位于传统抽象体系的底部，具有最好的移植性。只用 C 中最小的那些部分，可以写一份 breadth\-first search 算法，甚至写一个图形界面库：从数据结构出发渲染界面，可能是像素级渲染，最终需要某种后端。这部分如果用 C 写，就具有最好的移植性。

从电脑、超级计算机到手表、手环，再到只有 1KB 内存的小设备，都可以运行。前提是遵循 ISO C，以 portable 的方式写程序。例如，不能假设 int 一定有几个字节：小型机器上的 int 可能是两个字节，也就是 16 个 bit；今天常见的 32 或 64 位机器上则是四个字节、32bit。C 标准为了移植性规定了很多内容。

C 之上还有 POSIX。unistd\.h 中的 Fork、pipe 等函数及其行为，都由 POSIX 标准规定。几乎所有能用的操作系统，从 Linux、我的 Mac，到鸿蒙、OpenHarmony，基本都兼容。可能有同学用华为手机，我觉得它的生态还差一些。首先，这些系统必须有 C 编译器，才能编译别人写的东西，让代码几乎无需修改就能完整运行。再提供 POSIX 层，实现 pipe、execve 等函数，就能运行服务类应用，以及 coreutils 中的核心命令行工具。课上讲过 Busybox 这个小工具集；Android、鸿蒙系统，包括 Harmony OS 上还有 Toybox，它也是小型命令行工具集，基于 C 和 POSIX 接口实现。基本上，世界上任何还有一定复杂性的设备，都能找到 C 的身影，即便可能没有直接用 C 编译。
