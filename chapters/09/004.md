课件中的内联汇编片段

```
int a = 7, b = 5, result;
__asm__ ("leal (%1,%1,4), %0" // result = a*5
    : "=r" (result) // output operand
    : "r" (a)); // input operand
printf("%d * %d = %d\n", a, b, result);
```

最早的操作系统课会让大家写一点 Inline Assembly，体验很痛苦。我准备了它的手册，篇幅很长，语法也有很多奇怪之处。Inline Assembly 是一个 DSL，也就是 Domain Specific Language，为什么要这样设计？

最早设计时，编译器设计者希望省事：在 C 中直接嵌一段汇编是自然的需求，但还要兼容 C 语法，因为不想大改 C 的 Parser。

![图 15：GCC 手册中的操作数示例与 clobber 列表（00:14:56）。](/assets/images/09/0015.webp)

图 15：GCC 手册中的操作数示例与 clobber 列表（00:14:56）。

他们希望这段代码看起来像合法的 C 程序，而不直接把汇编指令嵌进来。汇编指令写在字符串里，按合法字符串解析，括号也必须配对，同时可以引用 Lexical Scope 中的变量。Inline Assembly 要让自己写的指令序列与 Lexical Scope 中的内容交互。例如，在 C 中定义 int x 和 int y，希望某条指令引用 X，另一条指令把结果写到 Y，最后 Return Y。为了做到这一点，这个设计付出了很大代价。

指令序列是一个字符串，要在其中引用外部内容，就会想到 C 的 printf 和 format string：用百分号 D 打印 integer，用百分号 S 打印 string。

![图 16：内联汇编与局部变量 x、y 的交互（00:16:26）。](/assets/images/09/0016.webp)

图 16：内联汇编与局部变量 x、y 的交互（00:16:26）。

内联汇编也用百分号 0、百分号 1、百分号 2 代表外面的操作数，再在后面描述它们。我觉得这套语法设计得很随意。例如，要把 assembly 中的结果写回 C 的世界，就用等于 R；R 表示放进一个 register，具体方式可以由编译器决定，再将结果写入 result。读取的输入，比如 A，也用百分号引用。这里先说百分号 0 是第一个，又要区分百分号 1 是第二个，读起来很费力。还有很多隐藏细节：如果一个变量既读又写，先读 x 到某个寄存器，之后再把值写回 x，该怎样描述？需要写两份吗？正确写法是把等号换成加号。我觉得它像是每增加一个功能，就在语法上添一笔。

更麻烦的是，编译器会生成优化后的指令序列，基本上可以使用手里的所有寄存器。由于所有代码都由编译器负责，它有时不必将寄存器恢复成原来的值。这意味着汇编代码不能随意使用寄存器，但有时又必须使用特定寄存器。例如 Syscall，调用系统调用时就有要求。看这台 ARM64 的手册，系统调用参数放在 X0 X1 X2 到 X5 寄存器中。做一次 System Call，必须向 X0 到 X5 写入值。当然，可以在 Inline Assembly 中先用汇编把这些寄存器的值保存到内存，等 Inline Assembly 调完再恢复。

![图 17：syscall 手册列出的系统调用参数寄存器（00:18:41）。](/assets/images/09/0017.webp)

图 17：syscall 手册列出的系统调用参数寄存器（00:18:41）。

但这样又违背了编译优化的初衷。这段 Assembly 理论上应该与编译优化协同：可以要求某个操作数放在寄存器中，具体寄存器由编译器决定；也可以声明代码会破坏 X0、X1、X2……X5，让编译器在这段代码附近避开这些寄存器。各种需求使它变成复杂的 Domain Specific Language。手册中有很多例子，可以看到加 R 的写法。

![图 18：GCC 手册里的 \+r 读写约束示例（00:19:32）。](/assets/images/09/0018.webp)

图 18：GCC 手册里的 \+r 读写约束示例（00:19:32）。

这种代码很难写对。字符串会交给汇编器，编译器完全不负责其中指令序列的行为，也不知道它属于什么指令集体系结构、指令是什么意思；它甚至可能是自己定义的指令，只要汇编器认识就行。编译器不解析其中语义，于是必须手动声明副作用。如果明明改了 X5，却漏报这个副作用，就可能出问题。当前编译器碰巧没使用 X5，生成的汇编代码就是对的，怎么测试都正常。下一次编译器升级，更积极地内联或执行其他优化后，可能用到了 X5；汇编将它改写，后面的代码又继续使用它，程序就会出现奇怪的问题。这样的问题，［听辨不清，00:20:47］，Linux kernel 中也有。

大概在 2019 年，我们研究过 Inline Assembly，结果做慢了，被别人抢先。看到对方论文摘要里写着 We are the first to blah blah blah，我的心就在流血，因为我们还没做完。当然，那个同学最后还是顺利博士毕业了。我们当时发现了很多 Inline Assembly misuse，想写一篇叫 Inline Assembly Demystified 的文章。

现在操作系统课已经不用再讲这些细节了。大家需要知道 Foreign Function Interface 这个重要机制：C 或其他编程语言可以通过它调用另一种语言。C 中可以嵌入汇编代码，读取上下文中的变量，也可以写回变量。这段汇编整体交给汇编器处理，经过可能的预编译或预处理，例如 %0、%1 替换成实际寄存器名字后，字符串会逐字符原样交给汇编器。有了这个正确概念，繁琐细节就没那么重要了。只要有足够的示例，AI 就能学会；让 AI 做强化学习、Self Play，它也能学。学会以后，告诉它想做什么即可。例如，Inline Assembly 在追求极致优化时有用。矩阵乘法或两个向量的点积该怎么写？在 Online Judge 做题，通常是 For I 等于 0 到 N，Sum 等于 Sum 加上 a\[i\] 乘以 b\[i\]。优化编译器会把这段代码优化得比较好，但并非所有代码都能如此。可以与 AI 对话，让它在适当的时候针对当前机器优化。

如果机器恰好支持某个指令集，可以让 AI 帮忙写出优化后的代码。大家需要知道这件事可以做。
