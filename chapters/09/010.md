除了 freestanding 环境中可用的指令集和计算封装，libc 还有一个重要功能：封装文件描述符。struct FILE 包含一个文件描述符。C 的 standard io api 与 unix 文件操作 api 几乎一一对应。

![图 62：标准 I/O 与文件描述符的封装（00:56:04）。](/assets/images/09/0062.webp)

图 62：标准 I/O 与文件描述符的封装（00:56:04）。

fopen 打开后返回 FILE \*，对应 struct FILE；open 则返回文件描述符。C 中的 fseek、ftell、feof 等操作都对应文件描述符，只要持有描述符，就能执行 lseek 等操作，lseek 也可以实现 ftell。standard io 就是对文件描述符的封装。musl libc 的 struct FILE 实现比 glibc 简洁，大家自己也能理解。里面重要的成员有 fd、pipefd，包含文件描述符；还有一个 pid，都与操作系统相关。

![图 63：musl 的 \_IO\_FILE：缓冲区、函数指针和 fd（00:56:54）。](/assets/images/09/0063.webp)

图 63：musl 的 \_IO\_FILE：缓冲区、函数指针和 fd（00:56:54）。

通过这些整数，就可以访问操作系统中的对象。除此之外，绝大多数成员用于其他功能，例如 stdio 可以带 buffer，结构中有指向 buffer 的指针。它也用 C 实现了面向对象：read、write、seek 等函数指针，就像刚才说的，在自己的项目中定义 struct element，需要支持 comparison 时，也会采用这种面向对象的方式。通过 read、write、seek、close，一个 \_IO\_FILE 可以对应多个不同的后端实现：可以是操作系统中的文件，也可以只是一个 buffer。例如 sprintf 向 buffer 打印，可以为字符串 buffer 实现对应的 struct FILE，只需实现 close、read、write、seek。

vfprintf 的实现与自己设想的 printf 类似：实现一个小 parser，接收 format string，再从左到右遍历其中的百分号 d、百分号 s 等。

![图 67：vfprintf 处理可变参数并调用 printf\_core（00:59:02）。](/assets/images/09/0067.webp)

图 67：vfprintf 处理可变参数并调用 printf\_core（00:59:02）。

parser 解析要打印的内容，再交给对应的处理函数，向 FILE 写入。printf 会逐级调用，最终相当于对 stdout 使用 fprintf。它使用 stdarg\.h 的 va\_list，将参数列表表示为一个对象。这个参数列表是一段内存，可以从第一个参数依次向后访问。printf 调用时取出参数列表对象，再逐级传递。处理过程就是一个循环，parser 不断向后解析。调试它，可以学到很多 C 的写法。虽然现在学习怎么写 C 可能已没那么必要，仍然能看到一些设计。printf family 中的 printf、sprintf、fprintf 没有 code clone，实际负责打印的代码只有一份，在 printf\_core 中。通过这种代码复用，项目维护会容易很多。
