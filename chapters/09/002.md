我们花了好多次课讲操作系统，从最早只有一个名叫 \_start 的函数、连退出都做不到的最小程序开始。在 \_start 里写一个死循环，它就可以无限运行。用 ld、as 这套工具链把它变成 a\.out，它就能在操作系统上执行。汇编代码可以使用系统调用相关的指令，访问操作系统及其中的对象。

我们讲过 fork、execve、exit 等 system calls：复制进程状态，reset 进程状态并选择一个可执行文件执行，或者用 exit 将整个进程状态从世界上消灭掉。无论用 C 还是汇编，进程都有指针和内存地址的概念。通过 mmap、munmap、mprotect，可以改变进程的地址空间；向操作系统申请后，原本无法访问的一些内存就可以访问了。unix 还提供了访问操作系统中各种对象的能力。例如，我的 fish 进程号是 6587，查看 proc 下 6587 下的 maps，就能看到它的地址空间。

在终端里也可以上网。要实现浏览器，需要通过类似 Open 的系统调用打开与网络远端的连接。AI 会告诉你，得到远端连接需要 Socket。有了连接，就能获取 HTML 网页，再解析和渲染。大部分工作都是普通计算，类似解析表达式或程序：写一个 HTML 解释器，在必要时向终端输出。

理论上，已经可以用这些系统调用实现任何东西。不过，整个应用软件生态并非完全直接构建在这些底层 API 上。写 Python 时，大家会喜欢用 pathlib，也会用 C\+\+。今天要讲的，就是怎样从 C 和 Unix 这组很小的 System Call 接口出发，逐步构建出开发者满意、便于开发的生态。第一个入口就是 libc。对于底层的汇编程序来说，它一方面可以执行指令，另一方面可以使用系统调用，但这两种方式都很难用。打印一个字符串，需要用 Write 逐个字符或逐个 Buffer 输出；所有代码都手写会很麻烦，需要复用机制。libc 就是第一个这样的机制。C 和 libc 之上后来发展出了完整的应用生态，包括 C\+\+、Python；Python 又发展出了今天的人工智能世界，而人工智能的一部分基于 CUDA C。
