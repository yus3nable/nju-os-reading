课件中的 sloppy counter，sum、lk 与 MAX\_TID 在其他位置定义：

```
int sum_local[MAX_TID];
void T_sum(int tid) {
  if (++sum_local[tid] == 100) {
    mutex_lock(&lk);
    sum += sum_local[tid];  // "Sloppy" counter
    mutex_unlock(&lk);
    sum_local[tid] = 0;
  }
}
```

load 到 sum 为 101 后，执行下一条指令时，它可能已经变了，看到的总是旧值，除非一直持锁执行 sum 等于 sum \+ 1。如果只是显示点赞数，允许略有出入、稍晚更新，就可以在线程本地 sum \+ 1，隔一段时间再合并。

这样大部分计算又留在本地，只有少量需要锁，这就是 sloppy、比较松散的 counter。现在看到的点赞通常也是松散计数，要延迟一会儿才精确。这个实现仍 overly simplified：可以每次 sum\+\+ 就更新，也可以达到阈值后更新，或每过一毫秒、timeout 一毫秒就更新。

一毫秒内即使没达到阈值，也把本地 sum 合回去，就能保证每次读取的计数都在一毫秒之内，仍然可用。牺牲及时可见性、强 serializability，可以实现更高效的并发数据结构。尽可能多地本地计算，是并发数据结构和 malloc 优化的重要方法。
