从 sloppy 的 sum\+\+、thread\_local 回到并行数据结构。数据结构维护状态，可以是线性表、数组、二叉树、图，都是 abstract data type。

![图 62：数据结构的局部性与几种锁的划分方法（01:16:21）。](/assets/images/18/0062.webp)

图 62：数据结构的局部性与几种锁的划分方法（01:16:21）。

abstract data type、ADT 提供接口，例如往队列或 list 中 push、pop。在高效接口的抽象基础上，可以构建各种应用。数据结构的信息分散存储在内存中，无论大数组还是二叉树。例如 set 中有一二五七，可以用平衡二叉树、红黑树维护 sorted set、ordered set；tree 有根和孩子，graph 也类似。结构越长越大，仍有局部性。

树上通常关心节点及邻近节点的性质，也可能问整棵树大小；集合关心元素是否存在，例如 5、8 在不在。set 还可以实现 map、dictionary，为 key 找到对应 value。这些数据结构天然具有局部性。

两个线程访问数据结构，可以用一把大锁，让大家排队；但访问不同元素可能没有冲突。删 7 与查询 7 需要锁保护；查询 5 与查询 7，或删 2 与读 7，可以并行执行。

这意味着，读写局部未必需要锁住整个结构。sloppy counter 也利用这个性质：把 sum 想象成 list，每次 \+1，也就是 sum\+\+，相当于 append 一个节点，查询 sum 就取 list 的 size。本地可以先积累一个 list。

每次先向本地 list 添加，达到 100 后再锁全局 list，一次把 100 个节点拼过去。这就是 sum 与一般数据结构的关系。

由此可以做锁的拆分，为不同部分分别加锁，让绝大多数操作并行，只有少数确实访问同一元素时才争抢同一把锁。
