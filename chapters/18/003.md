第二题都是细碎问题，无需直接写出命令。写不出也不要紧，例如说明 procfs 提供什么信息、怎样从中获取，就可以。

![图 6：静态与动态链接的检查方法（00:05:27）。](/assets/images/18/0006.webp)

图 6：静态与动态链接的检查方法（00:05:27）。

给出二进制，判断运行时是否需要加载 SO，可以看 ELF 文件，也可以在 GDB 中看。ELF 的 interpreter section 记录了路径，能据此判断是否动态链接；还可以用 ldd 等命令行工具。下一问是谁修改了 environment。

![图 7：用 watchpoint 观察 environ 的修改（00:05:59）。](/assets/images/18/0007.webp)

图 7：用 watchpoint 观察 environ 的修改（00:05:59）。

课件上的 GDB 观察命令：

```
watch environ
continue
bt
```

想知道哪条指令改了变量，就用 watchpoint。AI 对工具选择的直觉出乎我意料，只要提出需求，它就知道该做什么。答题时只需说明 GDB 能在某地址被修改时暂停，就能定位修改者。环境变量存在哪里、与栈有什么关系，也不需要背具体细节。

![图 8：环境变量与进程初始栈（00:06:32）。](/assets/images/18/0008.webp)

图 8：环境变量与进程初始栈（00:06:32）。

先 print your environment，拿到地址，再看地址 mapping，确定它位于地址空间哪里，就能回答。掌握概念，即使没记细节也可以答对。

![图 9：定位 mmap 的 syscall 指令（00:06:51）。](/assets/images/18/0009.webp)

图 9：定位 mmap 的 syscall 指令（00:06:51）。

课件上的两种定位方式：

```
mov $9, %eax    ; syscall number
syscall

catch syscall mmap
```

定位 mmap 的 system call 指令，可以 trace 全部指令，也可以单步并写 hook，每次停下时检查。这个方法也适用于下一问。

![图 10：从 \_start 到 main 的指令记录（00:07:05）。](/assets/images/18/0010.webp)

图 10：从 \_start 到 main 的指令记录（00:07:05）。

课件上的 GDB 指令记录流程：

```
starti
record full
tb main
c
info record
```

从 \_start 到 main 都能这样处理。AI 还知道 gdb 的 reverse execution 机制，它需要记录每条指令，恰好可以借此统计指令数。它反问：动态链接每次附加几万条指令，ld\-linux 的动态加载代价值不值？当然值得，上课说过，整个系统中只有一份 libc 代码拷贝。

为此花一点时间很值得。
