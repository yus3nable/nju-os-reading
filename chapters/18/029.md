至少可以先做锁的划分。例如 Hashtable 是高效的 key value 数据结构。元素 X 到来，先算 Hash function 找到格子，若为空，就放入 X。

Y 到来时也算 HY，再放入。这样能以接近 O(1) 的时间维护集合或序列。Hashtable 是数组，很容易划分锁：每格一把，或几个格子一把，例如 Lock1、Lock2。

![图 65：为哈希表的不同桶或区段分别加锁（01:23:59）。](/assets/images/18/0065.webp)

图 65：为哈希表的不同桶或区段分别加锁（01:23:59）。

若某段归 Lock3，访问 X 或该段元素时，只需持有 Lock3。hash 冲突后，若用链表、二叉树连接元素，就锁住这个局部结构，比较简单。但 open addressing 更麻烦：Z 的 h(z) 等于 h(x)，就要用 linear probing、quadratic probing 等找下一个位置放 Z。W 若也有 h(z) 等于 h(w)，同样放进后面的位置。开放寻址会给并发结构带来很多问题，例如删除 Z 时不能直接抹掉。

X、Z、W 由同一个 hash function 得到相同位置，找 W 时先遇到 X、再遇到 Z、最后才找到 W。抹掉 Z，查找就提前结束，明明 W 还在表里，却找不到。因此删除要用 tombstone，这在数据结构中很常见。更难的是 resize。

可能有人正遍历表，resize 却需要新分配一块例如 1\.5 倍大的 hash table，把元素迁移后删除旧结构。当然可以先上全部锁，慢慢迁移，但效率很低；扩容时整个数据结构都不可用，可能持续到秒级。

实际设计会细粒度加锁、逐步迁移。这很容易像 malloc 一样上错锁。下节课再讲 malloc，请保持对这个库函数的敬畏。
