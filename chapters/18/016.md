代码例子要画 6400 乘以 6400 的 Mandelbrot set，画面挺大。每个像素 XY 都执行一个［听辨不清，00:49:23］，先不管具体含义，只当作一个程序。

mandelbrot\.c 中的迭代函数，W、H 为画面尺寸：

```
static inline double mandelbrot(double x, double y) {
  int n = 0;
  double a = 0, b = 0, c, d;
  while ((c = a * a) + (d = b * b) < 4 && n++ < 880) {
    b = 2 * a * b + y * 1024 / H * 8e-9 - 0.645411;
    a = c - d + x * 1024 / W * 8e-9 + 0.356888;
  }
  return n;
}
```

每个 T\_worker 遍历整个图像，遇到分配给自己的像素，就求解并画上：pic\[x\]\[y\] 等于 mandelbrot(x， y)。

![图 42：T\_worker 计算本线程负责的像素（00:49:37）。](/assets/images/18/0042.webp)

图 42：T\_worker 计算本线程负责的像素（00:49:37）。

T\_worker 片段，像素数组、任务划分函数与原子计数器在其他位置定义：

```
void T_worker(int tid) {
  // Every pixel can be computed in parallel.
  for (int x = 0; x < W; x++) {
    for (int y = 0; y < H; y++) {
      if (worker_for(x, y) == tid - 1) {
        pic[x][y] = mandelbrot(x, y);
      }
    }
  }
  atomic_fetch_add(&done, 1);
}
```

还有 Monitor 线程实时追踪渲染进度。按课程线程库的用法，可以写 for (int i = 0; i &lt; nthread; i\+\+)。

main 中的 OpenMP 并行区域，其余初始化与监控线程省略：

```
#pragma omp parallel num_threads(nthread)
#pragma omp for schedule(static)
for (int i = 0; i < nthread; i++) {
  T_worker(i + 1);
}
```

循环中 spawn(T\_worker)，创建 nthread 个 T\_worker 即可。74 行到 77 行定义的也是计算图：若干 worker 完成后 join。另一种表达是 parallel、nthread 个线程，将顺序的 for (int i = 0; i &lt; nthread; i\+\+) 并行化。写代码时不必知道系统有多少 CPU，甚至无需了解并发编程，只需加这些声明。makefile 加上 \-fopenmp 即可。先看 Mandelbrot 一，从左到右逐渐渲染；这幅图取自局部放大区域，与刚才的例子很像。

学过 C、会写数值计算程序的物理系学生，即使没接触线程、没上操作系统课，也只需记住师兄或文档教的一句话，就能用上超算的 128 个线程，快 128 倍。实际 OpenMPI、MPI 还有更丰富的编程机制，包括同步、共享等。也可以把这个知识用在 prompt 中：让 AI 并行化 C 程序时，我认为它默认会倾向 Pthread，因为不会假设已经安装 OpenMP。只说利用多个 CPU，它大概就给出 Pthread 实现。

prompt 中增加“可以用 OpenMP”，就可能少改代码，让它保持干净整洁。Pthread 可能增加同步等代码，使人看不懂；OpenMP 可以把 dirty work 交给编译器。
