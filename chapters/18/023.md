所以你确实看到 thread\_local 它是在起作用的，非常好，那它是怎么实现的呢？怎么实现的？首先，编译器是知道每一个变量定义，到底定义成什么样的，对吧，包括你可以定义什么 const，volatile，这些编译器都知道每一个变量它的 modifier 是什么。然后我们的编译器，如果看到一个这样的 int x，全局的 int x，那对这个 x 的访问，它就是通过 IP 相对的，PC 相对的访问。然后如果是看到这里栈上的一个对吧。栈帧里面的一个变量 Y。那它就会用 RSP 相对的访问。

课件对三类变量的访问写法：

```
int x;  // x(%rip)

void foo() {
  int y;  // y(%rsp)
}

thread_local int z;  // z(%fs)
```

那么如果是一个 thread\_local，也是的，thread\_local 就是说我要相对于线程，对吧，我是相对于全局，这是相对于全局的数据区的一个 offset，这是相对于当前栈帧变量的一个 offset，那我这里就是应该是相对于这个线程的局部存储的一个 offset，但寄存器不够用了，在 x86 里面，他们就偷用了 FS 的寄存器。所以如果你们在你们的机器上面编译我的这个演示代码的话，并且你用 objdump去看的话，你会看到它会把这个访问翻译成一个 FS 的相对于。
