先看一种特殊情况：单处理器、操作系统内核代码要实现 make\_it\_work，方法很简单，关闭中断即可。无论是 sum\+\+，还是给数组写入 123 一直到 100 等许多内容，只有一个 CPU 时，关中断就意味着独占 CPU。

前面的状态机模型省略了一点：系统从 CPU restart 开始执行 firmware 和后续指令，每条指令执行时，只要中断打开，就还可能响应中断。因此计算机系统并不确定，中断是内核并发的来源。关闭中断，就去掉了这种可能性。再假设指令集体系结构 deterministic，即确定性的。

执行 x 等于 1、y 等于 1，PC 依次取指，执行过程就完全确定。内核关闭中断，也就实现了 make\_it\_work，系统其他部分无法打扰。当然，如果关中断后进入 while (1)，整个计算机系统也就卡死了，这也是需要 reset 的原因。

软件工程尚不成熟、大家还不懂怎样构造可靠操作系统时，windows 蓝屏很常见，bug 可能导致卡死或蓝屏，需要 CPU reset。我也让 AI 写了关中断再死循环的代码，需要少量汇编。所有演示代码都做了条件编译，能在大家的 x86 或我的机器上运行。我的机器会用 msr 写系统寄存器。

![图 5：cli\.c：在用户态尝试执行关闭中断指令（00:08:33）。](/assets/images/14/0005.webp)

图 5：cli\.c：在用户态尝试执行关闭中断指令（00:08:33）。

```
#include <stdio.h>
int main() {
    printf("Trying to disable interrupts in user space\n");
#if defined(__x86_64__) || defined(__i386__)
    asm volatile("cli");
#elif defined(__aarch64__)
    asm volatile("msr daifset, #2");
#else
    #error "Unsupported architecture"
#endif
    printf("This should not be reached\n");
}
```

寄存器中的中断位会被清掉。x86 对应 clear interrupt。学过 x86 版计算机系统［听辨不清，00:09:00］，就知道有 overflow、zero 等 flag，flags 记录上一条指令是否为零、是否溢出。其中 interrupt flag、中断位，可以由操作系统内核控制。

清掉这个位，处理器就不再响应中断。但运行用户程序，预期系统不会卡死。我的机器收到 SIGILL，即 illegal instruction。平时可能很少见，把二进制文件胡乱改写，也可能因为指令无法解码，遇到 illegal instruction。

![图 6：ARM 用户态执行后收到 SIGILL（00:09:46）。](/assets/images/14/0006.webp)

图 6：ARM 用户态执行后收到 SIGILL（00:09:46）。

arm 用户程序无权执行这条 msr，处理器会把它当作不合法、不存在的指令。x86 的设计不同，会产生 protection error，用户程序收到 segmentation fault，大家可以在 x86 电脑上尝试。这就是内核要实现的权限限制。
