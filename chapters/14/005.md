我现在我这 T\_sum 稍微还麻烦一点，如果我有个 n，我要做 n 次 sum\+\+，我会把中间的实际上要执行的东西，包在 lock 和 unlock之间，然后在中间我就可以干任何事了，你看我在这儿故意做了十次 sum\+\+，而且我在中间加了一个 compiler 的 barrier，我让这个编译器不要优化，因为如果我不加这个的话，编译器会把它优化成 sum 等于 sum 加 10。对吧，它就很短的一个这样我加上这个barrier 以后，我的编译器就每次都需要 load。

```
mutex_t lk = MUTEX_INIT();

void T_sum(int tid) {
    for (int i = 0; i < N / 10; i++) {
        mutex_lock(&lk);
        for (int i = 0; i < 10; i++) {
            sum++;
            asm volatile("" : : : "memory");
        }
        mutex_unlock(&lk);
    }
}
```

对吧？好。看起来是没有问题的，你可以运行更多次，来至少在一定程度上相信，确实 lock 和 unlock，给了你正确的互斥，好。
