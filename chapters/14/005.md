还可以有多个房间、多张桌子和多把钥匙，访问不同变量时用不同锁。例如 lock\_a、lock\_b，acquire lock\_a 后做 x\+\+，acquire lock\_b 后做 y\+\+。如果有两对线程，一对做 sum\+\+，另一对如 t4 做 x\+\+，sum、x 位于不同内存地址，相互不干扰。分别用 a、b 两把锁，就能正确实现 x 加 1 等互斥操作，避免上节课的奇怪结果。终于能写对 1 加 1，是个重要里程碑。

看准备好的 sum\.c。下载线程库，除了 thread\.h，还有 thread\-sync\.h，并发控制相关代码都在后者中。可以创建互斥锁，简称锁，创建多个 lock 也没问题，例如 lk、lk1、lk2。但同一个变量必须用同一把锁保护。T\_sum 该怎样写？

这里稍复杂：要执行 n 次 sum\+\+，将实际操作放在 lock、unlock 之间。在中间可以做任何事。我故意连续做十次 sum\+\+，还插入 compiler barrier 阻止优化。没有它，编译器会合并成 sum 等于 sum 加 10；加了以后，每次都必须 load。

随后加 1、store，再重复，共做十次 load、十次计算、十次 store，已经是一段较长代码。若并发、并行地同时读写，肯定会遇到上节课的问题。有 lock、unlock，就阻止了这些并发，预期应得到正确结果，可以编译运行看看。

![图 11：sum\.c：持有互斥锁时连续执行十次 sum\+\+（00:18:46）。](/assets/images/14/0011.webp)

图 11：sum\.c：持有互斥锁时连续执行十次 sum\+\+（00:18:46）。

```
mutex_t lk = MUTEX_INIT();

void T_sum(int tid) {
    for (int i = 0; i < N / 10; i++) {
        mutex_lock(&lk);
        for (int i = 0; i < 10; i++) {
            sum++;
            asm volatile("" : : : "memory");
        }
        mutex_unlock(&lk);
    }
}
```

看起来没有问题。多运行几次，至少能在一定程度上相信，lock、unlock 确实提供了正确互斥。
