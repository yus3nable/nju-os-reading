可以问 AI：为什么正常运行的 gettimeofday 能中止，debug 时 trace 指令序列却不停？CPU 每次时钟中断，都会给 clock 加一，相当于 clock tick 的 count 依次增加。

![图 106：询问 Agent：正常运行可结束，调试为何不结束（01:08:54）。](/assets/images/10/0106.webp)

图 106：询问 Agent：正常运行可结束，调试为何不结束（01:08:54）。

gettimeofday 的代码很短，调用过程中几乎不会遇到 clock 加一。先读一次 clock tick，记在寄存器中，再读一次；两次相同，说明没跨过一次 clock tick 加一，就认为读到了正确、稳定的值，可以据此计算精确时间。如果两次不同，就再试一次。AI 已经读出指令序列的含义，课堂上我也能分析，但要花很多时间，它做得很快。这类似 sequence lock，读取 clock count 时会取一个 sequence count。

![图 107：两次读取 sequence count，不一致时重试（01:10:14）。](/assets/images/10/0107.webp)

图 107：两次读取 sequence count，不一致时重试（01:10:14）。

Agent 引用的指令片段：

```
+32:  ldr w7, [x3]
+92:  ldr w4, [x3]
+96:  cmp w7, w4
+100: b.ne +32
```

+32 时读到 w7，+92 时再读到 w4，随后 compare。两次 tick 不相等就重试，相等才继续。单步执行时，每条指令间都有很大延迟，循环就一直无法结束。AI 找到了正确答案，也让我们从二进制指令序列理解了 gettimeofday 的实现。
