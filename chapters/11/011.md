我觉得上课更应该告诉大家有 ld\.so(8) 这份手册，它记录了动态链接和加载器的行为，包括 glibc 中很多有趣的行为。可以把手册输出成文本，让大模型归纳。里面有许多大家可能没听说过的内容。计算机系统基础课应该讲过 LD\_LIBRARY\_PATH，也让大家编译过动态链接库。库编译出来以后，默认无法运行、加载；把它放到 LD\_LIBRARY\_PATH 环境变量中，ld\-linux\.so，也就是刚才的加载器、interpreter，就能看到。

![图 96：man 8 ld\.so：环境变量与辅助向量（01:11:18）。](/assets/images/11/0096.webp)

图 96：man 8 ld\.so：环境变量与辅助向量（01:11:18）。

interpreter 读取这个环境变量后，就知道去哪里找动态链接库。修改它，就可以加载另一个 libc，行为是确定的。手册还记录了更多功能。

![图 97：Agent 归纳库搜索顺序与选项（01:11:35）。](/assets/images/11/0097.webp)

例如 LD\_PRELOAD，以及 LD\_BIND\_NOW：后者会在启动时解析全部符号，关闭延迟绑定。还可以输出调试信息。执行 LD\_DEBUG=libs ls，就能观察程序加载库的过程。

LD\_DEBUG=libs ls 会显示加载了哪些二进制文件，可能比想象的多一些。再试 code，打开 VS Code，会看到大量库函数的整个加载过程。VS Code 也确实打开了，先把它关掉。

手册的 see also 还列出许多值得读的资料，有兴趣可以花些时间看看。其中有 ldd 命令。ld 是链接，那 ldd 做什么？它模拟启动加载过程，让 ld\.so 假装加载，从而确定实际加载时会使用哪些文件。

![图 101：ldd /bin/ls 的依赖解析（01:13:04）。](/assets/images/11/0101.webp)

图 101：ldd /bin/ls 的依赖解析（01:13:04）。

例如 /bin/ls，它会递归解析依赖库。再试 code——它是脚本，脚本不行。可以改看 GCC，它的依赖很少，作为动态链接的二进制文件，依赖比 ls 还少。

刚才的 LD\_BIND\_NOW=1 可以用于调试，确保加载所有符号，覆盖测试时可能没有遇到的一些预期行为。文档还有 LD\_SHOW\_AUXV。前面说过进程初始状态中有 auxv，也让 AI 读了 linux 内核加载器代码，说明栈上放了什么。令 LD\_SHOW\_AUXV 等于一，就能让 ld\-linux\.so 加载器打印实际的 auxv。注意，每次运行，AT\_SYSINFO\_EHDR 都变了，也就是 vDSO 的映射位置每次都在变。

program header 的加载位置也变了，random、random number 同样在变。可以让 agent 读取并解释每个辅助向量的含义。它有足够的知识，例如知道 AT\_SYSINFO\_EHDR 字段是 vDSO 地址。

![图 106：Agent 解释本机辅助向量中的字段（01:15:17）。](/assets/images/11/0106.webp)

图 106：Agent 解释本机辅助向量中的字段（01:15:17）。

vDSO 用于快速系统调用。random 是栈上的随机数地址，用于 ASLR 和 canary，后面还会讲 canary。这些元数据由内核加载 ELF 程序后通过栈传递给运行时。

![图 107：辅助向量中的内存布局与用户、随机数信息（01:15:24）。](/assets/images/11/0107.webp)

图 107：辅助向量中的内存布局与用户、随机数信息（01:15:24）。

glibc 和 ld\.so 从这些元数据中获取内存布局、CPU 能力、链接器位置等信息。我这里是 AArch64 的 ELF。我觉得有 AI 辅助，学习变得前所未有地容易。
