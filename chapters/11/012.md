还有一个彩蛋：LD\_PRELOAD。动态链接和加载时，默认采用先到先得的机制。例如 a\.out 引用了 printf，谁先被加载、首次满足这个未定义符号，后面就调用谁。也可以通过传入参数改变这个行为，具体方法可以向 AI 询问。

用 LD\_PRELOAD 预加载一个库，就可以覆盖想覆盖的符号。例如，把 malloc 换成自己的 malloc；也可以继续调用原来的 malloc，只在调用前后打印消息。这就是钩子，即 hook：覆盖符号，保留原来的行为，在前后插入代码。

插入自己的代码后，就可以改变各种 api 的调用。例如前面讲过，程序通过系统调用感知时间，sleep 一秒就等待一秒。怎样改变它对时间的感知？

wheel\.c 中的 usleep 覆盖：

```
int usleep(useconds_t usec)
{
    static int (*real_usleep)(useconds_t) = NULL;
    if (!real_usleep) {
        real_usleep = dlsym(RTLD_NEXT, "usleep");
    }
    // 用更短的真实usleep来模拟虚拟加速
    useconds_t real_usec = (useconds_t)((double)usec / speedup);
    return real_usleep(real_usec);
}
```

Makefile：

```
CC = gcc
CFLAGS = -fPIC -shared -O2 -Wall -Wextra -D_GNU_SOURCE
TARGET = libwheel.so
SRC = wheel.c

all: $(TARGET)

$(TARGET): $(SRC)
    $(CC) $(CFLAGS) -o $@ $^

clean:
    rm -f $(TARGET)

.PHONY: all clean
```

知道这件事可以做，就有了线索。即使没有线索，也可以和 AI 讨论：“我想实现这样的外挂，有哪些实现途径？”它会告诉你 LD\_PRELOAD，因为很多人用这个机制改变程序行为。改变库函数能做很多事，例如监控程序运行，获取 malloc 日志，判断有没有 use\-after\-free 之类的错误。

这些也可以通过钩子实现。除了变速齿轮，还可以让 AI 想其他用法。它知道用 LD\_PRELOAD 覆盖 glXSwapBuffers 能实现透视外挂，也可以劫持 Random，让随机过程可控。例如程序随机扔骰子，或者迎新晚会上不断跳动的程序，理论上都不可信。即使看到代码使用随机数，也能通过 LD\_PRELOAD 改变行为。

修改随机数返回值、随机种子等，就能控制随机结果。还可以非侵入式地记录 malloc、free 日志，得到类似 strace 的日志。这是很有用的机制。
