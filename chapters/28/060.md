这两行按理都不会执行，因为前面已经 crash，但会留下 side effect。现在 CPU 有投机执行机制，比如 CPU 暂时不知道分支怎么走时，会进行分支预测。

![图 56：板书：异常之后的内核读取与 probe 数组（01:08:51）。](/assets/images/28/0056.webp)

图 56：板书：异常之后的内核读取与 probe 数组（01:08:51）。

这可能让分支预测器错误地认为这些代码会执行。前面的指令还没 commit，CPU 就提前取指、译码，暂存结果。它从 pointer 取出 d 时，没有检查权限，这是 CPU 实现的 bug。发现 de\-reference 非法，本应不返回数据，但 CPU 为了尽快取数、执行下一条指令，仍完成了读取。假设内核里的这个 byte 是 40，再算 40 乘以 4096，得到 index，执行 load，让对应 cache 变热。

之后发现 crash 条件满足，就把这些指令全部销毁。它们只是做了读，没有留下其他实际 side effect。

![图 57：板书：投机指令被丢弃，cache 副作用仍在（01:10:26）。](/assets/images/28/0057.webp)

图 57：板书：投机指令被丢弃，cache 副作用仍在（01:10:26）。

但对 cache 的影响保留下来了。
