防御方式有很多，最简单的是禁止栈执行。后来英特尔 CPU 的 page table 有 nx bit，叫 execution disable，禁止对应页面执行。

图 47：课件：栈溢出、经典论文与 return\-oriented programming（00:56:40）。

［课件中的两个 gadget 示例；随后返回 execve。］

```
pop rdi; ret
pop rsi; ret
```

分配给进程栈的页面都不可执行，即使注入代码，跳过去也会触发越权访问，CPU 给出 segmentation fault，程序 crash。它也能被绕过：从已有代码里找 return 结尾的片段，作为 gadget。栈上可以放多个数据和地址，比如 pop rdi return，控制第一个参数，再用 pop rsi return 控制第二个参数。先 return 到地址空间中的 pop rdi，再依次 return 到后续地址。

![图 48：板书：NX 下串联已有代码片段（00:57:44）。](/assets/images/28/0048.webp)

图 48：板书：NX 下串联已有代码片段（00:57:44）。

这样就按顺序执行这三个代码。这叫 return\-oriented programming，可以绕过 NX bit，是一个精巧的攻击。理论上，这个架构无法防御这种攻击。
