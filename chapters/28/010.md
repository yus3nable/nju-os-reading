然后以及你的程序里面，其实可能有一些时间复杂性的漏洞，所以专门就有一种攻击方式，叫做 Algorithmic Complexity Attack，叫算法复杂性攻击，比如说 Hash Table，会知道 OK，它有一个有好多一个 slot。对吧。然后你有一个，比如说一个字符串，Hello。好那 Hello，你会经过一个 Hash Function。然后会送到某一个 slot 里。这是 OK 的，然后如果你平均下来，每一个 Hash 的Operation 都是 O(1) 的，对吧。

它会均匀地分散在这个 Hash Table 里，但是如果你精心构造很多个字符串，它都 Hash Function 到同一个地址上，那就惨了，对吧，如果所有人都是，都全部映射到这个数组下标，不管你是这种开放的寻址，还是放一个链表。对吧，都会让 Hash Table 退化成一个线性时间的，很糟糕的数据结构。当然有一个办法是，你可以把这里换成一个二叉树，对吧，换成一个 worst case 比线性要好的数据结构，这样它就算被攻击了，可能也不至于这么糟糕。后来 Standard Library 应该是做过这个事情。

这个东西会变成一棵树，当大到一定程度的时候，它就会换一个数据结构，但是至少这个漏洞一直都是有，在很早以前就有了，然后最后修，比如说像 Apache，跟我刚才说，对 DeepSeek 发动那个攻击一样，你可以去雇佣，你甚至都不需要一万台肉机。
