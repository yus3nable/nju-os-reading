AppArmor 这类更新的机制有不同思路。执行一个 Binary，比如 LS 或 A\.out 时，程序通常会获得执行者的用户身份。刚才的 passwd 会知道当前用户，sudo passwd 时也知道自己是 root。程序代码不变，但继承父进程 UID，也就继承权限：root shell 启动的程序具有 root 权限，当前用户启动的就有当前用户权限。但 access control 还可以采用其他依据。

图 33：Agent 对 AppArmor 的程序维度投影解释（00:43:57）。

AppArmor 把权限限制施加在 program 上。比如 nginx，无论由什么用户运行，都能设置权限上限，只允许访问几个目录里的文件，因为它理论上不该调用系统其他部分。如果它偷偷调用 passwd，就很危险。

![图 34：Agent 展示 nginx profile 与程序权限上限（00:44:29）。](/assets/images/28/0034.webp)

图 34：Agent 展示 nginx profile 与程序权限上限（00:44:29）。

［画面中 Agent 给出的 AppArmor profile 片段。］

```
/usr/bin/nginx {
  /var/www/** r,
  /var/log/nginx/* w,
  /run/nginx.pid rw,
}
```
