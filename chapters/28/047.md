栈从高地址向低地址增长，方向其实无所谓。执行 call 时，先 push 一个 return address，再建立属于 main 或其他函数的 stack frame。

![图 40：vulnerable\.c：64 字节缓冲区与未限制长度的 scanf（00:51:54）。](/assets/images/28/0040.webp)

图 40：vulnerable\.c：64 字节缓冲区与未限制长度的 scanf（00:51:54）。

［课堂展示的 vulnerable\.c：先打印缓冲区地址，再读取并回显字符串。］

```
#include <stdio.h>

int main() {
  char buf[64];
  printf("%p\n", buf);
  fflush(stdout);
  scanf("%s", buf);
  printf("Got: %s\n", buf);
}
```

随后在这个 stack frame 里面 allocate buffer。低地址这边是 buffer 的 0，另一端是 63。buffer overflow 是 undefined behavior，未定义行为。输入很长的 a 字符串，就会从低地址向高地址不断写 a。如果用 memory copy，也会有覆盖其他栈数据的风险。

它可能覆盖返回地址，很危险。如果这个奇怪字符串作为机器地址没有意义，程序就会跳到不存在的页面，随后 crash。
