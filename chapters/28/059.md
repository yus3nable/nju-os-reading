timing side channel 还引出一个更严重的问题：Meltdown。代码与刚才的例子类似，先触发 segmentation fault，做一个非法操作。

［课件中的侧信道示意片段；数据和数组依赖原上下文。］

```
raise_exception(); // even an HTM abort
uint8_t volatile x = probe_array[data * 4096];
```

这个操作会让程序 crash，或者是 hardware transactional memory abort。按理执行到这里就该终止或跳到其他地方，后面的代码不应执行，因为程序按指定顺序执行。我作为一个进程，可以用指针访问自己的内存，Meltdown 出现之前，操作系统会把内核内存与进程内存映射在一起，一部分由 OS 访问，一部分由进程访问。如果进程拿 pointer 直接 de\-reference 内核部分，mmu 会判断非法，杀掉进程。我现在先触发 crash，再 de\-reference 这个 pointer，然后 read d 乘以 4096 对应的位置，其中 d 比如是一个 8bit 整数，看起来很奇怪。
