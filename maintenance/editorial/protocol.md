# 阅读版编辑规范

正文采用连贯的课堂讲解，保留讲述者第一人称、原有知识范围及推进顺序。按段落理解后润色，不用全局删词或正则替换充当语义编辑。

## 可以调整的内容

- 删除无意义的“对吧”“好”“然后”等口头填充、结巴、同句复说和纯预告。
- 合并同一段内重复的信息，补足能够从上下文明确确定的主语，理顺长句和标点。
- 按同一个例子或推导的内部层次分段，使条件、操作、状态变化和结果连续可读。
- “我觉得”承载真实判断或不确定性时保留；纯粹垫话的用法可以删除。避免把讲述者的判断写成已核实的事实。

## 必须保留的内容

- 独立信息、定义、例子、推导步骤、因果、条件、否定、比较对象、限定范围和先后顺序。
- 讲述者的个人经历、立场、幽默、合理的引导性提问，以及学生互动中的有效信息。
- 原讲述中有教学信息的先出错后更正过程，例如程序失败、数值更正；不能把后面的正确结论提前覆盖前面的错误。普通口头重启、结巴和语病，在上下文已明确原意时直接理顺，不必复现无信息的自我接续。
- 技术名称、API、命令、路径、URL、数值、版本号、成绩比例及单位。数字保持原有写法，避免无必要的阿拉伯数字与中文数字互换。
- 所有听辨不清或缺失标记，保持原样；不能凭常识补出不确定的人名、命令或事实。
- front matter、标题文字和层级、围栏代码块、行内代码、图片引用、图注、链接目标，逐字保持不变。不能调整图片在讲解中的先后顺序。

术语差异检查是复核提示。命令、API、专名和示例变量须准确保留；普通英文插语可以删除或自然译述，单复数等写法可以规范化并说明。不要为消除提示把同义词重复塞回正文。

## 文风

使用自然、直接、紧凑的现代汉语，保留技术准确性。避免套话、泛泛评价和无作用的复述。段落直接面向阅读者，不加入润色过程、编辑安排或其他幕后说明。

改写的散文正文禁用“不是……而是……”“是……而不是……”“不……不……也不……”“与其说……不如说……”“真正的 X 是……”“本质上……”等句式；直接陈述两者差异。保留其否定、比较对象及技术含义。引用、代码、已有标题、标识符等受保护内容不因这些句式而改动。

禁用“更值得注意的是”“更值得怀疑的是”“最值得……的是”“压缩成一句话”“在这里停一下”“觉得有意思”“很有意思”“非常漂亮”“非常狠”“非常重”“分量非常大”“尤其适合”“极强”；少用“其实”“关键”“核心”“反而”“反倒”“尤其”“特别”等无必要填充。不把正常技术解释改成比喻。

## 复核

先通读每个小节，再改写全部散文段落；已经清楚简洁的句子可以保留。对照原文逐段核查独立信息、数字、否定、条件、归因及不确定性，再冷读衔接。压缩比例和口头词数量只供定位，不能代替语义核对。

`scripts/audit_editorial.py` 对照编辑前 Git revision，核对受保护结构，列出需要人工检查的数值与术语差异。代码未运行时只报告文本保持，不宣称示例执行正确。旧的 PDF 字符一致性报告只记录初次转换，不能用于证明阅读版逐字等同原 PDF。
