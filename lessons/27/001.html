第 27 课 · 数据库系统

回顾：文件系统与应用数据

原片 00:00:00—00:02:34

上一节课的时候我们讲了文件系统的实现，所谓的文件系统它是磁盘上的一个数据结构，所以理论上说如果你在数据结构课的内容掌握得非常好的话，你应该是很容易理解，我们其实就是要做一棵目录树，对吧，或者是一个目录图，如果是 UNIX 的文件系统，然后我们需要以一个图的方式来存储这个数据结构，虽然说在这个块设备上面你是按照块来访问的，但本质上和你在内存里面用字节来访问是没有本质的区别。然后我还讲了两个额外的话题，一个是文件系统的 crash consistency，一个是应用程序的 crash consistency，然后这个是指在 persistence 里面特有的，你需要保证你的数据结构在随时都有可能消失的情况下，线程随时可能消失的情况下，依然它能够在你重启以后能够 recover 到一个正确的状态上，可能会丢掉最近的几次数据结构的操作，但是你的数据结构整体不能 corrupt，这样。

那接下来我们顺着这个文件系统再往后面讲，就是如果我们有已经有了一个好的文件系统的实现，不管是哪怕是像 FAT 这样的文件系统实现，或者 ext4，那我们可以用文件系统来做什么呢？文件系统是用来保存数据的，它保存的是应用程序的数据，然后其实啊，在这里有一点挺有意思的观点，就是其实我们从来，虽然说我们都说我们去访问这个文件，我们要访问这个点 PPTX，我们要打开这个作业点 DOCX，但其实真正访问这些文件的不是我们，是应用程序，对吧？你是通过和应用程序的交互，因为你最终和计算机的交互都是键盘和鼠标，然后通过屏幕，然后这上面其实是应用程序接管了你键盘鼠标的输入，然后向屏幕上面某一个区域做了一个输出，对吧？

所以其实真正访问文件系统的保存数据的其实是你的应用程序，哪怕是像我就是想把它 cat 出来，对吧？一个最简单的应用程序，那也是应用程序用了 read，open，这些系统调用，完成了文件的访问，所以这也是为什么我上一节课说，应用程序的 crash consistency 其实也很重要，对吧？如果你的文件系统是一致的，但是你的应用会有 data loss，你对于应用的使用者来说也是很难接受的，然后对我们来说，首先我们当然可以用文件系统来管理应用的数据，或者说我们一直也都是这样的，你的 PPTX，你的DOCX，你的电影，你的这些 OS Labs，它都是在文件系统的那套目录树的 API 上面工作的，对吧？文件和目录，那我今天这节课就会讲有没有更好的，如果你的应用程序，比如说你想要服务一万人，十万人。
