第 12 课 · 从零开始构建 Linux 应用世界

用 AI 阅读资料与实现想法

原片 00:36:19—00:46:14

从最早的 Altair 8800、Bill Gates 带一卷纸去运行 Basic，到 Evolution of the Unix Time-sharing System，我也可以告诉大家自己怎样读这些资料。刚开始上课时，我用的是豆包。

豆包表现不尽如人意，经常翻车。从上次或上上次课起，换成了千问 3.6 Plus。我没有 coding plan，只能用 API billing，上课时多花一些钱，换取更好的体验。这里展示的却是另一个东西，是豆包帮我做的。我没用龙虾，因为喜欢自己控制代码，用的是 Claude Code。想读文章时，即使是一百来页的博士论文 PDF，也可以直接放进 iCloud 的共享文件中。后台会自动处理，逐页 OCR，消耗 coding plans、豆包的 token，生成几个层次的 summary。最短的只有一句话：如果是领域专家，看到这一句就能还原整篇内容。

还有较长的摘要和一页纸摘要，列出重要信息。例如早期 UNIX 怎样从淘来的一台废旧机器开始，实现最简单的版本，当时连路径名都不支持，把目录视为特殊文件。

随后用 27 行汇编实现 fork，结合 shell 已有的能力形成 fork、exec 模型。管道到 1972 年，经过多次提议后才实现，再讲到竖线符号的来历。结合今天课上的例子，重要内容都在这里，原文也保留着。

打开 Claude 终端，就可以自由对话，问想知道的内容，历史对话中的知识也会作为 memory 记录。大家也可以装龙虾做这件事，我觉得它对自己来说不太可控，至少我现在这样学习。这样可能几分钟就能看完几百、一百多页的博士论文。

这也因为我可能对领域已有一定了解，但我觉得以前无论如何做不到，现在大家也可以做到。也许某个同学会想，做一个比龙虾更好的学习 Copilot，再去“贴吧”发帖请大家使用。这些故事都从零开始，而今天从零到零点一、从只有想法到做出原型，已经前所未有地容易。Linus 当时想在 486——386、486 上复刻一个性能好、自己能用的 UNIX 操作系统，那时需要天才才能实现。今天，只要想法足够偏门，对领域专家来说实现又没有显著门槛，就可以用 Copilot 花些 token 做出原型，界面也能做得好看。我觉得不太久以后，从零点一到零点九五可能也会容易，创新方式就会改变。

例如 Crazy OS，我一直在想能让它成为什么。可以给硬件增加指令，让它高效运行 Crazy OS，也许能做出新型计算机。我可以做 Hardware/Software Co-design，重新设计操作系统。以前可能有人做过类似的事，但至少可以从头再做一遍，从零到零点一很容易。

最近 Anthropic 发布了新模型，从 Opus 变成 Mythos，说 Finding bugs is easy。马上有人指出过度营销：它找到的 FFmpeg bug 位于几乎不可能进入、正常人不会走到的遗留路径中。不过我觉得，从零到零点一确实前所未有地容易。我们自己的工作也有例子。

我们也做测试。GCC、LLVM 都有 bug，可能把程序编译错，我在实际项目里就遇到过。编译错很麻烦，因为程序出错时，第一个怀疑的是自己逻辑写错，很少会怀疑编译器把代码翻译错，但它确实会。GPT4 时代，我们通过 Prompt Engineering 做过这样的工作。

只用一个 Prompt，就为 GCC、LLVM 找到 150 个 bug，而且那个 Prompt 写得很差，是学生写的；GPT4 的能力也比现在差很多。现在榜单中，一个 20B 的开源小模型都能超过 GPT4，而它当时是最大的模型。现在重做这项工作，我觉得找一两千个 bug 不会很困难。但找到以后又怎么样呢？

从 0 到 0.1 变得前所未有地容易。再看这两天的 caveman 项目，它用极致的 Prompt 压缩输出。我一直说，大语言模型被微调成“舔狗”，说什么都要伺候好主人。但在 Claude Code 中，这些内容浪费 Token。

说许多好话，对完成任务有没有帮助？caveman 用 Prompt、Skill 要求删掉无必要内容，能用文言文就用文言文，语法不正确也无所谓，尽量写短，只要大语言模型能看懂。我觉得精妙之处在于利用 Agent 的容错性。直觉上会担心，Prompt 缩短就会丢信息、降低准确率：以前说很多废话能做对的，现在可能做不对。但任务描述、程序输出没有变，Agent 有自主性，发现错误会再试，再做一次就可能做对。靠这种自主性弥补偶尔出错，只要准确率下降不多，Overall 仍能节省 token。

背后的道理就是这样。我自己的 CLAUDE.md 也要求回答简短、使用中文。上课提问全用英文，但 Claude Code 输出全是中文，确实也比较短。这和 caveman 的想法一样，只是它做得更极致，我觉得有趣。AI 时代，从 0 到 0.1 变得前所未有地容易。

最近审稿时又发现一些论文，做了很多事情，可能 ABCDE 加在一起，效果还不如 caveman。我不知道为什么一定要为了写论文而写论文，浪费每个读者的时间。现在从 0 到 1——至少从 0 到 0.1——已经前所未有地容易。

我想说的是，大家高中可能已经“坐牢”三年、burn out 了，但现在还有机会解脱出来。像 Linus 那样想一想，借助 AI，也许能做些了不起的事情，找到自己的状态。现在的选择可能仍是拿南大学位，回老家做公务员，一直躺到退休；但所有岗位都可能面临被替代，包括我自己。

自己能走多远，我还不知道，大家可能更需要向前走得远一些。
