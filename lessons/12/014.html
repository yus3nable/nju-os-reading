挂载磁盘、切换根与启动网络

原片 01:13:58—01:20:00

退出 shell 后，脚本会倒数三秒钟，321，再做后续操作。现在已经能挂载 /dev/vda：创建 /mnt，执行 mount -t ext4 /dev/vda /mnt，就成功了。/dev/vda 对应磁盘这个操作系统对象，磁盘中有文件系统目录树，挂载后，这棵目录树就出现在 /mnt 下。

这是准备好的 fsroot 目录，里面有网卡驱动 e1000.ko，以及另一份 init。它会打印 JYY’s minimal Linux。

先卸载这个文件系统，再看 /mnt，刚才的内容就没有了。现在退出 shell，经过 321 倒计时，又等了一会儿，网卡启动了。

日志打印 Goodbye, QEMU Console!，原来的 console 不能用了，另一个显示设备却可以用。它像前面的 Minix，是 QEMU 模拟的 VGA 显示设备。刚才一直通过模拟串口、类似调试串口的 /dev/console 交互。

之前几次误切到这个终端，画面一直黑着，没有输出。现在有了 /dev/tty，可以把 echo hello 输出到这里。需要留意，画面由 Linux 驱动逐像素绘制，能看到打印的 JYY 的 minimal Linux。这是可用的 Linux，这份 init 就是我们的操作系统。

initramfs 最后阶段执行 pivot_root 后，会换一个文件系统和 init，运行现在这份程序。新文件系统是空的，仍要为 BusyBox 的 ls、grep 等命令创建入口，再创建 procfs、sysfs 和 /dev 下的设备。接着配置网络：加载模拟 e1000 网卡驱动、设置 IP 地址。虽然现在运行在虚拟机中，理论上放到真实计算机上也没有问题。这里可以启动 httpd，在 8080 端口提供服务。

能明显看出终端打印变慢，因为现在模拟的是图形设备，画面逐像素绘制，已经离开刚才的字符接口。网卡显示 Link becomes ready，网络应该可以正常工作了。Makefile 中还有个彩蛋：QEMU 将虚拟机的 8080 端口映射到宿主的 8080 端口。

倒计时与切换根的片段：

echo -e "\n\n"
echo -e "\033[31mSwitch root in....\033[0m"
for sec in $(seq 3 -1 1); do
    echo $sec; sleep 1
done

# Switch root to /newroot (a real file system)
N=/newroot

mkdir -p $N
mount -t ext4 /dev/vda $N

mkdir -p $N/bin
cp $BB $N/bin/
cp $BB /init
exec switch_root /newroot/ /init

Makefile 的磁盘镜像片段：

fsroot:
    mkdir -p fsroot/modules
    cp $$(find /lib/modules/$K/ -name e1000.ko) fsroot/modules/

    dd if=/dev/zero of=$(IMG) bs=1M count=64
    mkfs.ext4 -F $(IMG)
    sudo mount $(IMG) $(MOUNT)
    cd fsroot && sudo cp -r * $(MOUNT)
    sudo umount $(MOUNT)

QEMU 的端口映射参数：

-netdev user,id=net0,hostfwd=tcp:127.0.0.1:8080-:8080

理论上，访问 localhost 的 8080 端口就能打开虚拟机网页。现在得到 404 是对的，因为没有 index.html。那虚拟机里有什么文件？

文件系统里有 init。如果实现正确，访问 localhost 的 8080 端口下的 init，就应该能看到脚本。确实看到了，证明这个 Linux 已经运行起来了。

第二份 init 的网络与终端配置片段：

# Configure network
insmod /modules/e1000.ko
ip link set lo up
ip link set eth0 up
ip addr add 10.0.2.15 dev eth0
ip route add 10.0.2.0/24 dev eth0

# Prepare the terminal
echo -e "\033[31mGoodbye, QEMU Console!\033[0m"
echo -e "\033[H\033[2J" >/dev/tty
echo "JYY's minimal Linux" >/dev/tty

经过这些步骤，从最早的 initramfs 开始，加载驱动、调用 Linux 提供的系统调用，再 pivot_root，最终能启动 httpd 网络服务器，并在外部浏览器访问网页。所有脚本都已经看过，从 initramfs 加载第一个进程开始，后续全部由系统调用实现。这体现了系统调用抽象的能力。initramfs 中的环境，和最终日常使用的 Linux 世界并不一样。
