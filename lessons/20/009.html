第 20 课 · CPU、SIMD 和 GPU

让一条指令多做一些事：SIMD 与 MMX

原片 00:23:30—00:28:01

另一条路径，是让一条指令处理更多数据。动态流水线以指令为调度单位。提到指令，我们会想到 mov eax；讲 RISC-V 时，一条指令通常只做很小的一件事。它做的事很少，维护这条指令的代价却很大，中间的差距就是税，相当于收入 100 块，有 99 块用于交税。

可以让一条指令操纵更多寄存器。比如引入一条指令，给所有寄存器都加一。当然，CPU 设计者实际不会这样设计，因为这会彻底改变 CPU 微架构，还需要遵守物理规则。但假设有这样一条指令，它可以执行很长时间，完成原来 32 条指令才能完成的事。

原来 32 条指令的工作，现在只需往队列里放一条，调度的税就分摊到了 32 分之一，而动态流水线的复杂度几乎没有显著增加。由此有了一个自然的想法：Single Instruction，Multiple Data，简称 SIMD。让一条指令多做一些事，可以提高 CPU 的效率。

SIMD 当然不会采用“给所有寄存器加一”这样的设计。1997 年，在 32 位机上出现了 MMX Multimedia Extension。Multimedia 叫多媒体，是个有年代感的名字，今天已经很少提了。它把图像和声音结合在一起，提供真实的体验。如今，打开智能手机上的抖音，默认就有这些功能，多媒体已经完全成为计算机系统的一部分。

MMX 为 32 位机增加了一组 64 位寄存器，每个可以当成四个 16bit 整数使用，再增加一组指令。这些寄存器需要支持 load、store，还允许同时对四个数字做某种操作。比如两个 MM 寄存器相加，可以让其中对应的四组数字分别相加。

这与一个64 位整数相加有区别。64 位整数加法中，两个16位数字相加溢出后，进位会传到相邻部分；Multimedia 指令集的设计不会让进位这样溢出。这个指令集在两个整数相加溢出时，还会保留最大值，有点像浮点数的 overflow 和 underflow。

为了展示技术，处理器发售时，每个处理器还附带一张光盘，展示 MMX 指令集的 killer application。1997 年，这看起来是很高清的三维渲染画面，而且有光照。留意子弹射出的过程，可以看到光照效果。

这样的效果以前很难实现。今天看，它还不如手机游戏；但在当时，这样的图形显示让人惊艳。

课件中的 popcount 函数；uint32_t 来自 stdint.h，保留原课实现。

inline int popcount(uint32_t x) {
  x = (x & 0x55555555) + ((x & 0xaaaaaaaa) >> 1);
  x = (x & 0x33333333) + ((x & 0xcccccccc) >> 2);
  x = (x & 0x0f0f0f0f) + ((x & 0xf0f0f0f0) >> 4);
  x = (x & 0x00ff00ff) + ((x & 0xff00ff00) >> 8);
  x = (x & 0x0000ffff) + (x >> 16);
  return x;
}
