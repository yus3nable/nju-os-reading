为每个像素执行同一段代码：CUDA 模型

原片 01:14:31—01:18:00

这样确实能实现矩阵乘法，也预示了今天用显卡做高性能计算的模型。回顾 shader program，它为大量同类对象执行同一段代码。

课件中的 CUDA 编程模型教学伪代码；spawn 表示启动像素任务，f 和设备内存初始化未列出。

__device__ int *screen;

void T_kernel(int row, int col) {
  int color = f(row, col);
  screen[row * 1920 + col] = color;
}

for (int row = 0; row < 1080; ++row) {
  for (int col = 0; col < 1920; ++col) {
    spawn(T_kernel, row, col);
  }
}

这又回到了操作系统课第一次讲并发时的内容。比如计算 Mandelbrot set，希望在 device，也就是显卡上，分配一块内存。screen 表示一张 picture；如果图片大小是1920x1080，就分配一个同样大小的数组。然后让显卡执行 T_kernel，也就是 pixel shader 程序。

为每个像素 spawn 一个线程，将 row、column 作为参数。用 row 和 column 计算 fcolor，得到这个像素的 color，再写到对应位置。这可以画图，也可以做科学计算。1920x1080p 大约是200 万像素，理论上，只要能在 GPU 上启动 200 万个线程，就能按这种方式计算。

假设 GPU 能提供足够轻量的线程，就得到了所需的并行计算：还是操作系统课最初学的线程方式，只是线程和内存都在显卡上。这就是 CUDA 的 Programming Model。我想这里应该有 sample，但我没有 CUDA，这个程序跑不起来。第一次打开 CUDA 的 sample 时，可能会被一些陌生写法吓到。

设备内存分配与 kernel 启动的画面片段；依赖 CUDA，W、H、gridDim、blockDim 和 kernel 已在其他位置定义。原课当前设备未运行此程序。

int *pic_d;
cudaMalloc(&pic_d, W * H * sizeof(int));
mandelbrot_kernel<<<gridDim, blockDim>>>(pic_d);

mandelbrot_kernel 的画面代码；依赖 CUDA、W、H 和设备端 mandelbrot 函数，其余程序省略。

__global__ void mandelbrot_kernel(int *pic_d) {
  int x = blockIdx.x * blockDim.x + threadIdx.x;
  int y = blockIdx.y * blockDim.y + threadIdx.y;
  if (x < W && y < H) {
    int n = mandelbrot(x, y);
    pic_d[y * W + x] = n;
  }
}

比如 __device__，以及 mandelbrot_kernel 后面的三个尖括号，都是平时写 C、C++ 没见过的语法。但它描述的事情可以用操作系统课第一节的概念理解：创建大量线程，并且要求这些线程运行同一段代码。这也是今天从游戏图形讲起的原因。

每个像素都可以理解成在执行同一段代码，这就是 CUDA 的 Programming Model。要实现刚才的设想，就需要 spawn 很多 T_worker，为每个 pixel 启动一个任务。

但即使采用上一节讲过的轻量线程方式，代价也很大。
