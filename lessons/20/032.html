访存方式与分支给 CUDA 带来的代价

原片 01:27:00—01:29:00

它鼓励你创建 200 万个线程，然后它通过内部的 GPU 上面的高效的调度，有点编译器的调度，有一点点那种 VLIW 的感觉，就这些机制都是有一些内在的联系的，非常有意思的一个编程模型，当然了，这也不是没有代价的，这就意味着，CUDA 的程序非常难写，一旦你写的有一点点不好，你的性能就会爆差。

课件中的两种索引写法；map 和 t 的定义省略。

map[row * 1920 + col] = t;
map[row + col * 1080] = t;

课件中的分支分化教学片段；A、B、X、Y、Z 为未展开的操作，保留图中的写法。

if (threadIdx.x < 4) {
  A;
  B;
} else {
  X;
  Y;
}
Z;
__syncwarp()

比如说你这样写，像我刚才如果，Row 乘 1920 加 column，是连续的，如果这一次可以生成一个连续的 Store，你就可以获得最佳的性能，但是如果你把它稍微这么改写一下，它立马就会得到非常差的性能，因为你的内存访问全部不连续了。然后你的这个内存控制，就要一个 word 去写，就要花非常多的时间，以及 CUDA 程序里面的分支，是一个非常非常讨厌的，你想 SIMT 怎么能实现分支呢？对吧，你们马上就有一个疑问，如果我只有一个 Program Counter，我怎么实现分支呢？

对吧，如果 if 什么，A Else，B，答案是，我们的 CUDA 的 C，它编译出来的所有的东西，都是没有这种二选一分支的，它要么就是那种无条件的那种跳转，或者那种，对吧，循环的这种指令，而如果你有一个 if A Else，B，它会为这个 if 算一个条件。然后把这个条件放到一个寄存器里。对吧，这个或者 if 的结果。对吧，Condition，它要把这个 Condition 放到一个寄存器里。
