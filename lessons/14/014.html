用模型检查器检验算法变体

原片 00:47:27—00:49:48

我这里有很多的例子，很多的整个操作系统里面的各种各样的概念，都可以用模型检查器来检查，然后比如说我这里写了一个。

# T_1 中举旗与礼让的顺序
heap.x = '🏴'
sys_sched()
heap.turn = '❷'
sys_sched()

# 观察与进入条件
t = heap.turn
sys_sched()
y = heap.y != ''
sys_sched()
if not y or t == '❶':
    break

Peterson 算法，大家可以忽略这个 sys_sched，这个就代表在这个时候可以切换到另外一个线程执行，x 先举起来，然后把手上的字条贴到门上，然后开始观察这样的一个过程，就是一个真正的可以执行的 Python 代码，然后我可以在命令行里面，我可以直接在命令行里执行它。然后执行它以后，就会得到一个状态图，状态图，你看各种各样的状态图，状态里面有程序的输出，有共享内存的状态，有局部变量的状态，做的就是这件事，就是我在黑板上，我可以把从一个状态开始。

Alice 执行一步到哪一步，用程序把它执行出来，然后我一方面我可以把它真的画出来，我往年的时候，我甚至都会把这个状态的迁移图给画出来，就像我以前在上课的时候要证明 Peterson 的算法是正确的一样，我刚才那份代码，我有一个小细节没有讲，谁在谁进入了临界区，我会把它以字符串的形式给标记出来。所以你看到现在，要么一在 Critical Section 里，要么二在 Critical Section里，没有它们同时进去的，至少没有它们同时进去的情况。好。那我们可以把这个算法稍微小改一下。比如说你们肯定会好奇，如果我们不是先，不是先举旗子再贴名字，而是先贴名字再举旗子，这还对不对，我后面我期中考试就出这种题，你看我 Peterson 算法有多少种变体，这个它就错了，为什么错了，对吧，你们需要花很长的时间才能想清楚，它为什么错了。

python3 mosaic.py -c examples/concurrency/peterson.py | grep cs | sort | uniq | grep -v source

"cs": ""

"cs": "❶❷"

对吧，先贴标签再举旗，不对，一秒钟我就知道了，如果放下旗子之后，把门上的字条撕掉还对不对，观察举旗和名字的顺序交换还对不对，是不是会存在一种两个人都没有办法进入 critical section，或者是对某一方不公平的行为。我们可以问很多这样的问题。然后如果我每一个都像我现在这样在黑板上面推一遍，那这节课就完全结束了。所以我们做 systems。
