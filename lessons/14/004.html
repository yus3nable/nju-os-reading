那么你会想，既然是 make_it_work，或者说是关中断和开中断，那我们也可以把这个机制稍微扩展一下，能不能有一个相当于是，叫我要开始这个关键的代码了，然后我要离开这个关键代码，对吧，关中断和开中断。然后这就有了我们今天要讲的最主要的内容，就是互斥的 API，所谓的互斥就叫互相排斥，Mutually Exclusive，它两个人不能同时进入一段代码。然后这个代码的时候叫 critical section，叫临界区，你们在很多教科书上都会看到它就是一段代码。

那我们实现的是在任何一个线程上，它都可以执行 lock，lock 完以后，我就可以执行任何的代码，比如说 sum++，然后等到我这个代码觉得 OK 了，我不再需要这个很强的，别人不能打断和我一起并发执行，我就 unlock。然后 lock 和 unlock，它其实就是把并发给消除了，当我 lock 返回的时候，也就是说当我这个代码开始执行的时候，我就再也不能和别人的 lock 的代码块并发了，我们同样可以画在时间轴上，如果我们有一个 T1。就跟刚才那个是一样的，如果我 lock。

T3 也执行了一个 lock，那它就必须要继续的等下去，这样我就把所有的并发都消除了，我就得到了一个确定的顺序，也未必是绝对确定的，但至少是有一个你能够排出 1，2，3 这样的顺序，第一次我会知道，第一次 T1 的 lock 调用了，返回了，T1 的 lock 里面代码执行了，它 unlock 了，等到这个 unlock 结束，我们的 unlock 还有一个额外的语义，它会保证所有在这个地方，写的数据全部都进入内存，不会像之前一样。

比如说我有一个我这写了 x 等于 1，我会确保另外的线程，在这 load x 的时候，可以看到这个 x 等于 1，好，这就是 lock 和 unlock给我们的保证，还是很直观的，你在，如果你把线程想象成人，把共享内存想象成物理空间的话，你就想象是有两个视角，一个是lock 和 unlock，就是这个锁的视角，就是有一个房间。对吧，就有一个小房间。然后这个房间里面只能容纳一个人。然后任何人进来以后，都会把那个房间锁上，别人就进不来了。然后你那个人就是代码。人就是线程，人就是代码，线程就可以继续，而如果有别人还想要继续执行代码，他就必须，他执行 lock 的时候，他必须要把这个房门打开，他要进入这个房间，他才能执行这个代码，这样如果有很多人都想同时进那个房间的话，他就只有一个人能进去，需要，其他人需要等。然后等吧，把我前面一个人把这个房间的使用权让出来以后，才可以。然后他还有一个解读的方法，就 lock unlock是锁，锁房间是一个解读，还有一个解读的方法，就是你的桌上有一把钥匙。然后所谓的 lock 和 unlock 就是，lock 需要得到钥匙。
