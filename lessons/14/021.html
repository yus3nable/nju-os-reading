第 14 课 · 并发控制：互斥

比较四种求和方式的实际性能

原片 01:15:08—01:22:42

最后一个例子是我很喜欢的实验：比较不同求和方式。今天讲了 exchange，库函数的 Mutex Lock、Mutex Unlock，以及内核 futex。它们各自什么时候快、什么时候慢？

可以通过实验了解。有 AI agent，实验比以前容易许多。我写了这样一个程序，总共执行 N 次 sum++，N 可以自己定。

long sum = 0, N = 10000000;
extern void T_sum();

int main(int argc, char *argv[]) {
    int T = argv[1] ? atoi(argv[1]) : 2;
    N /= T;
    for (int i = 0; i < T; i++) {
        spawn(T_sum);
    }
    join();
    printf("sum = %ld\n", sum);
}

把 N 次分配到 T 个进程，T 由命令行输入。将 Main 和不同实现链接：一种用原子指令，x86 是 lock add，Arm 用另一种机制完成原子加一；一种用 Mutex，直接调用 Pthread Mutex，与线程库 MutexLock 的实现相同；还有刚才的 SpinLock。

SpinLock 不断 Exchange，前面看过，每次执行一次 exchange。另外让 AI vibe code 了一个实现。

它在每次 acquire、Release，上锁、解锁时，都强制通过 Futex 系统调用进入内核。这样就能比较每次进内核究竟有多慢。

// 获取成功后仍强制进入一次内核。
// 此时 klock == 1，expected == 2 不匹配，立即 -EAGAIN 返回。
(void)futex_wait_int((int*)&klock, 2);

// 释放时无条件进入内核，即使没有等待者。
static inline void unlock_force_kernel(void) {
    atomic_store_explicit(&klock, 0, memory_order_release);
    (void)futex_wake_int((int*)&klock, 1);
}

spinlock_t lk = SPIN_INIT();
void T_sum() {
    for (int i = 0; i < N; i++) {
        spin_lock(&lk);
        sum++;
        spin_unlock(&lk);
    }
}

今天确实只用一个 Prompt 就完成了。需要想到这种量化研究方法，做系统和其他事情都重要。根据课堂线索，例如“一核有难八核围观”，猜测不同机制性能有差异，再准确测量变化。我给的 Prompt 就要求比较这些实现。

做控制变量实验：总 sum++ 次数固定，分配到一个、两个、四个、八个、十六个线程，分别为三种实验重复五次。实验必须可复现，不能 cherry picking，例如做一万次只挑最好的一次。

那样没人比得过你。要求统计每次 sum++ 平均时间，保存原始数据列表 CSV，生成带 error bar 的 plot。后来换了 Prompt，所以最终没有 error bar，但至少有实验脚本。不必先知道脚本怎么写，只要知道需要科学、定量的对比，就能获得有趣的 results。这里保存了实验原始结果。

结果画成两张图：一张是每次 operation、sum++ 的平均耗时，单位纳秒；另一张取倒数，表示每秒操作次数。符合预期吗？总次数相同，无论陷入内核、自旋、Mutex 还是 Atomic，一个线程时每次 sum++ 都最快。陷入内核的代价则明显更高。

一次 System Call 远比其他方式昂贵。只需几个 Prompt，就能测出进内核的额外代价，所以 Read 一次应尽可能多读数据。如果从较远地方读取，需要等待，系统调用成本很快就被等待时间抵消。我这台机器需几百纳秒，X86 应该更快。单线程只需几纳秒就能做一次 sum++。进入两个、三个、四个线程后，各种方式表现开始不同。这条曲线叫 Scalability，即多处理器扩展性。树莓派有四个处理器，从一到二到四，原子指令、Mutex、Atomic 的差距都不大；线程数超过处理器数后，情况就变了。

Mutex、Atomic 性能没有显著下降，Spin 却明显下降。持锁线程被换出后，其他在 CPU 上运行的线程都在自旋，浪费算力，实验能看到这个现象。再看 Operations Per Second，每秒能做多少次。如果只想 sum++，结果也很清楚。

原子指令性能最好。Mutex 与 Spin 的差距在这张图中更清楚：Mutex 的 Scalability 好，随线程增加基本仍是一条直线；每次进入系统的 trap 很慢。用这样的科学方法对待数据，随时做对比实验，就能清楚了解系统发生了什么。
