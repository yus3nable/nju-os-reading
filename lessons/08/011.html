注册和触发信号处理程序

原片 00:59:20—01:04:00

先讲单个进程怎样响应 Ctrl 加 C。所谓 interrupt，实际上是收到信号。假设世界里只有一个进程，问题还比较简单。看这段代码。

signal.c 片段：头文件、handler 和 cleanup：

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

void handler(int signum) {
    switch (signum) {
        case SIGINT:
            printf("Received SIGINT!\n");
            break;
        case SIGQUIT:
            printf("Received SIGQUIT!\n");
            exit(0);
            break;
    }
}

void cleanup() {
    printf("atexit() cleanup\n");
}

SIGINT、SIGQUIT 是不同信号。程序运行时可以转去执行 handler，即使正在 while (1) 中计算 i 等于 i 加 1，也能跳过去。

signal.c 的 main：接续前面的函数：

int main() {
    signal(SIGINT, handler);
    signal(SIGQUIT, handler);
    atexit(cleanup);

    while (1) {
        char buf[4096];
        int nread = read(STDIN_FILENO, buf, sizeof(buf));
        buf[nread - 1] = '\0';
        printf("[%d] Got: %s\n", getpid(), buf);
        if (nread < 0) {
            perror("read");
            exit(1);
        }
        sleep(1);
    }
}

正在 printf 时也可以转到 Signal Handler。开头用 Signal，为 SIGINT、SIGQUIT 注册同一个 handler，再按编号区分：SIGINT 打印 Received SIGINT，不做其他事；SIGQUIT 打印 Received SIGQUIT。

SIGQUIT 分支还执行 exit。之前用 atexit 注册 cleanup，希望退出时打印 atexit()cleanup。主循环则不断读 stdin。运行后能输入数据，按 Ctrl 加 C，就触发看起来像死代码的 handler，虽然程序没有主动调用它。

因为 signal 注册了 SIGINT 对应的 handler。无论程序在做什么，例如每次输入后 sleep(1)，收到信号都能立即打印。Ctrl 加反斜杠发送 SIGQUIT，就正常退出。

驱动确实会发送 SIGINT。若注释注册 SIGINT handler 的一行，再运行，就会像 yes 一样。

修改后的注册语句：

// signal(SIGINT, handler);
signal(SIGQUIT, handler);
atexit(cleanup);

默认行为是收到 SIGINT 后退出。还可以开另一个 tmux，主动发信号。

signal 程序运行时，Ctrl 加 C 能触发 SIGINT。另一个程序也能用 kill 发送同一信号，比如 kill -SIGINT 18834，也打印 Received SIGINT。信号既可能来自终端，也可能来自其他进程。

另一终端中输入的命令：

kill -SIGINT 18834

两种方式执行同一个 handler、同一个 printf，所以效果相同。这是底层机制，但还没回答信号到底发给哪些进程。
