第 08 课 · (Aside) 终端和 UNIX Shell

会话、进程组与作业切换

原片 01:04:00—01:11:27

SIGINT 究竟发给谁？程序因 bug 不断输出时，Ctrl 加 C 通常要结束相关父子进程，不能只停父进程，孩子仍打印。UNIX 为识别目标，做了一套复杂设计。

听过即可，不要求掌握。我觉得这是历史遗留，设计甚至应该被替代。当年需要解决：Fork 形成树，还可能托孤，104 成为 1 的孩子，Ctrl 加 C 却仍要停所有前台进程，避免后台误伤。于是有 Session、Process Group。这里 Session 与 Login Session 有区别，也密切相关。新进程继承父进程 Session，登录、SSH 时也会建立一个 Session。

每个 Session 有 Controlling Terminal，再分成 Process Group、进程组。Shell、Bash 其实有类似 Windows 多任务切换的功能。先开 Bash，用 Vim 编辑文件，相当于 Windows 双击打开。

课堂演示 99% 的时候，不用就关。但若还想编辑另一个文件，Windows 可以最小化。在只有 VT100、没有鼠标按钮时，能否如此？按 Ctrl 加 Z，当前程序就消失了。

程序仍存在，可以再编辑另一文件。jobs 列出作业，像 Alt Tab、Windows 加 Tab 查看不同窗口。

现在有两个 Vim，也可以启动不断输出的 yes，再切到后台。这些程序默认暂停，但能让它们继续后台运行。

用 Background 恢复三号，再挪到前台、Ctrl 加 C 结束。jobs 中可在多个程序间切换，类似多个窗口。Ctrl 加 Z 最小化，fg 则恢复，比如百分号二或一。现在想回 1，刚才按错了。

Foreground 恢复前台，再 Ctrl 加 Z，就又回去。终端一次显示一个应用，背后靠 Session、Process Group。

它们既为了判断 Ctrl 加 C 目标，也为了 Job Control，支持类似 Alt Tab 的切换，不只一个用途。Fork 出来的进程，即使父子关系因托孤改变，仍可作为同一作业管理。

Shell、Bash 启动新程序，会分配新进程组，像 Windows 新窗口。默认创建的进程会继承子进程的进程组，也有系统调用能修改自己的组。这些都是 API。Process Group ID、PG ID 把不同应用分开。

于是 Ctrl 加 C 的行为就明确了：操作系统向前台进程组全部进程发送 SIGINT。所有成员都会收到；至少在没有忽略 SIGINT 时，就能按预期结束前台任务。

我觉得这种解决方式有些粗糙，后面还有其他不便。
