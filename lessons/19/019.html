JavaScript 的诞生与语言设计

原片 00:54:00—00:56:30

这个是我们说是一个方案，就是说如果我们想要轻量化线程的话，我们就真的可以把线程的代价创建，管理的代价，切换代价变得非常低，全部在用户空间实现，甚至还可以借助操作系统的这个线程的机制，好，还有一条路，还有一条路，我们的计算做并行和并发计算的本质是计算图。那我们有没有可能在编程语言里面去更好地描述我们的计算图呢？

那这就要讲到 1995 年世界的另一条线，对吧，刚才我讲的是 UNIX 的那条线，然后到 go，世界上还有一条另一条并行的世界线，1995 年 Brendan Eich 加入了 Netscape，委以重任设计一个嵌入在网页里面的脚本语言，你们就知道是什么了。对吧。然后Brendan Eich 花了十天，糅合了 C，Java，Scheme，Self，各种编程语言的特性，因为他的主要的目的是，是要设计一个像 Java的编程语言。然后吸引大家，因为那个时候 Java 已经有点起来了。然后人类的齿轮就开始转动了，有意思的是，他的主要兴趣是函数式编程，所以他对这件事情其实不上心，他做了一些很糟糕的设计，但是要感谢他的机缘巧合，他的兴趣是函数式编程，所以他把 Function is first class citizen 放到了 JavaScript，然后所以你看到了这个很有意思的梗图。对吧，左边是 JavaScript Guide，然后右边是 JavaScript 的 good parts。然后看左边很厚，右边很薄。意思是 JavaScript 的这个 good parts 很少。

这是一个怎么样的，实践能设计出一个怎么样的语言呢？就有无数多的坑，比如说他的 this 是动态绑定，就 this 的语意和 C++、Python、Java 是完全不一样的，如果你们用过早期的 react 的话，你会发现他需要一个 bind(this)。然后就经常会用错，因为你们可能不熟悉这个语言的机制。然后还有调侃的三位一体，God is the father，God is the son，God is the holy spirit。但是他们互相之间都不是，the father is not the son。

然后但是在这个 JavaScript 里面，你马上打开一个那个 F12 的那个控制台，你就可以复现这个行为，因为这个是 ECMAScript，标准规定就是这个行为，然后你会看到零，它可以等于空的 list，可以等于字符串的零，可以等于字符串的 whitespace。但是这些东西又是互相是不等的，就设计说一个这样的语言。然后你就知道这个是很坑程序员的，因为它 weakly typed 的动态又好用，但你一不小心留神写一个看起来对的东西。
