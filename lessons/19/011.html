用 Python generator 创建一百万个执行流

原片 00:25:30—00:28:00

那我们就进入第一个比较疯狂的事情，就是我们能不能让线程变得非常轻量化，也就是说我们有没有可能在操作系统没有任何pthread，就没有线程库，没有什么 pthread 的 create，没有什么 mutex lock 这些，所有的函数都没有的时候，你有没有可能依然实现 spawn 和 join。

然后你会发现有些编程语言里面还真的可以做这件事，比如说 Python，Python 就支持在一个线程，它其实没有创建多个线程的时候，同时维护好多个程序的执行流，这个语法的特性就叫 generator，这个特性很有意思，你看，我创建了一百万个线程，所谓的，对吧，一百万，所谓的一百万个线程。然后我用了这样的定义叫 T_worker。然后这个 T_worker 真的是一个线程，因为它是一个死循环。对吧，它是 I 等于 0。然后 I 等于 I 加 1。

generator.py 的画面代码；使用 Python generator 与随机调度。

import random
import resource

THREADS = 1_000_000

def T_worker(name):
    i = 0
    while (i := i + 1):
        yield f"[{name}] i = {i}"

threads = [T_worker(i) for i in range(THREADS)]
count = 0
while count < 10_000_000:
    current = random.choice(threads)
    res = current.send(None)
    print(res)
    count += 1

这是一个无穷无尽的死循环，所以如果你理论上说你是一个顺序程序，比如说你不是像我这样写的，你是一个 Print I 的话，对吧，如果你要做这件事，T_worker 一旦开始调用，它就永远不会出来了，你一次只有一个 T_worker 可以执行。但是第九行的时候，我有一个神奇的 Python 的关键词叫做 yield，注意我这次创建了一百万个，一百万个。然后这个 yield 每次都会说我线程是几，线程的名字。然后我线程的 I 等于几。然后我用第十一行的这个代码。我可以创建一百万个线程。

注意这时候他们还没有运行，我只是创建了，我调用，你看我调用 T_worker 的时候，他们被创建的时候，我创建一百万个线程，然后做千万次，我每一次都会选择一个 random choice 一个 thread，从里面选择一个线程的对象。然后把它叫成 current，我会给current.send，说你可以跑了，这个 current.send 相当于是函数调用，有点像，这实际上就相当于比如说我现在选了 T_worker，第一个 T_worker。然后我就相当于是把这个函数调用。

调过去，然后但是调用以后，很有趣啊，我这个 send 会调到 T_worker，调进去以后，它会执行第七行，第八行，然后到第九行的时候，这个 yield 会把当前这个函数执行的状态暂存下来，暂存下来，然后这个 yield 就直接会返回到它的调用者，会返回到这。
