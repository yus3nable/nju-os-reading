我们有 register，有 memory，那我就 fetch，decode，decode，exec，它就到下一个状态了，这是 deterministic 的，对不起，这样的 CPU 太慢了，还记得刚才我画了一个这样的例子，我说，有个状态，我要 x++，我要 x++，我要 x++，我要 x++，编译器可以把它合并成一个 x += 3，我们的 CPU 也是一个编译器，这就意味着。比如说我可以 move，我把 rax 写到 1 里。

然后我再把 2 写到 rbx 里，好，这两条指令，对吧，相当于 rax = 1 和 rbx = 2，这两条指令，确实可以不用顺序执行，不用一定要顺序执行，我是不是可以先执行这个，再执行这个？没有——，因为如果你的程序是顺序程序，这两个的最终的调换指令顺序的结果，一定是一样的，它只论结果。对吧，处理器只论结果，它只在比如像中断啊，IO 的时候，它能够保证正确的数据送到外面，就可以了，和这个程序和编译器，保证正确的数据送到 system call 里面是一样的，好。这下处理器干了一件非常牛逼的事情。它不仅可以调换他们两个的顺序，而且可以让这两条指令，在一个时钟周期里执行，比如说你们的处理器不是，就没有任何道理阻止你的处理器，可以同时 decode 的不止一条指令，对吧，你的缓存一个 cache line，64 个字节，我现在反正我取指令的时候，我都把一个这条指令给取出来了，我为什么不顺便把其他的指令，也全部都译码了呢？这个时候，我们的 CPU，不是刚才看的那个memory 和 register，一个简化的模型，而是 CPU 有一个很复杂的 internal。
