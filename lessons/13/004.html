并发、并行与两种执行模型

原片 00:16:26—00:19:31

在我继续，进入继续之前，跟大家澄清一个概念，你们经常会看到这个概念，叫并发和并行，对吧，因为当我们说，一旦我们的线程进入这个模型以后，它就是并发的，或者是并行的，然后并发和并行有一个比较微妙的差别，并发意义上是逻辑上的同时执行，你可能只有一个 CPU，你只有一个 CPU，那你每次就真的只能执行一条指令，一个单周期的 CPU，每个时钟周期，它就真的只能执行一条指令。

但是呢，如果你有两个程序，你可以让它一会儿，一会儿是 A 程序在 CPU 上运行，一会儿是 B 程序在 CPU 上运行，那 ABABAB交错执行，在一个比较长的时间尺度上，你看起来他们两个都被执行了，这个就叫并发，它逻辑上是在一个时间段上面，它都有往前的进展，但实际上有可能是，操作系统和运行库模拟出来的，一个轮流的执行。当然如果他们真的是同时执行的，比如说就是两个CPU，两个线程被加载到两个 CPU 上，它同时运行，但这个就叫并行。那是真正意义上的同时执行。所以如果你的程序是并发的，它可能是并行的，也可能不是，但如果你的程序是并行的，那么它一定是并发的，它已经在物理时间上面，就同时发生了，所以它一定也是并发的，然后在这里有一个挺有意思的，就是在刚才那个概念模型上，我有两种表示方法，一种是，你看我现在有 T1 和 T2。然后我可以选 T1 执行一步，也可以选 T2 执行一步。这是我刚才定义的，对吧，因为我现在有两个线程。然后比如说我现在 T2，T1 T2。然后我现在如果执行 Spawn。比如说 T2。T1 执行 Spawn。

它就会到一个状态，T1 T2 T3，对吧，就会到一个这样的状态，你的状态看起来是，是这样的，这样它就可以选 T1，选 T2，选T3，然后还有一个模型，更接近于实际 CPU 实现的模型，是你有 T1 和 T2。然后你走一步的时候，相当于是 T1 和 T2，就同时往前走了一步。但是你们也知道，实际的处理器，处理每条指令的速度是不一样的，对吧，你有的指令，你这条指令你 cache hit 了，它就执行的比较快，有的指令 cache miss，你就执行的比较慢。然后你有的 LoadStore 的指令。

它就天生就比你寄存器的指令，要慢一点，你的乘法和除法，可能就要好几个周期，所以这个模型在，我说选两个线程，同时执行一条语句，这个就有点过度简化了，在实际的系统当中，就真实的 CPU 上，你是很难理解，并行程序执行，到底发生了什么，因为你不知道一条指令，到底执行的多快，执行指令，这条指令执行的快和慢，是取决于你当前，整个系统里面，各种各样复杂的状态的，这里面我给魔鬼，埋了一个伏笔。当然你们可以理解这两种。对吧，在概念上可以理解这两种，理解线程的方式。好。
