然后如果我用 -O2，sum 又奇迹般的对了，为什么呢？对吧，同一份代码，完全相同的代码，在不同的编译优化下，他们的行为差距非常的大，为什么呢？我们让他读汇编，然后在 AI 开始计算的时候，我跟大家介绍一下，如果你想要控制，编译器的优化行为，你有两种办法。

当然这不是我们操作系统课上推荐的方法，所以你们不需要知道，不需要掌握，操作系统课告诉你们，是不要跟 shared memory 做游戏，你们所有的，我后面会讲到这种两个线程，同时访问同一个内存地址，叫做 race condition，数据竞争，数据竞争在 C 和C++ 里面，是 undefined behavior，是未定义行为，非常非常危险的未定义行为。当然你在确信这个代码，会编译成什么样的二进制的时候，你还是可以，有的时候还是可以利用这个特性的，但你可以通过插入一些不可优化的，叫 compiler barrier。

这叫 compiler barrier，刚才我们说，这个 SimpleC x++，这两个东西编译器是可以优化的，但编译器如果碰到比如说碰到 syscall，syscall 就是一个 barrier，这个代码就不能优化了，同样的，如果你有刚才一个 compiler barrier，这个 asm，clobber memory，这个叫 clobber memory，说这段汇编会，它是一个空指令，我要告诉编译器，我的这一段长度是零的，它可能会修改任意的内存。所以你在内存的意义上不可优化。

这样它就，这个优化就不能跨过这个边界，后面，大家就不能合并了，你用一个 compiler barrier，第一个叫编译器的 barrier，还有一种就是，你可以把一个变量标记成，不可优化，你不能通过合并的方式，把它优化掉，你可以把它标记成 volatile，你在访问一个这个 memory-mapped register 的时候，我通常也需要 volatile 的关键词，你想如果我要从我要从一个设备上面读数据，我要先读一个字节，把那个字节扔掉。对吧。我先。如果我的这个指针。
