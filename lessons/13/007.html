以及刚才我们说，我们至少可以很便宜的，写一些程序，或者让 AI 写一些程序，来帮我们验证，关于共享内存，多线程的这样的模型，与此同时，我们也可以问自己，多线程的程序，能不能用 GDB 调试呢？答案肯定也是肯定的，我就直接展示一下。比如说我加一个 -g 的编译选项，直接运行这个 GDB，他就说全部都结束了，如果你想要调试一个多线程的程序，首先我可以打断点，我可以在两个线程的，入口的地方。比如说都打上断点。然后我可以，这些 AI 都可以告诉你，因为以前我们上这个课的时候。

我的第一句话就是，你去 read the friendly manual，这是 GDB 的文档，你看 GDB 里面的 threads，才告诉你怎么调试，多线程的程序去读吧，但现在 AI 帮你读过了，所以你相对来说，我就展示一下就可以了。这个时候，我可以看，GDB 还有一个功能，叫 info threads，你们可能没有用过这个功能，info 里面可以看。好多好多好多东西的，对吧，你看我 info 后按 Tab，补全一下，可以看到好多有用的信息。有些你知道。有些你可能不太知道。

你花点时间去学一下，还是很有好处的，info threads，你现在可以看到现在的线程只有一个对吧，id 是 1，然后呢，一般来说，如果我们要调试，多线程的程序，我们会用这样的一个叫 set scheduler-locking on，它做的是什么呢？我们刚才说，线程有两种模型，一种是你可以选一个 T1，选一个 T2，选一个 T3，执行一步，相当于是我选 T1 的时候，所有其他的线程，都是不执行的，都被暂停了，还有一种就是，我说我每次。

(gdb) b T_a
(gdb) b T_b
(gdb) info threads
(gdb) set scheduler-locking on

所有的线程都是往前推进的，然后如果我默认的时候，它的 scheduler-locking，是 off 的时候，那我线程一执行一步的时候，线程二和线程三，还在往前执行，那可能会影响我们调试，所以我这个 set scheduler-locking on，是把我们的调试器，退回到这个模式，我们每一次。比如说我现在，可以正常调试它。对吧，我可以正常调试它。但是如果我 continue 的话，你看我 continue 的话，我的 main 函数。实际上是在 join 的，main 函数后面。

我可以 info threads，这个时候你就可以看到三个线程了，一二三，那我可以到 thread2 上，我到 thread2 上 continue，我就在T_a，我到 thread3 上 continue，它就在 T_b。对吧，我可以在线程之间切换，这样我就完美的把我们一个实际的程序。
