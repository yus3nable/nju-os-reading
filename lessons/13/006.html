第 13 课 · 多处理器编程：从入门到放弃

验证共享内存与线程栈

原片 00:23:52—00:31:12

有了线程库就可以写代码。第一次接触多线程，可以提出哪些问题？怎样修改 T_a、T_b，实现有趣的功能，加深对线程的理解？至少能做几件事。

可以验证线程确实并行、共享内存，以及栈相互独立。每个线程的栈都在地址空间中，有头有尾，究竟多大？这些问题能帮助理解概念模型。刚才提过，在指令级视角下，线程和进程的地址空间是平坦的，是从零到某个大数字的字节数组。一切由寄存器中的地址控制：栈有栈顶指针，也能对 main 取地址并打印。要验证，就自己写程序。例如这里有两个线程，分别执行 x++、y++。

#include <thread.h>
#include <unistd.h>

int x = 0, y = 0;
void inc_x() { while (1) { x++; sleep(1); } }
void inc_y() { while (1) { y++; sleep(2); } }

int main() {
  spawn(inc_x);
  spawn(inc_y);
  while (1) {
    printf("\033[2J\033[H");
    printf("x = %d, y = %d", x, y);
    fflush(stdout);
    usleep(100000);
  }
}

x 每加 1 后 sleep 1 秒，y 每加 1 后 sleep 2 秒。main 每隔一小段时间读取 x、y 并打印。在一个线程写、另一个线程读，如果能读到，就说明共享内存。运行后确实能看到结果。

x 增长比 y 快，至少能确信数据部分共享。类似地，也可以验证代码部分共享，以及线程栈位于同一个地址空间。例如定义局部变量 x_local，打印它的地址；还可以把指向局部变量的指针传给另一个线程，让对方访问这个局部变量，因为它们在同一地址空间中。这些实验能帮助理解线程。接着还可以问，栈是否独立、究竟多大？

直接问 AI“线程栈多大”，它很快就能回答。能不能写程序验证？也可以。我准备了 test_stack.c，用 probe 做无穷递归。

char * volatile low[N];
char * volatile high[N];

void update_range(int T, char *ptr) {
  if (ptr < low[T]) {
    low[T] = ptr;
  }
  if (ptr > high[T]) {
    high[T] = ptr;
  }
}

void probe(int T, int n) {
  char scratch[64];
  update_range(T, scratch);

  if (n % 10 == 0) {
    printf("Stack(T%d) >= %ld KB\n",
      T, (high[T] - low[T]) / 1024);
  }
  probe(T, n + 1);  // Infinite recursion.
}

void T_probe(int T) {
  T -= 1;
  low[T] = (char *)-1;
  high[T] = (char *)0;
  probe(T, 0);
}

probe 每次调用都定义一个不用的 scratch 数组，每个栈帧分配 64 字节，再无限递归。总有一次 stack overflow，线程就会 crash。递归过程中，把局部变量地址范围记录到 high、low 两个指针中。

update_range 持续更新见过的最小和最大地址。老师声称线程栈在地址空间里，虽然暂时不知道具体位置，但刚调用函数时，栈只用了一点空间，大部分仍可用。它可以从高地址向低地址生长，也可能相反；实际这里是从高地址向低地址生长。每次调用增加一个栈帧。

栈帧中有 64 字节局部变量，不断递归，总会 overflow。在溢出前持续打印最小、最大地址，就能观察栈大小，看到它逐渐增长。

不断探测 Stack T1、T2、T3，最后打印 T1 的 Stack 大于等于 8183。大家觉得栈多大？8183 离 8192 很近，即 8192 KB，所以每个新线程有 8 兆栈。这和日常程序的栈有所不同。

Linux 中，默认程序可用的栈几乎无限，可以一直向后用。但每个线程的栈都位于地址空间中，创建时就必须决定大小，分配一段内存。至少现在知道这里是 8 兆。也可以让 AI 阅读、理解、运行这个代码。

它还能解释结果及原因。
