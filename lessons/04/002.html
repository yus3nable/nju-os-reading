Agents：推理、工具与工作区

原片 00:18:24—00:38:09

def main():

比如 lecture notes 函数，会自动生成课程主页上的讲义。回到刚才的话题：语言模型根据前面看到的全部内容，形成接下来的输出。

其中有一个 attention，也就是注意力机制，帮助它关注与当前任务有关的重要词，再确定下一个词。输出当前词时，后面许多词可能已经大致想好了，神经网络研究者经常研究这类现象。未来仍有不确定处，但当前词想清楚时，后面可能也已比较明确。这像翻译，我觉得也很像人。

我写代码、在物理世界解决问题也是如此。比如想今晚吃什么，脑中有问题、当前位置、当前心情，再继续往下思考。这个架构很符合人的思考过程，于是大家自然往模型上加能力。比如怎样让模型看到图片？

每个词，准确说每个 token，都会表示成向量，里面可能有 0.35、0.01 等数值。想看图片，也可以把 16 乘以 16 的一块图像变成向量，再处理下一块 16 乘 16 图像。这样就加入了另一种感官。OpenAI 做出 GPT-4o 时，我们觉得尝试很有意义：声音、图像等感官都对齐到同一空间。刚才说大是必须的，语言又是人类几万年形成的世界模型抽象。

把其他信息对齐到语言模型学出的表示，完全有可能，AI 也就有了眼睛、耳朵。之后还能给它草稿纸。我很喜欢一个给研究生的建议：做研究时，所有东西都只放在脑中，就只是有限状态机。

因为脑容量有限。但有了 paper、pencil，就像图灵机，有无限 working memory，计算能力便有区别。无限内存和有限内存的计算机，能算的东西并不相同。这是在劝大家记下想法、多做推导。语言模型也能这样，即使 context 并非无限，随着长度增加，也能一步步解决问题。比如 123 加 456，早期 ChatGPT 连加法都算不对，更别说乘法。但小学就知道，可以展开成 100 加 20 加 3，再加 400 加 50 加 6。竖式放在二维平面上，对人易懂，文本里也能做。模型先关注 123 加 456，把它像翻译一样展开，再关注百位、十位、个位，写成 100 加 400、20 加 50、3 加 6。

接着关注相邻的加法，逐个加起来。虽然心算可以直接给答案，展开看似绕路，却降低了训练心算的难度，不必用大量数据逼模型记住每个加法。

一步步展开，每次只关注要加的两个数，暂时忽略其他项，就是今天 thinking model 的思路。我觉得看 DeepSeek 的 thinking 过程挺有启发。问开放问题、期末题等难题时，它像人一样，先有直觉，尝试一种办法，推导后发现错了，再从头来。只要 self attention 训练得好，就能这样做。GPT-4 时代，加一句 think step by step，就能明显提高复杂任务表现，当时经常用，现在已经不需要。还有两个早期著名工作，ReAct 是姚顺雨的 paper，另一个是 Toolformer，教模型使用工具。123 加 456 可以展开，但遇到 123 乘以 456，人会本能地拿计算器。

把 123 加 456 敲进去、按等号，得到多少就抄回来，相信结果正确。模型也能学会，只要提供训练数据，让它输出特殊 token，比如 python，再写 123 乘以 456，运行后把结果贴在后面，就像自己按计算器。到今天，模型已经有眼睛看图、耳朵听声音。

这些能力都在语言这个世界模型上建立，再加计算器，就像活生生的人：会推理、犯错、纠错，尝试新办法，最后做对。以前操作系统课还会讲一个我很喜欢的纠错工具，甚至带过大四同学做毕业设计来加强它。人也像这样的模型，容易有幻觉、犯小错，工具可以帮助修复。

比如这里打错字，用一条命令，就能根据之前的命令历史提出修复。需要权限时，也会帮忙补上。

这是大模型以前的技术。大模型出现后，它们都被取代了。今天直接在 Claude Code 里说想做什么，AI 自己写命令，也会犯错，再按类似流程修复：尝试命令，查看结果。

LLM Agents：工具、上下文、工作区与循环

根据结果判断怎样修复。今天得到的是一个很全能、智力很高的模型，也就是能够 predict next token 的概率分布。它根据任务和已经做的事情，判断下一步。怎样充分使用这种能力？假设转生到异世界，导师成了宠物，给什么 instruction 都会 follow，该怎样用好这位导师？

先给它 workspace。它像人一样能尝试、会犯错，通过反复尝试推进进度，所以需要较大的 working memory。计算机里，一个目录、一个 workspace 就可以。里面放 README，做大任务就准备 docs，不同模块写不同 docs。

还可以放源代码、tests。软件工程多年的 best practice，刚好给 AI 准备了环境。我觉得 Git 简直像为它设计的。我曾问来保研面试的 candidate 什么是 Git，很多人回答是从互联网下载代码的软件，让我一时无话可说。Git 是分布式版本控制软件，更重要的特点是管理目录快照，有点像 persistent data structure。工作区可以任意修改，再提交。

无论改成什么样，都能回到过去的快照，丢掉不要的东西，也能 cherry pick 某些需要的改动，在另一个分支继续，像许多平行世界。大家玩过“死亡循环”吗？大模型也有类似处：每次启动，只有训练好的参数，可能再加 system prompt，之后开始对话。它没有 short term memory，而项目、过去的尝试、日志又太多，无法一次全部放进上下文。

像游戏里每天从同一地点醒来，丢掉所有记忆，再探索世界，被打死后下一天重来。模型每次开始，也可能面对一个看似全新的 repo，虽然之前已改过很多次，再根据任务继续修改。怎样完成现实任务呢？

收到任务，先规划。比如实现操作系统，先列 ABCDE，做一个粗 plan，再细化各项，把计划写入文件系统的 plan.md。用 markdown 记录第一件、第二件、第三件事，完成后打标记。下次上下文清零、重新打开项目，仍能看到做过什么、接下来做什么。人类开源项目也这样管理，规划近期、远期 milestone，逐个增加功能。

执行计划时，经验程序员会写代码、写测试，运行工具，用 lint 找低级错误，用单元测试判断实现是否符合预期，出错还会加 printf 调试。理论上，这些工具的使用和调用计算器一样，模型都可以做。

这样就容易理解课上 coding agent 的操作，也能理解小龙虾为什么必然会火。用目录、工作区管理 memory，其他人同样能用。学生学大学数学，可以放每个 lecture、知识点、习题和作业完成情况，做错题还可以记错题本。打开 Claude Code，就能问下一步学什么、复习薄弱处，或期末时准备模拟题。也可以让它上网、到 QQ 群发消息找往年题，找到后存进目录。

程序员熟悉的这种方式，也能管理日常其他事情。我早就把个人文档放进 database，用 repo 组织，再打开 Claude Code 请它帮忙填表。接上 Telegram 这样的前端也可以，它官方支持 bot 接口，就能用手机对话，比如让它发一个数学题给室友。

它可以从库里找到自己的数学学习经历，再给室友发题，challenge 一下。也能设置 cron job，UNIX 的 crontab 是一张定时任务表，可以每天备份、每小时播放声音，或每天早上七点自动抓天气预报，存入 memory，也就是 repo。

今天这些热门产品有历史上的原因，不必太惊讶。
