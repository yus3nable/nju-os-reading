C 语言与可移植的标准库

原片 00:23:10—00:29:45

这就是 C 的完全体了，它有指针，数组结构体，函数调用这些最基本的语言成分，或者是一个 SimpleC，SimpleC 再加上一个Foreign Function Interface，这就是可以实现世界上所有的东西。对吧，我可以调用一个系统，当我可以调用系统，调用以后，你在应用世界上看到的所有东西，都是可以实现的，所以这就有了我们一层一层的，像洋葱一样的，整个应用生态的世界。

对吧，它和历史，计算机系统发展的历史也是很像的，在 1950 年代的时候，就只有汇编语言，你所有人都被迫用汇编语言，或者说用戳孔的方式来写代码，但是到 1970 年代的时候，你用汇编语言编程就是行为艺术了，对吧，就是一个没有必要的，可能只有少量那种和机器相关的代码，才需要用汇编语言，但绝大部分的代码，像那个时候，C、Pascal 都开始普及了，有一个叫结构化程序设计，你们可能听说过，听说过这个我觉得今天在 AI 的时代，结构化程序设计又重新。不能叫死灰复燃。应该叫复活了，它告诉我们，如果你要设计一个软件的话，就要先把它分成比较抽象的几个部分，然后再逐渐 refine，refine，然后这个就特别适合，vibe coding，对 1970 年的时候，也有 UNIX，也有了 C 语言。所以在那个时候，C 语言是一个非常，非常重要的生态，生态入口，你只要，你只要用 C 语言写代码，你就可以在 UNIX 上运行。这是一个非常好的，好的特性，但到 2010 年的时候，又有意思了，C 语言又变成古法编程了，只有在，在学 computer science 的人。

就像只有学汽修的人，才去学这些东西，然后开汽车的人，人再也不知道，这个汽车是怎么，怎么构造的，虽然 C 语言在 2010 年的时候，还是一个很好用的，相当好用的编程语言，经久不衰，但在 C 的上面，又已经长出了，像 Python，C 上长出了 C++，C++上长出了 Java，长出了 Javascript，C 上又长出了 Python，这个语言长长长长长长，以后，大家更多的程序员，就不需要再用，那么底层的方式编程了，到今天。比如说我们用高级语言编程。都已经成为行为艺术了。

大家都调侃，我们是，每天都在做古法手工编程，对吧，非遗技能，在今天，我们绝大部分时候，都用自然语言编程，但我们不要忘记的是，我们在今天，能做自然语言编程的原因，是 C 语言给我们构建了一个一层一层的世界。对吧，你看我们刚才说，我们有一个Assembly。然后有这个 Foreign Function Interface。然后以及，有个 SimpleC，的模型，而就是这样的一个非常非常小的模型，它已经被标准化了，C 语言是有标准的，有 ISO C 的标准。它告诉你。

SimpleC 的语法语义，以及不仅是 SimpleC，一个更复杂的 C，然后在这个上面，还有 libc，然后还有 POSIX，这个叫 Portable System Interface，而这些，这个底座，这个世界底座。当然在这个上面，又长出了什么，Python，JavaScript，各种各样的东西，以及上面的所有的，比如 Android 的这些生态，Java，Java 上面还有 Android，我们的 C 世界，是有 ISO 标准的，这意味着什么呢？

你一旦我有了标准，大家都会倾向于，去努力的遵守这个标准，而且这个标准，它的制定，也不是为了为难你，是为了让大家，能够在一个共同的体系下说话，而这个稳定可靠的标准，你就不用担心，升级版本，你的实现会破坏，如果你用 JavaScript，Python，你今天开发一个东西，很爽，等到明天，它的 dependency 就 break 了，你当你迁移到新的 dependency 的时候，你的程序，可能就跑不起来了。然后你还得让 AI 给你修。然后修成了什么样。你自己也不知道。你的软件其实是一种，处于一种失控，能用但是又失控的状态，但 C 不是，C 代表了这个传统世界，非常经典的，这样一层一层一层的，抽象的最底端，你有世界上最好的移植性，比如说如果你只用，C 里面最小的那些部分，那么你的程序写一份。比如说你写一个算法，是 breadth-first search，或者写一个甚至是一个比如说图形界面库，你可以从比如说一个数据结构出发，去渲染出一个图形界面。当然可能你是像素级的渲染，最后你需要一个什么样的后端，但你如果是用 C 语言写的，它就世界上最好的移植性。

从你的电脑，超级计算机，到手表，手环，到那个非常非常小，只有 1KB 内存的设备，它都可以运行，前提是你用，前提是你用符合，这个 ISO C 的方式，并且以一个 portable 的方式去写程序，比如说你不会假设，一个 int 是几个字节，一个 int，其实实际上是有可能是，在你的小型的机器上，一个 int 是两个字节，16 个 bit。对吧。当然在今天的机器上，不管是 32 还是 64，它都是四个字节，32bit，但其实 C 的标准，规定了很多。为了移植性。

规定了很多，然后在 C 的上面，还有 POSIX，比如说像你的，unistd.h 里面，它有像 Fork，pipe，这些函数，以及它的行为，都是POSIX 标准所规定的，几乎所有能用的操作系统，从比如说 Linux，我的 Mac。然后你们的鸿蒙，OpenHarmony，和你们可能有，不知道有没有同学用，不太好用的华为手机，生态上稍微是差一些但是所有的，你能看到的这些系统，基本上都兼容，首先，它必须要有一个 C 编译器，因为它有 C 编译器。就意味着它可以编译。

别人写的东西，而且别人写的东西，几乎以一个不用修改的方式，就可以在它的系统上面，完整地运行起来，然后它再执行，给一个POSIX 层，像这些 pipe，execve，这些函数，如果有这些函数，它就可以跑一些应用程序，不管是服务类的，还是比如说像，你的coreutils 里面那些，核心的命令行工具，它都可以跑起来，像我上课的时候，讲过一个叫 Busybox 的，一个小工具集。然后在像Android，和你的鸿蒙系统上面，包括 Harmony OS 上。都有一个 Toybox。

一个小的命令行工具集，它就是在 C 和 POSIX 的，接口上实现的，所以基本上是，你可以在世界上的，任何一个还有一定复杂性的设备上，找到 C 的身影，即便可能你不是，直接用 C 来编译。
