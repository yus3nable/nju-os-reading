第 09 课 · C 标准库原理

环境变量与 environ

原片 01:12:05—01:20:45

libc 还封装了进程运行环境。刚才通过 LANGUAGE 环境变量影响了程序行为。environ 手册介绍了 libc 中名为 environ 的变量，通过它可以得到 key 等于 value 的环境变量。

execve 系统调用可以向 main 传递 envp：C 程序的初始状态除了 argc、argv，还有 execve 时指定的 envp。用来 execute file 的函数有一系列，有的带 e，有的不带。带 e 的函数都有 envp 参数，大部分时候却不需要它，例如使用 execl 或 execvp，可以执行指定路径的文件并传入 argv。

这时环境变量来自哪里？Unix 的设计是，默认由子进程继承父进程环境。底层 execve 系统调用必须指定完整的参数和环境变量；使用刚才那些 libc API 时，则默认继承父进程环境。

如果当前进程设置了 LANGUAGE，它就会传给所有子进程。例如 login 登录时知道用户语言，就把语言放到环境变量中。之后生成的 Shell、Shell 再 fork 的 Shell，以及 fork 的应用程序，整个进程树都带有 LANGUAGE。

只要不修改，它就能让这个用户看到英语；登录另一个配置法语的用户，error message 就是法语。环境变量看似只是操作系统传递参数的机制，却在不断复用。UNIX 经历了长期锤炼，虽然有些机制被滥用，但环境变量继承、进程树、fork 这些微小设计，逐渐发展成大家觉得还算好用的状态。

environ 在内存中是一个变量，与 stdout、stderr 一样由 libc 提供。libc 提供的只是这个符号，理论上可以用任意方式定义它，当然这里给出的定义才符合类型。

libc 还提供 end 符号，也可以定义成任意类型，像这样定义也合法。运行 end = NULL 的程序，可以看到正常中止，没有 crash。

随便写一种类型也可以赋值。这个函数给 environ 正确赋值了。这带来一个问题：它是 libc 提供的变量，对应一个符号，进程加载到内存后，它在地址空间中一定有地址。它的类型是 char **，是一个八个字节的指针。谁给它赋值？根据 ABI，也就是 Application Binary Interface，进程初始化或 reset 以后，参数、环境变量都放在栈上。地址空间随机化使栈地址不确定；除 Binary 指定固定加载位置的内容外，其他动态加载内容的位置也不确定。

每次运行时参数和环境还不一样，所以指针值也会不同。可以修改代码看看：取 environ 的地址、打印 environ、dereference environ，各自会得到什么？这些操作都合法，先取 environ 的地址，就得到一个地址。

图 87：分别打印 &environ、environ 和 *environ（01:18:04）。

env.c 中新增的三行

printf("%p\n", &environ);
printf("%p\n", environ);
printf("%p\n", *environ);

0x420108 对应 environ 这个 8 个 byte 变量的地址，刚才说成了 8 个 bit。它应该在数据区，准确些说应该是 BSS 区。调试时取 environ 的地址，与终端中刚才输出一致，取出的类型是 char ***。但进程刚启动时，打印 environ 得到零，这是对的：进程刚加载到地址空间，还不知道环境变量在哪里。libc 在背后做了很多工作，可以打一个 watchpoint 看看。

设置 watchpoint 后，可以看到是 __init_libc 在赋值。可惜今天没有准备好源代码，调试时翻车了；这些都是 musl libc 中可以调试的代码。

GDB 中两次缩写命令失败后设置观察点

(gdb) w environ
Cannot use this setting with the "with" command
(gdb) w environ
Cannot use this setting with the "with" command
(gdb) watch environ
Hardware watchpoint 1: environ

这些代码实际上都是 C 代码，可以在 musl libc 中找到 __init_libc。_start 接管第一条指令后，最终会调用到它。

environ 就由这段代码赋值。计算机系统没有魔法：C 世界中的操作围绕 SimpleC 模型进行。System V ABI 规定初始的 Initial Process Stack 布局，剩下的工作由代码完成。__init_libc 第一行的 __environ 等于 envp，正是 WatchPoint 停住的那句话。执行后，environ 指针就指向栈上正确的环境变量。这是对环境变量的补充。
