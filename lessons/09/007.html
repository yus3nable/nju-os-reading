第 09 课 · C 标准库原理

Freestanding：类型、宏与可变参数

原片 00:36:48—00:45:20

今天带大家看 libc 中的各种封装。Int、Long 类型与机器字长有关：32 位机上的 Long 是四个字节，64 位机上是八个字节。C 也允许定义 int64_t 这样的类型。

此外还有 int32_t、intptr_t 等与机器相关的重要定义。不同机器对 Float 浮点数的实现也不一样，Limits 则告诉我们各种整数的范围。这些库无需任何系统调用就能使用，对应 C 中的 freestanding 环境。看一下手册，这是 CPP reference，我觉得其中关于 C 的内容比较精炼，感兴趣可以课后阅读。这里同时讲 C 和 C++，两者一定程度上共享这些内容。程序有 hosted 和 freestanding 两种模式。hosted 有很多 FFI，类似对汇编的调用；这些汇编会进一步调用操作系统。

例如，执行 fopen 打开文件，需要持有一个文件描述符，必须通过 open 系统调用得到合法的文件描述符。没有操作系统，程序就无法运行。但 C 也可以用来实现操作系统：通过 inline assembly 直接执行指令，例如访问硬件，就可以开发操作系统内核，这叫 freestanding 环境。

还有 inttypes.h：想用 printf 打印 64 位整数，马上会发现无法直接确定格式；打印 32 位整数，到底用百分号 d 还是百分号 ld？百分号 d 打印 int，百分号 ld 打印 long，但具体大小随机器变化。32 位机器上的 ld 对应四个字节，64 位机器上对应八个字节。打印 int32_t，该用什么格式字符串？freestanding 环境或需要兼容性的程序会用到这些宏，stdint、inttypes 中提供了答案。

inttypes.c 中的格式宏片段

printf("int32_t: %" PRId32 "\n", si);
printf("uint64_t: %" PRIu64 "\n", ul);
printf("intptr_t: %" PRIxPTR "\n", intptr_x);
printf("uintptr_t: %" PRIuPTR "\n", uintptr_y);

例如 PRI 系列的 macro：PRId32、PRIu64、PRIxPTR，也就是百分号 x 的 pointer，以及 PRIuPTR。运行后，可以看到不同类型被正确打印。

还可以用 gcc -E 或 musl-gcc -E 查看 inttypes 的宏展开。展开前，uint64_t 这一行由带有 uint64_t、冒号和百分号的字符串、一个宏和 \n 组成。

预处理后的一行代码

printf("uint64_t: %" "l" "u" "\n", ul);

展开后变成了字符串拼接。在 C 和 python 中，把两个字符串常量直接写在一起，语言就会拼接它们。编程语言中的这些机制相互配合：C 允许这种 ab 的写法，在很多地方都用得上，因此能够写出这样的代码。freestanding 环境还有很多类似功能，例如 offsetof(T， m)。

课后可以查 offsetof(T， m) 的手册。它给出结构体某个 member 相对于结构体头部的 offset。例如，struct foo 中有 int x、int y，成员按照从左到右的顺序排列。要知道 y 相对于对象头部的地址，可以用 C 实现：把地址 0 强制转换成指向 struct foo 的指针，就好像 0 处有一个 struct foo，再引用它的 member。这里只是移动指针，不会实际 dereference，也就是解引用这个指针。

再取这个成员的地址，转换成整数，就得到 y 相对于对象头部的 offset。因为相当于对象位于 0，取出的地址就是偏移量。当然，编译器可能提供 built-in 方式，更好地实现它；这个操作在 C 中完全合法。还有很多这样的宏，感兴趣可以课后看。我在大家这个年纪时，就喜欢看这些奇怪的东西，有些记住了，有些没记住，久而久之也积累了一些概念。

freestanding 环境还有 stdarg.h，用来处理变参数。看看 printf 的代码，它可以写任意多个参数，12345678。

计算机系统基础课有没有讲过这个机制？在 32 位机器上比较简单，calling convention 把所有参数都压入栈中。调用函数时，参数在栈上形成一个数组，依次是第一个、第二个参数等。在 x86 上，只需取第一个参数的地址作为指针。例如这里写 int printf，假设类型正确，arguments 就可以通过第一个参数的地址得到。

现场尚未写完的声明

int printf(const char *, ...)

现代体系结构上，这个 hack 不管用，因为大部分参数通过寄存器传递，例如 RDI、RSI，参数都不在内存里。标准库会与编译器协作，生成正确的汇编代码，在变参数情况下把需要的内容放到内存，使我们能用 va_list、va_arg 这套宏访问多个参数。
