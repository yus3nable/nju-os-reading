第 18 课 · 并行算法和数据结构

几乎不需要通信的并行任务

原片 00:35:45—00:40:32

还有一类问题叫 embarrassingly parallel，“令人尴尬的并行”，名字不太好，意思是整个计算图几乎无需同步、通信。对比物理模拟：从 T 等于 0 到 T 等于 1，后一时刻的网格计算可能依赖相邻网格。

这样按 T 等于 0、T 等于 1、T 等于 2 逐层计算，已经可以很好并行。embarrassingly parallel 的计算图更简单：一次放出几百万、几千万个任务，最后汇总结果即可，很容易并行。

先划好任务，分别放到第一个、第二个、第三个计算机或线程上，就能 scale up and scale up。课上展示过很多例子，例如 tree search：下围棋第一步有十种下法，第二步也有十种，就有一百种、一千种、一万种。先用一个或几个线程搜索十层。

就会产生很多搜索子树，可能［听辨不清，00:37:38］，达到几百万、几千万个，再分配到机器上。前面划分方法较复杂，之后就是 embarrassingly parallel。我们实现过 fork-based DFS，可以直接参考答案。现在也可以让 AI 写，只要知道搜索子树能并行，提出这个要求。

只让 AI 用 Python 搜索，它会写顺序程序；指出可以用 fork-based DFS，它就能写并行版本，用好 CPU 的十几个线程，确实可能快十几倍。20 核 CPU 加速十倍，一分钟的任务只要六秒钟，差别很大。等五六秒还没出来，通常就会做别的事。我用 Claude Code 时也会这样，办公室机器设置了 hook，每当它 trap 到用户输入，就叮一声提醒，平时可以放在后台。这台机器没有设。现在 GPT、Codex 也有 pet，可以在桌面提醒运行结束。

任务从一分钟降到五秒钟，就不会打断思路，可以马上修改、继续操作，所以十几倍加速也很值得。除 tree search 外，还有 Monte Carlo 算法：为了逼近或拟合概率分布，不断独立采样，再估计均值等特征。例如未知分布，要估计随机变量均值。

采样一千万份，相加再除一下，就是 embarrassingly parallel。每次 Monte Carlo 采样独立，可以在第一、第二、第三台计算机各采样一百万次，实现 scale up and scale out。视频编解码也是例子：划好关键帧后，相邻关键帧之间的视频独立。

可以分给两个线程或两台机器处理，这些都是高性能计算的常见模式。
