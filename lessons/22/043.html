ioctl 承载设备配置

原片 01:07:48—01:11:30

这里面有一个系统调用，叫 ioctl，ioctl，如果你看它的手册的话，它告诉你，它说我的 control，我的控制，这个 api，是可以用来对设备发送一条设备相关的指令，它说，比如说你的终端想要改变一个大小，或者改变一个模式，你都是可以用 ioctl 来的，然后，那么，这就是所有的非数据的，不是这种 data 的设备的功能，全部都是用 ioctl 实现的，所以，仅仅这一个 api，就包含了巨量的复杂性，所有整个设备驱动世界里面，所有的复杂性都在这。然后 ioctl 这个系统调用。它的参数，是以不加解释的方式，就这些东西是以不加解释的方式，直接送给设备驱动的，因为，我们的应用程序，它可以写一个奇奇怪怪的结构体，然后我们的设备也是，甚至是对吧，是总线上的，你在，你的总线的设计者，在设计这个总线，设计这个接口的时候，甚至不知道这个设备会有什么样的功能。对吧，就现在是一个 GPU，下次可能是一个我自己发明的 GPU，也可能我自己又开发了一个 GPU，FPGA 的联合体，或者任何一个比如说核弹发射器，都是连到我的总线上的，那这个时候怎么和这个设备对话。

那就只有这个应用程序和设备驱动是知道的，对吧？我的厂商会发布一个应用程序，你们有没有买过那种，比如说能支持宏编程的鼠标，这样的东西，对吧？然后它会随机附带一个应用程序，然后那个应用程序你可以做配置，然后配置完以后应用程序又会和设备驱动再通信。然后这个设备驱动会把这些配置给生效，而所有的这一切都是用 ioctl 来实现的，它包含了比如说像打印机的卡纸，清洁自动装订。对吧，这些各种各样的配置的功能。然后你们的键盘可能有跑马灯。然后你的键盘。或者说你打比方。如果你想给一个TTY。

你自己做了一个 TTY，然后你想给这个 TTY 做一个跑马灯，那 TTY 它本质上还是一个终端，所以你还是得对吧，从里面读数据往里面写数据，还是一个终端，但是如果你要支持一个跑马灯，那对不起你就需要用 ioctl。然后你需要加一个额外的特别的字段。然后这个字段等于特别值的时候，就是一个跑马灯的控制，亮暗或者怎么跑。然后再比如说你磁盘的一个健康状况，它的缓存控制这些配置，全部都是用 ioctl 实现的，所以这是一个水面下的冰山，arguments, returns, and semantics of ioctl vary。

according to the device driver in question，所以比如说一个核弹发射器，刚才我展示的那个核弹发射器，是 password 的，你完全也可以用 ioctl 来实现核弹的发射，对吧？你可以不用 read 和 write，你可以用 ioctl 来说，用 ioctl 写入一个特定的字符串，来向内核询问核弹发射器，也可以 ioctl 写一个密码。然后把这个核弹发射出去，而且实际上对于核弹来说，用 ioctl 是正确的更正确的方式。

只是刚才那个驱动我用来展示了，我可以用来，我可以用 override 的这个 struct file 里面的 read 和 write 的 operation，我就得到了一个读写设备的能力，好。所以 ioctl 就是一个完全堆叠的屎山。
