第 07 课 · 访问操作系统对象；文件描述符

匿名管道与文件描述符的继承

原片 01:16:10—01:20:09

UNIX 里 ls pipe 给 wc，不需要创建匿名管道——说错了，不需要创建命名管道。它使用幻灯片上的匿名管道接口 int pipe。

pipe 返回两个文件描述符。我觉得 C 的 API 有点难用，需要先定义长度为 2 的 pipefd 数组，看看示例。

高级语言在这方面更方便，Python、JavaScript 可以用类似 readport、writeport 等于结果的语法。C 则要传入两个元素的数组。pipe 会在系统里创建管道，有读口、写口。

管道没有名字。假设 0、1、2、3 已占用，再分配两个描述符，比如 4、5。

int pipefd[2];
if (pipe(pipefd) == -1) {
    perror("pipe");
    exit(EXIT_FAILURE);
}

一个指向读口，一个指向写口。返回数组的 pipefd[0] 是读口，pipefd[1] 是写口，也就是返回两个描述符。

fork 后会更复杂，因为所有文件描述符都会继承。

子进程也有相同的 4、5，分别指向同一读口、写口。图画得有点乱，先不看。代码第 39 行定义 pipefd，第 42 行得到两个描述符，一个读、一个写。

fork 后双方都持有它们，再分别决定父子进程的操作。今天可以直接调试示例，不必只靠读文档、画图。程序状态随时能查看，刚才也看过进程打开的文件，因此能知道父子进程各有什么对象。

知道管道读写口的持有情况，就能画出关系图。
