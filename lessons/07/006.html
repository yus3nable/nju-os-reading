第 07 课 · 访问操作系统对象；文件描述符

文件系统目录与 UNIX Philosophy

原片 00:30:35—00:42:42

文件抽象有用，everything is a file。那么文件系统里有哪些内容？FHS，也就是 Filesystem Hierarchy Standard，规定了目录层次，可以让 AI 帮忙读。

ls / 能看到 home、dev、boot、usr、sys 等目录。大部分 Linux 遵循这个结构，也有例外，macOS 就不遵循。标准让不同系统上的知识可以复用，知道文件大概在哪里。

以前教计算机系统基础，新手第一次接触 Linux，细碎的目录知识很难讲。让大家查手册或读鸟哥的 Linux，借来一看那么厚，很容易放弃。过去要自己从整本书、搜索引擎博客里筛选所需内容。

今天 AI 可以帮忙找出相关知识，比如 proc 是包含进程、内核信息的虚拟文件系统，srv 放服务数据，sys 也是虚拟文件系统。

usr 是用户程序、数据等，感兴趣再追问即可。有这样一个能存放各种信息的文件系统，UNIX philosophy 就能发挥作用。Keep It Simple， Stupid，KISS principle，有三个要点：每个工具做好一件事。

比如 grep、sed、awk。工具要 work together，还要 handle text stream as a universal interface，以文本流作通用接口。textual interface 既方便人读，也方便机器处理，比如 proc 下 10718 的 maps，与 Windows API 返回形式不同。

像刚才 OJ 的比较，文件系统方便直接 hack。文本可读性的代价是降低性能。我觉得在 1970 年代，每个时钟周期还很贵时，选择这种 tradeoff 很勇敢。power user 看到文本就能理解。

Windows 则返回数据结构，其中有字符串、指针、16 进制数，需要再解释。当然也能接一个工具，把 API 结果翻译成文本。过去在 Windows 获得 UNIX 环境，有 Cygwin，现在也已经过时了。

UNIX 可以直接用文本访问工具输出和几乎所有文件，部分设备确实是二进制，属于例外。这是很有前瞻性的设计。

当时没有预想到大模型，而文本正适合它。Claude Code 这类 Coding Agent，在自然语言预训练模型上微调，既能理解命令行输出，也能写命令。刚才它一直调用 Bash。

每次 Bash 又组合几个小工具，命令也像自然语言。比如这个例子，要换 Bash，Fish 不支持这种语法。用 shell 通配符，查 /proc 下所有进程的 status。

从中找 VmRSS Field，就能以 Quick and Dirty 的方式得到物理内存占用。再通过管道交给另一命令，把各进程 VmRSS 求和。

UNIX 命令与文本接口，支持这种接近自然语言的表达，PowerUser、Hacker 写起来很快。我想理想形式可能是脑机接口，脑中想到任务，立即执行。

grep -s VmRSS /proc/[0-9]*/status | awk '{sum += $2} END {print sum " kB"}'

再把结果直接传回脑中，有点可怕。这里求得全部进程物理内存总和约 2.369 GB。还可以对照 free 查看系统剩余内存。以前要花很多时间讲 free 输出格式，现在 AI 能解释。

它调用 free，还直接读 /proc 下的 meminfo，有点出乎意料。文本接口让它能直接获取信息，原来 free 就从这里读取。系统有许多对象。

进程状态、内存、系统状态都作为文件，平常的 .c、.markdown 也一样，能复用统一工具。管道把一个程序的输出接给另一个作输入，今天会讲相应 API。这样对象、数据和工具都能组合复用，在自然语言和编程语言之间取得平衡。还有一本 Unix Haters Guide，讲这种设计的问题。现在访问被拒绝了。

可以另找这本吐槽 Unix 的书，它提的问题都是真的。Windows 接口结构化、规整；Unix 的文本需要解析，就有各种麻烦。Windows 文件名有空格，通常不是大问题。

Unix、Linux 用户却常避免文件名空格，宁可用减号。空格会被 shell 分成多个参数，需要加引号，否则传给其他工具就可能错误。GNU、Legacy make、Makefile 至今也不能很好处理。

还要再叠其他办法解决。现在 agent 好像也在反复执行命令。

先不看它。UNIX 允许快速写出 dirty、大致正确的命令，帮助 hacker 完成工作流。我觉得它也逐渐完成历史任务，成为大模型语料。GitHub 上的代码也是如此，程序员可能亲手推动替代自己的技术。Agentic AI 时代，脚本语言会成为历史，UGH 吐槽的诡异行为，很多都来自这种取舍。

quick and dirty type 容易有这些问题。模型如果能快速、准确生成 token，写出 strongly type 的 Python 或 Rust，就能写好 Parser 来 parse 内容，甚至直接用 API 获取准确内核数据，再转换为需要的形式。但 Unix philosophy 中的组合、复用仍有启发。

everything is a text、everything is a file，对今天的大语言模型也很友好。
