操作系统中的对象与 API

原片 00:10:09—00:17:42

所以我们再回到应用程序开发者，我们一直说，操作系统其实是给人，给开发者提供服务的，那我们再想一想，你们写过很多大作业，比如说你们好像在，高级程序设计的时候，要写一个游戏，还是类似的东西，那你们在写这些程序的时候，除了比如说写一个算法，那就是把一个数据结构，变成另外一个数据结构。对吧，把一种数字，或者一个打包好的数字图，这样的结构，变成另外一个结果，结论性的东西。比如说你要做个 AI，你可能要做一个棋盘上的计算，做一个状态空间搜索，除此之外。其实你还希望的是，你请求。就你要调用一个库函数，来完成一个不是计算类型的任务，而这些任务，大部分背后，它都有一个操作系统，比如说你想要去，网，发出一个网络请求，比如说我可以让，让我的 coding agent，去读一下那个网页，我有一天，让我的 coding agent，去读那个POSIX 的一个手册。然后说命令行参数的，规范是什么样的，那如果你要读取，一个网络请求的话，你这件事情，确实是要交给别人，一个库函数，和操作系统一起做的，然后包括你还想要，写入一个文件。还要想和其他进程的通信。

我刚才讲过，它这些事情的本质，都是去访问，操作系统里面的对象，所以你在这个程序员的脑袋里面，你写的想的可能是，比如说如果你要，去实现一个游戏修改器，对吧，我上节课的游戏修改器，那你就想要做这件事，你脑袋里面，你脑袋里面想的，其实不是什么，FD 等于 open 什么什么，虽然你们上，计算机系统基础课的时候，已经讲过 FD 等于 open 什么什么，你想的其实是一个更加面向对象，一个比较抽象的，对吧，你就想用 pathlib，Python 的 pathlib。把 proc 下的，1234 下的 maps。

当文本读出来，这是你想做的事情，当然背后，底下它做了什么，这是我今天的内容，以及比如说你想要，甚至你想要一个更加舒服方便的接口，比如叫 GetMemoryMap，PID，对吧，这才是你真正想要的，那我就知道，返回一个数据结构给我，我就知道，每一段，它从哪开始，到哪结束，它的访问权限是什么，以及我还想要。比如说 ReadProcessMemory，我想要指定一个 PID，一个address，一个 buffer，一个 size。然后我把那一段。进程内存给我。给我读出来。

而操作系统设计者，脑子里面想的，就是任何应用程序，开发者，他想做的事情，都是对的，操作系统是一个通用的，机制，它为了让应用生态，能够繁荣地发展起来，就像最早的时候，UNIX 操作系统里面，甚至没有网络的功能，直到后来有了套接字，可能写过一点点套接字，没关系，一开始甚至，没有这些功能的时候，操作系统的设计者，会一点一点，把这些 API，加到他们的操作系统当中。然后操作系统设计者，他脑袋里想的，就是要提供一套，简单稳定通用的 API，或者说一个抽象层。然后这个 API。

它可以是，就是完全迎合，这个程序员的，比如说我就真的提供，一套 GetMemoryMap，然后也可以是，另外一套，不太一样的机制，比如说 UNIX，Linux 世界里面，我有一个 /proc，然后我把进程相关的信息，以文件的形式，放在里面，那这样，我就不需要提供一个额外的系统调用的 API，我可以复用文件，和目录的 API。对吧，我有文件的 API，Open，你们知道一点，open、read、write。然后以及目录，也是 Open，我可以用 Open。打开一个目录。

然后用那个，Read Directory Entry，来扫描这个目录里面的，目录项，我就可以复用这些，本来已经实现好的 API，让应用开发者，可以访问操作系统对象，从而实现像这种，GetMemoryMap，ReadProcessMemory。实际上在 Linux 里面，如果你要做这三件事情的话，使用的是一套 API。但是这不代表，在其他的操作系统上，也要这样实现。比如说在 Windows 上，Windows 其实是一个软件工程意义上。设计的非常好的产品。它的 API 就不像 Linux 一样。它有一种，Unix 和 Linux，都有一种，我是 Hacker，所以我就要用那种，特别干净又舒服的，hack 去解决这个问题，像它把所有东西，以文件形式，塞在 Proc 底下，这其实带来一些麻烦，因为你看，如果你想要知道，进程的地址映射。

比如说我可以用 pmap，7583，对吧，我可以打印出这样的，进程地址空间映射的样子，但是这个程序背后，它会以文本文件的形式，去打开那个，/proc 下的 7583 下的 maps，对吧，maps。

然后它会把这个 maps，做一个文本的解析，解析完了，再把它加工成，这个输出的样子，其实是很浪费的，这些信息在操作系统内核里面，是一个数据结构，然后它为了，实现成 procfs，就实现成 /proc 下的，这个 7583 下的 maps，它要把那个数据结构，变成文本，有一次的序列化。然后你的 pmap 那个命令，从这里读出来以后，它要再做一次文本的解析，这不是很浪费吗？因为那个数据结构，就在内核里，你如果能直接把内核里，那个数据结构搬出来。
