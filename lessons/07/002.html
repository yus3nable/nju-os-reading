回顾进程与地址空间

原片 00:06:56—00:10:09

上节课的时候，我们讲了程序和进程，我们讲，其实上周啊，讲了一组系统调用，包括 fork，execve 和 exit，我可以，一个程序在运行起来以后，它就是一个状态，它有内存和寄存器，可以通过系统调用去请求操作系统。然后如果我希望，我的程序本身希望创建这样的进程，那我可以用 fork，做一份状态的完整的复制，也可以用 execve 去重置到另外一个二进制文件，所指定的进程状态上。然后或者我可以 exit 摧毁一个进程，以及我们在进程的内部，我们说进程内部的状态。

有内存和寄存器的时候，我一个指针，对吧，一个很基础的问题，如果一个指针扫过一整个进程的地址空间，对吧，它从零开始，那我到底什么东西是可读的，什么东西是可写的，我能不能读它，能不能写它，对吧，我们甚至用一个游戏修改器来告诉大家，我真的是可以读写别的进程的内存的，那我对于一个进程来说，我就可以用 mmap，munmap 和 mprotect 三个系统，当时还有一个msync，它可以同步，可以把你一段内存里面，你写进去的数据，可以同步到那个映射的文件上。但这个你们在需要用到的时候。

你自然就会知道，比较重要的是 mmap，因为你可以通过它来分配内存，我给 mmap 一个非常大的十几个 GB 的内存，然后我马上立马就可以用了，它只要非常短的时间，我马上就可以用这一整段非常大的内存，然后以及我 mmap 还可以映射一个文件。比如说我可以把一整个磁盘，或者是 GPIO 的端口，都映射到我的地址空间里。OK。好，那其实你已经可以创建，一整个应用程序的世界了。对吧，你用 fork 就可以创建出一整棵进程树。然后你用 mmap 可以调动系统里面。各种各样的资源。

那么下一个问题，如果你要真正写出一个应用程序来，比如说终端，模拟器，比如说浏览器，你们可能自己就有点跃跃欲试，你们真的可以马上就回家，就 vibe coding 一个自己的浏览器，或者自己的一个 coding agent，都是 OK 的，在这个时候，你免不了就会和操作系统里面，更多的对象来打交道。比如说文件，我们已经很熟悉文件了，但只有我今天，我才正式的开始讲文件，以及我们用fork execve 创建出来的两个进程，它就是完全分离的，对吧。我们上课的时候讲了一个很有意思的例子。

它可以打印出好多的，好多的很多的，这两个进程，父子进程，它就完全的分离了，各管各的，那如果他们两个之间想要交换数据呢？对吧，你们有想过，如果我，我现在一个科学计算的程序打比方，我为了利用好我 CPU 上面的，电脑上面 128 个核心，那我就创建了 128 个进程算。然后每一个进程，它都算出来一个数字。比如说什么东西，一段区间里面的什么值，你想把这个数字加起来，你怎么办，你发现你光用这一套，像 fork execve exit，你做不到这一点。所以你需要的是在操作系统里面。

创建一个新的对象，然后让父子进程都能访问他，你可能就能共享，实现这样的共享了，所以我今天的主题，就是操作系统中的对象，和管理他们的 API。
