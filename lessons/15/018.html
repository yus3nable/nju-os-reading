第 15 课 · 并发控制：条件变量和万能同步方法

运行括号程序并用脚本检查

原片 00:46:23—00:48:56

实现中用宏表示 condition，同步条件未满足就 while、wait。打印左括号，再 depth++，相当于桌上苹果数加一。

producer 的 CAN_PRODUCE 为苹果数小于 n，CAN_CONSUME 为苹果数大于 0，直接套用同一份模板，代码就应正确。命令行有两个参数：嵌套深度 N，以及创建多少对生产者、消费者线程。

void T_consume() {
    while (1) {
        mutex_lock(&lk);
        while (!CAN_CONSUME) {
            cond_wait(&cv, &lk);
        }
        printf(")");
        depth--;
        cond_broadcast(&cv);
        mutex_unlock(&lk);
    }
}

输入 1、1，会看到一放一拿，因为桌上最多一个苹果。允许放两个或更多，输出就会改变。

这里像是先放两个，再拿一个、放一个，来回进行，看似没问题。但并发编程不要只相信眼睛。做 malloc 实验就会知道，一旦有不止一把锁，很容易错。能输出日志、检查正确性时，就用另一个程序核验。这里的 check.py 很简单，从标准输入读字符。

import sys

limit = int(sys.argv[1])
count, n = 0, 65536
while True:
    for ch in sys.stdin.read(n):
        if ch == "(": count += 1
        if ch == ")": count -= 1
        assert 0 <= count <= limit

左括号加 1，右括号减 1，检查任意时刻苹果数都在合法范围。让 check.py 长时间运行而没有报错，可以一定程度上相信实现正确。若把上限改小，用 check.py 1 检查允许两个苹果的输出，它就会报错。这就是生产者消费者。
