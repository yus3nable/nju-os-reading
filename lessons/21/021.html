第 21 课 · 一个 Token 的旅程

用计算图表达 Serverless 业务

原片 00:51:35—00:55:30

今天怎样为复杂的分布式系统编程？回到前面说的，并发编程任务都可以看作计算图，最好的编程方式就是描述这张图。

课件中的 Serverless 教学片段；数据库环境、导入和推理实现未展开，... 保留为省略。

const dynamo = new AWS.DynamoDB.DocumentClient();
exports.handler = async (event) => {
    const apiKey = event.headers['Authorization']
        ?.replace('Bearer ', '');
    const user = await dynamo.send(new GetCommand({
        TableName: 'APIKeys', Key: { apiKey }
    })).Item;
    if (!user || user.disabled) {
        return { statusCode: 401, body: ... };
    }
    return {
        statusCode: 200,
        body: do_llm_inference(...), // 就剩下它了
    }
}

计算图怎样执行、分发到哪台机器，最好交给底下的 System Implementation，程序员无需管理。这也解释了为什么选 Promise API、事件编程：有足够好的分布式数据库，再有能描述计算图的编程语言，就能处理这些问题。这就是今天的 Serverless Computing，无服务器计算。

以前建网站，要先租服务器。比如我的课程网站在阿里云租一台服务器，获得固定 IP，再去 DNS 域名厂商买域名。大家买过吗？我觉得每位同学都可以试试。

比如买较便宜的 .xyz 域名，搭个人网站。在这种模式下，一切以服务器为中心，通过 SSH 连接，运行 Nginx 并配置。这就是把数据带到计算，以计算机、计算为中心的思路。Serverless 则要求放下 Server 的概念，以数据为中心，因为数据表达的是状态。

比如有多少用户、哪些用户 active、哪些 API key inactive、每个 API 用了多少量。至少增删改查的业务逻辑都由事件驱动：有人要 disable API key，应该做什么；有人查看 dashboard，需要汇集哪些数据。这正是 JavaScript 面向事件编程擅长的方式，可以用 JavaScript 写数据中心程序。

我让它假设写一个基于 Amazon S3 数据存储的 serverless 程序。它是一个 event handler，从 event 的 header 中找到 http header，再找 authorization 对应的 value，提取 API key。

拿到请求中的 API key 后，查询另一个数据库，判断是否 valid。无效就返回 401，和今天最初的请求一样，到此结束；检查通过后，再做 LM inference。这样写好函数，部署到云服务厂商，剩下的问题交给 infrastructure。

这就是 write once planet scale。只要云厂商能承受，大量请求短时间涌入时，就会动态分配更多服务器；厂商也会预测业务量，提前预留资源，并约定价格。每次 function call 以很低的价格按需租用服务器，程序员只需要写出计算图。
