第 21 课 · 一个 Token 的旅程

域名、IP 与逐跳转发

原片 00:13:02—00:15:31

比如说我可以让他做这件事，我让他用这个命令去看一下这个 DNS 到底发生了什么，然后随着你把在本机上面你把这些行为一点一点的展开，你就会发现有越来越多有趣的问题，只向今天在实际的计算机系统当中会发现的，比如说你们都知道我们用这个 curl 也好，这个就像刚才那个 strace 也好，我的远端的服务器是一个 IP 一个端口。然后让你知道这个 443 是 HTTPS 的端口。所以 OK你这理所应当是这样的，那当然是这样的，比如说我对我的课程主页也是，但是如果是 DeepSeek。

比如说这个 api.deepseek.com，就非常有趣了，如果你要用 DIG 去看一下它的 IP 的话，你会发现它有不止一个 IP，为什么它有不止一个 IP，就是因为这是一个很大的服务提供商，然后这个服务提供商可能又用了别家的服务，去做一个分布式的 DNS，它告诉你看有两个 IP 都可以用，58.49.197.113，218.92.141.107，而且你在地球的另外一个地方，如果执行同样的命令，你很有可能会看到不同的 IP，也就是说一个真正的严肃的一个网站。

一个向全球人提供服务的网站，它之后比你想象的要复杂，DNS 它有好多，它有很多个可能的 IP，然后甚至它能告诉你这个是腾讯运营的 CDN 的域名，这个 API 请求并非是直连的 DeepSeek 的源站，而是走的 CDN 的节点。对吧。然后你通过这个方式，你就可以去把网络课的期末考试再去复习一下。然后同样的，如果你想要知道这个包是怎么样到达一端的，你可以去 traceroute。

课件中的 DNS 查询和路径探测命令：

dig api.deepseek.com +short
traceroute api.deepseek.com

对吧，这个是你们在网络课上也学过的，我也可以让它去 traceroute，当然 traceroute 的时间可能会稍微要长一点，你们在网络课上应该讲过，这是通过操纵 Time to live 的值，对吧？相当于一点一点，让它的寿命长一点，长一点，长一点，长一点。然后去，因为你 Time to live 长一跳，你就可以往更远的一个节点走一跳。然后它就用这个方式去探查这个网络链路上面经过的这些路由器，这个应该是你们网络课上也展示过的内容。
