第 21 课 · 一个 Token 的旅程

文件、数据库与 MapReduce

原片 00:48:30—00:51:35

从 Google File System Bigtable 到 MapReduce，建立了它的帝国，其实它就是干了这样的一件事，它反过来的，Everything is a file，这件事在 Unix 的时代成功了，在分布式计算的时代依然可以，它只需要做好一个文件系统的抽象，一个 Google File System，我会从下一节课开始讲，Persistence 部分的内容，它只要能把文件系统给做好，文件是什么，是一个 Byte Array。然后如果我能够在分布式的存储。

就好多好多电脑上，我讲说有好多好多台电脑，构建一个可靠的分布式的文件系统，然后这个分布式的文件系统，它可以随便存储，比如说你一个文件有一个 PB，就是没有一个比如说我们像的 PC 机，可以存下一个 PB 的数据，在他们那个时候，也没有一个单台的服务器可以。但是它通过把这些文件分片以后存到不同的机器上。对吧。比如说有这一部分存到这两个机器上，这部分存到了那三个机器上，它可以把文件切开存到不同的机器上。但是它完全不让你看到这些机器，你在编程的时候。

你看不到机器这个东西，你只能看到这个文件，然后你可以对这个文件做操作，然后做操作以后可以再写到下一个文件，所以你其实是，你还是做操作，你还是有 Program 的，这个 Program 依然还是可以非常复杂，有非常复杂的算法，但这个 Program，它不是不再是说，我现在把 Program 运行起来以后，把数据塞进去，而是我以文件系统里的文件为中心，这个文件系统，我要把这个程序去，相当于和这文件里面的一部分给联系起来。然后把这个程序再写到一个新的文件里。所以你看到的永远是说。

我要启动一个程序，然后这个程序做了一个数据的处理，然后有一点这种把数据带到计算，然后和把计算带到数据的这个不同，然后它就在这个基础上，在文件的基础上，可以构建一个数据库，key-value Database，解决这个增删改查的问题，因为如果你有一个key-value Database，你就可以做这个 API Key 的鉴权，可以做这个 API Key 的删除。对吧，就像刚才那个 DeepSeek 里面的一个例子。所以在文件的基础上，他们做了一个 Database。

然后做 Database 以后，那 C10M 的问题一定程度上就已经解决了，对吧？我只要查询这个 Database 就可以了，然后它背后是分布在很多很多数据中心的一个分布式的数据库，它的读取很快，它的写入也相对来说比较高效。然后以及他们还为这样的这个大的文件，大的超大的文件上的计算，开发了一个大数据的处理系统叫 MapReduce，这个很有名的，他们的三个 Paper，开启了分布式计算的一个新时代，解决了就，反正就解决了分布式计算里面的编程的问题。

然后他把实现的细节留给分布式系统，最终他们每一台计算机还是一个 Linux，但是它对外的暴露的接口就不再是 Linux 这种非常底层的一个 open/read/write。
