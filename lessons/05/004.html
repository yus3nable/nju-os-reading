创建进程：spawn、fork 与进程树

原片 00:33:59—00:50:29

现在进入系统调用。刚才 CrazyOS 有个局限：进程都在命令行参数里写死，比如运行 CrazyOS，传 p1.bin、p2.bin，就固定创建两个进程，既不能交互，也不能退出。真实操作系统并非如此，用 pstree 看看。

操作系统里的进程有共同的根 systemd。这说法不够严谨，后面可能讲 Linux 怎样逐步加载，第一个程序其实不叫 systemd，但后来会变成它。所有运行进程都有这个共同祖先，再逐级派生。找找我的 Fish。

pstree 展示终端、Shell 与 Python 进程关系

这里有多个 Fish，都在 Foot 下面。Foot 是终端模拟器，里面运行 Shell，再有 Python3。两个 Python 程序负责播放幻灯片。系统启动后，先有一号进程 Init，再由 Process1 创建整个应用世界，比如 VSCode、浏览器等。操作系统提供一组进程管理系统调用，用来创建、销毁进程。开发者需要创建新进程，该提供怎样的 Syscall？

进程管理：创建、销毁、复制与复位

用状态机看，可以设计 Spawn。程序执行到这个系统调用，传入 Path，即二进制路径，以及参数，比如 /hello，就创建新进程。原来的 init 仍在，pid 是 1，新 hello 的 pid 可能是 2，ppid 是 1。根进程的 ppid 可以指向自己，也可以用非法值，取决于系统设计。有 spawn 就能创建进程，马上可以在 CrazyOS 实现。现场考考豆包，我没提前准备。

实现应该不难，和 main 初始调用 proc_init 一样：创建新进程，申请一个结构体。

分配 struct proc，准备内存、寄存器，设置正确的初始 program counter，就是 proc_init 的工作。但豆包没遵守命名规则，看现有代码应该知道，所有 system call 都用 sys 前缀，它却直接给了 spawn。

它遵循指令不够好，但实现已经不错，spawn 基本和 proc_init 做相同的事，先让它继续。windows API 也有这种创建方式：指定 .exe 文件，再给 main 传参数，程序就能启动。类似在 Dev-C++，或者现在的 vscode 写好 C 程序。

点击运行，后台先编译成 .exe，黑窗口弹出时，就通过类似 spawn 的方式创建进程。这是合理设计，Unix 却采用另一种抽象。再看正在执行的程序状态。

UNIX 的创建方式：fork 复制状态机

Unix 提供 fork。spawn 创建新状态机，从新程序的初始状态执行；fork 则把现有状态机完整复制一份，A copy。可以理解为在 CrazyOS 中，逐字节拷贝内存、寄存器。

也复制相关操作系统内部状态。比如进程 A 持有指向终端 tty 的指针，复制后，两个进程共享这个 tty。VS code 的终端里，父进程输出字符。

子进程默认也输出到同一终端，因为继承父进程资源，包括内存、寄存器现场。用 CrazyOS 很容易理解：复制进程本身以及相关的操作系统状态，但不包括管理数据结构自身的状态。还要区分父子进程。

fork 的返回值与复制行为

如果一个字节都不差，就无法区分原进程和副本。所以 fork 在父进程返回子进程 PID，比如新 PID 是 100，就返回 100；子进程副本返回 0。这是用来区分两者的方式。代码可以这样写，类型也能用 pid_t，我现在在古法编程。

PID 等于 -1，就做 error handling；等于 0，执行 child 分支；否则执行 parent 分支。也可以按不等于 0 来安排两个分支。

假设 fork 成功，程序经过这里时，就有两个进程、两份状态。可能先后到达，但都会经过这个程序点：一个 PID 等于 0，走子进程路径；另一个不等于 0，走父进程路径。

pid_t pid = fork();

// Two copies
if (pid == 0) {
    // child
} else {
    // parent
}

这样只用 fork，也能写不同的父子进程逻辑。开始可能有点绕，回去可以再理解。无论 fork 还是 spawn，创建出来的进程都有父子关系。

进程树：父进程退出后怎么办

调用者创建孩子，也就是 descendant、后代。比如 A fork 出 B，再 fork 出 C，B、C 又可以继续 fork，就形成进程树。早期 UNIX 只有 fork 这一种创建途径，今天方式更多。不过系统每增加一点功能，也会带来新问题。

比如 A 是 B 的父进程，B 是 C 的父进程，三者独立运行，能执行任意代码。如果 B 退出，C 的父亲是谁？继续指向 B 也有问题，因为 PID 有限，未来可能被另一个进程复用，父亲就变成别人了。UNIX 的处理利用了一号进程永不终止这一点。

没有父亲的进程会转挂到一号进程，成为它的孩子，叫托孤。这样 PPID 始终合法，不会用空或错误的 parent。如果向 1 发消息，它会忽略。这是广泛使用的 workaround。PID 终究会重复利用，现在应该能到 100 万。

也能配置更大。Linux 还有专门子系统，用另一方式确保 unique PID，但第一门操作系统课不讨论细节。听到托孤，就能让 AI 写程序验证。比如这是去年演示：一个 prompt，要求创建五层进程树，再随机退出部分进程。

观察父子关系，我还要求把树画出来。AI 时代，知道能做什么、该做什么，tedious 工作交给它。程序输出 mermaid 关系，重定向到 markdown 文件，打开 preview，就能看到进程树。

比如 24363 的孩子有 24367、24377。还能观察托孤：一些父进程被杀，子进程变成一号进程的孩子。也可以要求增加杀进程日志，便于对照。

托孤后的进程还能继续有子进程。课间又让豆包在 CrazyOS 里实现 fork。看实现，真实操作系统，包括早期 unix，fork 也可以这样理解：先找未使用的数据结构，new 一个 struct proc，再完整复制旧进程信息，只把父进程返回值设为子进程编号，子进程返回值设为零。现在它好像仍在调试，不知道调到什么程度，但最原始的 fork 就是完整状态复制。回头想想，这有没有舍近求远？
