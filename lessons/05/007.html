第 05 课 · 程序和进程；fork, execve, exit

execve、环境变量与进程退出

原片 01:12:11—01:25:08

fork 能创建进程，却还不能实现最初想做的“原神启动”。Android 情况特殊，普通系统要启动 LS、WC，只靠 fork 做不到。如果只有 init，它 fork 后还是 init，再复制，世界里始终只有同一种程序，无法像 spawn 那样启动原神.exe。unix 因此提供了另一个系统调用。

execve：把状态机复位为另一程序

程序 a fork 后，得到 a 和 clone。另一个调用叫 execve：execute，v 表示参数向量，e 表示 environment、环境变量。还记得 C 语言状态机的初始状态吗？main 通过 argc、argv 得到命令行参数。若 A′ 调用 execve，指定 a.out，原来复制自 a 的全部状态就在原地销毁，再变成新程序的初始状态。这可以理解为状态机复位。a 执行、fork 复制，到了 execve，就替换成另一个程序，还能传入 main 参数和环境变量。

大家最早写简单的 main，后来知道它能带参数，今天又看到完整形式。argc 是 argument 的 count，也就是参数数量。

execve 设置参数、环境变量和程序入口

#include <unistd.h>
#include <stdio.h>

int main() {
    char *const argv[] = { "/bin/bash", "-c", "env", NULL };
    char *const envp[] = { "HELLO=WORLD", NULL };

    // Reset the state machine to "/bin/bash"
    execve(argv[0], argv, envp);

    // We are here only on error.
    printf("Hello, World!\n");
}

argv 是 argument 的 vector。argv0 是命令行调用的程序，比如 a.out。运行 ./a.out 1 2 3，argv 的 1、2、3 分别是 1、2、3，这就是 procfs 的 command line、cmdline 中看到的参数。此外，main 还能接收环境变量，不使用这个参数也没关系，程序可能不 care 环境。在 C 里，也可以通过 environ 访问当前环境变量，无须从 main 参数取出。

状态机复位解释了这些信息怎样产生。在 UNIX 世界，这是执行程序的唯一系统调用，所以用 strace 追踪任何程序，第一条调用都是 execve。

比如 strace ls，或更简单的 true，甚至自己写 a.c、用 ld 链接的 minimal。

空的 _start 看起来没调用任何系统调用，strace 看到的第一条仍是 execve。传入 1、2、3、4、hello，记录里也会出现 execve、a.out 和这些参数，后面还有 43 个环境变量。

最小 _start 程序与 execve

void _start() {
    while (1);
}

gcc -c a.c
ld a.o
strace ./a.out 1 2 3 4 hello

现在 43 个环境变量，临时加 A 等于 B，就多一个；再 export X=Y，就变成 45 个。env 能查看全部变量。幸好我没把 OpenAI 的 API key 放进去，那有点危险：fork 默认继承环境，execve 还要显式传入环境变量，不过可以传更安全的一组。

A=B strace ./a.out 1 2 3 4 hello
export X=Y
strace ./a.out 1 2 3 4 hello

进程复位后，操作系统资源默认会继承，讲文件描述符时还会讨论。用 execv 库函数启动，也默认继承环境变量，OpenAI 的 API key 就传给子进程；子进程若有不良行为，可能把 key 泄露。我担心龙虾这样做迟早出事，但不确定它是否把 key 放在环境变量，因为现在也有更好的管理方式。许多人仍喜欢这样配置，早期教程也常要求在 .bashrc 里 export OpenAI API key。

这样所有应用都能使用 key，也有风险；若我刚才这样展示，就得赶快 disable API key。环境变量还有许多日常用法。echo $PWD 能获取当前 working directory；term 表示终端类型。我使用 foot，但它伪装为兼容的 xterm-256color。

echo $PWD
echo $TERM

还有 path、PATH，表示路径。这里 fish 的显示和路径分隔方式不同，可以用 env 查看。

PATH 中的可执行文件查找顺序

查找可执行文件时，从 PATH 第一项开始。比如找 gcc，先看这个位置，找到了就运行，否则逐项往后。我很讨厌 opencode 污染环境变量，把自己的目录放在最前面。现在 gcc --version 正常运行；把 PATH 设成点，就变成 unknown command，找不到 gcc。设置正确 PATH，比如 /usr/bin，就恢复正常。再联系 CrazyOS：进程自己看到 memory、register，操作系统还维护许多状态。

gcc --version
PATH=. gcc --version
PATH=/usr/bin/ gcc --version

比如 PID、ENV、PPID。environment 在进程内也有副本。应用能通过系统调用等方式查询这些信息，行为由状态决定。计算机世界没有魔法，可以看看 gcc 的 strace。

有时古法编程比自然语言，［听辨不清，01:22:21］，可能快一点。我用 unix philosophy 调外部工具，再把结果贴过来，能方便地查看 PATH。

PATH 环境变量决定外部工具的搜索路径

这里是 PATH，GCC 会按它的路径顺序找工具：先试 OpenCode 的 bin 有没有 as，反复返回 -1、ENOENT，表示找不到；再试 /usr/local/bin、/usr/local/sbin，直到某次 execve 成功。

把 PATH 改成 /usr/bin，前面那些失败尝试就没了。这确认 GCC 确实读取环境变量 PATH，按分隔符解析路径，再依次查找。

计算机行为都有解释，机器按规定执行。借助 AI，可以理解观察到的现象。有 fork、execve，原则上就能构造任意进程世界：复制自己，再启动其他程序，真正实现原神启动。最后还需要销毁状态机的 API，Exit。

exit：销毁进程状态机

系统调用像全身麻醉，程序暂时失去对世界的感知。fork 复制，execve 重置，exit 让状态机消失。三个系统调用就构成 UNIX 的进程世界，也就是 pstree。还有一小段 demo code，回去可以运行，再让 AI 解释。
