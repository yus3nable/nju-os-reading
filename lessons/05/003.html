第 05 课 · 程序和进程；fork, execve, exit

程序、进程与操作系统保存的状态

原片 00:20:13—00:33:59

P1、P2，比如 p1.c，叫作程序。

程序是状态机或语义的静态描述，也可以理解成配方、步骤：从这里开始做 ABCDE，该计算就计算，该系统调用就调用。无论 ELF 二进制还是源文本，本身都是字节序列。加载到操作系统、真正运行起来，才成为 Process、进程，也就是前进中的程序。同一份 P1，可以运行很多份 p1.bin，形成多个进程。每运行一份，操作系统都分配资源，包括内存每字节的值、各寄存器的值，每个进程有各自的副本，此外还有操作系统内部状态数据。

比如刚才的 buffer。操作系统也像执行指令的机器，只是会做进程时分复用：选一个进程在 CPU 上运行一会儿，再换另一个，遇到系统调用，就履行相应契约。这就是进程运行的模型。

操作系统还为进程保存了哪些状态

从这个基本模型出发，已经知道操作系统会保存程序运行需要的状态。还会保存哪些进程信息？比如调试 CrazyOS，用 gdb crazy-os、start，随时能观察程序本身。调试器看到的是它的寄存器、内存，info registers 能查看寄存器值。

也能打印变量，比如 x 在内存中的值。真实操作系统除了寄存器、内存，还保存哪些进程状态？

先想到进程编号。Windows 用 Ctrl+Shift+esc 打开任务管理器，能看到编号。若在 CrazyOS 实现，可以在 Proc 中加 int process_id，或者 PID，在 proc_init 时分配 ID。这个 Unique ID 至少要在当前系统中唯一。

这里的写法只是示意，不能直接这样实现。有了小模型，就能继续问：真实操作系统怎样维护进程资源、状态和其他信息？现在有 AI，我觉得自己快能退休了。这次启用较大的模型，让 Anthropic 最新模型写了一段程序。

Claude Opus 4.6 生成的进程信息工具

读完代码，我感到很有压力，觉得明年也许不该再来上这门课了。未来一年模型还会更强。它凭编程直觉，规范、全面地展示进程有哪些状态，连 show_personality 这样的功能都包括，有点像刚才的 Makefile。

又学到了不少以前不知道的细节。再比较豆包。

相同 prompt 交给豆包，结果也不差，但和一线模型仍有很大差距。世界在变化，模型越来越强，今天 600B 模型能做的，未来 30B 可能就能做。现在千问 9B 已比 170B 的 GPT-3.5 强，让人感到压力。豆包也可能赶上，或许通过蒸馏大模型，再被公开吐槽。它已经做得很好了。先编译运行，Warning 暂时忽略。真实进程持有的资源、信息，比想象中多。本学期只会讲其中一部分，不涉及全部。先看 PID。

除了进程编号，还有 PPID，也就是 Parent 的 PID；PGID，也就是 Process Group ID。这些带着历史遗留因素，课堂会 cover 一部分。此外还有 UID、EUID、EGID，以及启动进程的命令行。

进程身份、命令行与运行状态

现在用 ./proc-info 运行。点表示当前目录，重复写当前目录仍然是同一位置，也能启动程序。但 Process Identity 会发生变化，记录下实际使用的 Command Line。

看起来命令执行后，启动信息就丢了，实际上操作系统仍保存着。除了进程自己能看到的 Memory、Register，操作系统还知道许多其他信息。

比如运行时间、内存用量、打开多少文件。Scheduling Information 里有一些整数，不懂可以问 AI。所谓打开的文件，是进程持有的操作系统对象指针，后面会讲；内存下节课讲，还有其他高级内容。即使用豆包，也能让它读运行结果。

再结合源码解释，就可以聊很久，了解操作系统给进程提供什么。我真觉得自己明年该退休了。看过解释，还能再问：这些状态不在进程的内存、寄存器中，进程怎样查询？

查询进程状态：系统调用与 procfs

一定要经过系统调用。程序只能看到自己的内存、寄存器，C 语言状态机之外的事情，都要通过这个接口。具体哪些调用能获取进程状态？让模型用 strace confirm 一下，再 Explain。它会追踪系统调用、整理完整日志。总结来看，查询运行时间、内存占用等自身信息，有两条途径，第一条是直接调用系统调用。

比如 getpid、process control，可以让它进一步解释，也可以查手册。第二条是 procfs。UNIX Philosophy 用文本接口连接小工具，和今天大模型很像。操作系统提供 procfs 文件系统，目录在 /proc，后面实验还会探索。

当前进程有专用目录 /proc/self。比如用 PS 查 PID，现在 shell 是 12984，就能进入 /proc 下的 12984，看 cmdline，了解 shell 启动时的命令行参数。

里面还有许多文件。以前探索 procfs 很困难，要看 kernel documentation。博客之外，权威途径是内核文档，其他内容不可靠。今天多了模型这个中间工具，可以让它读这些文件。

现在它卡住了，回去也可以自己做。我基本认为模型回答很可信，也全面，不像一篇博客只覆盖几个基础点。只要问出进程怎样通过系统调用获取自身信息，再逐步追问，就能了解更多。它现在也列出了 procfs 的内容，包括调度信息、优先级、out of memory 情况、内存映射等。

从 CrazyOS 这样的小例子出发，知道进程是什么、操作系统怎样管理进程，整门课也许能用三十到五十个问题组织起来。感觉这样确实用不着老师了。这是今天第一个重要概念：程序和进程。
