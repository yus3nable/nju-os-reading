第 11 课 · 链接和加载

LD_PRELOAD 与变速齿轮

原片 01:16:04—01:22:17

还有一个彩蛋：LD_PRELOAD。动态链接和加载时，默认采用先到先得的机制。例如 a.out 引用了 printf，谁先被加载、首次满足这个未定义符号，后面就调用谁。也可以通过传入参数改变这个行为，具体方法可以向 AI 询问。

用 LD_PRELOAD 预加载一个库，就可以覆盖想覆盖的符号。例如，把 malloc 换成自己的 malloc；也可以继续调用原来的 malloc，只在调用前后打印消息。这就是钩子，即 hook：覆盖符号，保留原来的行为，在前后插入代码。

插入自己的代码后，就可以改变各种 api 的调用。例如前面讲过，程序通过系统调用感知时间，sleep 一秒就等待一秒。怎样改变它对时间的感知？

调用 gettimeofday 能知道当前时间。可以让 AI 用 LD_PRELOAD 覆盖所有 time-related functions，实现一个变速齿轮，它也确实实现了。看看 hook 了哪些函数：gettimeofday、clock_gettime、usleep、alarm 等，覆盖了不少与时间有关的代码。

查找原 gettimeofday 函数的片段：

if (!real_gettimeofday) {
    real_gettimeofday = dlsym(RTLD_NEXT, "gettimeofday");
}

按速度计算虚拟时间的片段：

double real_elapsed =
    (now.tv_sec - real_start_tv.tv_sec) +
    (now.tv_usec - real_start_tv.tv_usec)/1000000.0;

double virtual_elapsed = real_elapsed * speedup;

wheel.c 中的 usleep 覆盖：

int usleep(useconds_t usec)
{
    static int (*real_usleep)(useconds_t) = NULL;
    if (!real_usleep) {
        real_usleep = dlsym(RTLD_NEXT, "usleep");
    }
    // 用更短的真实usleep来模拟虚拟加速
    useconds_t real_usec = (useconds_t)((double)usec / speedup);
    return real_usleep(real_usec);
}

睡眠、设闹钟都与时间有关。还有 select：从别处读取数据、和其他进程或窗口管理器通信时，会设置 timeout，例如希望 30 毫秒后超时。

超时后程序就被唤醒，即使没有按键信息，也要更新图形界面。select、poll 等函数中的时间都会替换成修改后的时间。再看 makefile，一系列 CFLAGS 把代码编译成 libwheel.so。

Makefile：

CC = gcc
CFLAGS = -fPIC -shared -O2 -Wall -Wextra -D_GNU_SOURCE
TARGET = libwheel.so
SRC = wheel.c

all: $(TARGET)

$(TARGET): $(SRC)
    $(CC) $(CFLAGS) -o $@ $^

clean:
    rm -f $(TARGET)

.PHONY: all clean

现在有了 libwheel.so，libwheel 是当前体系结构下的动态链接库、shared object，计算机系统基础课上做过这件事。系统里有很多与时间有关的程序，可以用来试试。

例如 cmatrix，会打印黑客帝国片头风格的掉落字母。

看起来不错。还有贪吃蛇游戏 nsnake，但我觉得它太慢了。

可以按上下左右控制它，速度确实慢。令 LD_PRELOAD 等于 ./libwheel.so，再运行，就能感觉它快了很多。

它确实变快了。再对比 cmatrix，普通版本正常掉落，十倍速度的版本连 VS Code 都弄卡了。

卡的是 terminal emulator，字符输出太多、太快，发生了卡顿。

还可以试 sleep 1，普通情况下正常等待一秒；预加载后，同样 sleep 1，0.1 秒就返回了。通过覆盖与时间有关的系统调用，确实改变了应用对时间的感知。

普通运行与预加载的命令对照：

sleep 1
LD_PRELOAD=./libwheel.so sleep 1

知道这件事可以做，就有了线索。即使没有线索，也可以和 AI 讨论：“我想实现这样的外挂，有哪些实现途径？”它会告诉你 LD_PRELOAD，因为很多人用这个机制改变程序行为。改变库函数能做很多事，例如监控程序运行，获取 malloc 日志，判断有没有 use-after-free 之类的错误。

这些也可以通过钩子实现。除了变速齿轮，还可以让 AI 想其他用法。它知道用 LD_PRELOAD 覆盖 glXSwapBuffers 能实现透视外挂，也可以劫持 Random，让随机过程可控。例如程序随机扔骰子，或者迎新晚会上不断跳动的程序，理论上都不可信。即使看到代码使用随机数，也能通过 LD_PRELOAD 改变行为。

修改随机数返回值、随机种子等，就能控制随机结果。还可以非侵入式地记录 malloc、free 日志，得到类似 strace 的日志。这是很有用的机制。
