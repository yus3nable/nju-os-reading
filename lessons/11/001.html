第 11 课 · 链接和加载

可执行文件与进程初始状态

原片 00:00:00—00:03:53

前面的课程一直在讲，怎样基于系统调用接口逐层构建应用程序。从 libc 到正常的程序，我们最早讲过一个最小的 minimal.s：直接写一段指令序列，通过系统调用访问操作系统。后来又讲了 fork、execve、mmap 等系统调用，大家一边做实验，一边学习怎样用它们实现用户空间需要的功能。

今天讲链接和加载，内容有些不同，但仍然基于系统调用，也完全可以用系统调用实现。M3 已经发布，大家可以在网上查看。

先看可执行文件，例如 /bin/ls，或者自己编译出来的 a.out。

它会告诉你，这是一个 ELF64bit 的 executable，也就是可执行文件。你们可能用 x86，我这里是 ARM，另外还有一些信息。到底什么是可执行文件？

学操作系统之前，大家想到的可能是双击就能弹出窗口的 Steam，或者双击“原神启动”。学过操作系统后，对可执行文件会有更深的理解：它是操作系统里的一个对象，也是普通文件。既然可以用 file 查看 /bin/ls，也可以直接 cat /bin/ls，把二进制文件的内容打印到终端。如果读起来困难，可以通过管道交给 hexdump 这样的程序，打印整个二进制序列。可以看到头部有 45 7f 46 4c，即 0x7f 和 ELF 的二进制十六进制表示。

这是小端存储，所以看到 45 在前面、7f 在后面。既然它是普通文件，也可以用文本编辑器编辑。用文本编辑器打开，就能看到 ELF 三个字。

编辑这种文件对人有些困难，大语言模型好像也能办到。说到可执行文件，还应该想到：它是描述进程初始内存布局的数据结构。这个定义更精确。为什么可执行文件可以执行？能执行的是程序、进程。第一个进程是 init，它可以通过 fork 创建子进程，通过 execve 执行另一个程序。谈到“执行”，说的就是 execve 系统调用。Execute，execve 手册里的 name 叫 ExecuteProgram，即执行程序。它的第一个参数是 const char * 类型的 pathname，指向可执行文件；这个文件描述了进程的初始状态。System V ABI 的 initial process stack 规定了进程初始时 SP 指向的位置。

那个位置上有参数数量、参数向量等数据结构，由操作系统提供。其余部分由可执行文件描述，包括代码、数据分别位于哪里等初始内存布局。

a.out 头部的数据结构：

struct exec {
    uint32_t a_midmag;  // Machine ID & Magic
    uint32_t a_text;    // Text segment size
    uint32_t a_data;    // Data segment size
    uint32_t a_bss;     // BSS segment size
    uint32_t a_syms;    // Symbol table size
    uint32_t a_entry;   // Entry point
    uint32_t a_trsize;  // Text reloc table size
    uint32_t a_drsize;  // Data reloc table size
};
