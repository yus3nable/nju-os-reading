可执行文件与进程初始状态

原片 00:00:00—00:03:53

经过一段时间的学习，我们一直都在讲系统调用这样的一个接口是怎么样在这个上面一层一层一层地构建各种各样的应用程序的，对吧？从 libc，然后到一个正常的程序，我们最早的时候讲了一个最小的 minimal.s，我可以直接写一段指令序列，然后这个指令序列可以通过调用系统调用的方式访问操作系统，然后我们就讲了各种像 fork、execve、mmap 这些系统调用，你们一边做实验，一边去知道，怎么样用系统调用来实现各种各样你们在用户空间想要实现的功能。

那我今天会讲一个有一点点不一样，但是其实它还是基于系统调用，你也完全可以基于系统调用实现的，就是链接和加载，我们的M3 已经发布了，大家可以在这个网上查看。

好，那我们要讲链接和加载的时候，我们的第一个讲的对象就是可执行文件，对吧？比如说我们可以看一下，比如说/bin/ls，或者你们，你们编译出来的一个 a.out。

他会告诉你，这是一个 ELF64bit 的一个 executable，对吧，一个可执行的文件，当然你们可能是 x86，我这里是 ARM，然后有一些其他的信息，那到底什么是可执行文件呢？

对吧，你们在学操作系统之前，你们就会知道是那个双击可以弹出窗口的那个 Steam，对吧，双击，然后或者原神启动的那个双击，但学了操作系统以后，你对什么是可执行文件的概念，产生了一些小的变化，或者说有更深的理解了，首先可执行文件，它就是操作系统里的一个对象，它是一个普通的文件。对吧，我刚才说我可以用，我既然可以用 file 去查看这个/bin/ls，我也可以用 cat 对吧，直接 cat /bin/ls。然后我可以把这些二进制文件的内容，直接打印到终端上。那如果你觉得它读起来比较困难。我当然可以把它管道给另外一个程序，像 hexdump 这样的程序，对吧，它就可以把二进制的整个二进制的序列给打印出来，然后你可以看到它的头部有那个 45 7f 46 4c，是那个 0x7f，然后 ELF 的二进制十六进制表示。

这是小端的，这是小端存储，所以你看到这个 45 在前面，7f 在后面，它是一个普通的文件，所以意味着你也可以，当然我们也可以用任何一个文本编辑器去编辑它，你看我如果用一个文本编辑器打开它，你可以看到我确实有 ELF 三个字。

当然，对你来说编辑这个东西有点困难，对于大语言模型来说，好像这件事情也是可以，可以办到的，然后但你们当你们说到可执行文件的时候，你们更多的时候应该想到它其实是描述了进程初始内存布局的一个数据结构，这个才是可执行文件的一个更精确的定义。对吧，因为为什么？为什么可执行文件可执行呢？什么东西是可以执行的，是程序，是进程。对吧，我们的第一个进程是 init。然后它可以通过 fork 创建子进程，通过 execve 执行另外一个程序，那什么叫执行。对吧。当我们谈执行的时候。说到的是 execve 这个系统调用，对吧，Execute，execve 的 name，你看它手册里面 name 就叫 ExecuteProgram，叫执行程序，那这个 execve 执行的参数，第一个参数，一个 const char *，一个 pathname，它是一个可执行文件，而这个文件就描述了一个进程的初始状态。对吧，进程初始状态的时候，我们有 System V ABI 里面的那个 initial process stack，它会把 SP 指向一个位置。

然后那个上面有参数的数量，参数的向量等等，一个整个数据结构在，就是操作系统给它的，而剩下的部分就是在可执行文件里，它描述了进程的初始的内存布局，比如说哪里是代码，哪里是数据，这些这样的内存布局，好。

a.out 头部的数据结构：

struct exec {
    uint32_t a_midmag;  // Machine ID & Magic
    uint32_t a_text;    // Text segment size
    uint32_t a_data;    // Data segment size
    uint32_t a_bss;     // BSS segment size
    uint32_t a_syms;    // Symbol table size
    uint32_t a_entry;   // Entry point
    uint32_t a_trsize;  // Text reloc table size
    uint32_t a_drsize;  // Data reloc table size
};
