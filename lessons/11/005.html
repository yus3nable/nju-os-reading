第 11 课 · 链接和加载

学习方式与知识网络的反思

原片 00:22:59—00:28:58

准备这些内容时，我连 token 都不太想花了，因为每个人都可以提出自己的设计。既不喜欢 JSON，也不喜欢 markdown，只喜欢图形，那就用 SVG 构建二进制文件。可以 vibe code 一个程序，把 .o、a.o 这样的 ELF 文件翻译成 SVG 图形，再把 SVG 图形链接起来。

把两个图形画布拼起来，就有两幅图，也完全可以用 SVG 实现链接和加载，发挥想象就行。过去每年我都花很多时间构造这些 demo，现在可能没那么必要了。我们需要建立知识网络：我一定要告诉大家去读 ELF 手册，知道 readelf -a 这个命令，它能显示 relocations 等全部信息。

有一个 a.o，就应该用 readelf -a 看一下。例如，定义一个 int foo，再 extern int x，令 x 等于一，这是合法代码。用 gcc -c 编译 a.c，可以成功。再对 a.o 执行 readelf -a，就会看到很多重要信息。

这些是我一定要告诉大家的。这里有 text 的 relocation，即重定位信息。再用 objdump 看，取地址的位置是零，arm 指令里的 26 位立即数这里也是零。

链接时，这个零会被重新填入相应数字。知道这一点后，就能用自己喜欢的方式学习，也可以预先准备一些 prompt，花些 token 来理解它。就在这两天，Andrej Karpathy，也就是提出 vibe coding 这个词的人，又发布了 LLM Wiki，大家应该看过这个新闻。他有一个不算长的 prompt，大意是：为了学习，需要维护一个事实池，即 fact 池，不断添加内容并消化，形成自己的知识库。从本科到博士毕业，我很大程度上都在手工做这件事。现在 AI 也可以做。我们需要提出正确的问题，把握解决方向，有足够好的模型，并具备 critical thinking，能够质疑和确认结论。

可以质疑这些内容或做法有误，但程序的运行不会骗人。当你生成一段指令序列，确定它通过系统调用向终端打印 hello，再把它链接、加载、运行，确实看到 hello 输出，就确认了这个结论，也知道链接器和加载器正确生效了。我觉得这指向一个有点可怕的未来，所以说我是“人奸”。可以这样想：拿出一本字典……现在准备四六级考试，还要背字典、背单词吗？

应该不会背单词吧。我们那时准备英语考试，都会买一本单词书，至少翻一遍。这个学习方式效率不高，但可以做。假设有一本包含 AA、abandon 等全部英文单词的字典，从长度为一的单词开始，按一二三四五枚举到某个上限，例如二十或五十，再对所有能枚举出的句子逐一做 research。

就像今天这个疯狂想法：“我们总可以在等价的描述形式之间转换。”接着可以问，能不能用 SVG 实现链接和加载，用 markdown 或 emoji-based 的方式写链接和加载的格式？这些问题可能有创意，AI 暂时还想不到；其余 do research 的工作，agent 完全可以做。

它有手和脚，可以自行尝试、反思，最后写代码验证。这样是否就能产生人类几乎所有的知识？大家觉得我课上有些新意的内容，可能也都能产生出来。那我们还要学什么？这个问题我到现在还没想清楚。但可以确定，不久以后，所有课程的教法和学法都会发生根本变化。我觉得大学很快就要没有了，大家会不会是最后一代大学生？回到加载。
