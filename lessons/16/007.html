信号量 API 与互斥锁这个特例

原片 00:21:25—00:24:24

所以信号量就是这样的一个跟刚才一模一样的 API，我可以用更严谨的方式来写出来，对吧，我的 P 操作，我有一个 semaphore 信号量，它对应的是 acquire 或者是 try and decrease，我会先获得一把互斥锁。

void P(sem_t *sem) {  // Acquire
  mutex_lock(&sem->lk);
  while (!(sem->count > 0)) {
    cond_wait(&sem->cv, &sem->lk);
  }
  sem->count--;  // 消耗一个 token (信号)
  mutex_unlock(&sem->lk);
}

void V(sem_t *sem) {  // Release
  mutex_lock(&sem->lk);
  sem->count++;  // 创建一个 token (信号)
  cond_broadcast(&sem->cv);
  mutex_unlock(&sem->lk);
}

这是万能同步同步的写法，然后如果我的同步条件不达成，我就会……减一，消耗一个这个东西……就会等待，然后如果达成了，我就会把这个玩具给拿走，然后 V 操作对应的就是一个 count++，然后 broadcast，这个是非常适合像停车场游泳馆这样的应用场景的，对。好。那我们来看一看，用信号量怎么来实现各种各样的同步，首先，信号量天生就是互斥锁，我们说互斥锁是信号量的特例，也说信号量是互斥锁的扩展，为什么呢？你初始化一个 counter 是 1 的信号量，就是说我手上有一个玩具。

或者桌上只有一把钥匙，或者是一个只有一个车位的停车场，然后那么只有一个车位的停车场，就意味着任何人想要进入，任何车想要进这个停车场，它也是一样，它是 P 这个 semaphore，对吧？

sem_t sem = SEM_INIT(1);

void lock() {
  P(&sem);
}
void unlock() {
  V(&sem);
}

或者说是 acquire，然后那只有一辆车能进，谁把这个钥匙拿走了，谁就进，然后进了以后再有再多的车想要进，都进不来了，那这就是互斥，对吧？最多只有一个人能进，mutually exclusive，然后我如果要出临界区，要 unlock，要解锁，要 release，我就把这个玩具还回去，又变回 1，那我因为任何时候只有一个人能进。所以在任何时候，如果 lock unlock 是配对的，那又只有一个人能出，假设你的代码写的是对的，如果你没有一条程序的路径上有一个 bug。

那这个 bug 上面 unlock 了两次，对吧？如果你 unlock 了两次，这个就不对了，然后从此以后，你相当于你就变出了一个车位，对吧？停车场，如果你你的那个 bug unlock 两次，相当于你，你违反了停车场只有一个车位的，这个我们基本的使用约定，而是你，你直接 V 操作，它就可以变出一个车位来，那从此之后，都有两辆车可以进入，进入停车场了，但确实是你看，我就这样实现互斥锁的，这也是我们说互斥锁是信号量的特例，或者说信号量是互斥锁的扩展的，这样的原因。你理解信号量是互斥锁的扩展。

就从这里来，就这两个代码，这是用条件变量实现的互斥锁，这是用条件变量实现的信号量，然后它们确实是这样的一个一个扩展关系，好，这是大家容易理解的，然后。
