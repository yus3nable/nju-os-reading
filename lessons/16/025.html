第 16 课 · 并发控制：信号量

引入 waiter：用消息队列管理叉子

原片 01:17:45—01:21:30

没关系，你不需要知道底层的细节，好，这就意味着我们不应该用信号量来实现，比如说像哲学家吃饭这样的问题吗？

void T_philosopher(int tid) {
  while (1) {
    send_message_to_waiter();
    P(&can_proceed[tid]);
  }
}

也不绝对，我们还有一种方法，可以把理论上说，可以把任何的同步问题都变成生产者消费者，怎么把任何的同步问题都变成生产者消费者呢？在现实世界你人的意义上，就是为哲学家引入一个 waiter，引入一个服务员，一个服务员的线程。然后好，这个服务员的线程，相当于他来管这个全局的同步条件，他知道谁有哪些叉子，或者说他就把所有的叉子，五把叉子都放在自己手上，12345，所有的叉子都在他自己手上，你只要禁止我们每一个线程，直接去访问那个全局的状态，并发控制就完成了。所以这其实是另外一种并发控制的方式。

不要，就是不要让你们每一个线程去 self-organize，去 ad-hoc 的去自组织的方式，每一个人，就相当于我们所有人商量好一个协议，你先拿左手，再拿右手，但是对不起，如果你左手编号比右手大的，你先拿右手再拿左手。对吧，你是说我们商量出一个这样的protocol 来，每一个人不管不顾其他人，也不用看全局状态就可以实现这样的同步，但这是没有必要的，也没有，在绝大部分时候的性能也不会有绝对损失的，你引入一个全局的管理者。对吧。你可以叫他 waiter。

他手上有五把叉子，那每当有任何一个任何一个线程，比如说 T_philosopher，有一个哲学家想要吃饭的时候，他就会给 waiter send 的一个消息，发一个消息说，我想吃饭了，所以 waiter 他就是一个 while 循环，他去从 buffer 里面，你看消息队列是可以用buffer 来实现的，对吧，所谓 send 就是往这个 buffer 里面放一个放一个球。然后所谓 receive 就是从这个 buffer 里面取一个球。所以这就是标准的生产者消费者问题。

我是 P(empty) V(fill)，P(fill) V(empty) 这样对称的过程，好，那我如果要吃饭了，我就给哲学家的管理者发一条消息，然后消息以后，我们的服务员，他手上有所有叉子的控制权，所以他知道他左手和右手的叉子是不是都在，对吧。比如说我现在，我现在甚至我不是这两把叉子，我现在我说，我想要的是编号为 431 的叉子，你能不能给我，服务员看一下 134 都有，134 都有，那行好，他就从自己的内存里面，甚至不是全局的一个内存，他是在自己的一个内存里面。把 134 给去掉。

然后告诉他 OK，好，这个 OK 就可以用 PV 操作来实现了，对吧，一个在这里 V 相当于 release，然后这里有一个 P，它是相当于是一个 acquire，我先把这个消息发给服务员，然后我再等服务员把叉子给我，我就可以继续了。然后我做完以后我再发一个消息说，我要把这个叉子还回来给你，这样就可以实现同步了，还是可以用信号量。但是你的用法不是去 ad hoc 的自己实现一个协议，而是由一个服务员来管理现在全局的状态。然后这样就从这种你需要去考虑指数多个可能的调度，变成我服务员的逻辑是简单的，它是串行的，对吧。

它把所有的 send 都排好队。
