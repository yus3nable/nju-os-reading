第 17 课 · 并发 Bugs 和应对

ThreadSanitizer 的现场尝试

原片 00:56:15—01:00:30

race.c 故意在一条路径上漏掉 Lock，类似平时可能出现的错误。我以十分之一的概率执行未保护的 sum++，其他 sum++ 都有 Lock 保护，所以多次运行结果不同。Harness Engineering 的思路是记录所有事件，检查是否存在没有 happens-before 关系的 ReadWrite 或 WriteWrite data race。

课程线程库上的全局变量、T_sum 和 main：

#define N 1000000
long sum = 0;
mutex_t lk = MUTEX_INIT();

void T_sum() {
  for (int i = 0; i < N; i++) {
    mutex_lock(&lk);
    sum++;
    mutex_unlock(&lk);

    if (i % (N / 10) == 0) {
      sum++;
    }
  }
}

int main() {
  spawn(T_sum);
  spawn(T_sum);
  join();
  printf("sum = %ld\n", sum);
  printf("2*n = %ld\n", 2L * N);
}

这样可以提前找到问题。我知道有 race detector，甚至无需知道 ThreadSanitizer 的名字，就能让 AI“Compile race.c with a race detector”，检查 data race。

AI 知道要加 -fsanitize=thread flag。它的环境变量与我的隔离，我这边有环境变量，已经编译成功并开始运行。随后发现树莓派不支持 TSan，看看它怎么解决；我之前没试过。DeepSeek V4 Pro 先关闭 Address Space Layout Randomization 再试，仍失败，又用 QEMU 用户模式绕过，还是 Unsupported。不过，这个程序在大家的 X86 上可以正常运行，直接找到 data race。我对 ARM 经验不多，它对这些东西比我熟悉。

看它一点点解决问题，不管最终成功与否，都能学到这台树莓派或其他机器的知识，我觉得这是更现代的学习方法。它可能还会搜索互联网，我相信问题应该能解决。现在它开始尝试 Clang，认为 Clang 的 ThreadSanitizer 运行时可能处理得更好，我也想过这样试。我没有预想到它真会这样尝试，这个过程像有位老师带着学习。

它尝试改变页大小，消除 ThreadSanitizer 的 error message。它把程序跑起来了。

但这次运行仍然失败，发生 segmentation fault。它还想尝试 static 编译，我们就不再试了。上下文足够长时，它确实可能解决问题，这展示了今天 agent 和 Harness Engineering 的能力，但不再占上课时间继续尝试。

为了上课演示 ThreadSanitizer，我今天在树莓派上编译时把系统编译死机了，可能过热，我不确定，最后没有编译完。
