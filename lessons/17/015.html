第 17 课 · 并发 Bugs 和应对

常见错误：上错锁和忘记上锁

原片 00:46:55—00:49:45

但从这几个例子来看，你们会觉得 data race 是一个我不太可能发生的事情，对吧，我怎么会蠢到不上锁呢？其实不是的，你最常见的错误是这样的，你们不是不上锁，你们也知道任何共享的数据结构都要保护，但是当你的数据结构越来越复杂的时候，就像一个链表，我前面讲，互斥锁的时候，你这 Lock Data Structure，你为了访问这个节点的时候，你不仅要持有它的锁，你还必须要持有它的 Previous 和 Next 的锁，否则你对它做任何结构性的修改。

void T_1() { mutex_lock(&A); sum++; mutex_unlock(&A); }
void T_2() { mutex_lock(&B); sum++; mutex_unlock(&B); }
void T_1() { mutex_lock(&A); sum++; mutex_unlock(&A); }
void T_2() { sum++; }

其实都是错的，所以你们实际上发生的是，第一上错了锁，对吧，我在一个线程里面 Lock A，另一个线程里 Lock B，你看起来是互斥了，但其实没互斥，你这两个 sum 还是可能会发生这样的 data race，sum++ 这个就是又有 ReadWrite，又有 WriteWrite 的data race。然后第二个 Case 是，你在一些比较罕见的路径上面，你就忘了上这把锁，这也是很有可能的，对吧。比如说你可能在Ctrl+C 那个 handler，在异步事件的处理上。

在那个路径上，你忘记了这个代码还会并发的，你忘了上锁，它就形成了一个 data race，data race 可是 UndefinedBehaviour，它很有可能会有比较毁灭性的后果，当然了，你也会说，无非就是那两种情况，我只要保持大脑清醒就行，不过我觉得现在，比如说你们要实现一个像那种高性能的 malloc，你想要上锁。

比如说你第一遍没做对，你只要让 AI 直接仔细的分析一下，每一个地方应该上什么锁，哪一些是共享变量，哪些是共享数据结构，它真的能给你做对，所以这还是，还是件很离谱的事情，以前让你们要受很多苦的，我觉得应该有很多同学偷偷让 AI 帮你们修代码了，反正它一下就修了。然后它修了以后也就是加一行代码。对吧，加一个 Lock，加一个 Unlock。然后那代码就神奇般的对了，曾经我们要花很大的代价才知道。但是 AI 很清醒，它大脑很清醒，以前我们。我觉得这也很有意思。以前我们要花很长时间。给同学建立这些概念，什么是 data race，对吧，在什么时候会发生 data race，我们如果一门课讲的像百度百科一样，它最大的问题，就是你们不 make sense，它说的每句话都对，但是你不理解它背后的，比如说我现在要讲说，你们遇到的都是这种情况，上错了锁，忘记上锁。但是在实际当中，它们是怎么发生的，只有你自己被这个死锁，或者被这种数据竞争坑过，你才知道，在那种地方会有一些犄角旮旯的 sum 加加，你确实是很，对人来说确实很容易忘记。然后我们以前的办法就是让你们做实验。

做实验的时候，你们会体会到很多有趣的 data race。
