第 17 课 · 并发 Bugs 和应对

死锁与同一线程重复获得一把锁

原片 00:02:53—00:05:32

死锁是指一个群体中的每个成员都在等待其他成员采取行动，也可以自己等自己：A deadlock is a state in which each member of a group is waiting for another member, including itself, to take action。图中是去年 11 月班上同学的投稿，事情真实发生过。我觉得条件挺苛刻：公交车头尾连在一起，没有一辆能继续前进。并发程序也可能遇到这样的情况。死锁有多种类型，先看 AA 型：同一个线程重复获得同一把锁。之前讲保护 sum++ 时，t1 先 lock，再执行 sum++，最后 unlock；所有线程必须用同一把锁，且假设 lock 和 unlock 配对。讲信号量时提过一种特殊用法：在 main 中先 acquire 一把锁，再到另一个线程中 unlock。

例如由 t1 release 建立 happens-before。不过通常的互斥用法是：t2 也 lock 同一把锁，等待 t1 unlock 后重新获得锁，再执行 sum++。之前没有讲的是，同一个线程 lock 任意一把锁之后，再 lock 一次，会发生什么？

站在操作系统或 API 设计者的角度，可以考虑两种实现。其中一种是维护计数器：lock 一次加一，再 lock 一次减一。获得锁之后，这个计数器可以由线程本地维护。两个 lock 必须有两个 unlock 配对才能解开：第一次 unlock 只把计数器减一，还没减到零；第二次 unlock 才能释放锁。

实际行为是否如此？我已经告诉大家，这叫 AA 型死锁。学线程库时，即使课上没有讲，也可能自然想到这个问题；以前要写程序验证，却比较麻烦。
