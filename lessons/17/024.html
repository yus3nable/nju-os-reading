真实系统中的并发 bugs 与 ABA

原片 01:14:30—01:17:40

ASPLOS 2008，2008 年对吧，真的是上一个时代，20 年以前的工作了，后来他在 2018 年的时候，得到了 most influential paper award，他确实是他开辟了这个整个大家都去研究并发这件事的一个很好的先例，他做了一个 empirical study，一个实证研究，他去找了像 MySQL、Apache 在那个时候都是顶流级的，有最好的那些程序员，LibreOffice，OpenOffice 可能不算，有一些最好的程序员维护的项目。

比如说你看，Mozilla 的 Firefox，Rust 就是他们的团队里面出来的，都是很顶级的程序员，他们依然有 105 个真实的系统里面的并发 bug，然后他们去把这些 bug 找出来，Learning from mistakes。然后去观察是不是存在有意义的结论。所以他们找到结论就说，这些像 ABA 这样的问题，在现实中程序员还是会写出来的，比如说比如说这个 atomicity violation，这个例子其实是一个 data race，大概是，这是一个非常常见的模式。

跟你们的支付宝，支付宝是一样的，支付宝是说我先用 if 判断，判断一个条件是不是满足，然后这个条件如果满足的话，我就可以做了，对吧，如果我身上的余额大于，大于那么多钱，我要扣掉的钱，我就可以把这个钱扣掉了，就像这个如果我的这个指针不是空，我就可以往这个指针里面写东西，结果，哪怕是你上着锁，你有一个有一个别人把资源释放掉了，你这个就是一个 crash。然后这样的 ABA 型的问题，其实很多，它不仅出现在，像，像这种 data race 的情况，还有什么呢？你可以 use-after-free。

你有另外一个线程，比如说你把这个指针，交给别的线程了，然后别的线程，或者说你的整个系统认为，这个指针再也不会访问了，它就把它安全的 free 掉了，free 掉了以后，这里面就变成 use-after-free，它去读一个读一个已经 free 的内存。

检查与使用 proc_info 的片段，其余语句省略：

if (thd->proc_info)
{
  fputs(thd->proc_info, ...);
}

这是非常危险的，因为你可能会读到不属于你的数据，你就可能有隐私泄露，内核里面有很多这种，use-after-free 的，这种严重的安全，安全漏洞，当然如果你 free 的时候，同时把这个指针，清掉了。比如说改成 NULL 了。那这个程序也可能，发生一个crash，这样的问题，不仅在你的程序里会发生，在你的系统里面，也会发生。

比如说就刚才那个例子，支付宝的那个例子，就是一个叫 TOCTTOU，time of check to time of use，你检查和使用的，中间是有时间差的，对吧，你 if 什么 condition，然后你其实你是认为，是 assert 这个 condition 的，对吧，你是希望是 assert condition 的，但如果你没有正确的，实现互斥上好一把锁。那这个 assert 是有可能不成立的，支付宝就是这个例子。所以你看到条件变量，是一个非常经典的，非常好用的同步机制。

就是因为它可以保证，这个 condition 是成立的，当你用那个 while 循环，while not condition 的时候，这个 condition 是可以成立的，但是有些时候。
