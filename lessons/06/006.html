第 06 课 · (入侵) 进程的地址空间；mmap, munmap, mprotect

使用 mmap：大内存分配与文件映射

原片 00:38:20—00:47:08

再看 mmap 的实际用法。

修改地址空间，概念简单，用途却多。比如一次申请巨大内存。一个 CPU 核心每秒可能运行 10 亿到 100 亿条指令，能力有限。现在直接申请 8GB，而树莓派总共只有 8GB，操作系统和其他程序还要占用一部分，申请量已经超出可用物理内存。

#define GiB * (1024LL * 1024 * 1024)

volatile uint8_t *p = mmap(
    NULL,
    8 GiB,
    PROT_READ | PROT_WRITE,
    MAP_ANONYMOUS | MAP_PRIVATE,
    -1, 0
);

VSCode、终端也消耗内存，按这个想法，8GB 应该分配不出来。但调用能成功，随后还能在 2GB 处写 1、4GB 处写 2、7GB 处写 3。

*(p + 2 GiB) = 1;
*(p + 4 GiB) = 2;
*(p + 7 GiB) = 3;

也可以读取合法持有区域里的其他位置。运行并计时，1 毫秒左右，实际是 1.62 毫秒就完成了，为什么？

mmap 成功返回指针，2GB、4GB、7GB 都能访问，中间也可访问。但它只改变了 VR 眼镜配置。load、store、取指一次只能看到几个字节，比如 load 八字节，视野很小。操作系统先标记这块内存属于进程，真正读写某处时，才配给实际内存。

flags 的细节暂时不必记，AIGC policy 也允许让 AI 写这些代码。先知道这个 API 能新增地址空间，分配内存或映射文件，而且很快。用 strace 看 Memory Allocation，能找到申请 8GB 的 mmap，参数也对得上。

权限是可读可写，flags 是 MAP_PRIVATE、MAP_ANONYMOUS，长度对应 8GB，返回地址……6630000，也和 printf 一致。瞬间就完成了。UNIX 还强调 everything is a file，比如 procfs 文件能查看进程运行时间、command line arguments 等。mmap 因此还支持文件描述符：用 open 打开文件，再按 offset、length，把文件一部分映射进进程地址空间。

甚至能映射磁盘，比如 /dev/sda。现在用树莓派，不做这个演示。以前用 U 盘启动讲台电脑，就拥有整机控制权，能访问真实磁盘。用 128 左移 30 位指定大小：左移 10 位是 1024，20 位是 1024 平方，30 位是 1024 三次方，也就是 Gigabyte、GB。

这样能把磁盘 128G 全映射进内存。64 位地址空间的好处是能映射很大设备，比如 1TB，32 位机做不到。映射后只是指针指向地址空间新增部分，可以是新内存，也可以是文件、设备。若 memset 覆盖它，磁盘内容就没了。

也可以映射树莓派 GPIO，用指针写 0、1 控制灯亮灭。我真的用 memset 抹过一次磁盘，导致下一节课的老师出现教学事故，此后不敢再做。这些机器有还原卡，但映射物理设备的操作似乎绕过了它，说明还原卡设计有缺陷。

我也不知道怎样绕过去的，但磁盘确实被覆盖。mmap 管理地址空间，内存相关功能基本通过刚才这几个接口完成，可以向操作系统要内存。

初始 VR 眼镜里看哪里都黑，可以请求在这段放楼、那段放其他东西，像 Minecraft 堆方块。除了分配，还能做 memory-mapped I/O。比如 /dev/gpiomem 是设备文件，可以像磁盘那样映射进来，把 GPIO 引脚对应到进程地址空间。

再往外甚至能接核弹发射器。结合其他接口，还能做进程共享内存：shm_open 返回文件，实际对应共享内存，其他进程用文件描述符、mmap 就能共享。mprotect 的另一用途是动态代码。用 mmap 或 malloc 分配内存，填代码，再把可读可写改成可执行。GPT 说得对：字节、内存本身没有类型，含义由 CPU 指令集决定。PC 可以跳到可读、可执行的位置。通常出于安全考虑，普通数据不可读；若 PC 误入数据区，就可能执行恶意代码。自己生成了代码，则用 mprotect 允许执行，再跳过去。这可以实现 just-in-time 编译器。

浏览器最典型，后端 Java、JavaScript 也有 just-in-time 引擎，把慢脚本编译成较快机器代码，再跳转执行。一边运行、一边生成代码，需要 mmap 等相关功能。
