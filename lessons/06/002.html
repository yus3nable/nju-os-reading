第 06 课 · (入侵) 进程的地址空间；mmap, munmap, mprotect

地址空间、指针与 volatile

原片 00:03:55—00:12:54

先看进程地址空间。AI 给出标准答案：Address Space 是操作系统为每个进程提供的独立、连续的虚拟内存地址范围，也叫虚拟地址空间。计算机系统基础课已经介绍过。它用于隔离和保护，比如上次 fork 实现 DFS，各分支进程有独立内存副本，像模型中每个进程自己的 memory，互不干扰。两个进程可以写同一地址，实际写到不同内存，便于扩展和管理。程序还可以认为自己拥有大片连续内存。今天会看到，分配巨大内存能瞬间完成，但实际上还没真正给它，像先画一个大饼，吃的时候才逐渐做出来。此外，在隔离前提下，也允许有限共享。

这是 GPT-5.4 给出的教科书式定义，但也可以更直观。AI 要成为好老师，可能需要相应 prompt。写教科书时，作者已经理解知识，再反向总结；学习则可以正向构建，从历史早期或最简单模型出发。

从简单模型理解现代系统，换个等价角度看地址空间：进程由程序构成，指令里有 load、store。

地址空间与指针

load、store 都需要地址、位宽，也可能有 mask 等其他信息。它们从内存地址取值或写入数据。内存是按字节寻址的序列，地址空间就是进程能访问的这个字节序列。在编程语言中，通过指针访问。比如代码定义 volatile char、pointer，可以给 pointer 赋数值。

从键盘输入任意 64 位整数，把它当成指针，就能尝试 load、store。两种操作在编程语言意义上合理，但操作系统未必允许。比如空指针，可能导致 segmentation fault，程序 crash。

编程课经常遇到，今天 AI 也常写出触发 segmentation fault 的代码。那对于 64 位机的 C 程序，从 0 到 2 的 63 次方减 1，每个位置都能有 pointer 指向它，尝试 load、store 会怎样？

代码、数据、堆、栈都在同一地址空间。弄清楚 64 位机从 0 到 2 的 63 次方减1 这个可寻址数组里，各处能读写什么，就理解了进程地址空间。

可以让 AI 写程序验证。先做个 quiz：这里为什么需要 volatile？它和 C++ 的 keyword const 相似，都能修饰有内存地址的对象。const 表示只能读、不能写，volatile 表示对这块内存的访问不能优化。这里有一次 load，但没有把结果赋给任何变量，不产生效果。

如果赋给其他变量，再打印出去，最终传到 system call，就不能优化。单独这行读取没有用途，编译器可以删掉，所以用 volatile 修饰字符对应的内存，保留访问。如果要修饰这个指针，我就写 volatile char *，让 pointer 也变成 volatile。和 const 一样，可以加两个，能放 volatile 的位置也能放 const。

volatile char *ptr = input();
*ptr;       // load
*ptr = 1;   // store

以前学编程要仔细弄清这些 trick，今天不太需要自己记住了。接着让 AI 写一个 c 程序，用指针指向代码、数据、栈，打印地址并读取数据，还能发现一些现象。

uint8_t *main_code = (uint8_t *)main;

for (int i = 0; i < 20; i++) {
    printf("0x%02x ", main_code[i]);
    if ((i + 1) % 8 == 0)
        printf("\n");
}
if (20 % 8 != 0)
    printf("\n");

比如 main 可以赋给函数指针，函数指针也指向内存位置，用 printf 的 %p 能打印 pointer value。既然都在地址空间里，就能打印 main 指向的二进制代码，再反汇编，比较它和文件中的代码是否一致。运行后，能看到 main 的 address，比如 5555 开头的位置。

这里应该是数据，使用 %p 打印 global variable 地址。大致能看出，5555 附近是代码，稍高一点是数据，比如 ca0048、c80a08。

更高的某个位置是栈，也能取得栈变量地址。

还能 verify main 的 binary code。这里打印前 20 个字节，有 fd7bbda9，对照反汇编确实相符。arm64 和 x86 一样用小端，能看到 fd7bbda9 对应的汇编代码。

可以这样交叉验证，也可以让 AI 写程序扫描地址空间，随机选择 pointer，检查哪些尚不了解的位置允许 load。
