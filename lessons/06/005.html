第 06 课 · (入侵) 进程的地址空间；mmap, munmap, mprotect

地址空间管理：brk、mmap、munmap 与 mprotect

原片 00:29:03—00:38:20

现在知道，即使 minimum、最小的 a.out，地址空间也有这些内容。如果程序超出 while (1) 死循环，需要实现复杂功能呢？

比如调用 malloc 申请很大的内存。既然事情应该可行，就应该有办法。初始地址空间有 a.out、栈、vdso、vvar，先略去后两者。现在要一个 GB 或十个 GB 的数组，但指针访问空白区域会 segmentation fault，malloc 怎样实现？应该有系统调用提供帮助。

进程自己做不到，就要请求操作系统修改地址空间。未画出来的地方都是 dead zone，指针碰到就出错，比如地址零这一页默认不可访问，读写会 crash。出现空指针，也就知道程序有 bug。需要一个能申请内存的系统调用。

假设就叫 malloc，申请一兆、一百兆、一个 gb，系统从 dead zone 划出一块，允许读写，初始为零。有这样的调用，就能实现 malloc，也能构造各种地址空间布局。

依靠的是计算机系统基础讲过的 mmu、虚拟内存。可以这样理解：物理世界是一整块 memory，我是一台计算机，是 cpu internal state。后面讲并发，也会让大家想象自己是线程或计算机。物理世界相当于共享内存，但我看见的世界，未必就是真实世界，可能只是水缸里大脑看到的环境。

没人能证明自己没有处在虚拟环境。mmu 像操作系统给用户进程套上摘不掉的 VR 眼镜。进程只能执行部分指令，不能随便配置 mmu、执行系统指令，自己主要做 load、store、计算，再加系统调用。它不知道外面是否还有世界，实际上操作系统就在外面。

VR 眼镜展示什么，由操作系统配置。所有访存都经 load、store，取指也可以看成 load，都会经过 mmu。操作系统配置 mmu，就能让访存触发异常，或把访问路由到某个物理页面。

有了这套机制，系统调用就能分配内存。大家可以想几秒，怎样设计修改地址空间的接口？UNIX 的早期答案是 brk、sbrk。system calls manual 里写 change data segment size，是很有历史的 system call。早期 a.out 包括 code、data、bss：code 是代码，data 是 x 等于 1 那样的初始化全局数据。

bss 是未初始化数据。数据末端叫 break，再往后内存就不合法。sbrk 改变 break：需要更多内存，就向上移；上面的内存释放、不再需要，就向下移。这是 unix 最早改变进程地址空间的系统调用。

今天它不太够用，还有集成更多地址空间功能的 mmap。地址空间可以理解成一块块允许访问的内存，mmap 的行为很直观。

mmap、munmap 与 mprotect

// 映射
void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);
int munmap(void *addr, size_t length);

// 修改映射权限
int mprotect(void *addr, size_t length, int prot);

比如最简单的 a.out 中，有一块 8kb 可读、可写、可执行区域。mmap 从地址空间里找位置，指定大小，再加一块。

也能指定用途、权限，映射到文件，或分配新内存，功能很多。有分配就有回收，munmap 对应移除映射，甚至能只移除已分配区域的一部分。比如用 MAP_ANONYMOUS。

MAP_ANONYMOUS 表示匿名映射，申请可用、初值为零的内存。比如要 1 GB，就分配一个 gb，再把前面 512 兆 munmap，灵活修改映射。mprotect 则修改已有内存权限，比如只读改成可读可写。

或给 malloc 分配的内存填入代码，再用 mprotect 设成可执行。这让我想到一个还没实现的想法：CrazyOS 原来有 putchar，上次 vibe coding 加了 fork，还能把 mmap 等 Linux 全部系统调用加进去。

这样 CrazyOS 理论上就能运行 RISC-V 的 Linux 程序，系统调用都由用户态模拟。如果明年还开课，也许可以试这种做法。回去也能让 AI 在 CrazyOS 实现 mmap，模型足够好，应该可以一次做对。
