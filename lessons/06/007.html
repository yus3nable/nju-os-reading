第 06 课 · (入侵) 进程的地址空间；mmap, munmap, mprotect

从调试器到 Game Genie：读写另一个进程的内存

原片 00:47:08—00:56:34

学过地址空间，马上能做新的事情。今天第一个例子，接收 PID、解析地址空间，还读出了另一个进程的数据。这是调试器做的事：它本身是程序，却能读取其他程序内存。过去实现它，需要读许多手册，理解操作系统；现在还没掌握细节，也已经完成了。

只知道事情可能可行，就能借 AI 探索。访问另一个地址空间原本很难。比如 GDB 怎样打断点？目标 a.out 有一段只读可执行代码，要在某条指令上设断点，GDB 先使它可读、可写、可执行，再修改指令。X86 上改成一字节的 int3、int 指令，让程序继续。运行到 int3 就进入操作系统，ptrace 系统调用能拦截它。

控制权交回 GDB，再 patch 回原指令，继续执行。这依靠 mmap、ptrace 等内存相关调用。过去在计算机系统基础讲 GDB，要花一节课，今天回家几分钟，就能 vibe code 最小 GDB，支持在一个位置打断点，走完整流程。Code is Cheap 的今天，像又回到个人电脑兴起的 1970 年代，有 Bill Gates、Steve Jobs 等人物；2010 年自媒体兴起，人人能发视频，我也把操作系统课放到网上。最近和小朋友看“从零开始文明重启”系列，开局一把刀，像 Minecraft，自己盖房、堆窑、烧青铜器、种棉花、纺线。

再织成衣服，很好看。过去历史、化学、物理没这样教过，自媒体把知识结合起来，起点只是一个好想法。大家也常有好想法，在 2020 年、现在 Agentic AI 的时代，想法更容易实现，几分钟就能做出 GDB 这样的小原型。

再掌握工程实践，甚至能做成产品。借进程地址空间，讲一个以前的产品，它能入侵、修改内存；刚才的软件例子已经做过类似操作。

游戏卡带与中间连接装置

先看硬件。前面把 MMU 比作 VR 眼镜，更早的个人电脑没有 MMU，就有劫持物理内存的产品。内存通过总线连接计算机。DRAM 用行、列选通信号，电容存 1 bit，有导线传地址、数据、读写使能。大家可能在 Verilog 里实现过。既然是导线、电路，就能剪断，再接入自己的设备。switch 有卡仓，能插卡带，有些同学应该用过。

游戏可能有几十 GB，插卡相当于做一次 mmap，不过映射到固定地址。ROM 多大，就映射多大 size，里面有可读、可执行的代码和数据。卡带也是存储器、大字节数组。

内存控制器通过另一组线连卡带。插上后，ROM 进入游戏机地址空间，Firmware 也可能在同一空间，先启动、显示加载界面，再允许跳转游戏。小时候的 NES、红白机、小霸王，插卡开机，Firmware 执行后，就跳到 ROM 固定地址，开始游戏。

Game Genie 利用卡带与接口间的空间、裸露导线，在中间接一个硬件外挂。

它是简单的可编程逻辑，先劫持 Firmware 的跳转，让程序进入 Game Genie 界面。

界面允许输入字母，每个游戏有作弊码，比如八位、八字符的 ABCDEFG，存入 lookup table。基本规则是 address 等于 X、Data 等于 Y，就把 Data 改为 Z，也可以用 XYZ、AXY 来表示。

先逆向游戏，找特定地址、数值，再替换它。比如 game_init 初始化 life 等于 3，马里奥有三条命，这个 3 是指令中的立即数，只需在 lookup table 匹配那条指令的地址。

知道对应指令，就能替换数值，变成 99 条命。

产品会发布许多游戏的作弊码，相当于在内存意义上给卡带打一个小 patch。初始化完成后，跳回游戏，行为已经改变。我觉得这种设计很有创造力。感兴趣可以让 AI 帮忙读技术文档，这里不展开。
