malloc、free 与内存管理的约束

原片 01:10:58—01:20:53

剩下一点时间，讲 malloc 和 free。大家都用过：malloc 分配 size 大小的内存，free 释放。刚才已展示一个错误用法。

malloc 后再 free，之后就不能继续使用这个指针。C 标准库还提供 calloc、realloc、reallocarray，都可以用 malloc、free 实现，后两者是最基础的机制。

其他接口有便利之处，例如 calloc 保证 memory set to zero。现在出于安全考虑，一般 libc 中的 malloc 基本也会返回零内存，哪怕牺牲一些性能。malloc/free 是一道数据结构题，数据结构课可能会让大家实现 malloc。

malloc、free 既能处理小内存，也能处理大内存，小到一个字节，甚至可以为零。刚才手册写着：size 为 zero 时，malloc 返回 unique pointer value，之后可以成功传给 free。

尽量不要依赖这个行为。malloc 也能分配很大内存，例如 1 GB。操作系统却不支持那么细小的分配。有 sbrk 和 mmap 两种方式，理论上 sbrk 可以 set 两个、四个字节；mmap 的分配大小与系统配置有关。页大小为 4 KB 时，最终内存就是页大小的整数倍，操作系统无法分配半页。

无法向 mmap 只要两个、四个、八个字节。libc 在 syscall 之上提供 malloc，支持小块内存：先用 mmap，或更老的 sbrk，在地址空间中取得一大块可用内存，自己维护内存池。malloc(4)、malloc(8) 时，从中找出四个、八个字节的小块，将指针返回。可以让 AI 生成随机 malloc 的代码，再用 strace 看怎样分配、怎样调用系统功能，就能验证背后使用了 mmap、sbrk。

我觉得 malloc、free 是设计有问题的 API。最近去世的 Tony Hoare，1934 到 2026，称自己发明空指针是 billion dollar mistake，因为它是重要的 bug 来源。malloc、free 也类似。在 libc 中，它们像操作系统的系统调用，提供最小的完备机制，让机制与策略分离。

操作系统提供 write、read、open 等文件描述符接口，文件内容用 Unicode 还是 ASCII、怎样编码，都由应用程序负责，操作系统只管字节序列。这套 API 简单、最小，不理解字节含义也没太大问题。malloc、free 却增加了要求：任何可能路径上，malloc 都必须有配对的 free，否则浪费内存；free 后指针立刻非法，不能再用。刚才 free(p) 后紧接着 *p = 1 的代码就很危险，在 C 代码形式上合理，却违反 free 语义。理想情况是像 Rust 一样拒绝编译这样的代码。

图 115：free(p) 后继续执行 *p = 1（01:16:37）。

指针被别人拿走后，就无法在当前作用域继续访问它。C 中有很多内存引起的安全漏洞。AI、coding agent 的黑客能力增强后，发现系统漏洞的能力也更强，经常能看到 AI 在 Linux 内核等处发现 zero day，其中很大一部分由指针问题导致。很多 coding standards 要求，free 后立刻将指针置空，再次 use 时就会 crash，避免继续 use-after-free。这又遇到了 Tony Hoare 的 a billion dollar mistake：只要有一处违反指针、malloc 使用约定，程序就 crash，无法继续提供服务。为了满足 malloc、free 的要求，人类走过很多弯路：Java、JavaScript 不再暴露指针，C、C++ 则有 resource allocation as initialization，用对象管理资源。例如 Lock the object，在作用域中定义变量，初始化、构造时上锁，析构时解锁，保证退出时释放。

这里如果在 if 中提前 return，就很危险：上面有 malloc，末尾才 free，提前返回便会泄露，必须在返回处也 free。

现场用于说明提前返回的伪代码：

void foo() {
    LockedObject lk(mutex);
    ptr = malloc(4);
    for (i = 0; i ...) {
        if (...) {
            return; // Release?
        }
    }
    free(ptr);
}

这些代码很难写对，实际系统中有大量这样的 bug。C++ 采用 RAII，在作用域内使用资源，以构造器、析构器确保释放；现在 Rust 又提供 ownership。

malloc 引入的要求与文件描述符不同。write 写入数据后游标向后移动，行为和要求都简单；malloc、free 却让程序员承担很大的心智负担。若要实现它们作为作业，基本思路是：大块内存直接 mmap，向操作系统申请。例如 100 兆，头尾浪费一点也没关系。M 不大时，就成了数据结构题：维护一组互不相交的小区间。

每次 malloc，从空闲区域中找足够大的一块，将它切出，从空闲集合删除，供程序操作。学算法会得到 Balanced Binary Search Tree 的 Solution，现代 Memory Allocator 的实现则不同。
