第 10 课 · 调试 C 标准库

从 _start 单步走到 main 和 exit

原片 00:35:16—00:40:54

第一个调试例子是 crt，也就是 crt1.o 和程序初始化。先调试最小的 dummy.c，它只 return 1。strace dummy 可以看到确实由 musl libc 编译，execve 后只做了很少的几件事，随后 dummy exit，正常退出。

dummy.c：

int main() {
    return 1;
}

用 gdb dummy 可以从第一条指令开始调试。这里是 _start，这一小段应该是汇编，所以 layout source 找不到源代码。

进入第一个函数 _start_c 后，它有一个 long *p 参数。上节课讲过，从这个指针可以 reverse 出初始进程栈。也可以让豆包 read crt1.c，根据代码给出初始进程栈。

crt1.c 中的入口片段：

hidden void _start_c(long *p)
{
    int argc = p[0];
    char **argv = (void *)(p+1);
    __libc_start_main(main, argc, argv, _init, _fini, 0);
}

p 指向栈，argc 等于 p[0]，argv 是 p 加 1，再往后应该有一些字符串。现在 argc 为 1，打印 argv[0]，数值正确。继续 step 进去，看到 envp 是 argv 加 argc 加 1，打印 envp 的 0，确实是环境变量。查看 env，还能看到一些 VS Code 相关环境变量。

还可以打印 envp 的负 1，在调试器里访问 C 意义上非法的地址。p[0] 是参数数量，参数后有一个 0，再往上是环境变量，这些都能在程序中完整看到。我确定初始栈是这样的。豆包读完文件，也知道目标是 ARM64，没有假设为 x86。

不过图中的低地址和高地址写反了。

方向反过来以后，应该依次是 argc、argv，后面还有辅助向量。它也会说明这些代码在哪里。继续调试 __init_libc，上节课看过的 26 行就在这里：将 envp 赋给全局 environ 变量。

接着跳过所有 envp：从 i 等于 0 开始，只要 envp[i] 还是合法字符串就继续。每个参数都是指针，指向 null-terminated 字符串。跳过全部环境变量后，继续逐项处理辅助向量。

处理完后调用 stage2。打印它可以看到，这是指向 libc_start_main_stage2 的函数指针。跳转后，下面还有 __libc_start_init，不过这段代码应该没有执行实质内容。

接着就到 libc 中最经典的一句：自己实现 libc 时想写的那句话，确实就在这里。这个调用会进入 main。

libc_start_main_stage2 中的一行：

exit(main(argc, argv, envp));

main 返回 1，然后执行 exit(1)。exit 会执行刚才看到的清理逻辑，［听辨不清，00:40:15］，包括 __stdio_exit，最后到 _Exit，直接调用 syscall。libc 封装 system call，屏蔽其细节，上层无需了解底下是什么操作系统。

这里是一个参数的 syscall，最后调用汇编中的 syscall，程序结束。这样就看到了从 _start 接管第一条指令开始，怎样沿着 initial process stack 走到 main，以及 main 正常返回后的流程。
